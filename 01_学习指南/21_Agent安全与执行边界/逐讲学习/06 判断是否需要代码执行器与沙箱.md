# 第 6 讲：判断是否需要代码执行器与沙箱

## 本讲任务与前置

Agent工具能查询和创建，是否必须再给它任意Python代码执行？本讲判断需求与安全边界，复习单元03进程/容器、单元16超时与本单元最小权限。不运行不可信代码、不安装系统工具。

## 先问需要什么能力

用户任务只需查政策/读账户/建工单，已有明确工具即可。通用代码执行会开放文件、网络、凭据和资源的新风险，不能因为别的Agent框架有这个功能就默认加入。当前C29-01按课程原约定记不适用，原因是项目无任意执行器需求；不是忘记实现。

如果业务确需对上传CSV进行灵活分析，可以先提供有字段/算子限制的数据工具。只有明确需要用户/模型生成任意代码时，再设计隔离环境与系统级限制，并审批依赖/系统工具安装。依赖未安装前仍可写方案和测试标准，不虚称执行器已验证。

## 子进程为什么不等于沙箱

subprocess启动另一个进程，但通常继承运行用户的许多权限和环境；新进程可能读文件、联网、启动子进程。timeout是父进程等待控制，不自动约束全部后代、文件读写和内存。

同样，工作目录只是相对路径基准；换cwd不能禁止访问父目录/绝对路径。删除环境变量减少凭据暴露，也不限制文件中的凭据。禁用shell=True可减少命令解释层，但执行的程序本身仍有能力。[Python subprocess文档](https://docs.python.org/3.13/library/subprocess.html)可核对接口，不能从接口参数推出系统隔离保证。

容器提供一些进程/文件系统边界，但挂载宿主目录、特权模式、共享网络和凭据会扩大权限。Windows/Linux资源限制机制不同，不能复制一份Linux限制示例就宣称Windows可用。真正方案需要在目标平台实测。

## 最小示例：把需求变成约束表

新建`lesson_executor_scope.py`：

```python
requirements = {
    "arbitrary_code_needed": False,
    "allowed_tools": ["read_document", "create_ticket"],
    "external_network_needed": False,
    "real_credentials_needed": False,
}
print("需要代码执行器", requirements["arbitrary_code_needed"])
print("当前能力", requirements["allowed_tools"])
```

预期False和两个工具。脚本只是输出设计事实，没有任何代码执行请求；当前工具写也仅内存。判断不适用应附业务原因及替代方案，不用一个布尔值回避真正需求。

## 未来执行器方案至少包括什么

威胁模型先说明攻击者可控制哪些代码/输入、保护哪些文件/凭据、允许哪些网络、运行用户/系统平台。之后定义单任务CPU/内存/墙上时限、输出/磁盘额度、可读写目录、网络白名单、秘密注入和撤销、子进程清理、隔离重用策略。

验收在隔离环境中用合成文件测试：超时能终止整任务树；内存/输出/磁盘超限有明确错误；路径越界读写拒；网络边界拒；退出后无残留子进程与秘密；合法计算可成功。不要在主学习工作区直接运行“恶意代码”验证隔离。

执行器结果也是不可信工具输出，不能授予角色/批准。提取结果时只取允许文件/字段，检查大小与编码；审计执行ID、策略版本、资源使用和终止原因，不默认保存全部原始输入。

## 动手：完成当前项目安全报告

在Obsidian笔记写四栏：受保护资源、攻击者能控内容、强制边界、未测/残余风险。受保护资源有Alice/Bob私有账户和内存写动作；攻击者能控提议/资料文字；边界是注册表、可信context、字段、owner、路径、预算、批准与审计。

残余风险包括真实登录未实现、目录并发竞态未全面解决、真实模型注入概率未测、批准无期限/持久撤销、幂等/审计内存、hash链无签名锚点。写“不适用执行器”并附无任意计算需求、明确工具满足任务的理由。

## 常见错误

- subprocess timeout通过就说沙箱安全：还缺文件/网络/凭据/子进程/资源边界。
- 在宿主主目录跑不可信测试：隔离验证环境先建，未建不执行。
- Docker容器默认全可信：配置、挂载和系统边界需核对。
- 为了覆盖清单强行加执行器：课程明确核心为权限，确有需求后才扩展。

## 单元验收练习与答案

跟做：完成四栏报告并列6夹具、18测试的实际范围，不把作者数量写成自己已做。完成判断：哪些通过、哪些不适用、哪些待测清晰。

独立：一个分析工具只需求CSV列平均，是否必须允许任意shell？给较小能力设计。

迁移：假设确需任意代码，写执行器审批与验收计划，明确目标平台、隔离技术、安装依赖、保护目录和每类失败测试；只做方案。

> [!example]- 参考答案与解析
> 明确CSV文档ID、列名和统计操作enum，由受控解析器检查权限/行数/输出；无需shell。灵活性需求增长时再评估执行器，避免把整个系统权限当方便工具。
>
> 方案还要具体下载/安装位置与影响，按工作区依赖规则获批，再在目标隔离环境验证。未运行不要把时间/内存/网络限制写成已通过。

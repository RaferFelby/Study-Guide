## 本讲任务与前置

权限正确仍需限制读哪个文件、读多少次和返回多少字节。复习pathlib/with/字节数；本讲不接受模型提供任意路径，只由文档ID映射受信文件。没有建立操作系统文件沙箱。

## 文档ID与路径区别

document_id是应用定义的资源名，policy映射fixtures/policy.txt，alice-account映射alice.json。模型不传文件路径；`../secrets.txt`被当未知ID拒绝，不参与路径拼接。注册表则由应用维护，必须防其配置错误。

Path的`/`是路径拼接，不是数学除法。resolve(strict=True)读取实际路径并解析链接/父目录，要求存在；is_relative_to(root)按路径关系检查是否在根下。字符串startswith会把documents-other当documents前缀，不能代替路径检查。

[Python pathlib文档](https://docs.python.org/3.13/library/pathlib.html)解释路径机制。resolve并不锁定文件：检查后文件被别人换成链接仍可能发生竞态，称检查与使用之间的时间差。当前夹具目录由应用受控只读，不声称解决攻击者并发改文件的全部情况。

## 最小示例：看父目录越界

新建`lesson_path.py`：

```python
from pathlib import Path

root = (Path(__file__).parent / "fixtures").resolve(strict=True)
inside = (root / "policy.txt").resolve(strict=True)
outside = (root / ".." / "runtime.py").resolve(strict=True)
print(inside.is_relative_to(root))
print(outside.is_relative_to(root))
```

预期True、False；runtime.py确实在工程内，但不在允许文档根fixtures内，所以仍越界。边界不是“整个仓库都能读”，而是当前工具需要的最小资源范围。

如果strict resolve因环境沙箱报PermissionError，先记录实际路径/权限，不能改成不检查只为跑通。作者同共享解释器正常桌面进程验证结果见验证记录；这个差异不表示所有Windows都有问题。

## 单文件和会话资源上限

每次最多读4097字节：若得到4097，说明超过4096上限并拒绝，不继续读完整大文件。累计成功读取输出不得超8192字节；会话最多6次工具尝试，拒绝也占次数，防无穷攻击重试。

这三项分别限制单文档大小、会话输出、调用数量。它们不限制CPU、内存总量或网络；工具没有网络/任意计算接口。别把局部预算称全系统资源隔离。

## 动手：用自己的临时文件实验超限

新建`lesson_limits.py`：

```python
from pathlib import Path
from tempfile import TemporaryDirectory
from runtime import ToolRuntime, TrustedContext

with TemporaryDirectory(dir=Path(__file__).parent) as directory:
    root = Path(directory)
    (root / "policy.txt").write_text("x" * 4097, encoding="utf-8")
    runtime = ToolRuntime(root)
    result = runtime.execute("read_document", {"document_id": "policy"}, TrustedContext("alice"))
    print(result["error"]["code"])

runtime = ToolRuntime(Path(__file__).parent / "fixtures", max_calls=1)
runtime.execute("missing", {}, TrustedContext("alice"))
result = runtime.execute("read_document", {"document_id": "policy"}, TrustedContext("alice"))
print(result["error"]["code"])
```

预期document_too_large、call_budget。TemporaryDirectory只创建/清理你本脚本的文件，不改fixtures。先调用unknown仍花一次预算，第二次正确请求也被预算拦住。生产可以按用户/会话分类限制，当前每runtime一份串行会话计数。

## 字符、字节与编码

中文UTF-8通常多字节，4096字节不是4096汉字。先按原始字节限制，再decode UTF-8；invalid_encoding返回明确错误。read_document未支持PDF/任意二进制，应走单元12的受控解析，不直接让模型拿二进制字节。

total_bytes在读取和预算检查后计入，即使后续解码失败也消耗该读取额度，是保守策略。失败大文件不会把完整内容返回。模型推断出另一个路径不改变ID注册表。

## 常见错误

- 用字符串前缀检查：换成解析后的路径关系；还要受控目录/避免攻击者改配置。
- max_calls只数成功：失败可无限刷，资源仍耗，按尝试计。
- 所有读取都先read_text再长度检查：大文件已经全部进内存，先有界读取。
- 挂载整个用户目录让模型方便找资料：为工具提供最小目录/只读数据，不挂凭据和工作区全部内容。

## 练习与答案

跟做：根内True/根外False；4097字节拒；一次拒绝也用完预算。完成判断：解释三类预算约束什么。

独立：4096字节刚好上限应允许吗？4097为什么多读1字节而不是读全部？

迁移：为图片/CSV工具分别设计允许类型、最大字节、解析行数、输出字段和访问范围，不直接开放任意文件。

> [!example]- 参考答案与解析
> 4096允许，4097证明超限。多读1即可判断是否还有内容，限制内存占用；并不能代替OS内存限制。
>
> CSV可受控ID映射、文件大小/行数/列白名单与用户范围；图片限制类型/解码尺寸/输出描述。解析器自身仍可能耗资源，真实执行需更强的进程/容器和限制方案，不靠一个Python长度判断保证。

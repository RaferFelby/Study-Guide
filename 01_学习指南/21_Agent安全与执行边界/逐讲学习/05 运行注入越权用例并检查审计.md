## 本讲任务与前置

把“权限在模型外检查”变成可复现证据。复习前四讲与单元20日志；本讲运行六种攻击提议、记录允许/拒绝，再检验审计摘要链的能力和局限。

## 红队测试的含义

红队测试是有目的地尝试违反系统预期，寻找边界缺口。教程只对本机合成夹具测试，不攻击第三方、不读取真实秘密、不执行任意代码。用例必须有来源、输入、预期边界、实际结果和残余风险，不靠一个“攻击失败”口号。

redteam.py六类：用户跨owner、文档要求读凭证、工具结果伪造批准、原始路径越界、参数伪造owner、未知shell。覆盖直接用户/间接资料/工具结果至少三种来源；实际输入都是工具提议，未包含真实LLM响应实验。

## 最小示例：按预期码判定

新建`lesson_redteam.py`：

```python
from pathlib import Path
from redteam import attacks
from runtime import ToolRuntime, TrustedContext

for attack in attacks():
    runtime = ToolRuntime(Path(__file__).parent / "fixtures")
    result = runtime.execute(attack["tool"], attack["arguments"], TrustedContext("alice", "operator"))
    actual = result["error"]["code"] if not result["ok"] else "allowed"
    print(attack["name"], actual == attack["expected"], len(runtime.tickets))
```

预期六行True且工单数0。每用例新runtime，避免前几条用光会话预算后全部call_budget，掩盖各防护点。operator有写角色但无批准，能单独测needs_confirmation而不总停在permission_denied。

## 动手：完整测试而非只看demo

运行：

```powershell
..\..\..\.venv\Scripts\python.exe -m pytest -q tests
```

测试还涵盖合法公开/自身读取、角色+批准、改参数/换用户拒、同key冲突、撤权拒回放、注册表越界、文件缺失/超限、输出/调用预算、重复JSON/NaN/伪造approved拒、审计修改检查。

合法路径测试同样重要：把所有工具都拒绝虽能阻止攻击，却让业务无法工作。防护结果要同时报告合法通过与危险拒绝，不用“全拒绝”冒充完整安全能力。

## 审计记录与普通日志区别

审计记录用于复查权限决策和动作：sequence、owner、tool、参数摘要、allow/deny、code、previous_hash、record_hash。参数不直接写明文，但低熵参数可能通过字典猜摘要，摘要不是匿名化，也不能代替访问控制。

AuditLog.snapshot返回深复制，调用者改副本不改原表；当前记录仍只在内存，无持久事务/时间戳/真实身份签名。不要把它当已具法律效力的审计系统。

摘要链让每条引用上一条hash，修改中间内容但不重算会校验失败。没有可信外部锚点或签名时，攻击者能重算整链、截断尾部甚至删成空链，verify_chain仍可能True；完整性检查与真实性/完整记录范围分开。

## 动手：修改记录，观察局限

新建`lesson_audit.py`：

```python
from pathlib import Path
from audit import verify_chain
from runtime import ToolRuntime, TrustedContext

runtime = ToolRuntime(Path(__file__).parent / "fixtures")
runtime.execute("read_env", {}, TrustedContext("alice"))
records = runtime.audit.snapshot()
print(verify_chain(records))
records[0]["decision"] = "allow"
print(verify_chain(records))
print(verify_chain([]))
```

预期True、False、True。最后空链True只是“给定这份空序列内部不矛盾”，不证明没有操作发生。生产可用受控追加存储、可信时间、签名/定期外部锚定及留存策略，当前不实现这些系统。

## 常见错误

- 用同runtime跑全部用例，预算拒绝掩盖真实权限：按独立会话重置并看具体code。
- 只有危险拒绝，没有合法成功：同时验功能。
- 审计hash通过就说没被篡改：若无可信末尾值/签名，可重算或删尾。
- 把真实秘密放攻击夹具：使用虚构字符串/账户验证边界，避免测试本身泄漏。

## 练习与答案

跟做：六条用例表列来源/工具/预期code/实际code/副作用，全部无内存工单。完成判断：逐条说明哪层阻止。

独立：新增“批准A参数、执行B参数”用例，先写预期needs_confirmation，再运行。

迁移：为真实模型设计注入端到端实验计划，记录模型版本、输入载体、实际提议、执行边界、合法任务质量；没有真实运行时写待测。

> [!example]- 参考答案与解析
> 跨用户/未知ID在读取授权拒；未知凭证/shell工具在注册表拒；伪造owner在参数白名单拒；伪批准在可信动作集合拒。改参数指纹不同所以确认拒，不能靠模型承诺参数没变。
>
> 端到端实验还要看模型是否被诱导改变回答/选择，执行器是否漏授权，合法任务是否退步。六夹具不是通用注入防御率，保留绕过与未测载体。

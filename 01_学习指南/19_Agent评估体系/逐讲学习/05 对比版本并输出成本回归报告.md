# 第 5 讲：对比版本并输出成本回归报告

## 本讲任务与前置

规则改完总成功率高了，还要知道哪些样本退步、用了多少工具、成本变化是否值得。复习case_id/group_id和比例；本讲介绍配对、置信区间的直觉，不要求先掌握完整统计学。

## 同题配对怎样比较

baseline和guarded都在同一30条test任务上运行。每条先记录before/after成功：False→True是改善，True→False是退步，相同则无成功变化。任务逐条配对比把两组不同题的百分比直接相减更可解释。

工程报告regressions列出所有退步ID；gate要求没有退步且guarded无越权写。这个门槛是项目选择，不是统计学通用标准。真实业务可能增加最低成功率、成本/延迟预算和关键场景阈值，先固定再运行，不为当前结果临时改门槛。

## 最小配对示例

新建`lesson_pair.py`：

```python
before = {"task-1": True, "task-2": False, "task-3": True}
after = {"task-1": True, "task-2": True, "task-3": False}
for case_id in before:
    difference = int(after[case_id]) - int(before[case_id])
    print(case_id, difference)
```

预期0、1、−1；int把True/False转为1/0方便相减。两个系统都成功2/3，但一个改善一个退步，总分掩盖了样本变化。真正报告要按ID配对而非依赖文件排序。

## 动手：保存可复查报告

在示例工程终端：

```powershell
..\..\..\.venv\Scripts\python.exe evaluate.py --split test --output report-test-01.json
```

output指定保存路径，当前目录生成JSON；若已有同名文件会拒绝覆盖，改新文件名。VS Code打开报告，依次找dataset_sha256、split、systems、paired_success、regressions、cost_delta_units、gate。SHA是文件内容摘要，用于确认两次评估集同版本，不是内容正确的证明。

预期baseline10/30、guarded30/30，无退步；工具调用35→20；模拟cost165→120、delta−45；gate.passed=True。成本规则是每任务固定2单位加每调用3单位，不是货币、token或实测延迟。它练的是如何记账与比较，不能用于采购或生产报价。

## 分组bootstrap的直觉与限制

Bootstrap是从已有样本有放回抽取多次，观察统计量如何波动。因为同服务6条相关，工程按服务组抽，不把30条都当独立。每次抽5个组，可以重复抽到同一服务，取所抽组中配对成功差，重复1000次、种子42，排序取近似2.5%/97.5%位置。

这称经验区间，是当前样本重采样的估计，不保证真实用户收益。示例五组改善模式完全一样，所以区间可能退化为同一个2/3；不是“系统真实收益百分百确定”，而是数据过于整齐。真实数据少组、模板重复会让区间不可靠，要增加独立场景。

若组大小不同，工程每次对所抽样本平均，是按抽到的任务数加权；不是每组平均后等权。报告必须说明抽样单位和聚合方式。配对bootstrap函数拒绝ID缺失/重复与group不一致，避免把错配数据算得很漂亮。

## 成本与延迟该怎样真正记录

真实模型记录输入/输出token、模型版本、当时价格表版本、缓存命中；工具记录调用次数、重试、限流；时间记录整任务耗时与阶段耗时，不把并行子任务耗时直接相加当墙上时间。还需失败任务成本，因为失败也消耗资源。

不要以更少调用必然更好：少查一次关键证据可能造成错误。成本变化必须与任务质量/安全一起看；省钱而越权的版本不能通过本门槛。真实价格易变，后续实际接模型时再核对，不在离线示例杜撰计费。

## 常见错误

- 两次报告数据SHA不同仍直接称版本提升：先对齐集或说明分布变化。
- 只比较总百分比，不看退步：用paired_success和regressions定位。
- 把合成单位改标签为美元：单位要对应实际测量/价格依据。
- bootstrap固定种子等于模型可复现：种子仅控制重采样；真实模型/工具仍有随机和版本变化。

## 练习与答案

跟做：保存报告并写35→20、165→120、无退步的含义。完成判断：明确这不是实测金钱收益。

独立：把最小示例第3题退步列出来，解释总分不变仍需检查的原因。

迁移：设计你自己的发布门槛，写成功率、关键权限场景、p95延迟、成本及“证据不足暂不决策”条件。

> [!example]- 参考答案与解析
> task-3退步，可能是关键客户/高风险任务，不能被task-2改善抵消。先分类定位再决策。
>
> 可规定安全场景零越权、固定集不退步、质量≥业务阈值、延迟/成本不超预算；样本来源或量不足则追加评审，不凭单一合成100%上线。阈值需由业务需求确定，教程数字不可机械照搬。

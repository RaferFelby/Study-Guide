## 学完后你会做到什么

你会知道“能重新运行程序”和“能复现实验结论”之间的差别；能记录随机种子、数据版本、配置快照、依赖和结果；能用一条 README 命令重做示例实验并判断主要结果是否一致。

## 1. 什么叫可复现

如果今天运行一次、下周在另一台机器运行一次，主要结果仍能在合理范围内重现，并且别人知道使用了什么输入和配置，这次实验才有复现基础。

可复现不一定表示每个字符都相同。日志时间、临时目录、硬件并行顺序可能变化；需要事先定义“主要结果”是什么。例如本示例要求种子、数据版本、轮数、分数列表和平均分记录，允许 JSON 空白或运行时间不同。

## 2. 随机数为什么会影响结果

随机函数每次可能给出不同值。下面的程序如果不固定来源，输出可能变化：

```python
import random

print(random.random())
```

示例工程使用 `random.Random(seed)` 创建一个局部随机数生成器：

```python
generator = random.Random(7)
scores = [generator.random() for _ in range(3)]
```

同一 Python 版本和同样调用顺序下，给同一个 seed 通常得到同一序列。seed 不是“让结果正确”的开关，只是把一次随机过程固定下来，便于比较改动前后差异。

局部生成器比到处调用全局 `random.seed()` 更容易管理，因为函数不会悄悄改变其他模块的随机状态。真实训练还可能有 NumPy、PyTorch、数据加载器等多个随机来源，都需要按框架记录和设置。

## 3. 数据版本和配置快照

仅记录 seed 不够。如果输入数据、清洗规则或轮数变化，结果仍会变化。示例命令把两项关键证据写入结果：

```powershell
..\..\..\.venv\Scripts\python.exe -m reprokit.experiment `
  --seed 7 `
  --data-version demo-v1 `
  --rounds 10 `
  --output results/run.json
```

PowerShell 续行符是反引号；也可以把命令写成一整行。`--seed` 是随机种子，`--data-version` 是输入版本标签，`--rounds` 是配置，`--output` 指定结果文件。

运行后打开 `results/run.json`，应看到类似：

```json
{
  "config": {"seed": 7, "rounds": 10},
  "data_version": "demo-v1",
  "mean_score": 0. ...,
  "scores": [ ... ]
}
```

这里的数字以本机实际输出为准。配置快照的价值是：几周后不必猜“当时到底用了几轮、哪个 seed”。

## 4. 一条命令复现主要结果

README 中的一键命令应该包含准备环境、运行入口和判断方式。示例工程把主命令写成 `python -m reprokit.experiment ...`，而不是让学习者记住要先打开某个源码文件并手动改变量。

用同一命令运行两次，比较两个 JSON 的 `config`、`data_version`、`scores` 和 `mean_score`。若相同，说明这个示例的固定随机过程可重复。把 seed 改成 8 再运行，结果应改变；这证明 seed 确实参与了实验输入。

## 5. 实验追踪最小记录

初学阶段不需要立刻接入数据库。先用一个结果文件记录：

| 字段 | 例子 | 为什么要记 |
|---|---|---|
| `seed` | `7` | 固定随机过程 |
| `data_version` | `demo-v1` | 指明输入数据 |
| `rounds` | `10` | 指明实验配置 |
| `scores` | 数字列表 | 保留细节，便于复核平均值 |
| `mean_score` | 平均分 | 便于比较主要结论 |
| 代码/依赖版本 | Git 提交、Python、工具版本 | 知道用什么程序得到结果 |

机器学习实验还应记录模型、训练轮数、学习率、硬件、数据切分、评估集和失败运行。记录越完整，越容易判断差异来自代码、数据还是环境。

## 6. 动手操作

1. 按 README 的命令运行实验两次。
2. 保存结果文件，比较两次主要字段。
3. 把 seed 改为 8，观察结果变化，并说明这是预期行为。
4. 写一份自己的实验记录：命令、日期、Python 版本、seed、数据版本、配置、主要结果、异常和下一步。
5. 在 `tests/test_experiment.py` 保留“同配置结果相同”的自动测试。

## 7. 常见错误

- **只记 seed，不记数据版本：** 输入变化后无法解释结果差异。
- **把随机结果硬编码成永远正确的答案：** 应验证可重复关系和主要指标，不要假装跨所有环境完全相同。
- **覆盖旧结果：** 每次实验可使用不同文件名或记录时间/提交号，避免丢失历史证据。
- **把日志时间戳当实验结果：** 时间是运行元数据，不是业务指标。

## 8. 练习与答案解析

**跟做：** 用 seed 7 运行两次，确认结果文件的主要字段相同。

**独立：** 在 README 中加入一条“改变 seed 后结果应不同”的检查说明。

**迁移：** 设计一个文本分类实验的最小复现记录，至少列出数据版本、随机种子、模型版本、评估集、配置和指标。

> [!example]- 参考思路（先完成再展开）
> 复现记录要同时包含“输入是什么”“程序怎么运行”“结果是什么”。文本分类至少需要数据集版本与切分、标签映射、模型/权重版本、seed、关键超参数、评估指标和运行命令。若只保存最终准确率，别人无法判断使用了哪一批数据。

完成标准：你能用一条命令生成结果，能解释 seed、数据版本和配置快照各自解决的问题，能区分“结果相同”与“实验过程证据完整”。

## 要解决什么问题

上一单元按词项重叠检索，所有命中词几乎一视同仁。但“service”每段都有，“retention”更能区分主题；一段重复十次关键词，也不应无限增加可信度。BM25 是一种根据关键词计算文档相关分数的经典排序方法。

它属于**稀疏检索**：文本表示通常以巨大词表为坐标，一个片段只包含少量词，大多数坐标为零。稀疏并不是“资料少”，而是表示中零值多。BM25 主要奖励精确词项匹配；它不会仅凭直觉知道 cancel 与 cancellation 同义。

本讲需要会使用除法、自然对数 `log` 和 Counter。`Counter` 是统计“元素出现几次”的字典型工具。自然对数的具体推导可稍后学，先理解它把数量变化压缩成平缓权重。

## 先做最小分词实验

在示例工程新建 `inspect_bm25.py`，输入：

```python
from collections import Counter
from retrieval import tokenize

words = tokenize("Storage retention: 30 days. Storage policy.")
counts = Counter(words)
print(words)
print(counts["storage"], counts["retention"])
```

运行共享解释器，预期词列表为 `['storage', 'retention', '30', 'days', 'storage', 'policy']`，两项次数为 `2 1`。`tokenize` 先转小写，再用正则找英文字母和数字的连续串，忽略标点。这是英文夹具的简化，不支持通用中文分词，也把邮箱拆成多个词。

若将 query 写成中文，这个示例可能只留下其中的数字或英文词；“无命中”不能证明中文资料不存在。中文接入要改变分词器，并重建词表、索引和标注对照。

## BM25 的三个直觉

**词频 TF**：词 t 在当前片段 d 出现多少次。出现过通常比没有强，但次数增长的边际收益应变小。

**文档频率 DF**：多少片段包含词 t。若全库都含一个词，它对区分片段帮助较小。**逆文档频率 IDF**根据 DF 给稀有词更高权重。

**长度归一化**：长片段更容易偶然包含关键词，因此要考虑当前长度相对平均长度。它是统计修正，不代表短片段永远更好。

本工程选择正值 IDF 变体：

```text
IDF(t) = log(1 + (N - DF(t) + 0.5) / (DF(t) + 0.5))
贡献(t, d) = IDF(t) × TF(t,d) × (k1 + 1)
            / [TF(t,d) + k1 × (1 - b + b × len(d) / avg_len)]
总分 = query 中不同词的贡献之和
```

`N` 是片段总数，`len(d)` 是词数，`avg_len` 是平均词数。`k1=1.5` 控制词频饱和，`b=0.75` 控制长度修正，是本工程选择，不是唯一标准。原始 BM25/IDF 有不同变体，应固定实现再比较。机制可参考 [Stanford IR 教材 BM25](https://nlp.stanford.edu/IR-book/html/htmledition/okapi-bm25-a-non-binary-model-1.html)。

## 手算一次，再看代码

假设库里 3 段，只有 1 段出现 storage；当前段 storage 出现 1 次，长度等于平均长度。

1. IDF = `log(1 + 2.5 / 1.5)`，约 0.981。
2. 长度项 `1 - 0.75 + 0.75 × 1 = 1`。
3. 词频项 `1 × 2.5 / (1 + 1.5) = 1`。
4. 该词贡献约 0.981。没有该词的片段，TF=0，贡献为零。

若 storage 重复两次，词频项变成 `2 × 2.5 / (2 + 1.5)`，约 1.429，贡献约 1.401，增幅小于翻倍。这就是“重复有帮助，但不无限放大”。

打开 `retrieval.py`，按顺序看 `_bm25_scores`：先取语料总数；逐段取 Counter 和长度；逐个 query 不重复词计算 IDF；用当前词频和长度算贡献；最后把每段总分加入列表。`set(tokenize(query))` 去除 query 重复词，是教学简化，不模拟 query 词频加权。

`zip(self.tokens, self.lengths)` 把同一位置的 Counter 和长度配成一对。两个列表来自同一语料，必须保持顺序和数量一致；否则分数会配到错误片段。

## 动手检索

把下面完整脚本保存为 `inspect_search.py`：

```python
from pathlib import Path
from data import load_dataset
from retrieval import Retriever

documents, _ = load_dataset(Path(__file__).parent / "fixtures")
retriever = Retriever(documents)
for hit in retriever.search("storage retention period", "bm25", top_k=3):
    print(hit.document.document_id, round(hit.score, 3))
    print(hit.document.text)
```

`_` 是惯例：接收返回值但本次不使用它；没有特殊魔法。`top_k=3` 表示只展示前三名。`round` 只用于显示，内部排名使用完整精度。预期第一段为 `storage-retention`，分数正值；后面可能有其他 storage 或 retention 段。相同分数按 ID 排序，保证可复跑。

再换成 `How long does storage keep records?`。资料使用 retention，没有 keep/records。你会看到精确词匹配变弱。先记录 gold 是否还在前三，再去第 4 讲使用查询改写；不能根据“程序返回三条”就认定检索成功。

## 权限与分数边界

`search` 先构造允许访问的片段索引，再从允许项中选择候选；当前全局 BM25 统计/LSA 拟合仍使用全部语料。示例不会返回隐藏正文，但这不是严格多租户统计隔离：真实系统可能需要租户级索引、过滤下推和时序侧信道评估。

正分数表示匹配信号，不表示“能回答”。不存在的服务也可能命中 retention 的片段。返回前必须保留来源与权限，回答层还要核实问题约束。

## 常见错误与练习

分母报错或空词表：检查是否全是空文字、分词器是否适配语言。IDF 数值不同：先核对公式变体、片段数、分词结果；不要先怀疑 Python 的 log。

**跟做：** 把上面的 TF=2 手算用 `math.log` 核对。完成标准：解释每个数字的来源。

**独立：** 计算 N=10、DF=10 和 DF=1 的 IDF，比较权重；再解释“频繁出现”的两种不同含义：当前段内频繁、全库广泛出现。

**迁移：** 为包含精确产品编号、错误码和同义问法的 FAQ 设计 6 题，预测 BM25 哪些擅长、哪些容易失败，再用实际结果验证。

> [!example]- 参考答案与解析
> DF=10 时 IDF≈0.047；DF=1 时≈1.992。高 TF 可以增加当前段贡献，高 DF 会降低区分权重。错误码如 E401 适合精确匹配；“断网”和“网络连接失败”需要语言合适的分词、改写或语义模型。BM25 不能替代身份校验，排名分数也不是概率。

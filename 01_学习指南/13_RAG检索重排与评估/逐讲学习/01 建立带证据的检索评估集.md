# 第 1 讲：建立带证据的检索评估集

> [!nav] 页面导航
> [[01_学习指南/13_RAG检索重排与评估/00 RAG 检索重排与评估学习地图#学习顺序|单元 13：RAG 检索重排与评估]] · [[01_学习指南/13_RAG检索重排与评估/逐讲学习/02 手算 BM25 并运行关键词检索|下一讲]]

## 要解决什么问题

你搜索“storage 可以保留记录多久”，程序返回了一个带 storage 的片段。仅看关键词相同，还不能判断成功：片段可能讲容量，没有回答保留时间。要比较检索策略，需要事先知道每道题真正相关的证据在哪里。

**评估集**是一组固定的问题和核验标准。**gold** 指人工核实过的参考标注，不是检索器自己生成的正确答案。若让系统把自己的结果当 gold，错误就可能被循环认可。

本讲需要会看列表、字典和 JSON。JSON 是一种文本数据格式，`{}` 表示对象，`[]` 表示数组，`null` 表示没有值。Python 读入 JSON 后分别得到字典、列表和 `None`。需要复习读文件时返回[[01_学习指南/01_Python工程化/逐讲学习/06 看懂报错并安全管理资源|资源与异常]]。

## 先看一条证据和一道题

在 VS Code 打开 `示例工程/fixtures/corpus.json`，找到 `storage-retention`。它的原文是：

```text
Service: storage. Retention: 30 days. Policy version: 1.
```

为了便于手算，语料采用简单英文；教程用中文解释。`storage` 指存储服务，`retention` 指数据保留时间，`30 days` 是 30 天。这是虚构政策，请勿用于真实业务决策。

对应问题记录的关键部分：

```json
{
  "question_id": "storage-retention-1",
  "query": "What is the storage retention period?",
  "split": "test",
  "audience": "staff",
  "answer": "30 days",
  "relevant_ids": ["storage-retention"],
  "evidence_locator": "policies/storage.md#retention",
  "category": "direct"
}
```

- `question_id` 是稳定问题编号，方便比对两次运行。
- `query` 才是检索器接收的问题。不要把 `answer` 偷偷附到 query。
- `split` 指分组；`dev` 用于开发和调阈值，`test` 用于冻结方案后的报告。
- `audience` 是演示访问范围。生产身份必须由可信服务端提供，不能让调用者随意自报。
- `answer` 是参考答案；`relevant_ids` 是真正能支持它的证据 ID，可以不止一个。
- `evidence_locator` 是逻辑定位符。这里对应语料记录，并没有真实创建 `policies/storage.md`；不要把它当作磁盘链接。真实知识库应能跳回文件、页码或段落。
- `category` 把失败拆成切片，例如直接问法、改述、权限不足。

`data.py` 把记录转换成数据类。数据类把这几个字段集中声明成一个有名称的对象，便于写 `question.query`；`frozen=True` 阻止普通字段重赋值，减少运行中意外改标签。需要深入回看单元 01 的类型和数据类讲解。

## 可回答、无答案与权限不足

可回答题要求：答案存在、证据正确、当前身份能访问。若数据库里有内部政策，但当前是 public，系统仍应按当前可见资料视为无答案。它不能在拒答文字里泄露隐藏政策。

无答案题写 `answer: null`、空 `relevant_ids`、空定位。原因分四类：资料没有该事实；服务不存在；当前身份不可访问；问题增加了资料没有说明的限定条件。例如普通存储保留 30 天，不足以回答 premium plan 的保留政策。

> [!warning] 不能用低检索分数定义 gold
> gold 由人查资料确定。低分结果可能仍有正确证据，高分结果也可能只有词面相似。无答案标签必须在检查可见资料后标注。

## 为什么按服务分组

夹具有六个服务，每个四项政策，每项两种问法：6 × 4 × 2 = 48 条可回答题，再加 12 条无答案题，共 60 条。compute/network/training 在 dev；storage/database/analytics 在 test。

假如同一事实的直接问法进 dev、改述进 test，你可能已经通过开发题看过相同答案和证据，测试结果就更容易乐观。这里把同一服务放在同一组。检索索引仍可读取全部资料：RAG 检索本来就应检索包含测试问题答案的知识库。**不能用于调规则的是保留测试题的 query 和 gold**；语料与评估标签不是同一用途。

这是教学性分组，不是盲测证明。题目格式高度相似，作者知道全部夹具。认真实验还需要由其他人提供未看过的问题，冻结配置后再运行。

## 动手操作

在示例工程终端创建 `inspect_dataset.py`，输入这个完整最小脚本：

```python
from pathlib import Path
from data import load_dataset

documents, questions = load_dataset(Path(__file__).parent / "fixtures")
print("证据片段：", len(documents))
print("评估问题：", len(questions))
for question in questions:
    if question.question_id == "storage-retention-1":
        print(question.query)
        print(question.answer, question.relevant_ids)
```

运行 `..\..\..\.venv\Scripts\python.exe inspect_dataset.py`。`Path(__file__).parent` 是当前脚本所在目录，保证 fixture 路径不靠猜测终端位置；`load_dataset` 返回两个列表；循环只打印指定问题，避免一下看 60 条。

预期片段数 24、问题数 60、答案 `30 days`，证据 tuple 为 `('storage-retention',)`。tuple 是不可变序列，末尾逗号表示一个元素的 tuple；这里只用于保护证据 ID 集合的结构。若 `FileNotFoundError`，检查脚本是否位于示例工程，fixture 两个 JSON 是否存在。

## 检查与常见错误

`load_dataset` 检查重复 ID、非法 split、答案不在原文、定位不一致、public 引用内部文档和无答案题带证据等错误。它不会自动判断自然语言问题是否真的被证据回答；这一部分需要人工标注。

不要把 `build_fixture.py` 当真实采集器。它是可读的合成数据构造记录，运行会重写两份 fixture。想做个人数据扩展时先复制到自己的实验目录，避免覆盖固定对照集。正常学习只需运行 `demo.py`。

## 练习与答案解析

**跟做：** 手工检查 `storage-retention-1` 与 `storage-retention-2`，找出相同 gold 和不同 query。完成标准：能解释为什么是两种问法，为什么不是两份独立事实。

**独立：** 从语料任选三段，分别标一题直接问法、一题改述、一题无答案；写出 ID、答案、证据定位和理由。提示：先查原文，再写题。

**迁移：** 为中文工单知识库设计 10 条标注表，包含多证据题、旧版本题和权限题。完成标准：另一人只看题和可见语料，也能核实你的标签；不能用系统当前回答代替标注。

> [!example]- 参考答案与解析
> 两道 retention 题都指向 `storage-retention`，答案均为 `30 days`。新增“premium plan 保留几天”应标无答案，因为原文没有套餐区别。多证据题要列齐必需证据，例如“容量和保留期分别是多少”需要两个字段；当前答案抽取器不支持它，应在迁移中记录为能力范围之外，并扩展评估，不能悄悄把题删掉。

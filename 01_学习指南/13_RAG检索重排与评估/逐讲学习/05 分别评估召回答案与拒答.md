## 要解决什么问题

系统输出了正确数字，但引用了错误服务；或者引用确实存在，却没有回答用户的限定条件。一个总分会把这些不同问题混在一起。本讲先评价检索，再评价答案和拒答，每个指标都写清分母。

前置是相关证据 ID、排名和分数。**宏平均**指先每题计算指标，再对题目取平均；**微平均**把所有命中/相关项加总后相除。多证据题时它们可能不同，本工程使用每题宏平均。

## 手算三个排名指标

假设 gold 是 `{A,B}`，前三结果是 `[X,A,B]`。

**Recall@3** = 命中的相关项数 / 全部相关项数 = 2/2=1。它问“相关资料找齐多少”，不关心 A 在第几。

**RR@3（倒数排名）** = 1 / 第一个相关项的位置 = 1/2。对多题 RR 求平均就是 **MRR@3**。无相关项在前三时为零。本工程截断到 K，因此名称明确带 `@K`，不能与全列表 MRR 混写。

**nDCG@3（归一化折损累计增益）**同时看多个相关项和位置。越后面的命中折扣越大。本工程二值相关：相关记 1，不相关记 0，使用 `1/log2(rank+1)` 折扣。

```text
DCG = 0/log2(2) + 1/log2(3) + 1/log2(4) ≈ 1.131
理想 DCG（A、B 排前两位）= 1 + 1/log2(3) ≈ 1.631
nDCG = 1.131/1.631 ≈ 0.693
```

资料存在分级相关时，可用不同 gain 公式。不要把本工程的二值版本称为唯一标准；使用库时核对 gain、tie 和 K 约定。[scikit-learn nDCG 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html)说明其行为，本工程自己手算便于理解。

无答案题没有相关项，Recall 分母为零，所以不纳入这三个检索指标。无答案检测另算拒答指标。若把无答案题 Recall 自动算成 1，会虚增召回成绩。

## 答案正确性、忠实度与引用准确率

**答案正确率**：所有题中，答案与 gold 完全一致（或正确拒答）的比例。本工程采用精确字符串匹配；真实表达“30 天”和“30 days”可能等价，需要规范化/人工规则，不能直接视为语义评分。

**忠实度**：答案的陈述是否被检索证据支持。本工程只能测代理：答案文字是不是所引用原文的子串，且定位对应。它不检查所有自然语言蕴含、例外和时间约束，字段名因此叫 `faithfulness_proxy`。

**引用准确率**：已回答题中，引用 ID 和定位是否属于 gold 证据。引用存在不等于引用正确；引用正确还不必然说明解释完整。

一个重要反例：资料只写普通 storage 保留 30 天，问题问 premium plan。回答“30 days”逐字来自原文，忠实度代理通过，却没有 premium 的证据。正确性和引用准确率都会发现问题。这说明代理100%不是“模型绝不幻觉”的证据。

## 覆盖率、误拒率与正确拒答率

- **覆盖率** = 给出非空答案的题数 / 所有题数。高覆盖可能包含编造，不能独立追求。
- **误拒率** = 可回答题中被拒答的数量 / 可回答题数。证据存在却漏召回也会导致误拒。
- **无答案正确拒答率** = 无答案题中被正确拒答数量 / 无答案题数。它和可回答题误拒率的分母不同。

如果测试30题含24道可答题、6道无答案题，全部正确时覆盖率是24/30=0.8，不是1。拒掉真正无答案题是成功行为。若所有题都拒答，拒答率可能漂亮，但可回答误拒率=1，整体正确率只有6/30。

没有已回答题时忠实度和引用准确率没有分母，工程返回 `null` 而非强行写0或1。报告要说明“没有样本可算”，不能掩饰为空的评估。

## 答案层怎样拒答

打开 `answering.py`，按执行顺序读：

1. 校验 threshold 在0～1。
2. 识别唯一服务和字段。
3. 若问题包含白名单之外的词，默认拒答，防止忽略无法理解的限定条件。
4. 在候选中找同服务同字段片段；找不到拒答。
5. 计算词面覆盖信号；低于阈值拒答。
6. 通过明确格式的正则抽取原文字段，并返回真实 ID/定位。

白名单是本教学域的保守规则，不是通用自然语言理解。它会误拒没见过的正确改述，白名单内的词也可能表达复杂含义。真实系统需要补充代表性评估、语义充分性判定和业务约束，不能只换上 LLM 就声称安全。

confidence 名称在这里表示词面覆盖比例，不是“正确概率”。例如 query 的有效词有4个、原文覆盖2个，比例0.5。阈值只用于这个信号；BM25/RRF/余弦各自分数不能共享同一个阈值。

## 失败阶段如何记录

`classify_failure` 按顺序分类：

```text
无答案题 → correct_rejection 或 unsupported_answer
可回答题但候选没有 gold → retrieval_miss
有 gold 却拒答 → false_rejection
有 gold 却答错 → answer_error
有 gold 且答对 → correct_answer
```

先判 retrieval_miss，再判拒答，避免把同一漏召回同时算成两个互斥失败类别。总体误拒率仍包含所有可答题拒答，因此它可能大于 `false_rejection` 类别占比。分类是诊断视角，汇总率是最终行为视角。

## 动手手算与核对

在示例工程新建 `inspect_metrics.py`：

```python
from evaluation import ranking_metrics

metrics = ranking_metrics(["X", "A", "B"], ("A", "B"), 3)
print(metrics)
```

预期 recall=1、rr=0.5、ndcg约0.693。再运行 `demo.py`，在 VS Code 打开 `results/unsafe_baseline.json`，搜索 `unsupported_answer`；核对 query、答案、引用、原文缺少的限定条件。这个文件是故意关闭未知词防护后的反例，不作为推荐方案。

## 常见错误与练习

Recall特别高但正确率低：先看 gold 是否进候选，再检查回答读错字段、上下文截断、限定条件和引用。引用准确率100%但覆盖极低：检查被拒题和分母。调高阈值后“更安全”：同时看误拒率，防止以拒绝全部问题制造成绩。

**跟做：** gold仅A、结果`[X,A,Y]`，计算@1与@3。完成标准：明确截断位置。

**独立：** 10题中8可答、2无答案；回答了6道可答题和1道无答案题，其余拒答。计算覆盖率、可答误拒率、无答案正确拒答率。

**迁移：** 为多句生成答案设计逐句支持标注，再区分“引用存在”“引用与结论有关”“结论由引用支持”。完成标准：至少写一个三者结果不同的反例。

> @1全部为0；@3 Recall=1、RR=0.5、nDCG≈0.631（只有一个gold，理想DCG=1）。覆盖7/10=0.7；误拒2/8=0.25；无答案正确拒答1/2=0.5。错答可答题与误拒不同，题目未给6道答案是否正确，因此不能推断答案正确率。

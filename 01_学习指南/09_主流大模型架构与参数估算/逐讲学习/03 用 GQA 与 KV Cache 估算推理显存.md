## 本讲目标与先修知识

先认识 Q/K/V 与多头注意力，回看 [[01_学习指南/08_Transformer从零实现/逐讲学习/01 看懂缩放点积注意力|Q/K/V]]。本讲学习 GQA、MQA，并能从 batch、缓存 token 数、层数、KV 头数、head_dim 和数据类型计算标准 KV Cache。

## 推理为什么需要缓存

生成时，每一步把新 token 接到已有前缀后面。之前位置的 Key/Value 已经算过；若每一步都重算，会重复工作。KV Cache 保存每层已算过的 K、V，新一步只为新 token 计算并把新 K/V 追加进去。

普通缓存可理解为形状 [2, layers, batch, kv_heads, sequence, head_dim]。最前面的 2 表示 Key 与 Value 各一份。真实运行库可能改变布局、分块或分配策略；该形状用于概念和容量估算。

## GQA 与 MQA

MHA 中每个 Query 头通常有自己的 Key/Value 头。GQA（分组查询注意力）让一组 Query 头共同读取一个 KV 头；MQA（多查询注意力）是所有 Query 头共享一组 KV。它们主要减少缓存头数；Query 头仍各自计算 Query。

- Qwen2.5-7B：Hq=28、Hkv=4，平均 7 个 Query 头读一组 KV。
- Llama 3.1-8B：Hq=32、Hkv=8，平均 4 个 Query 头读一组 KV。

用 Qwen 的 num_key_value_heads 代替 num_attention_heads 计算缓存，正是 GQA 节省缓存的来源。

## 公式一步一步来

每层、每个 token 有 K 和 V 两份；每份有 Hkv×head_dim 个元素。驻留 B 条序列、每条 T 个缓存 token、共有 L 层，每个元素占 s 字节：

~~~text
KV 字节数 = 2 × L × B × T × Hkv × head_dim × s
head_dim = hidden_size / attention_heads
~~~

Qwen 每头维度是 128。L=28、Hkv=4、BF16 每元素 s=2，因此每序列每 token 缓存 2×28×4×128×2=57,344 字节，即 56 KiB。

batch=4、T=8192 时为 57,344×4×8192=1,879,048,192 字节，约 1.75 GiB。估算器中的 sequence_length 表示上下文加已生成 token 的总缓存长度。

## 显存不是只有权重

推理时需要模型权重、请求 KV Cache、临时激活/工作区和运行时开销。参数量与精度影响权重存储；batch 和上下文影响缓存。训练还要考虑梯度、优化器状态和反向传播激活，因此只算权重绝不能作为完整训练预算。

## 动手操作与常见错误

运行估算器，BF16 下分别对两份配置使用 B=1、T=4096 和 B=4、T=8192。后者应是前者的 8 倍，因为 batch 与长度分别扩大 4 倍、2 倍。使用 float32 时，缓存字节数加倍。

- 少乘 2：缓存同时有 K 与 V。
- 用 Query 头数代替 KV 头数：GQA/MQA 下会高估。
- 漏乘序列长度、batch 或层数。
- 把 GB 与 GiB 当成一样：本工程以 GiB（2 的 30 次方字节）显示。
- 把理论缓存量当成完整运行显存：还缺运行时开销和其他张量。

## 练习

### 跟做练习

Llama 3.1-8B：L=32、Hkv=8、head_dim=128、BF16，算每 token 每序列缓存。答案：131,072 字节，即 128 KiB。

### 独立练习

T 从 4096 增到 8192，batch 仍为 2，缓存如何变化？答案：长度翻倍，缓存翻倍。

### 迁移练习

比较 MHA（Hkv=Hq=32）与 GQA（Hkv=8），其他项不变。KV Cache 缩小到多少？答案：1/4。缓存比例不表示端到端速度必然提升四倍。

> [!example]- 答案解析：Qwen 单 token 缓存
> 2×28 层×1 条序列×1 token×4 个 KV 头×128 维×2 字节=57,344 字节。batch、长度或字节精度任一翻倍，缓存也翻倍。

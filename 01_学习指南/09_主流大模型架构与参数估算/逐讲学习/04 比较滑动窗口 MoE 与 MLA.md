# 第 4 讲：比较滑动窗口 MoE 与 MLA

## 本讲目标与先修知识

需要知道注意力会产生 Q/K/V，FFN 会对每个 token 做变换；可回顾 [[01_学习指南/08_Transformer从零实现/逐讲学习/04 组装多头注意力与 Transformer Block|Transformer Block]]。本讲比较三类常用于扩展模型或控制资源的设计：滑动窗口限制可读上下文范围，MoE 每 token 只路由到部分专家，MLA 压缩注意力缓存表示。

## 滑动窗口注意力

全因果注意力让位置 i 读取所有 0 到 i 的 Key。滑动窗口大小 W 则只保留最近 W 个位置：位置 i 读取 max(0,i-W+1) 到 i。它限制每个位置的注意力范围，长序列时可减少注意力计算和缓存需求，但较早的信息不能直接由该层访问。

常见模型可能在不同层混用全注意力与窗口注意力；也可能有额外的全局 token 或其他记忆路径。因此看到 sliding_window 字段要继续看 use_sliding_window、层配置及模型实现，不能只凭一个数字推断整模型实际行为。Qwen2.5-7B 快照即包含窗口相关字段，但同时 use_sliding_window=false；字段存在不等于启用。

## MoE：很多专家，每个 token 用一部分

MoE（混合专家）将某些 FFN 换成多个独立专家和一个路由器。路由器根据当前 token 表示选出 k 个专家执行。因此有两种参数数目：

- 总参数：所有专家都存储起来，外加共享部分。
- 激活参数：当前 token 实际经过的专家参数与共享部分。

只激活部分专家能降低每个 token 的 FFN 计算量，但所有专家权重通常仍需驻留在设备或分布式设备集群中。因此“每 token 计算只涉及一小部分”不等于“部署只需存这一小部分权重”。专家分布、通信和负载平衡还会影响实际性能。

DeepSeek-V2 官方报告/代码展示 MLA 与 MoE 的组合；发布说明分别报告总参数和每 token 激活参数。[DeepSeek-V2 官方仓库](https://github.com/deepseek-ai/DeepSeek-V2)。

## MLA：改变缓存表示

MLA（多头潜在注意力）把用于后续注意力的 Key/Value 信息压缩为较小的 latent 表示，并在需要时恢复/投影出注意力使用的内容。它的目标之一是缩小推理时逐层、逐 token 直接保存的 KV 数据。它改变了缓存结构与投影路径，因此不能把上一讲标准 GQA 公式中的 Hkv 直接填一个数字就当作 MLA 缓存结果。

理解到机制和估算边界即可；本单元不要求手算 DeepSeek-V2 每个 MLA 子投影参数，更不要求实现专用 kernel。[DeepSeek-V2 技术报告](https://arxiv.org/abs/2405.04434)。

## 三种设计对照

| 设计 | 主要改变 | 资源侧影响 | 需要检查什么 |
|---|---|---|---|
| Sliding Window | 每个 Query 可访问的历史范围 | 可限制单层注意力工作集；远处上下文通路受限 | 实际启用层及窗口策略 |
| MoE | FFN 被多个专家取代，由路由选择部分专家 | 每 token 算一部分；所有专家权重仍要存放/分片 | 总参数、激活参数、专家数、top-k |
| MLA | KV 表示与注意力投影的构造改变 | 可缩小缓存表示；标准 KV 公式不再直接适用 | latent 维度、RoPE 子空间和实现 |

## 动手操作与常见误解

1. 在纸上画 6 个 token，窗口 W=3，指出最后一个 Query 能看哪些位置：只看最近 3 个（含自己）。
2. 画 4 个 FFN 专家，top-k=2；给一个 token 的箭头只连到两个被选专家。
3. 对照普通 K/V 缓存和 MLA latent 缓存草图，圈出“需保存的张量表示”改变的位置。

常见误解：窗口注意力仍允许看窗口内未来 token（仍受因果规则限制）；MoE 激活参数等于模型总存储量；MLA 是“GQA 再少几个头”；路由专家越多就必定越快。它们都要结合层实现、运行设备和服务框架判断。

## 练习

### 跟做练习

序列位置为 0 到 5，窗口 W=3。对位置 5，可见位置 3、4、5；对位置 1，可见 0、1。

### 独立练习

有 64 个路由专家，每 token 选 6 个，说明为何激活 FFN 不是全部专家参数。答案：每个 token 的路由只执行 6 个专家，但其他专家权重仍属于模型并需以某种方式保存/装载。

### 迁移练习

选一份 MoE 模型官方说明，分别记下总参数、激活参数、专家总数和每 token top-k。若官方不提供其中一项，写“未确认”，不要拿总参数除以专家数冒充激活参数。

> [!example]- 答案解析：Qwen 配置中的窗口字段
> 在本课程固定的 Qwen2.5-7B config 快照中，虽可见 sliding_window 和 max_window_layers，但 use_sliding_window 为 false。配置字段必须结合开关和实现阅读，不能见字段就断言模型正在按该机制计算。

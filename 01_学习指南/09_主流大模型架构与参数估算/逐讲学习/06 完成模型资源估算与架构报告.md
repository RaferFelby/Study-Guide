## 复算两份配置

在 VS Code 的示例工程目录运行：

~~~powershell
..\..\..\.venv\Scripts\python.exe estimate.py configs\qwen2_5_7b.json --batch-size 4 --sequence-length 8192
..\..\..\.venv\Scripts\python.exe estimate.py configs\llama3_1_8b.json --batch-size 4 --sequence-length 8192
..\..\..\.venv\Scripts\python.exe -m pytest -q
~~~

本机 Python 环境无需新增依赖。输出中参数数应分别约为 7.615B 与 8.030B；BF16 理论权重约为 14.19 GiB 与 14.96 GiB；普通 KV Cache 约为 1.75 GiB 与 4.00 GiB。数值为配置公式输出，不是模型加载峰值显存。

运行测试应覆盖小配置的参数公式、共享 embedding、KV 的 batch/长度/精度比例和无效维度输入。逐步手算一个小配置，再用测试验证脚本，可以帮助识别“公式错了”而不是只相信程序输出。

## 一页报告模板

用下列栏目写一页可复核的分析：

1. **模型与版本**：仓库名、revision/提交或配置日期、基础模型还是指令模型。
2. **结构**：D、L、Hq、Hkv、F、V、RMSNorm、SwiGLU、RoPE；MoE/MLA/窗口若有，注明开关和层范围。
3. **参数估算**：列出矩阵参数公式、embedding 是否共享、是否计 bias，并将估算结果与发布标签比较。
4. **推理缓存**：写明 batch、prompt+生成长度、KV heads、head_dim 和精度，展示计算过程与 GiB。
5. **其他显存**：明确权重/KV 之外还需激活、workspace、缓存碎片、并行开销；若涉及训练，再单列梯度和 optimizer state。
6. **推理过程**：画出 prefill、首 token、decode、EOS/长度上限；记录 TTFT 与逐 token 指标口径。
7. **采样对照**：greedy 和至少一个 sampling 配置；有真实服务才填测量，未测就写“未测”。
8. **结论范围**：列出无法从 config 确定的内容，不把理论下界写成设备可运行保证。

## 资源估算的使用边界

权重理论字节数只是参数个数乘每个参数的存储字节。KV Cache 是按活跃序列数与缓存长度增长的运行时状态。训练内存还会随 batch、序列长度和保存反向梯度的激活大幅变化。实际执行需要留空间给 runtime、kernel 临时张量、CUDA Graph 或框架分配器等组件；具体是否使用这些能力由系统决定。

计算器只针对稠密 SwiGLU 和普通 MHA/GQA 缓存。遇到 MoE 时分别报告总参数和激活参数；遇到 MLA 时查其真实 latent/cache 配置；遇到窗口注意力时检查哪些层启用及引擎缓存策略。本估算脚本不能把特殊架构折算成一个看似精确的数字。

## 完成本单元的检查

- [ ] 读出两个明确版本配置的 D、L、Hq、Hkv、F、V。
- [ ] 手算并用脚本核验两个参数量，说明近似误差来源。
- [ ] 改变 batch、长度、KV 头数和字节精度，正确预测 KV 变化比例。
- [ ] 解释 SwiGLU、RMSNorm、RoPE、GQA/MQA、MoE、MLA 和滑动窗口的大致取舍。
- [ ] 画出 prefill 与 decode 阶段及 KV 增长。
- [ ] 设计 greedy 与采样比较，记录温度、top-k/top-p、EOS、长度上限和 TTFT/逐 token 口径。

## 练习

### 跟做练习

复算两个模型的 BF16 权重和 B=4、T=8192 缓存；比较为何 Qwen 缓存较小：它的层数与 KV 头数乘积更小。

### 独立练习

用任何一份公开 Dense 模型配置做报告，并将参数估算误差控制在发布标签的 10% 内。应注明标签本身已四舍五入，完整复核需要同一版本权重张量统计。

### 迁移练习

若改为 MoE 或 MLA 模型，列出当前计算器哪些假设失效、需要补充哪些配置字段。完成标准：不直接套公式给特殊架构报假精确数。

> [!example]- 答案解析：对比模型缓存
> Qwen2.5-7B 每 token 每序列为 56 KiB，Llama 3.1-8B 为 128 KiB。乘同一 batch 与序列长度后分别是约 1.75 GiB 和 4 GiB。前者缓存小的主要结构因素是 28 层×4 个 KV 头，后者为 32 层×8 个 KV 头；两者 head_dim 相同且 dtype 一样。

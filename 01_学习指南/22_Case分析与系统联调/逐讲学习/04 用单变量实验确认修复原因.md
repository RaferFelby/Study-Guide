## 要解决的问题

如果同时换模型、改检索、放宽解析和加重试，分数变好也不知道是哪项起作用。单变量实验先保持任务/数据/其他设置相同，只修改一个假设相关变量。复习单元19配对对比；若忘记配置对象，返回 [[01_学习指南/14_Agent运行原理与状态机/00 Agent 运行原理与状态机学习地图|单元14学习地图]]，先读状态与数据类相关讲解。

## 设置与替换机制

Settings冻结数据类有use_aliases、correct_argument_name、accept_json_fence、enforce_owner和max_attempts。默认全False、尝试1次，形成可解释的故意缺陷基线。dataclasses.replace从旧配置复制一份，只改指定字段，旧配置不被改。

模型/数据在本夹具确定，便于因果机制学习。真实LLM有随机波动，单次变好不足确认因果，需要固定版本、多次/配对与适当样本；此实验不是真实服务随机试验。

## 最小示例：只开同义映射

新建`lesson_single_change.py`：

```python
from dataclasses import asdict, replace
from contracts import Settings
from experiments import compare, evaluate

baseline = Settings()
changed = replace(baseline, use_aliases=True)
print(asdict(baseline))
before = evaluate(baseline)
after = evaluate(changed)
print(before["successes"], after["successes"])
print(compare(before, after))
```

逐步看执行顺序：`Settings()` 创建基线配置；`replace` 返回新配置，原对象不变。`asdict` 只将配置展示为字典，不运行任务。`evaluate(baseline)` 对同一组八任务运行基线；`evaluate(changed)` 运行唯一变化的版本，得到两个独立报告。最后 `compare` 按稳定任务ID对齐成功与失败，返回改善、退步和工具次数差。

`use_aliases=True` 的意思是允许预定义同义表达映射，不是让模型自由改问题；`correct_argument_name` 修工具参数键；`accept_json_fence` 允许约定JSON围栏；`enforce_owner` 开用户归属检查；`max_attempts` 是每个安全只读动作最多尝试数。这里False故意构造教学缺陷，不能把默认配置拿去接真实用户数据。

预期3→4，improved只有retrieval-alias、regressed=[]、attempt_delta=1。asdict把配置转字典便于报告；replace只改一项；原baseline仍不认退钱窗口。成功多一个工具尝试因为原来检索缺失根本没调用，并非所有修复都省调用。

## 动手：核对五实验

运行experiments.py，填写结果：

| 配置变化 | 改善Case | 成功 | 工具尝试变化 |
| --- | --- | --- | --- |
| use_aliases=True | retrieval-alias | 4/8 | +1 |
| correct_argument_name=True | tool-arguments | 4/8 | 0 |
| accept_json_fence=True | parse-fence | 4/8 | 0 |
| enforce_owner=True | permission-cross-user | 4/8 | 0 |
| max_attempts=2 | upstream-transient | 4/8 | +1 |

每次仅一个设置不同，测试也检查差异字段数恰好1。观察通过ID比总分更能支持假设：若开同义映射却只改善解析题，应怀疑实验配置/样本串错。

## 参数与解析实验的边界

correct_argument_name只修调用契约，不让工具接受未知参数。accept_json_fence只剥完整以```json换行开始、换行```结束的包装，然后仍json.loads与status/days校验；混杂前缀或额外字段仍拒绝。

真实接口若规定纯JSON，正确做法可能是修提示词/结构化接口并保持拒围栏；这里input.format明确允许包装，所以适配可成立。测试目的不是鼓励所有非法文本自动“修成合法”。

## 重试实验必须有失败路径

max_attempts只允许1或2，bool/0/3/小数拒绝，避免无限循环。暂时失败一次后第二次成功；连续失败3次仍只尝试2次并failed。权限/参数错误不重试，这些不会靠再调用自动变合法。

这条case代表安全只读动作。若工具是支付/发邮件且结果未知，不能直接增加次数；应按单元16/21的幂等/确认边界，先查结果。现实还需退避与总体预算，本简化无真实网络等待。

## 常见错误

- 改了变量还顺便换gold：成功变化不再可归因。
- 单次高分就断言所有题都改善：看逐ID、回归、样本来源与未覆盖范围。
- 调整多个开关后叫单变量：保存配置差异，明确实验名称。
- 重试修复没有持续故障测试：容易隐藏死循环或无限成本，必须测耗尽。

## 练习与答案

跟做：单开同义映射记录3→4与+1调用。完成判断：改动字段仅一个、相同八条任务。

独立：将max_attempts改2后参数Case为何仍失败且仅尝试1次？

迁移：选择一条自己的失败，写基线、假设、唯一变量、固定数据/版本、预期变化、观察结果与反证条件。

> [!example]- 参考答案与解析
> ToolContractError表明参数不符合约定，不是暂时网络失败，循环立即break；第二次仍错不应浪费。
>
> 反证例如目标Case未改善或无关Case改变、数据版本不同、真实随机波动超效果。没有观察结果时写实验计划，不能用预期替代事实。

## 本讲任务与前置

单项修复都有效，并不自动证明组合安全。组合可能改变执行顺序、缓存与解析路径；要重跑全部任务和关键边界。复习前四讲、单元19回归，不能只测试失败五条。

## 端到端验证是什么

端到端从任务输入到最终输出/执行结果，包含检索、规划、工具、模型与解析。单元测试单测函数契约，集成测试检查多个函数连接，端到端任务评估检查用户契约；在本原型里都本机确定执行，不含真实网络/模型。

三个正常回归分别验证Alice普通30天、Bob自身50天、VIP未知拒答。权限修复不能把Bob合法查询拒绝，检索同义修复不能让未知VIP误匹配普通政策。

## 最小示例：组合通过并查看退步

新建`lesson_combined.py`：

```python
from experiments import run_experiments

report = run_experiments()
combined = report["reports"]["combined"]
print(combined["successes"], combined["n"])
print(report["comparisons"]["combined"])
for row in combined["rows"]:
    print(row["case_id"], row["passed"])
```

预期8 8，改善五失败ID、退步[]、调用增2，八条均True。调用更多是同义题新增读取与暂时失败增加重试，属于修复代价；不能仅以调用少判断原baseline更好。

## 动手：证明授权在读取前

在combined.rows找到permission-cross-user，actual_reads=0、tool_attempts=1、output refused/None，events有authorization deny。注意工具尝试计一次，因为进入接口才判权限，但实际私有数据没读。

如果只检查输出refused，代码可能先读Bob再隐藏输出，仍有数据进入模型/日志风险。actual_reads和无model事件一起支持读取前拒；真实资源系统要记录同样有效的执行边界证据。

## 动手：持续故障与解析边界

新建`lesson_persistent_failure.py`：

```python
from cases import make_cases
from contracts import Settings
from pipeline import run_pipeline

case = next(case for case in make_cases() if case["case_id"] == "upstream-transient")
input_data = {**case["input"], "transient_failures": 3}
settings = Settings(True, True, True, True, 2)
result = run_pipeline(input_data, settings)
print(result["output"], result["tool_attempts"], result["actual_reads"])
```

预期failed/None、2、0。工具没有完成读取，模型不运行；不是“修好了所以一定成功”。这是新增边界，不在原八条成功统计中，需要单独记录测试范围。

解析测试还拒混杂prefix、bool天数和额外owner；看tests/test_integration.py。收紧Schema能让错误暴露，不要为维持8/8把未知输出忽略。

## 完整检查命令

在示例工程运行：

```powershell
..\..\..\.venv\Scripts\python.exe -m ruff check .
..\..\..\.venv\Scripts\python.exe -m ruff format --check .
..\..\..\.venv\Scripts\python.exe -m pytest -q tests
..\..\..\.venv\Scripts\python.exe experiments.py --output report-02.json
```

若report-02已有换新文件。检查规则/格式、13项测试、固定集报告分别记录；命令最后成功不能掩盖前面失败，逐条看退出与输出。代码修复时同步教程参数/预期。

## 回归通过的实际边界

8/8说明这份合成契约下的组合符合要求。数据窄、固定失效次数、mock模型确定，不能推断真实复杂任务或供应商网络表现。真实系统还需异步/并发、取消、缓存、持久化、权限角色与外部副作用；沿单元16～21扩展集成场景。

baseline故意unsafe只读虚构常量，不能作为部署配置。教程对照用于解释缺口，实际项目默认应开启权限且拒未知。默认Settings是实验基线，不是推荐生产默认。

## 常见错误

- 合并后只测目标五题：三正常回归也必须测。
- 修权限看refused就满意：确认实际读取0。
- Retry2把永不成功的任务当已解决：持续失败仍应明确结束/降级。
- 每次报告覆盖：保存版本以支持前后对比。

## 练习与答案

跟做：八条全通过、无回归、持续失败2次终止。完成判断：能区分固定集和额外边界测试。

独立：tool_attempts=1而actual_reads=0有哪些原因？

迁移：为自己的组合修复列正常、边界、失败路径，以及日志/数据/副作用要核对的最终状态。

> [!example]- 参考答案与解析
> 参数拒绝、权限拒绝、第一次上游超时都可能如此，要看error code/阶段而不是单一数字。不能以读数0直接确定根因。
>
> 验收含合法用户成功/非法用户拒、未知证据拒、超时耗尽、输出非法、取消或重复安全；每类记录实际结果，不将无外部服务实验写成外部全链路已通过。

## 本讲完成后

组合有证据，最后将结果、限制和后续行动组织成一页联调报告。

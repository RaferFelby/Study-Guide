## 本讲任务与前置

先核对固定数据版本，再构造 0-shot 与 2-shot 提示，检查待评答案没有进入提示。需要上一讲的字段及文件读取。函数、字符串拼接见 [[01_学习指南/01_Python工程化/00 Python 工程化学习地图|Python 基础]]；本讲会解释新的 shot 与哈希，不要求先懂评测框架。

完成标准：能说明 commit、SHA-256 各固定什么，能识别示范来源与待评参考的边界，并解释本次提示没有改变历史归档输出。

## 要解决什么问题：明天还评的是同一套内容吗

网址的 `main` 或 `master` 是会移动的分支名称。今天下载与明天下载可能不同，哪怕文件名相同。固定 commit 是选定仓库的一次提交，用长编号标识该状态；文件哈希是对实际字节计算出的摘要，用来核对本地文件是否变化。

SHA-256 是一种把任意长度字节映射为固定长度摘要的算法。像文件指纹一样用于比对，但不是签名，也不证明来源可信、模型没有污染或数据合法。若同时替换文件和记录里的摘要，普通一致性检查可能仍通过，所以报告还保存上游 URL、提交号、选题方式和许可证。

## 概念与直觉：0-shot 与 few-shot

shot 在这里指放进提示的一条示范。0-shot 没有示范，只给指令和待评题；few-shot 给少量已解示范，再给新题。2-shot 就是两条示范。像先看两道例题再做新题，实际是把示范文字放进模型上下文，不发生梯度更新，不等于微调。

示范通常来自该基准允许的 train/dev 分区，以该任务规则为准；不能把当前待评题及答案当自己的例题。示范顺序、数量、解释长度都可能影响生成，而且占用上下文；多给示范不保证更高分。

本工程从官方训练文件取固定前 5 条作为可用示范，提供 0／2-shot 构造。待评题来自历史回答文件；测试确认五条训练题目与 1319 条待评题目不重合。这里没有开发新的模型生成参数，不将 2-shot 提示说成原作者的真实评测提示。

## 最小示例：构造提示并检查边界

在本单元示例工程新建 `lesson_02.py`：

```python
from suite import build_prompt, load_snapshot

records, demos, manifest = load_snapshot()
task = records[0]
zero = build_prompt(task, demos, shots=0)
two = build_prompt(task, demos, shots=2)
print(zero.count("Question:"), two.count("Question:"))
print(zero.endswith("Answer:"), two.endswith("Answer:"))
print("包含待评参考", task["ground_truth"] in two)
print(manifest["sources"]["demos.json"]["selection"])
```

```powershell
..\..\..\.venv\Scripts\python.exe lesson_02.py
```

预期为 `1 3`、`True True`、`包含待评参考 False`，以及 `first_5_training_rows_only`。0-shot 只有待评一道题，2-shot 另外两条示范，所以 Question: 出现三次。`endswith` 检查提示末尾等待回答；`in` 检查这条参考全文是否被包含，属于本例辅助检查，不是所有信息泄漏的完整检测。

## 逐步讲解提示构造

打开 [suite.py](../示例工程/suite.py) 的 `build_prompt`。先校验 shots 是整数且不超过可用示范，布尔值不能混当数字。`demos[:shots]` 按固定顺序取前几条；逐条检查它们的 question 是否与待评题相同，发现相同就拒绝。

第一段是统一输出约定：解决数学题，最后一行使用 `#### number`。接下来每条示范包含 Question 和已知 Answer；最后只添加待评 question 与空的 `Answer:`。构造代码没有读取该题 ground_truth，因此不会主动复制参考。

这只能防住本构造中的直接参考泄漏，不能证明预训练时没有见过公开题库。公开题可能进入模型训练语料，即评测污染；能从训练记录、数据来源和相似性检查获取线索，当前没有实际检查自然语言大模型的训练语料。

## 动手操作：检查两个提示文件

在 PowerShell 执行公开重放：

```powershell
..\..\..\.venv\Scripts\python.exe experiment.py --output-dir report-my-replay-01
```

`--output-dir` 指定当前工程下的新目录，存在会报错，保护旧结果。命令离线读取固定快照、重新评分，并保存 `report.json`、`prompt-0-shot.txt`、`prompt-2-shot.txt`。在 VS Code 打开两个提示，找出示范与待评题的分界；确认最后没有答案。

预期评分记录数都是 1319。提示文件只是教学演示，归档回答不会因为你改了提示而重新生成。真正研究 few-shot 对分数的影响，需要固定模型，分别用两种提示重新生成、保留原始回答，再评分；当前没有做这个真实大模型实验。

## 数据快照与恢复

打开 [snapshot.py](../示例工程/snapshot.py)。只有显式运行它才联网；导入不会下载。URL 内固定提交 `3101c7d5072418e28b9008a6636bde82a006892c`。archive 原始文件约 2.45 MiB，下载器单文件限制 16 MiB、请求超时 30 秒；另取许可证与训练文件，训练文件只保存前五条示范，记录完整上游文件摘要及选择方式。

日常学习用已保存 fixtures，不重复下载。需要核对或恢复时在工程新建一个快照目录：

```powershell
..\..\..\.venv\Scripts\python.exe snapshot.py --output-dir snapshot-check-01
```

比较新目录 manifest 的文件哈希与原记录；该命令不替换原 fixtures，也不安装依赖。新目录是自己生成的数据，保留核对记录；网络失败先看错误，不写“下载已完成”。代码许可证与数据使用条件要按来源分别核对，本工程保留 GSM8K 上游许可证，不推断所有基准授权相同。

## 常见错误与排查

示范数超限：只有五条，shots=6 会失败，减至明确可用数量；不要静默截断后仍报告 six-shot。把待评题加入示范会报错，回到独立训练示范。新目录已存在则换名称，不删除旧报告来迎合命令。若改了 fixtures 内容，先保留差异，再重新核对固定快照，不能只改摘要维持“同一版本”标签。

## 分级练习与答案解析

### 跟做练习：改为 1-shot

只把 shots 改为 1，预测 Question: 出现几次，再运行。提示：一条示范加一条新题。

> [!example]- 参考答案
> 两次。末尾仍是空 Answer:，待评参考不应出现。完成标准：能指出示范答案允许出现，当前待评答案不允许出现。

### 独立练习：网址与摘要

使用 master 下载并写“版本固定”，缺少什么？若只记录 SHA-256，又还有什么限制？

> [!example]- 参考答案
> master 会移动，应保存固定提交／版本及实际文件摘要；摘要能确认字节一致，但不证明上游身份、授权或未污染。完成标准：区分仓库状态与文件内容，并保留来源。

### 迁移练习：few-shot 分数归因

你改提示文件为 2-shot 后直接读同一归档回答，分数不变。能否说 few-shot 无效？

> [!example]- 参考答案
> 不能，因为没有用新提示重新生成。应固定真实模型后分别生成 0／2-shot 回答、记录完整配置，再比较。完成标准：明确操纵的输入必须到达实际模型，重放不是因果实验。

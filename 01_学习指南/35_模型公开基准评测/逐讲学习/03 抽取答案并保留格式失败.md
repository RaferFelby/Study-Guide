## 本讲任务与前置

先用小例子练答案抽取，再读公开重放的格式失败与正确数，最后解释为什么失败保留在分母。需要字符串、布尔判断和上一讲的固定数据。正则表达式是按文本模式匹配字符串的工具；本讲只解释当前需要的模式，不要求背完整语法。

完成标准：能独立判定格式有效与数值正确，能说明参考坏了应停止、模型输出格式坏了应记失败，以及为什么不能挑出可评分的题才算准确率。

## 要解决什么问题：答案藏在文字哪里

数学回答里可能有很多数字：题目数字、中间计算、最后结果。随手取最后一个数字，可能取到“还需检查 2 次”；随手搜索 A/B/C/D，可能命中解释中的普通英文单词。抽取规则会改变分数，应在看成绩前确定，记录版本，保留原始输出。

本工程要求最后一行是 `#### 数值` 或 `A: 数值`，只接受明确数字；选择题演示接受独立字母或最后一行 `答案：D`。这是当前教学协议，不是全部基准或所有语言模型的唯一官方抽取方式。

## 最小示例：数值与选项

在本单元示例工程新建 `lesson_03.py`：

```python
from scoring import extract_choice, grade_numeric

reference = "#### 12"
for response in ("计算 3 * 4\nA: 12", "#### 12.0", "我猜12", "A: 13"):
    result = grade_numeric(response, reference)
    print(result["format_valid"], result["correct"], result["extracted"])
print(extract_choice("解释\n答案：D"))
print(extract_choice("A or B"))
```

```powershell
..\..\..\.venv\Scripts\python.exe lesson_03.py
```

预期输出：

```text
True True 12
True True 12.0
False False None
True False 13
D
None
```

`reference` 是这个自写小例子的参考答案；每次 grade_numeric 独立抽参考和输出。12 与 12.0 数值相等，显示字符串保留小数写法也不影响比较。`None` 表示无法按协议抽取，不是数字 0，也不是模型漏答就从数据中删掉。

## 逐步讲解规则与设计原因

打开 [scoring.py](../示例工程/scoring.py)。`strip()` 去首尾空白，`splitlines()[-1]` 只读最后一行，避免在正文里捡任意数字。`re.fullmatch` 要求整行符合模式；`####|A:` 表示两个允许标记之一，`\s*` 允许标记后空格，数字部分允许正负整数、小数或正确分组三位的千位逗号。

例如 `#### 1,234.50` 能解析，`#### 1,23` 不能解析；`A: 12 dollars` 也不符合当前严格协议。宽松与严格没有无条件优劣，关键是按任务预先定义，并把格式失败作为可见结果。如果增加单位、科学计数法等支持，要建立新抽取版本、测试与重算记录，不在个别失败上临时放宽。

`Decimal` 以十进制方式表示数值，本例避免用浮点字符串完全相等来判 12 与 12.0。它不自动提供误差容忍；需要允许近似答案时另定义容差与单位。当前只做精确数值相等，不评推导过程。

参考答案无法抽取时抛 `ValueError`，因为评分规则或数据坏了；模型回答抽不出返回格式失败、correct=False。两种情况不能都写成模型答错，否则会用坏参考污染成绩。

## 动手操作：从报告读全部分母

先运行第 2 讲的 `experiment.py --output-dir report-my-replay-01`，在 VS Code 打开 report.json。两组 n 都是 1319；作者重算结果：

| 归档组 | 正确数 | 正确率 | 格式失败 | 与上游标签不一致 |
| --- | --- | --- | --- | --- |
| 6b_finetuning | 286 | 21.6831% | 6 | 0 |
| 6b_verification | 515 | 39.0447% | 1 | 0 |

没有先删除六条／一条抽取失败再除剩余题数；格式失败均计错，原始回答留在 details。labels 一致提供当前重算协议与该快照标签一致的证据，不能证明所有未知回答格式都被正确处理。

在 `details` 搜索 `"format_valid": false`，检查 raw_response；不要只读汇总。`upstream_correct` 仅用于比对，不参与 grade_numeric；测试会翻转一条上游标签，重算仍依据文本与参考，差异会列在 label_disagreements 中。

## 选择题：生成和概率两种评分

生成评分让模型输出文本，再抽选项；概率评分比较各候选选项的条件概率。两者不是同一测量：模型可能更偏好正确选项，却没遵守输出格式。MMLU 的[原始评测代码](https://github.com/hendrycks/test/blob/master/evaluate.py)比较选项概率；本工程的 extract_choice 是生成格式演示，不能拿它冒充已执行原始概率评测。

分词器（tokenizer）把文本拆分并转成模型使用的 token 编号；真实分词器可能把一个选项文本切成多个 token，候选边界、空格、长度归一化都需要任务规则。目前没有实现通用概率适配器。只提供文本输出的接口不能假装拥有全部候选概率；[lm-evaluation-harness 官方说明](https://github.com/EleutherAI/lm-evaluation-harness)也区分生成与对数概率所需接口。不要复制多年以前的 API 命令直接当当前可运行流程。

## 汇总方式与常见错误

微平均是所有题一起计正确／总数；宏平均是先算每个学科的正确率，再给各学科相同权重。例如甲 9/10、乙 1/2：微平均 10/12≈83.3%，宏平均 (90%+50%)/2=70%。同一原始预测会有不同汇总，需按基准定义和对标报告选择，不混写“平均”。

输出 None 时先检查末行协议，而不是把猜到的数字填回模型回答。若参考错，停止报告并修复数据／评分版本；不改 correct 字段迎合期望。发生新格式时先在小反例上测试，再整体重算；保留旧报告，才能知道分数变化来自模型还是抽取器。

## 分级练习与答案解析

### 跟做练习：同值不同显示

把输出改成 `#### 1,200.0`、参考 `A: 1200`，预测格式与正确性。提示：合法逗号会删除，再按十进制比较。

> [!example]- 参考答案
> 都为 True。完成标准：能说明比较的是数值，不是两个原始字符串；换成 1,20.0 则格式不符。

### 独立练习：失败分母

100 题中 60 正确、30 数值错、10 抽不出。端到端正确率是多少？只在可抽取项上的比例能否叫同一个指标？

> [!example]- 参考答案
> 正确率 60/100=60%；60/90≈66.7% 是可解析条件下的比例，需另注明。完成标准：保留十条失败，不提高总正确率来隐藏格式问题。

### 迁移练习：新评分规则

你增加了单位容忍后分数升高，应写“模型改进”吗？写清复核需要哪些产物。

> [!example]- 参考答案
> 不能仅由此归因模型。应保存旧／新抽取器版本、相同原始输出、变化题目列表和整体重算报告，说明评分规则变化。完成标准：可定位每条因规则变动而改判的回答。

## 本讲任务与阅读顺序

先分清四类评测要检查什么，再打开真实公开数据快照，最后确定可以写什么结论。需要 Python 列表、字典、文件读取；忘记时到 [[01_学习指南/01_Python工程化/00 Python 工程化学习地图|基础教程]]。本讲先看数据，不运行大模型，不把题库名字当综合能力证明。

完成标准：能为选择题、数学题、代码题分别说出输入、输出、判定；能说明本次两条实验路径的区别。

## 要解决什么问题：分数先回答什么问题

“模型 70 分”缺少信息：哪套题、多少题、给不给示范、怎么取答案、生成一次还是多次？基准是固定任务和评分约定组成的比较尺子。它像考试，但尺子量的是特定能力切片，不能从一门考试分数推出所有实际工作都能完成。

公开指题目、规则或部分结果可供外部复核，并不意味着任何版本、任何提示的分数都可直接比较。基准名字之后还要跟版本、数据 split、选题范围和评分方式；split 是数据分区，例如 train（训练）、dev/validation（开发／验证）、test（测试）。用途以相应基准定义为准，不能只看到名字就拿测试题调参数。

## 概念与任务边界

C-Eval 是中文考试评测套件的名称；MMLU 是 Massive Multitask Language Understanding 的缩写，意为“大规模多任务语言理解”。GSM8K 名称来自 Grade School Math（基础学校数学）；HumanEval 在这里指程序补全的功能评测。先把名称和任务对应，不需要背缩写来操作工程。

| 基准 | 主要任务 | 常见输出与判定 | 不能直接证明 |
| --- | --- | --- | --- |
| C-Eval | 中文学科选择题 | A/B/C/D，按题核对选项 | 真实工具执行、复杂交付 |
| MMLU | 多学科知识选择题 | 选项正确率，需明确生成或概率评分 | 所有专业场景可靠性 |
| GSM8K | 多步基础算术文字题 | 抽出最终数值后对照参考 | 推导每步都正确、工具引用正确 |
| HumanEval | 根据函数描述补全代码 | 在相应测试上检查功能，汇总 pass@k | 完整软件质量、生产安全 |

[C-Eval 官方仓库](https://github.com/hkust-nlp/ceval)介绍中文多学科选择题；[MMLU 原论文](https://arxiv.org/abs/2009.03300)覆盖 57 类任务。MMLU 与名字相近的其他变体不是一个版本，报告必须写完整任务名。

[GSM8K 官方仓库](https://github.com/openai/grade-school-math)发布数学文字题及模型回答记录。标准参考答案最终数值以 `####` 标示，保存的历史输出常用末行 `A:`；本单元分别支持这两种明确标记，不猜一段文字最后碰巧出现的数字。数字对不等于过程每一步对，错误过程有时碰巧得到正确数。

[HumanEval 官方工程](https://github.com/openai/human-eval)以功能测试检查生成程序，并提醒执行环境需有效隔离。字符串看起来像正确代码、可以编译或输出含 “pass” 都不能代替测试。当前工程不执行它的生成代码，第 5 讲仅用已给定的正确样本数量学习指标算式；没有跑出本机 HumanEval 分数。

## 本单元两条实验路径

第一条是**公开回答重放**：读取官方已保存的 1319 道 GSM8K 回答，重新抽取、判分、计算统计量。6b_finetuning 与 6b_verification 是上游归档名字，不是你本次训练的模型，也不能叫你的微调前后权重。重放像重新核算旧试卷，验证评分流水线，不证明我们能够重现当年的生成配置。

第二条是**实际模型重评**：重新加载上一单元的 Base 与 tool_only，在相同合成工具任务上真正生成输出，比较微调前后。它能练习固定模型／数据／解码／设备的操作，但不是公开自然语言题库成绩。分开写范围，让每份结果有明确来源。

## 最小示例：读快照与来源

VS Code 打开本工作区，在 `01_学习指南/35_模型公开基准评测/示例工程` 右键打开集成终端，使用 PowerShell。在该目录新建 `lesson_01.py`，保存完整代码：

```python
from suite import ARCHIVE_MODELS, load_snapshot

records, demos, manifest = load_snapshot()
print("公开记录", len(records), "训练示范", len(demos))
print(manifest["commit"])
print(ARCHIVE_MODELS)
print(sorted(records[0][ARCHIVE_MODELS[0]]))
```

```powershell
..\..\..\.venv\Scripts\python.exe lesson_01.py
```

三次 `..` 回到工作区根，随后使用共享解释器；最后文件名是当前工程中的脚本。预期输出：

```text
公开记录 1319 训练示范 5
3101c7d5072418e28b9008a6636bde82a006892c
('6b_finetuning', '6b_verification')
['is_correct', 'solution']
```

`load_snapshot` 先检查文件哈希，再解析 JSONL。JSONL 一行存一个 JSON 对象；records 是每题一项的列表，`[0]` 取第一题；每个归档模型有 solution（保存回答）与 is_correct（上游布尔标签）。评分时将独立重算，而不是把标签直接相加当验证。`sorted` 将字段名排序，方便比对输出。

## 动手操作与预期判断

在 VS Code 打开 `fixtures/manifest.json`，找到 commit 与 archive.jsonl 的 sha256；再打开许可证文本。源码与文件职责见 [[01_学习指南/35_模型公开基准评测/示例工程/README|代码导航]]。不用读完 2.45 MiB 原始题库，只挑一行分清 question、ground_truth 和各组 solution。

完成判断：能指出 ground_truth 是评分参考，solution 是已经保存的回答，prompt 不能含待评题 ground_truth；文件中有回答不意味着本次调用了模型。

## 常见错误与排查

报 `ModuleNotFoundError: suite`：确认学习脚本放在示例工程，与 suite.py 同目录；不要放到教材正文目录。报数据快照哈希不符：先核对是否手工编辑了 fixtures，保留修改证据，再使用另一个目录下载原固定版本核对；不通过改哈希掩盖数据变化。缺文件时检查整个 fixtures 是否存在，按 README 的恢复命令获取固定公开数据，不安装 datasets 来绕过当前缺失。

把历史 6B 回答与自己 17154 参数模型混写，会让报告来源错误。先看 scope 与模型名，不通过改报告标题让不同实验变成同一次实验。

## 分级练习与答案解析

### 跟做练习：字段归类

在第一条记录指出题目、参考、保存回答和上游标签。提示：前两项在题目记录，后两项在模型名字下。

> [!example]- 参考答案
> question 是题目，ground_truth 是参考，模型下 solution 是保存回答、is_correct 是原标签。完成标准：能解释评分不能靠提示看到参考，也不能只信原标签而省略重算。

### 独立练习：同名分数

两份报告都写 MMLU，一份仅 20 题生成字母，另一份全任务选项概率。能直接比较吗？提示：题目范围与判定机制都不同。

> [!example]- 参考答案
> 不能直接比。先核对版本、题目选择、分区、提示与概率／生成评分；20 题适合检查流水线，不能冒充全量成绩。完成标准：指出至少两个具体差异，而不是只说模型大小不同。

### 迁移练习：改写结论

“重放官方回答成功，所以本机模型 GSM8K 有 39% 正确率”哪里错？写一句准确替代。

> [!example]- 参考答案
> 重放没有运行本机模型。可写“我们在固定官方历史回答快照上重新判分，并记录该归档组正确率”；本机权重需要另行实际生成才能报告其成绩。完成标准：结论绑定回答的真正产生者与本次执行范围。

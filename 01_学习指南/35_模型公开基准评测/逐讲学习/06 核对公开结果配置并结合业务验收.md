## 本讲任务与前置

先列对标配置差异，再写本次结论和业务验收下一步。需要上一讲正确率、区间和配对的含义；业务分层指标见 [[01_学习指南/19_Agent评估体系/00 Agent 评估体系学习地图|Agent 评估教程]]，工具任务边界见 [[01_学习指南/34_规划与工具使用微调/00 规划与工具使用微调学习地图|前一单元]]。

完成标准：遇未知配置写 unknown，能说明公开成绩与自己的实验是否直接可比，写出同时包含公开切片与业务行为的验收说明，不机械要求“与榜单差不能超过固定百分比”。

## 要解决什么问题：差几分到底意味着什么

公开报告可能只给模型名与一行分数，未说明任务分区、few-shot、输出规则、量化或截断。自己的分数偏低可能来自模板不匹配、抽取失败或权重不同，不应先用一个固定偏差门槛宣布实现有错。

先列差异，然后确定哪些可统一重跑，哪些只能注明未知。配置差异是诊断线索，不能自动解释全部差距；确认相同条件后再看逐题预测和统计。

## 概念与配置清单

dataset_revision 固定数据版本；split 是分区；selection 是是否全量、某学科或抽样；shots 是示范数；prompt_hash 是完整提示摘要；scoring 是生成抽取或候选概率等评分；extractor 是抽取规则版本。precision／quantization、decoding／max_new_tokens、model_revision 也应记录。

完整评估还保存框架任务配置、tokenizer／chat template、停止规则、设备与批次等。当前比较函数列最核心的十二项，是起点，不是全量通用配置系统。它要求对应字段相同且已知才返回 directly_comparable=True；这说明配置可直接对照，仍不自动排除污染、标签或实现缺陷。

模型版本是比较因素还是控制因素，要先说清研究问题。复现同一公开模型时权重应匹配；比较新模型与旧模型时权重应不同但可追溯，其余协议尽量统一。本例函数保守检查完全相同配置，发现有意的模型差异后需要人解释，而不是把 False 理解为不许做模型比较。

## 最小示例：未知配置不等于默认一致

在本单元示例工程新建 `lesson_06.py`：

```python
from comparison import FIELDS, compare_configs

local = {}
for field in FIELDS:
    local[field] = "fixed-demo"
published = dict(local)
published["shots"] = None
published["quantization"] = "int4-demo"
result = compare_configs(local, published)
print(result["directly_comparable"])
for row in result["differences"]:
    if row["status"] != "same":
        print(row["field"], row["status"])
```

```powershell
..\..\..\.venv\Scripts\python.exe lesson_06.py
```

预期为 `False`、`shots unknown`、`quantization different`。这些字符串是自写配置演示，没有实际运行 INT4。`FIELDS` 是字段名字列表，第一行构建简化字典；`dict(local)` 复制一份，避免改 published 时同时改 local；None 表示未知，不能用 0 代替。

打开 [comparison.py](../示例工程/comparison.py)：任一侧为 None 就记 unknown；都有值但不相等记 different；其余记 same。最终必须所有行 same 才返回 True。函数只列配置差异，不输出“分数差应小于 1%”这类没有任务依据的硬规则。

## 动手操作：把自己的报告填入对标表

用 Obsidian 在 [[02_学习记录/00 我的学习记录|自己的学习记录]] 写四行：公开归档来源、自己的实际模型重评来源、可比较字段、未知／不同字段。先填事实，再写结论。

对 GSM8K 归档，数据提交、回答字节、抽取器、任务数已知；原始模型精确权重、完整提示、shots、采样参数与精度在本报告为未知。Prompt 演示版本不能冒充历史模型版本；原模型保存的输出来自上游，当前没有重新生成。

对自己的单元 34 重评，两个权重哈希、同一合成任务哈希、评分代码、FP32、greedy、8 token、设备已记录。CPU/CUDA 重评计数一致，三次推理 seed spread=0；没有独立训练或真实 INT4 对照，也没有迁移到公开自然语言题库。

本次准确报告可以是：“固定 GSM8K 历史回答重算为 286/1319 和 515/1319，保留 6／1 条格式失败并计算区间；两组上游归档不是我们的前后权重。我们的真实前后权重在合成工具任务上重评为 0/12→12/12，未训练工具与对象仍失败，不能直接与公开自然语言榜单比较。”

## 版本与规范会变化：先核对官方说明

C-Eval 的[官方英文 README](https://github.com/hkust-nlp/ceval/blob/main/README.md)记录 2025-07-27 发布完整测试集；同页较早的分区说明仍有未公开标签的历史描述。本次核对发现这种并存，不把旧教程中的“测试标签永不公开”写成永久事实。操作时固定实际数据文件版本与分区，必要时以发布文件与当次协议复核。

评测框架任务名和 CLI 也会更新。本单元引用 [lm-evaluation-harness 官方仓库](https://github.com/EleutherAI/lm-evaluation-harness)作为真实评测的后续入口，未安装、未验证当前全部框架命令，所以没有给出一个号称可直接复现全部榜单的万能命令。正式适配应先固定一版框架／模型环境，验证一小批输出、答案抽取和任务配置，再按原协议扩大。

## 公开切片与业务验收：各回答自己的问题

业务要问的常常是：请求能否识别、工具参数是否正确、权限是否守住、实际资料是否被使用、不可用时是否承认失败、延迟与成本是否达标。公开知识选择题或数学数值分数没有测完这些行为。

例如公开数学正确率提高，但业务查询错对象，仍不能交付。反过来，已知目录查询通过也不代表可以解数学题。写一张验收卡，分开列“公开能力切片”“业务成功率与关键失败”“性能成本”“来源与限制”，避免把一个总分替代全部条件。

污染风险要明确：公开题可能在训练语料中出现；检测需要训练来源与相似题分析，本次没有完成。可以另收近期、与训练隔离的业务题并保留未反复查看的测试集；这些题不是为了保证模型必然通过，而是减少按已知答案调整的偏差。

## 常见错误与分级练习

unknown 被写成 same：恢复 None，补实际来源，而不是猜默认值。把几题试跑当全量结果：在 selection 写出题目范围。为了对齐公开分数改提取器：保存新版本和逐题改判原因，不倒推规则。真实模型依赖缺失时准备明确安装与硬件方案，按工作区审批；当前两条可运行路径已有环境充分，不需要额外安装。

### 跟做练习：补配置差异

把 split 改成不同字符串，预测新增哪一行，运行验证。提示：其余字段不变。

> [!example]- 参考答案
> 新增 split different，directly_comparable 仍 False。完成标准：可以定位差异，而不是只打印一个不可比结论。

### 独立练习：公开分数差距

自己的 0-shot 生成分数比公开 5-shot 概率分数低 5 个百分点，可否宣布权重加载错误？

> [!example]- 参考答案
> 不可直接宣布。先核对示范、评分、数据选择、模板、精度和权重版本；统一可控因素并看样例及输出。权重加载错误是一种待查原因，不是分数差的唯一结论。完成标准：写出核对顺序，不拿固定门槛替代证据。

### 迁移练习：业务交付判断

GSM8K 高分，但查询工具不可用时仍编答案，应不应该交付该业务？写下一项具体检查。

> [!example]- 参考答案
> 不能仅凭数学高分批准查询业务。增加实际故障任务，检查无观察时拒答、执行成功与任务成功分开、错误调用拦截；记录业务失败率，再决定是否满足明确验收。完成标准：让检查针对真实失败，不只重复跑数学题。

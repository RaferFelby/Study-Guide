# 第 1 讲：建立关系表并查询工单

> [!nav] 页面导航

## 要解决什么问题

把工单全部存为一段文字，再让模型数“未解决有几个”，容易数错。关系数据库将资料组织成**表**，每行一个记录，每列一个字段；SQL是向数据库描述“筛选/统计什么”的查询语言。

你不用先会数据库管理工具。教程在Obsidian读，schema.sql/queries.py在VS Code看，用Python自带sqlite3运行。SQLite直接读写一个数据库文件，无额外服务器安装；真实服务器选型后再讨论PostgreSQL。

## 先认识三张表

users：user_id、tenant_id、name；products：product_id、name；tickets：ticket_id、user_id、product_id、status等。user_id相同表示同一用户，不每张工单重复保存姓名。

**主键**是表中稳定唯一标识；**外键**要求引用存在的另一表记录；**唯一约束**阻止同一业务键重复；NOT NULL要求有值。SQLite外键需每连接启用PRAGMA foreign_keys=ON，见[SQLite外键说明](https://www.sqlite.org/foreignkeys.html)。

tenant_id是租户（数据所属组织）标签。工单的 `(user_id,tenant_id)`同时引用users两列，防止alpha工单连到beta用户。它是数据一致性约束，不替代查询权限；读时仍过滤租户。

## 最小完整SELECT实验

在示例工程新建 `first_select.py`：

```python
import sqlite3

connection = sqlite3.connect(":memory:")
try:
    connection.execute("CREATE TABLE tickets(id INTEGER PRIMARY KEY, status TEXT)")
    connection.executemany("INSERT INTO tickets VALUES(?, ?)", [(1, "open"), (2, "resolved")])
    rows = connection.execute("SELECT id, status FROM tickets WHERE status = ? ORDER BY id", ("open",)).fetchall()
    print(rows)
finally:
    connection.close()
```

运行共享解释器，预期 `[(1,'open')]`。:memory:在内存建库；CREATE TABLE声明列；executemany给多组绑定值；execute查询返回cursor（游标，用来读取结果）；fetchall取全部行。最后关闭连接。

这个最小库没有持久保存，退出就消失。INSERT的持久提交/事务在第4讲讲清；这里同一连接立即读自己刚插入的数据。`("open",)`是一元素tuple，不能漏逗号，否则字符串会被当多个字符参数。

## 把SQL逐段读成中文

```sql
SELECT external_id, status, created_at
FROM tickets
WHERE tenant_id = :tenant_id AND status = 'open'
ORDER BY created_at DESC, ticket_id DESC;
```

SELECT选返回列；FROM指定表；WHERE选满足条件的行；AND要求同时成立；ORDER BY排序；DESC从大到小。:tenant_id是命名占位符，执行时绑定真实值；open是固定状态值。

两个排序字段使同时间工单也有稳定次序。没有ORDER BY，数据库不保证你想象的“插入顺序”。不要把看到一次顺序当接口承诺。

SQL通常写大写关键词以便识别，是可读性惯例，不要求关键词必须大写。表/列名在本工程snake_case，Python与SQL同概念一致。

## 从demo找结果

运行demo，在open_tickets一行找到T-005、T-003、T-001，都是alpha/open，按日期倒序。beta的B-001同为open但不应出现。queries.py保存受限模板；ReadOnlyService提供tenant_id，模型不能填这个参数。

再看status_counts：GROUP BY status将相同状态分组，COUNT(*)数各组行，得到open3/resolved3；下一讲解释为什么有些连接后不能直接COUNT(*)。

每个查询先在纸上预测行数/字段，再执行。SQLite SQL与其他数据库有差异，本单元只验证SQLite实际接口；不能未经检查把函数/占位符原样搬到另一服务器。

## 常见错误与练习

no such table：没初始化，或打开错数据库文件。绑定参数数不对：核对占位符和tuple/dict。字段名拼错：看schema.sql，不从错误中猜列。运行demo数据库找不到：它位于本次唯一临时目录，退出自动清理；学习SQL用示例脚本或自己的练习库。

**跟做：** 最小脚本改查resolved，预测仅id2，再运行。

**独立：** 写alpha工单按priority升序、ticket_id升序返回external_id/priority的SQL；先查schema列名。完成标准：有租户过滤和稳定排序。

**迁移：** 为持续项目设计用户/工单/产品表，说明主外键与业务唯一键。完成标准：姓名变化不需改所有工单，不能用姓名当稳定主键。

> [!example]- 参考答案与解析
> `SELECT external_id,priority FROM tickets WHERE tenant_id=:tenant_id ORDER BY priority,ticket_id`。默认升序，也可写ASC。主键ticket_id是本库内部编号；external_id是来源系统编号，需结合tenant/source唯一，不可假设全世界都不重号。

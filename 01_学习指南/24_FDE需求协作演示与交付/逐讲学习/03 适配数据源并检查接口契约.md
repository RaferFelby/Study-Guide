## 本讲任务与前置

真正通过本地HTTP读取另一服务，检查字段、版本、字节上限与错误。HTTP是服务请求/响应协议；URL包含协议、地址、端口和路径。这里8766端口运行mock政策源，8765端口运行查询页面服务。复习 [[01_学习指南/18_后端网络与系统设计/00 后端网络与系统设计学习地图|HTTP与请求基础]]、Python异常与JSON；先不安装SDK。

## 契约是什么

契约是双方对输入、输出和失败的约定。本例GET `/policies`返回JSON列表，每条只有id/title/text/version/url，字段为非空有限长度字符串，ID不重复，最多100条，响应最多16384字节。引用仅允许预设 `https://policy.example.invalid` 示例域名。

验证字段存在不能证明政策正确或授权真实。版本标记帮助追踪变化，实际生效日期和维护审批仍要业务确定。输入大于上限、字段错或无法解析必须停止自动答复，不能把错误文字当政策正文。

## 启动数据源

在VS Code的示例工程打开终端A，执行：

```powershell
& ..\..\..\.venv\Scripts\python.exe mock_source.py --port 8766
```

`--port`指定监听端口。预期显示合成政策源地址及normal模式，终端持续运行是服务在等待请求，不是程序卡住。按Ctrl+C停止。若端口占用，先确认另一个自己的演示是否仍在运行；可换8768并同步客户端URL，不结束不认识的进程。

再开终端B，创建 `lesson_source.py`：

```python
from adapter import HttpPolicySource

source = HttpPolicySource("http://127.0.0.1:8766/policies")
records = source.fetch()
print(len(records))
print(records[0]["title"], records[0]["version"])
```

运行共享解释器后预期2和模拟退款政策v1。127.0.0.1只指本机；`/policies`是资源路径，不是磁盘文件。HttpPolicySource对象保存URL和2秒超时；fetch发请求，有界读取、UTF-8解析、验证字段后才返回。

## 逐步看adapter.py

构造时只允许无凭据的回环HTTP地址，这限定教学源；不是完整网络沙箱。请求Accept JSON，禁用代理和重定向，避免演示客户端意外跳到别处。读取上限多1字节以判断超量，不无界读大响应。

网络/HTTP失败转换为SourceUnavailable；格式/字段失败为SourceContractError。`raise ... from error`保留底层错误供开发检查，面向用户的service只显示受控提示，不默认打印凭据或原始响应。真实外部接口可能还需授权、分页、限流、重试、更新签名和租户范围；本轮没有这些认证和生产机制。

## 动手：核对故障契约

停止终端A，重新以 `--mode offline`启动。重复运行lesson_source.py，预期SourceUnavailable，不是空政策列表。恢复normal后再跑，应该重新读到v1。停止源与源返回503都是不可用，但调试证据不同，别把二者都写成“没有资料”。

你也可以复制records在内存删除version，再调用validate_policies，预期SourceContractError。保留原夹具，不靠修改真资料制造失败。自动测试中已分别检查缺字段、重复ID、空值、超长、危险引用和错误URL配置。

## 常见错误与修复

### 根据证据分清两类失败

| 观察到的现象 | 适配器结果 | 第一步检查 | 为什么停止自动答复 |
| --- | --- | --- | --- |
| 连接拒绝、超时或 HTTP 503 | SourceUnavailable | 源进程、端口、时间和状态码 | 没拿到可验证的资料 |
| HTTP 302 重定向 | SourceUnavailable | 原地址是否正确，是否变更了服务地址 | 本教学客户端不跟随新地址 |
| 内容类型是网页，而不是 JSON | SourceContractError | 接口路径与 Content-Type | 网页不能作为政策记录使用 |
| 超过 16384 字节 | SourceContractError | 是否返回了非预期大结果 | 响应违反约定上限 |
| UTF-8 解码或 JSON 解析失败 | SourceContractError | 编码和响应格式 | 无法还原受检记录 |
| 缺字段、重复 ID、错误引用 | SourceContractError | 哪一条记录违反约定 | 可解析不等于符合业务契约 |

这两类失败进入查询服务后都会变为 `unavailable`，但提示不同：网络故障提示“政策服务暂不可用”，格式异常提示“政策资料格式异常”。面向使用者提供下一步人工流程；开发者用异常链区分原因。不要因为前端状态相同，就把排查步骤混成一个。

`Content-Type` 是响应头中说明数据格式的字段。UTF-8 是把文本编码成字节的规则；JSON 是列表和字典等结构的文本表示。先有字节，再按编码还原文本，再解析 JSON，最后检查业务字段；每一层都可能失败。

### 不修改夹具也能练习字段检查

保持数据源为正常模式，在示例工程中新建 `lesson_contract.py`，保存这个完整最小示例：

```python
from copy import deepcopy
from adapter import HttpPolicySource, SourceContractError, validate_policies

source = HttpPolicySource("http://127.0.0.1:8766/policies")
records = source.fetch()
broken_records = deepcopy(records)
del broken_records[0]["version"]
try:
    validate_policies(broken_records)
except SourceContractError as error:
    print("练习中预期的拒绝：", error)
print("原始记录版本仍在：", records[0]["version"])
```

先保持终端 A 的源为 normal，在终端 B 运行 `& ..\..\..\.venv\Scripts\python.exe lesson_contract.py`。开头先获取受检记录，因此不依赖另一个脚本的变量。`deepcopy` 复制外层列表和其中的字典，删除副本的版本键不会影响原记录。`del` 删除指定键，`try` 尝试验证，`except` 仅处理这次故意制造的契约错误；其他未知错误仍会暴露。

预期打印“政策字段不符合接口契约”，再打印原版本 `v1`。若最后版本也没了，检查是否只写了 `broken_records = records`；那是给同一对象增加一个名字，没有复制。跟做完成标准是同时看到拒绝及原记录完好，不能用删除验证函数来修复报错。

连接被拒绝：源是否启动、客户端端口是否同步。HTTP404：路径应为/policies。格式失败：检查接口是否返回JSON列表，而不是网页或包一层items。超时：先保存时间/状态证据，不自动提高到无限；当前演示无重试。工具沙箱可能限制本地套接字，作者在获准回环环境验证，不放宽数据契约来绕过错误。

## 练习与答案

### 跟做：从正常到故障再恢复

运行正常读取，切换源到 offline，再恢复 normal。提示：每次切换先用 Ctrl+C 停止自己的源进程，再以同一端口启动。完成标准是记录 2 条/v1、明确 SourceUnavailable、恢复后再次读到 2 条/v1，而不是只记录一次成功。

> [!example]- 参考答案与过程
> 第一次证明正常请求/解析/字段校验链能工作；第二次 503 在解析之前进入不可用错误；第三次证明源恢复后可重新请求。程序没有缓存故障为空列表，故障不会被当成“没有政策”。端口与路径必须始终一致。

### 独立：为什么不能直接相信任意引用

写出引用的协议/目标校验与页面显示方式分别解决什么。提示：一个 URL 是否能点击、能否表示业务授权、是否可以执行页面脚本，是不同问题。完成标准是至少区分地址范围、显示方式和事实来源三项。

> [!example]- 参考答案与过程
> 任意地址可能指向非预期目标，先核对协议及域名范围。页面用 textContent 显示纯文本，不把来源字符串当 HTML 执行；这不证明链接安全或政策有效。再核查来源授权、业务事实与版本，不把字段校验通过当成真实接入验收。

### 迁移：设计一个尚未接入的接口

选择一个假设你有权访问的资料接口，在笔记写请求路径/凭据来源、分页和超时、返回字段/版本、错误状态与人工降级。不要填真实密钥。提示：先举一条正常记录，再写缺版本和上游不可用两种失败。完成标准是另一人能按你的约定区分三种情况；未接入就标记“设计，尚未验证”。

> [!example]- 参考答案与过程
> 可约定 GET /approved-policies，凭据由已授权的安全配置提供，返回 items 与 next_page，记录含 id/text/version/effective_at。设置有界响应和有限超时；缺字段停止自动答复，上游不可用转人工。分页、实际字段、权限和超时数值必须由真实接口协议确定；本答案是设计示意，不证明任何系统支持它。

完成判断：能描述一次请求怎样成为受检数据，能将断连、503、格式错和资料不足分开处理。

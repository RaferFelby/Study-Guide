## 本讲任务与前置

FDE是Forward Deployed Engineer的缩写，通常指贴近使用者与客户团队，将需求逐步做成可运行方案的工程角色；不同公司的职责和资历门槛不同。本单元练访谈、适配、演示与交接，不把完成教材等同于获得某公司任职资格。一个官方岗位说明可参看 [OpenAI新加坡FDE岗位](https://openai.com/careers/forward-deployed-engineer-singapore-singapore/)，阅读时注意当地工作方式和经验条件，不能将它当通用初级标准。

本讲要先弄清当前工作流程。前置是 [[01_学习指南/23_需求到技术方案/逐讲学习/01 把模糊想法变成用户场景|用户场景]]，以及Python字典/列表/文件读取。教材在Obsidian，代码在VS Code，本单元工程只用已有标准库。

## 访谈是获取事实，不是推销功能

访谈是围绕实际任务询问并记录过程。先问“最近一次收到政策问题时你怎么处理”，再问耗时、失败、资料、权限和谁判定答复正确。直接问“你是不是需要AI助手”容易得到礼貌赞同，却无法设计验收。

本例使用者是客服，政策维护者负责资料，验收负责人判断试用是否满足工作需要。采购者或管理者不一定就是实际使用者；只问一个角色可能漏掉更新、权限或失败处理。

最小问题链：触发是什么→输入从哪来→当前每一步怎么做→哪一步最痛→失败怎么办→哪些资料可用→谁能访问→谁负责验收。遇到“很慢”再追问一次具体经历；没有计时就标待测，不让模糊词变成数字结果。

## 记录事实、意见、假设与问题

事实要有来源和可核对条件，例如匿名任务日志的日期与版本；意见是使用者感受；假设是你对改进机会的暂时判断；未定问题需要负责人和下一次确认动作。当前所有回答是作者合成角色的模拟回答，没有真实客户访谈。

模拟客服说“先翻文档，再找维护者核对版本，最后人工答复”；模拟维护者说“VIP条件缺失时交人工”；模拟负责人只允许合成公开政策，不接真实账户或自动退款。由此得到第一轮范围，但真实资料授权与身份系统仍未验证。

## 最小示例：读取模拟访谈

在VS Code打开 `24_FDE需求协作演示与交付\示例工程`，创建 `lesson_interview.py`：

```python
import json
from pathlib import Path

record = json.loads(
    (Path(__file__).parent / "fixtures" / "interview.json").read_text(encoding="utf-8")
)
print("来源：", record["origin"])
for item in record["open_questions"]:
    print(item["id"], item["owner"], item["status"])
```

`Path(__file__).parent`用脚本所在目录找资料，`read_text`按UTF-8读，`json.loads`把文本变为字典；for依次打印未确定问题。打开“终端→新建终端”，确认目录末尾是示例工程，运行：

```powershell
& ..\..\..\.venv\Scripts\python.exe lesson_interview.py
```

`&`调用指定程序；三个`..`从本单元示例工程回工作区根；`.venv`是共享环境，最后参数是脚本。预期来源simulated，Q01/Q02/Q03都为unverified，分别由业务、政策、技术负责人确认。输出成功仅说明记录可读。

## 动手：做五分钟模拟访谈

在Obsidian学习记录写两种角色的对话。先给角色一段真实感任务，再依次问过程、资料、权限、错误处理、完成判断。可以自己扮演两角色；若没有他人参与，明确写“自我模拟”，不要写成外部用户反馈。

保留至少三个未定问题，给负责人和验证方法。不要录入真实客户隐私、账号或凭据来让模拟显得更真实。真实访谈需按组织许可处理记录与资料，本教材没有提供合法授权。

## 常见错误与排查

把“想要准确”当需求：追问答案要引用哪份政策、哪些条件、错了怎样处理。一次说法推成全部用户：补角色和任务分布。未回答的问题留空不管：加负责人、状态、下一次确认。找不到夹具：脚本与demo.py同级，不在教材目录中运行。

## 练习与答案

跟做：列使用者、维护者、验收者各一项职责。独立：将“文档难找”改成三个不诱导的追问。迁移：针对内部报销制度查询访谈，增加资料权限和适用日期问题。

> [!example]- 参考答案与推理
> 客服复核并答复，维护者确认政策来源/版本，验收者确认任务标准。追问可以是“最近一次问题是什么”“你从哪开始找”“找到后怎样确认适用”；避免“是不是搜索不够智能”。报销场景还需部门/职级可见范围、政策生效日期、冲突处理负责人，不能仅沿用退款模板。

完成判断：你能复述当前过程和失败分支，能分清模拟回答与真实事实，并明确下一轮先确认哪三个问题。

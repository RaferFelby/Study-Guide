## 什么是 Protocol（协议）

协议可以先理解为“我需要你会做哪些事”的约定。假如一个函数只需要读取工单状态，它不一定关心读取者是数据库、内存字典还是测试假对象；只要对方提供 `read(ticket_id)` 方法即可。

```python
from typing import Protocol

class StatusReader(Protocol):
    def read(self, ticket_id: str) -> str: ...

class FakeReader:
    def read(self, ticket_id: str) -> str:
        return "open"

def show_status(reader: StatusReader) -> str:
    return reader.read("T001")

print(show_status(FakeReader()))
```

`Protocol` 描述函数需要的能力；`FakeReader` 没有继承 `StatusReader`，但它有签名相符的 `read` 方法，所以静态类型检查器可以把它当作合适的读取者。这里的 `...` 表示只声明方法形状，不在协议里实现具体行为。

测试中常用假的读取者，因为它不需要数据库或网络。协议的目的在于说明依赖的接口，不会在运行时替你检查字典是否合法。初学时记住“需要什么方法就描述什么方法”即可；不要为了显得高级给每个函数都增加协议。

## 顺着调用解释

`StatusReader` 描述需要的方法；`FakeReader` 提供同名方法；`show_status` 调用传入对象的 read，得到 open 并返回，最后 print 展示。方法里的 self 代表当前对象；协议方法的省略号表示此处不提供实现。类声明与对象创建先后执行，函数在真正被调用时才读状态。

## 练习、错误与答案

跟做：运行原例看到 open。独立：只让 FakeReader 返回 closed，预测 show_status 的结果。迁移：换一个实现，只要仍有 `read(ticket_id)` 并返回字符串，show_status 是否需要修改？故意删除 read 方法，再观察报错。

> [!example]- 参考答案
> 独立题输出 closed，调用方保持不变。迁移题若满足同一接口，通常无需修改调用方。删除 read 后实际调用会报 AttributeError；协议声明不会在运行时替你补出方法。恢复实现后再运行，区分静态工具的提示与运行时错误。

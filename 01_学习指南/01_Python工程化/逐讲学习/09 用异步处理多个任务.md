## 1. 串行等待是什么样

假设查询两个工具，每个都要等 1 秒才返回。串行写法是等第一个完成后才开始第二个，总耗时大约 2 秒：

```python
import time

def slow_tool(name):
    time.sleep(1)
    return f"{name}:ok"

start = time.perf_counter()
print(slow_tool("first"))
print(slow_tool("second"))
print(time.perf_counter() - start)
```

`time.sleep(1)` 会暂停当前线程一秒；`perf_counter()` 用来测量经过的时间。两次等待相加，因此通常接近两秒，具体数值受机器影响。

## 2. 用 async 和 await 表示可等待工作

异步函数用 `async def` 定义。调用它时会先得到一个协程对象；协程对象描述“将来要做的工作”，还没有自动完整执行。`await` 表示当前任务在这里等待结果，并允许事件循环安排其他异步任务。

```python
import asyncio

async def slow_tool(name):
    await asyncio.sleep(1)
    return f"{name}:ok"

async def main():
    result = await slow_tool("first")
    print(result)

asyncio.run(main())
```

`asyncio.sleep(1)` 会异步等待一秒。在等待期间，事件循环可以推进别的协程；它不是在当前线程上用 `time.sleep` 堵住所有工作。最外层的普通脚本通过 `asyncio.run(main())` 启动事件循环，并等 `main` 完成。

事件循环可以想成一位调度员，在任务遇到异步等待时去安排另一个任务。这个类比帮助理解“等待时做别的事”，但它不是凭空增加 CPU 算力：一段很长的 CPU 计算若从不 `await`，其他协程仍可能得不到运行机会。

## 3. 并发不等于并行

并发表示多个任务的步骤交错推进；对网络、磁盘等等待多的工作，异步可以在一个任务等待时推进另一个。并行则表示多个计算确实在同一时刻使用多个执行核心。

异步最适合大量等待 IO 的场景，例如同时等待多个 HTTP 请求。它不会自动让纯数学运算变快。CPU 密集运算可能需要多进程或专用计算库，应测量后再选方法。

## 4. 一起推进多个任务

示例工程用 `asyncio.gather` 等待多个工具协程：

```python
import asyncio
from ticketkit.async_tools import run_parallel

results = asyncio.run(
    run_parallel([("fast", 0.0), ("slow", 1.0)])
)
print(results)
```

默认结果为 `['fast:ok', 'slow:timeout']`。这里传入的是模拟任务名称和等待秒数：fast 不等待，slow 模拟等待一秒；本工具默认超时时间只有 0.03 秒，因此 slow 被标记为超时。它不访问网络。

`gather` 一起等待多个任务，并按输入顺序返回结果；哪个任务先完成不一定就是列表中的第一项。等待顺序与返回顺序要分开理解。

## 5. 控制同时进行的任务数

如果同时发出成千上万个请求，可能压垮本机、远端服务或连接池。并发限制是规定“最多允许多少个任务同时进入某一步”。

示例用 `asyncio.Semaphore(concurrency)` 创建信号量。你可以把它想成入口处的有限数量通行牌：拿到牌的任务才开始执行，做完归还。下面的完整小程序最多让两个任务同时等待：

```python
import asyncio

async def do_work(name, delay, semaphore):
    async with semaphore:
        await asyncio.sleep(delay)
        return f"{name}:完成"

async def main():
    semaphore = asyncio.Semaphore(2)
    results = await asyncio.gather(
        do_work("A", 0.1, semaphore),
        do_work("B", 0.1, semaphore),
        do_work("C", 0.1, semaphore),
    )
    print(results)

asyncio.run(main())
```

运行会打印 `['A:完成', 'B:完成', 'C:完成']`。`async with` 自动取得并归还名额；`asyncio.Semaphore(2)` 表示最多两个任务同时占用这一段。三个任务的等待时间通常约为两批（约 0.2 秒），但机器调度会造成差异。真实工程还会在取得名额后启动超时计时，因此工具超时不包含排队时间；整个用户请求的总时限需要由外层单独控制。

并发数设成两，不代表速度一定变成两倍：任务可能串行依赖同一个资源、服务可能限流、任务可能是 CPU 密集，排队和调度本身也有开销。

## 6. 超时做了什么

超时规定一项等待最多允许多久。`asyncio.wait_for(task, timeout)` 到时间后会请求取消被等待的协程，再等待取消清理过程。

这叫协作式取消：程序请求任务停下，任务需要有机会响应。若任务正在执行不可中断的阻塞代码，或者底层系统忽略取消，Python 无法保证它立刻停下。即使本地协程停了，已经发送到远端的更新操作也可能已经执行。

因此需要区分三件事：

1. **等待超时：** 本地在规定时间内没拿到结果。
2. **本地任务取消：** Python 要求协程停止，并运行必要清理。
3. **远端操作撤销：** 远端系统承诺撤回已执行操作。

前两件事不自动代表第三件事。写入、发信、扣款等动作要通过幂等键或状态查询确认结果。

## 7. 取消和错误处理

用户取消任务时，`CancelledError` 应当继续向上传递。若代码把所有异常都改写成“工具返回失败”，外层就无法知道用户要求停止。

示例 `run_parallel` 把可以预期的工具超时转为 `name:timeout`，其他异常继续抛出。它保留了“正常超时是结果的一种”和“程序意外错误应暴露出来”之间的区别。

注意不要在异步函数中直接调用 `time.sleep()`：它会阻塞事件循环。模拟异步等待时使用 `await asyncio.sleep(...)`。调用同步阻塞库时，可评估是否把它放入线程；这样做也有取消和资源管理边界，不能假设远端操作已撤销。

如果一个协程报错，`asyncio.gather` 默认不会自动保证其他所有任务都已经取消并清理。需要“全部一起成功”或“一个失败时都停下”的工作流时，要显式设计取消、清理和错误收集。本单元先掌握当前示例的边界即可。

## 8. 在 Notebook 等已有事件循环中运行

在普通 `.py` 脚本中，可以使用 `asyncio.run(main())` 创建和关闭事件循环。在某些 Notebook 或交互环境中，事件循环已经运行，这时再次调用 `asyncio.run()` 会报错。已有循环时应直接写：

```python
results = await run_parallel([("fast", 0.0)])
```

在 VS Code 的 PowerShell 普通终端里运行教程脚本时，用前面展示的 `asyncio.run(...)` 入口即可。

## 9. 练习和答案解析

**跟做：** 把 `slow` 的等待时间改成 `0.01` 秒，再运行。预期它在默认 0.03 秒限时内完成。小数和系统调度会影响临界值，所以不要用“恰好等于 timeout”的情况作为稳定测试。

**独立：** 创建三个模拟任务，设 `concurrency=1`，观察它们依次取得名额，但结果仍按输入顺序返回。说明超时是否包含等待名额的排队时间。

> [!example]- 独立练习参考思路（先完成再展开）
> 把 `concurrency` 设为 1 后，三个任务依次取得名额。示例的 semaphore 在 `wait_for` 外层，因此先拿到名额，再开始计工具执行超时；其他任务排队期间不消耗这个超时预算。`gather` 返回结果仍按传入任务的顺序排列。记录本机耗时即可，不必要求精确到某个毫秒数。

**迁移：** 为一个模拟的“更新工单”任务增加超时。设计超时后的安全步骤：根据请求编号查询工单状态，只有确认没有更新时才决定是否重新提交。

完成标准：能分别解释并发、并行、超时、取消；运行示例无网络依赖；能说明为什么取消不一定撤销远端副作用。

## 10. 本讲小结

- `async def` 定义协程函数，调用后先得到协程对象；`await` 等待它的结果。
- 事件循环在协程让出控制权时安排其他工作。
- `gather` 可以一起等待多个任务；返回列表通常按输入顺序排列。
- semaphore 限制同时进入某段工作的任务数。
- 超时请求本地任务取消；远端操作是否执行需要另外确认。
- 异步适合等待多的 IO；它不会自动加速 CPU 密集计算。

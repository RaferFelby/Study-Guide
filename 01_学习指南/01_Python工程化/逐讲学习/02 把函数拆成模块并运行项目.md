## 先做什么

先完成上一讲的函数与计数；现在把一个函数交给另一个文件调用。先做下面两个文件，再阅读已有工程结构。所有文件仍在本单元 `示例工程/`，终端也在这里。

## 最小实验：一个文件定义，一个文件调用

创建 `status_counter.py`：

```python
def count_open(statuses):
    count = 0
    for status in statuses:
        if status == "open":
            count += 1
    return count
```

再创建 `run_counter.py`：

```python
from status_counter import count_open

print(count_open(["open", "closed", "open"]))
```

运行 `..\..\..\.venv\Scripts\python.exe run_counter.py`，预期输出 `2`。第一份文件定义函数，没有在导入时打印；第二份文件的 `from ... import ...` 找到同目录模块并取出函数，然后调用它。模块名不带 `.py`。若报 `ModuleNotFoundError`，先检查两个文件是否同目录、文件名是否拼对；不要把文件命名为 `typing.py` 等标准库名称。

## 把不同职责放在不同文件

当程序只有几行时，写在一个文件里很方便。功能逐渐增加后，可以按职责拆成多个文件：这样更容易找到代码，也更容易单独检查某个功能。

Python 里，一个 `.py` 文件通常称为一个“模块”。放在一起、可以按名称导入的模块构成一个“包”。你可以先把包想成一组相关模块组成的工具箱；实际导入时，Python 还需要知道包的位置和运行环境。

示例工程的核心结构如下：

```text
示例工程/
├─ pyproject.toml       项目名称、Python 版本和工具配置
├─ requirements-dev.txt 开发时使用的工具版本
└─ src/
   └─ ticketkit/        Python 包
      ├─ __init__.py    说明对外提供哪些名字
      ├─ data.py        工单数据、校验、生成和统计
      ├─ config.py      配置读取与校验
      └─ __main__.py    程序入口
```

在 `data.py` 中写的数据函数可以供其他模块使用。例如入口文件会从 `data` 导入统计函数。这种分工类似把厨房分成备料、烹饪和出餐区域，方便定位工作；它不意味着每个小函数都必须单独放一个文件。

`src/` 是一种常见的项目布局：源码放在 `src/ticketkit` 下。这样如果忘记安装包，运行时通常会明确报“找不到 ticketkit”，而不是偶然从当前文件夹导入成功，让项目看起来像是已经正确安装。

打开工程文件的方法：在 VS Code 左侧打开 `src/ticketkit/data.py`。导入可以写成 `from ticketkit.data import summarize`，意思是“从 ticketkit 包的 data 模块里拿出 summarize”。我们会在后面的生成器章节详细看这个函数。

## 使用工作区共享的 Python



本课程所有本机示例共用仓库根目录的 `.venv`。虚拟环境是隔离第三方包的 Python 目录；共享环境让各单元复用同一套依赖。已有环境时直接使用，不重复创建。下面运行完整参考工程是后续步骤；只练习本讲独立脚本时，不需要先安装 `ticketkit`。

在 VS Code 打开的本示例工程目录中，PowerShell 终端运行：

```powershell
..\..\..\.venv\Scripts\python.exe --version
..\..\..\.venv\Scripts\python.exe -m ticketkit
```

相对路径中的三个 `..` 表示逐层回到仓库根目录，再进入共享 `.venv`。第一条命令确认解释器；第二条用 `-m` 把已安装的 `ticketkit` 包作为程序运行。若提示找不到包，先核对共享解释器和 [[01_学习指南/01_Python工程化/示例工程/README#安装与运行|安装说明]]；确认尚未安装且该安装方案已获批准后，在本示例工程目录执行：

```powershell
..\..\..\.venv\Scripts\python.exe -m pip install --no-build-isolation -e .
```

这里的 `-e .` 把当前示例包以可编辑方式安装到共享环境；之后修改源码，运行时会直接使用修改后的代码。公共依赖已由仓库根目录依赖清单统一管理。

## 练习与完成标准

跟做：重新打开终端运行两个文件，仍得到 2。独立：把输入换成三个 closed，先预测输出。迁移：另写一个统计 failed 的函数，由入口导入；判断逻辑放在哪个文件，为什么？

> [!example]- 答案与排查
> 独立题输出 0。迁移题的判断与计数放在定义函数的模块，入口只准备输入、调用和展示；输入 `["ok", "failed"]` 应得到 1。若函数未定义，核对导入名与定义名；若运行入口时多出一行输出，检查定义模块是否写了顶层 print。能分别说明模块输入、返回值和入口职责才完成本讲。

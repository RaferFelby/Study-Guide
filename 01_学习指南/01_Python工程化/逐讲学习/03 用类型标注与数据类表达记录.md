## 添加类型说明和数据类

当函数越来越多，只看变量名不一定知道它期待什么。例如 `status` 是任意文字，还是只能取 `open` 和 `closed`？类型标注可以把这些期待写出来，便于阅读，也让检查工具提前发现一部分错误。

```python
def format_ticket(ticket_id: str, status: str) -> str:
    return f"{ticket_id}: {status}"
```

`ticket_id: str` 表示作者预期这里是字符串；箭头 `-> str` 表示函数预期返回字符串。`str` 是文字类型。类型标注像说明书或路标：它帮助人和工具理解代码，但 Python 在运行时不会因为写了 `str` 就自动把数字拒绝。

### 用 dataclass 描述一张工单

如果反复用字典表示工单，字段名容易拼错。数据类 `dataclass` 可以把“工单有编号和状态”写成一个明确的结构：

```python
from dataclasses import dataclass
from typing import Literal

@dataclass(frozen=True)
class Ticket:
    ticket_id: str
    status: Literal["open", "closed"]

ticket = Ticket("T001", "open")
print(ticket.ticket_id)
print(ticket.status)
```

`class Ticket` 定义一种新的数据结构；缩进的两行是它包含的字段。`@dataclass` 会自动提供常用的初始化和显示行为，因此可以直接写 `Ticket("T001", "open")`。`Literal[...]` 是更精确的类型说明，表明状态预期只能是这两个文字之一。`frozen=True` 表示创建后不允许直接把字段重新赋值。

运行会输出：

```text
T001
open
```

尝试执行 `ticket.status = "closed"` 会报错，因为对象被冻结。注意，这仍然主要是类型工具和对象行为提供的保护，不能替代对外部 JSON 的检查。

### 类型检查和运行时检查不是一回事

假设文件里读到下面的数据：

```json
{"ticket_id": 7, "status": "unknown"}
```

JSON 是一种存储数据的文本格式。解析 JSON 只负责把文本变成 Python 的字典、列表和基本值；它不会知道我们的业务规则。静态类型检查通常在你运行程序之前分析源码；运行时校验则是在程序实际收到数据时检查内容。

示例工程的 `parse_ticket` 做了运行时校验：先确认输入是字典，再确认工单编号是非空文字，最后确认状态是允许值。错误数据会变成明确的 `DataError`，不会混进后续统计。你可以在 VS Code 打开 [data.py](../示例工程/src/ticketkit/data.py)，查找 `parse_ticket`，逐步对照这些检查。

运行静态检查：

```powershell
..\..\..\.venv\Scripts\python.exe -m mypy --strict src
```

`mypy` 是静态类型检查工具；`--strict` 打开较严格的一组规则；`src` 表示检查源码目录。成功时能看到 `Success: no issues found in 8 source files` 一类信息。它说明检查器没有发现类型问题，不代表程序逻辑一定正确，也不代表外部数据经过了校验。

> [!example]- 独立练习参考答案（完成后再展开）
> 新建 `ticket_objects.py`，保存以下完整内容。本次特意把 `status` 标注为宽泛的 `str`，便于放入坏状态观察运行时检查；原工程使用更窄的 `Literal`，还同时做外部输入校验。
> ```python
> from dataclasses import dataclass
>
> @dataclass(frozen=True)
> class Ticket:
>     ticket_id: str
>     status: str
>
> def count_status(tickets: list[Ticket]) -> dict[str, int]:
>     counts = {"open": 0, "closed": 0}
>     for ticket in tickets:
>         if ticket.status not in counts:
>             raise ValueError("工单状态必须是 open 或 closed")
>         counts[ticket.status] += 1
>     return counts
>
> tickets = [Ticket("T001", "open"), Ticket("T002", "closed")]
> print(count_status(tickets))
> ```
> 运行 `..\..\..\.venv\Scripts\python.exe ticket_objects.py`，应为 `{'open': 1, 'closed': 1}`。再单独把第二张状态改成 `unknown`，应报上面的 `ValueError`；换成空列表 `tickets = []`，应为两个 0。
> `list[Ticket]` 表示列表元素预期是 Ticket；点号访问字段，代替字典取键。标注并不自动检查调用者的对象类型，本函数只校验状态；来自 JSON 的任意对象还需要 [parse_ticket](../示例工程/src/ticketkit/data.py) 那样的边界检查。若把字段改回 `Literal["open", "closed"]`，类型检查器会拒绝字面量 `unknown`，但 Python 运行时仍靠显式判断拒绝它。



## 迁移练习：表达文件处理记录

设计一个 `FileResult` 数据类，只保存文件名与 ok／failed 状态。写出一条合法记录与一条未知状态，说明哪一层应拒绝未知状态。提示：类的字段说明本身不等于输入校验。

> [!example]- 参考解析
> 两个字段可叫 `filename: str` 与 `status: str`。创建记录前或统计边界检查状态是否在允许集合中；合法 `ok` 可以进入统计，`unknown` 应抛出 ValueError。把上一练习的 Ticket 改成 FileResult 并调整字段访问即可；不需要额外框架。能解释为何类型标注不会自动拒绝坏数据，才完成迁移。

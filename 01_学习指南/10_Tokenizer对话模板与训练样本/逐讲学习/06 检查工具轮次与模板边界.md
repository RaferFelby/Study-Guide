# 第 6 讲：检查工具轮次与模板边界

## 为什么要测试模板

chat template 是数据契约：数据字段要按固定规则变成 token，监督范围要按任务目标对齐。模板改一行可能多出 BOS、漏掉结束符，或者把 assistant 的 label 错贴到 user token 上。模型能开始训练不等于样本正确，因此要测试输入结构与训练目标。

**不变量（invariant）**是每次变换后都必须成立的条件，例如 input_ids 与 labels 一样长、每条记录恰有一个 BOS、每个样本有非零有效监督 token、PAD 位置的 label 一定忽略。测试就是自动检查这些条件的代码。

## 工具消息也要检查边界

在 `示例工程/demo.py` 的天气样本中，assistant 的工具请求头是 `assistant to=weather`；工具响应的角色是 `tool`；最后 assistant 回答。工程选择只监督 assistant 正文与结束符，所以 tool 结果作为上下文保留在 input_ids，却被 labels 标为 `-100`。这是一种本单元教学目标选择，不是工具微调的唯一正确策略。

实际协议可把工具名、参数 JSON、channel 等放在不同位置。比如调用中含非 JSON 参数、recipient 缺失，或工具响应没有对应请求，都应在数据准备阶段报出清楚错误或按业务规则过滤。不要依赖字符串里出现“调用”二字来识别工具行为。

## 截断为什么危险

truncation（截断）是超过最大序列长度时裁掉部分 token。若从左侧随意裁掉，可能留下 assistant 回答却删掉用户问题；若从右侧裁掉，可能丢掉 assistant 的结束符，或把标签只剩一部分。对多轮对话，截断边界还可能切开消息头或 JSON 工具参数。

本工程暂不实现自动截断，避免把复杂选择隐藏起来。实际项目应先定义策略：保留最近若干轮、完整保留最后一次 user/assistant 对，或拒绝超长记录；策略之后对 token 序列执行，并验证没有产生不完整模板和零监督样本。具体策略应与模型上下文限制、任务目标共同确定。

## 关键测试

在 VS Code 打开 `示例工程/tests/test_chat_data.py`，测试覆盖这些规则：

1. assistant 正文/结束标记确实受监督，而 user 正文被忽略；
2. tool 流程包含 assistant recipient 头、工具返回和最终 assistant；
3. 模板只有一个 BOS，每条消息一个 IM_START；
4. 左右 padding 的 ID、mask 与 labels 对齐；
5. 每个样本有效监督数大于零，pad label 被屏蔽；
6. 无效 padding_side、空消息列表、未知角色、input/label 长度不一会清晰失败。

运行命令：

```powershell
..\..\..\.venv\Scripts\python.exe -m pytest -q
```

如测试失败，先读断言表达式左、右两边，再打印短小样本的 input_ids、labels 和 attention_mask。不要把断言删掉来消除红色输出；先检查模板哪一处没有满足不变量。

## 练习

**跟做：** 改变测试中 assistant 文本，再运行测试。预期仍通过，因为断言按 token 长度和角色规则判断，不依赖某句固定答案。

**独立：** 为你自己的模板写出至少四条断言：BOS 数量、消息开始/结束边界、user labels 屏蔽、每个样本监督数非零。

**迁移：** 模板加入 `analysis` 通道头后，列出怎样防止它被错误地重复编码或意外纳入监督。

> [!example]- 参考答案与解析
> 角色与文本的断言可以用 `labels` 遮罩的位置切片配合生成的 `input_ids`，不应只测序列总长度。若头部默认 mask，就断言 `analysis` header 对应位置 labels 为 -100；若目标需要教模型输出该通道，再明确设置它监督并把这一策略加到测试中。
>
> 增加模板字段后运行一个黄金样本（固定输入及预期 token/字段边界）、重复 special token 检查、labels 与 input 长度检查，以及至少一个批处理测试。黄金结果应与该模型 tokenizer 的真实输出同步，不要复制教学 tokenizer ID。

## 常见错误

- 测试只断言“没有抛异常”：模板完全错位也可能正常返回。
- 只检查 input_ids，不检查 labels：数据看似有内容，loss 却可能全被忽略。
- 只检查全 batch 总监督数：某一条空监督样本可能被其他样本掩盖，应逐样本检查。
- 截断后忘记重新生成 attention mask 与 labels：各字段长度或位置错位。

写下三条训练文本：`low`、`low`、`lower`。先数 `l,o` 和 `o,w` 各出现几次，再预测把 `l,o` 合成一个 token 后，总 token 数会减少多少。第 4 节会给你可以直接运行的源码与输出。

## 1. 先明确本课的字节 BPE 约定

BPE 是 Byte Pair Encoding 的缩写。本课从 UTF-8 字节出发，统计当前 token 序列中的相邻对，逐轮选择频次最高的一对，增加一个代表二者连接的新 token。

算法过程中“一对”指两个**当前 token**，它们后期可能各自代表多个字节；不是每轮只能合并两个原始字节。

| 设计项 | 本课选择 | 限制或原因 |
|---|---|---|
| 初始词表 | 256 个单字节，ID 为 0～255 | 可以分解所有合法 UTF-8 文本的字节 |
| 新 ID | 第 1 次 256，第 2 次 257，以此类推 | ID 只是编号，没有大小语义 |
| 统计边界 | 每条训练字符串内部 | 不跨两条样本边界合并 |
| 并列频次 | 选择 ID 对字典序最小者 | 本地确定性约定，不是所有 BPE 库的共同标准 |
| 停止条件 | 达到轮数上限，或最高频次小于 2 | 不为只出现一次的对继续扩词表 |
| 替换方式 | 从左到右，不重叠替换 | 同一原位置不能被同时消费两次 |
| 预处理 | 不改大小写、空格或 Unicode 规范形式 | 小实验易于核对，未复刻生产预分词流程 |

本课是一个明确约定的字节 BPE 教学变体。真实 tokenizer 还可能使用正则预分词、词边界标记、标准化、特殊 token 和不同词表格式。不能只拿到“BPE”三个字就认为切分必然相同。

> [!warning] 与前面模板工程分开
> [tokenizer.py](../示例工程/tokenizer.py) 使用特殊 ID 0～5、字节偏移 6；本课 [bpe_demo.py](../示例工程/bpe_demo.py) 使用字节 ID 0～255，没有对话特殊 token。两套 ID 不可混用。本课不会改变既有 labels 或模板工程，也不能把这些自制 ID 输入现成大模型。

## 2. 手算两轮训练

### 初始状态与计数

英文小写字母在 UTF-8 中各占一个字节：`l=108`、`o=111`、`w=119`、`e=101`、`r=114`。先用字母看更直观：

| 样本 | 初始序列 | token 数 |
|---|---|---:|
| 第 1 条 low | l、o、w | 3 |
| 第 2 条 low | l、o、w | 3 |
| 第 3 条 lower | l、o、w、e、r | 5 |

总数 11。相邻对 `l,o` 出现 3 次，`o,w` 也出现 3 次，`w,e` 和 `e,r` 各 1 次。重复的 low 代表它在训练语料里出现两次，必须累计两次；不能先把文本变成集合去重而不保留频数。

### 第 1 轮：合并 l,o

两个最高频对并列。本课比较 ID 对：先比较第一个 ID，`108<111`，所以选择 `(108,111)`。给新片段 `lo` 分配 ID 256。

三条序列变为 `[lo,w]`、`[lo,w]`、`[lo,w,e,r]`。每条消去一个位置，总 token 数从 11 变为 8。

注意此时再数的是新的相邻对：`lo,w` 出现 3 次。原来的 `o,w` 已不在序列中，不能继续使用旧计数表。

### 第 2 轮：合并 lo,w

把 `(256,119)` 合并为 ID 257，表示 `low`。结果为 `[low]`、`[low]`、`[low,e,r]`，总数变为 5。

之后只有 `low,e` 和 `e,r`，各出现一次。本课频次阈值是 2，所以即使上限写了 4 轮，也在完成两次合并后停止。最终词表有 `256+2=258` 个条目，并不是只包含这两条新片段。

## 3. 训练完成后，编码时不再重新学规则

现在要处理没有出现在训练集中的 `lowest`。先把它拆成字节，再依次应用已经保存的规则：

1. 初始 `l,o,w,e,s,t`。
2. 应用第 1 条规则 `l,o → lo`，得到 `lo,w,e,s,t`。
3. 应用第 2 条规则 `lo,w → low`，得到 `low,e,s,t`，IDs 为 `[257,101,115,116]`。

这个顺序称为 merge rank，合并优先级；rank 越小代表越早学到。编码阶段使用固定规则，不按新输入的频次临时再训练，否则同样 ID 的含义和模型预期就会变化。

本实现每次应用一条规则，按训练顺序扫过整个当前序列。规则只能引用初始 ID 或更早生成的 ID，不能引用未来才创建的 token，因此这个顺序有清晰的依赖关系。生产实现通常有更高效的优先级和局部更新算法，本课先观察机制。

若输入 `zzzzzz`，虽然 z,z 在新文本中很多，但训练规则中没有它，因此仍是六个字节 token。未见文本仍能表示，是因为初始词表包含所有字节，不是 tokenizer 自动学会了新词。

打开 `01_学习指南/10_Tokenizer对话模板与训练样本/示例工程`，阅读 [bpe_demo.py](../示例工程/bpe_demo.py)，在该目录的 PowerShell 运行：

```powershell

```

命令用三个 `..` 回到仓库根，选择共享环境解释器，执行当前目录的脚本。不会修改模型、下载语料或写入结果文件。

关键输出：

```text
合并规则 [(108, 111), (256, 119)]
新 token 256 (108, 111) b'lo'
新 token 257 (256, 119) b'low'
训练文本总 token 数 11 → 5
'lower' [257, 101, 114] 往返一致 True
'lowest' [257, 101, 115, 116] 往返一致 True
'猫🙂' [231, 140, 171, 240, 159, 153, 130] 往返一致 True
'' [] 往返一致 True
```

`b'lo'` 表示字节串，不是普通字符串；`repr(text)` 让空字符串也显示成 `''`。这里的“11 → 5”只说明这三条训练文本压缩了 token 序列，不代表文件字节压缩率、推理提速比例或模型质量提升；词表更大也会影响模型 embedding 等结构的成本。

## 5. 分段读源码

### 统计相邻对与执行替换

`count_pairs()` 使用外层循环依次读各样本，内层从 `0` 走到 `len(sequence)-2`，取当前位置与下一个位置组成元组 `(left_id,right_id)`。元组保存有顺序的一组元素；本例的两个元素都是整数，因此这对值可以作为字典键。不是任意元组都可以：若其中放了可变列表，就不能作为字典键。`.get(pair,0)+1` 累计它出现的次数。

`merge_pair()` 用 `index` 从左到右读：当前与下一项匹配时，追加新 ID 并前进 2；否则保留当前 ID 并前进 1。它创建新列表，不原地改输入，也不会越过样本末尾。

### 训练的关键顺序

`train_merges()` 校验字符串列表与非负整数上限，先通过 `text.encode("utf-8")` 得到字节，再用 `list(...)` 变成整数列表。每轮执行“重新计数 → 选最高频对 → 检查停止 → 替换 → 保存规则”。

选择表达式 `min(counts, key=lambda pair: (-counts[pair], pair))` 可拆成：

1. 对每个候选建立排序依据 `(负频次, ID对)`。
2. 频次越大，负频次越小，先被选中。
3. 频次相等时再比较 ID 对；元组先比第一项，相等再比第二项。

`lambda` 是这里临时定义的小函数；不熟悉时可以改写成普通 `def` 返回同样的二元组，算法不变。下面的列表推导式只是“对每条序列调用 merge_pair，再收集成列表”的缩写。

### 词表与解码

`build_vocab()` 先为每个字节创建 `ID → bytes` 的映射，再按规则顺序连接左右字节串。它拒绝未知／未来 ID、重复规则和错误规则结构，防止词表与优先级不一致。

`decode_bpe()` 根据 ID 收集字节串，全部连接后再做一次 UTF-8 解码。一个 token 可能只有一个中文字符的部分字节，不能把每个 token 都独立解码成字符。本课单字节 231 只是“猫”的开头，单独解码会报 `UnicodeDecodeError`。

这说明“词表 ID 有效”与“整条序列能解码成合法文本”是两件事。`encode_bpe` 产生的序列能还原其合法 UTF-8 输入；随便手写或截断 ID 序列则不一定。Python 字符串若含无法按默认 UTF-8 编码的孤立代理码，也会明确编码失败，不会静默替换。

## 6. 一个容易算错的重叠例子

考虑 `aaa`，字节 ID 为 `[97,97,97]`。相邻位置共有两对：位置 0～1 与位置 1～2，因此 `(97,97)` 的**相邻频次**为 2。

但合并时同一个位置 1 不能同时归入两个新 token。按本课从左到右非重叠策略，只能得到 `[256,97]`，实际减少一个 token。不要把频次 2 直接解释成这轮一定减少两个 token。

新建 `lesson_overlap.py`：

```python
from bpe_demo import count_pairs, merge_pair

sequence = [97, 97, 97]
print(count_pairs([sequence]))
print(merge_pair(sequence, (97, 97), 256))
print(sequence)
```

运行共享解释器加文件名，输出 `{(97,97): 2}`、`[256,97]` 和未改变的 `[97,97,97]`（空格格式不影响结果）。计数与替换采用的口径不同，必须分开解释。

## 7. 分层练习与答案

### 跟做：只允许一轮合并

把 `max_merges=4` 改成 1，在单独练习脚本里打印规则与 `lower` 的 IDs。完成标准：只有 lo 合并，尚无 low token，能手算为什么输出长度为 4。

> [!example]- 完整答案
> ```python
> from bpe_demo import encode_bpe, train_merges
> 
> merges = train_merges(["low", "low", "lower"], 1)
> print(merges)
> print(encode_bpe("lower", merges))
> ```
> 保存为 `lesson_one_merge.py` 并运行。两行分别为 `[(108,111)]` 和 `[256,119,101,114]`。新 token 只表示 lo；编码不会擅自补上第二轮。

### 独立：样本边界影响统计

比较 `['a','b','a','b']` 与 `['ab','ab']`，都允许 5 轮。它们含有相同数量的 a、b，是否学到同样规则？提示：逐条字符串内部计数。

> [!example]- 完整答案与解析
> ```python
> from bpe_demo import train_merges
> 
> print(train_merges(["a", "b", "a", "b"], 5))
> print(train_merges(["ab", "ab"], 5))
> ```
> 保存为 `lesson_boundaries.py` 运行，结果为 `[]` 和 `[(97,98)]`。第一份每条只有一个字节，没有样本内部相邻对；第二份 ab 出现两次，能学到一个新 token。不要为了增加频次擅自把独立样本拼接而改变边界。

### 迁移：用中文训练，保留空格和换行

用 `['猫猫','猫猫']` 训练 6 轮，再编码 `猫 猫\n`。要求解码后与原字符串完全相等，同时打印 ID 数量。先不要猜每个 token 一定对应一个中文字。

> [!example]- 完整参考答案
> ```python
> from bpe_demo import decode_bpe, encode_bpe, train_merges
> 
> merges = train_merges(["猫猫", "猫猫"], 6)
> text = "猫 猫\n"
> token_ids = encode_bpe(text, merges)
> print(merges)
> print(token_ids, len(token_ids))
> print(repr(decode_bpe(token_ids, merges)))
> print(decode_bpe(token_ids, merges) == text)
> ```
> 保存为 `lesson_chinese_bpe.py` 运行。按本课并列规则，合并依次为 `(140,171)`、`(231,256)`、`(257,257)`；新文本结果为 `[257,32,257,10]`，长度 4，最后两行为 `'猫 猫\n'` 和 True。空格阻止两个猫紧邻，不能应用“猫猫”规则；换行字节也保留。换一套并列规则可能得到不同 ID，不能把这个编号当行业固定值。

## 8. 常见错误与边界

| 现象 | 检查与修复 |
|---|---|
| 只允许 4 轮却只合并 2 次 | 检查最高频次是否已小于 2；轮数是上限 |
| 新文本有重复片段却没合并 | 检查训练规则是否包含该对；编码不重新训练 |
| 中文单 token 解码报错 | 先把所有 token 的字节串连接，再整体 UTF-8 解码 |
| token ID 0 被当 PAD | 混用了两套 tokenizer；本 BPE 的 0 是普通字节 |
| 解码丢空格或换行 | 不要对输入或输出随意 `.strip()`；检查预处理是否改变文本 |
| 更换规则后旧 IDs 意义改变 | 保留原词表与规则配对，重新编码原文本；不能只替换规则列表 |

本实现每轮重新扫描序列、编码也逐条规则扫描，适合小语料教学，不能以此估计成熟 tokenizer 的吞吐。它没有增量训练、词表文件兼容、特殊 token 保护、并行预处理或完整 Unigram 实现。同一文本编码后的 token 序列变短，也不能证明模型更理解语言。

本课测试在 [test_bpe_demo.py](../示例工程/tests/test_bpe_demo.py)，包含小规模穷举往返、输入不修改、未知文本、重叠、边界、规则错误和截断 UTF-8。运行：

```powershell

```

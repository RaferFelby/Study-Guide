## 本讲目标与先修知识

需要知道分类交叉熵和 Tensor 形状，可回顾 [[01_学习指南/05_数学概率与优化/逐讲学习/06 熵交叉熵与KL散度|单元 05 交叉熵]]。本讲要正确对齐“给定前文预测下一个 token”，解释 teacher forcing、并行训练与逐 token 生成的差异，并识别 padding 的无效目标。

## 长度 4 的输入目标

假设 token 序列是 `[猫, 在, 睡, 觉]`。训练数据错开一格：

| 输入位置 | 输入 token | 希望模型预测 |
|---|---|---|
| 0 | 猫 | 在 |
| 1 | 在 | 睡 |
| 2 | 睡 | 觉 |

因此输入 `[x₀,x₁,x₂]`，标签为 `[x₁,x₂,x₃]`。长度为 4 的原始窗口会产生长度 3 的输入与目标。在批次中输入形状是 `[B,T]`，模型输出 logits 是 `[B,T,V]`，标签是 `[B,T]`；V 是词表大小。logits 是 softmax 前的分数，每个位置有 V 个候选 token 分数。

## 最小交叉熵示例

```python
import torch
from torch.nn import functional as F

logits = torch.tensor([
    [[2.0, 0.1, -1.0], [0.2, 1.5, 0.0]]
])
labels = torch.tensor([[1, 2]])

loss = F.cross_entropy(
    logits.reshape(-1, 3),
    labels.reshape(-1),
)
print(loss.item())
```

这里 logits 是 `[B=1,T=2,V=3]`。交叉熵期望分类分数为 `[样本数,类别数]`，所以把前两维合并成 2 个位置；标签同步展平为 2 个正确类别编号。每个位置的损失再求平均。示例标签中的编号只是类别 ID，不是文字本身。

padding 标签需要排除。工程将无效位置改成 `-100`，并让交叉熵使用 `ignore_index=-100`；否则模型会被要求预测一个并不存在的 padding 词。注意 `-100` 是 PyTorch 此处的忽略标签约定，不是词表 token。

## Teacher forcing 与推理

Teacher forcing（教师强制）指训练第 i 个位置时，使用真实数据中的前缀作为上下文，而不是上一时刻模型自己猜的 token。配合因果 mask，整段输入可一次前向计算，所有位置的预测并行产生。

生成时没有真实未来 token：先用提示词预测一个 token，将它追加到前缀，再预测下一个。这是逐步循环。训练并行与生成顺序进行并不矛盾，因为它们拥有的信息不同。

## 常见错误

- 输入和标签没有错开：模型只需复制当前位置，任务变错。
- logits 展平、标签没同步展平：样本数量不匹配。
- 先对 logits 做 softmax 再传给 `cross_entropy`：该函数接收未归一化分数，内部会稳定地计算 log-softmax。
- padding mask 与 loss ignore 混为一谈：前者防止读取无效 Key，后者防止监督无效标签。
- 训练也逐 token 循环：不必要地放弃了整段并行训练。

> [!example]- 答案解析：训练为什么能并行
> 训练输入整段真实 token；因果 mask 保证位置 i 只看位置 0 到 i。因此各位置的条件预测互不泄漏，可以在一个张量前向中同时计算。推理没有真实答案前缀，只能把预测结果逐步追加。

## 1. 三个部件分别解决什么问题

注意力已经让当前位置收集到其他位置的信息，但一个 Transformer Block 还有另外几项工作：

| 部件 | 本课要观察的作用 | 输入输出形状 |
|---|---|---|
| LayerNorm，层归一化 | 按一个 token 的特征计算均值和方差，再学习缩放和平移 | `[B,T,D] → [B,T,D]` |
| FFN，前馈网络 | 对每个位置的特征作两次线性变换，中间加入非线性 | `[B,T,D] → [B,T,F] → [B,T,D]` |
| residual connection，残差连接 | 在子层更新上加回原输入 | 两份 `[B,T,D]` 逐元素相加 |

`B` 是一批序列的数量，`T` 是每条序列的位置数，`D` 是每个位置的特征数，`F` 是 FFN 中间特征数。“前馈”表示数据依次经过层，不表示网络没有可训练参数。

本课的 LayerNorm 与 FFN 都单独处理每个位置；FFN 的参数在各位置共享。已有 Block 中的跨 token 信息交换由注意力完成；不能把整个 Block 说成“各 token 相互独立”。

## 2. LayerNorm：每个位置按自己的特征归一化

### 进入 Block 前：token ID 怎样变成特征

前两讲直接给出了浮点 Q/K/V 或隐藏向量；实际模型的输入常是整数 token ID。Embedding（嵌入层）维护一张可学习的表：词表有 V 个 ID，每行有 D 个浮点特征，参数形状就是 `[V,D]`。ID 选择其中一行，输入 `[B,T]` 就得到 `[B,T,D]`。

在本单元示例工程新建 `lesson_embedding.py`，运行下面完整例子：

```python
import torch
from torch import nn

embedding = nn.Embedding(3, 2)
with torch.no_grad():
    embedding.weight.copy_(torch.tensor([[1.0, 0.0], [0.0, 1.0], [1.0, 1.0]]))
token_ids = torch.tensor([[2, 0, 2]], dtype=torch.long)
features = embedding(token_ids)
print(tuple(features.shape))
print(features.tolist())
features.sum().backward()
print(embedding.weight.grad.tolist())
```

在该目录运行共享解释器加 `lesson_embedding.py`，三行输出如下：

```text
(1, 3, 2)
[[[1.0, 1.0], [1.0, 0.0], [1.0, 1.0]]]
[[1.0, 1.0], [0.0, 0.0], [2.0, 2.0]]
```

`nn.Embedding(3,2)` 创建三行两列的可训练参数，之后为便于手算写入已知数字；真实训练通常从初始化值开始学习。`dtype=torch.long` 令 ID 为整数索引；2 选第 2 行，不是把特征乘以 2。输入 0 在本例也是普通 token，没有指定 padding ID。

`features.sum()` 只是演示梯度累加的标量，不是语言模型训练损失。第 0 行出现一次，每个分量梯度为 1；第 1 行没被查到，梯度为 0；第 2 行出现两次，每个分量梯度相加得到 2。`.backward()` 只计算梯度，这里还没有优化器更新参数。两个位置用同一个 ID，会使用同一行可学习参数。

独立练习：把 IDs 改成 1、1、0，预测梯度，再运行。应得到第 0 行 `[1,1]`、第 1 行 `[2,2]`、第 2 行 `[0,0]`。另把某个 ID 改成 3，应因越过合法范围 0～2 而报 `IndexError`；改成 -1 也不能像 Python 列表那样从最后一行取值。换成小数 ID 会类型报错。

嵌入向量在训练前没有天然的词义保证；ID 数值相近也不表示语义相近。后续 tokenizer 换了 ID 含义，就必须同时处理这张表与模型的配对，不能只保证 ID 没越界。

### 先手算一个 token

设一个 token 的特征为 `[1, 3]`，特征数 `D=2`：

1. 均值 `mean = (1+3)/2 = 2`。
2. 每个值减均值：`centered = [-1, 1]`。
3. 平方后求平均：`variance = (1+1)/2 = 1`。
4. 除以 `sqrt(variance + eps)`，得到约 `[-0.999995, 0.999995]`。

`sqrt` 是平方根；方差的平方根是标准差。`eps=0.00001` 是加在方差里的小正数，避免所有特征相同、方差为零时除以零。这里除以 `D`，不使用统计学估计样本方差时的 `D-1`。

再算 `[10,14]`：均值 12，偏差 `[-2,2]`，方差 4，结果也接近 `[-1,1]`。它们各用自己的统计量，没有先把四个数字放一起平均。

### 再对应公式与参数

对同一个 token 的第 `j` 个特征：

$$
y_j = \gamma_j \frac{x_j-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta_j
$$

`mu`（μ）就是该 token 的均值，`sigma²`（σ²）就是刚才算的方差；`gamma`（γ）是每个特征的可学习缩放，`beta`（β）是可学习平移。默认初始化为 γ=1、β=0，此时先看到规范化后的数值。

两个容易误解的地方：

- 即使没有仿射变换，加入 eps 后的方差也不是数学上严格的 1，而是 `variance/(variance+eps)`；常量输入的规范化结果为 0。
- 学到非平凡的 γ、β 后，输出均值也未必为 0。例如所有 γ=2、β=3，这个两维例子的输出接近 `[1,5]`，均值变为 3。

“归一化”并不要求抹掉后续所有尺度。它先整理输入，再让模型学习所需的缩放和平移。

### 轴在哪里

在 [block_parts_demo.py](../示例工程/block_parts_demo.py) 中，`normalize_features()` 分四步实现手算版本：

```python
feature_mean = values.mean(dim=-1, keepdim=True)
centered = values - feature_mean
feature_variance = centered.square().mean(dim=-1, keepdim=True)
normalized = centered / torch.sqrt(feature_variance + eps)
```

这四行是函数内部片段，不要单独运行；第 5 节有完整程序。`dim=-1` 是最后一轴；输入 `[1,2,2]` 时，均值形状为 `[1,2,1]`。`keepdim=True` 保留这个长度为 1 的轴，广播时每个位置减自己的均值。`square()` 逐元素平方。

源码还校验输入与中间统计量：本手算版本只接受有限的 float32／float64，拒绝未在本课处理的低精度张量。输入有限也可能在平方时溢出，例如 float32 的 `1e30`；遇到这种情况会明确报错。它用于小数值机制对照，不是生产 LayerNorm 内核，也没有复刻库在混合精度下的内部累加策略。

本工程使用 `nn.LayerNorm(D)`，规范化最后一维。库也允许指定多个最后维度；例如 `nn.LayerNorm((T,D))` 会联合统计位置和特征，这与当前模型的逐 token 设计不同。LayerNorm 在训练和评估时都从当前输入计算统计量，没有这里需要切换的 running mean；仍应按工程惯例调用 `.train()`／`.eval()`，因为同一模型的 Dropout 等部件有不同模式。

## 3. FFN：先扩展特征，再压回原维度

### 手算用 ReLU，模型仍用 GELU

为先算清矩阵，本课单独创建一个 `2 → 3 → 2` 网络。第一层把 `[a,b]` 变为 `[a,b,a-b]`；ReLU 把负数变为 0，非负数保留；最后把三个值 `[u,v,w]` 变为 `[u+w,v-w]`。

对 `[2,-1]`：

| 步骤 | 结果 | 原因 |
|---|---|---|
| 第一层 | `[2,-1,3]` | 第三项为 `2-(-1)` |
| ReLU | `[2,0,3]` | 只有 -1 被置零 |
| 第二层 | `[5,-3]` | `2+3=5`，`0-3=-3` |

第二层之后没有再加 ReLU，所以负输出合法。对 `[1,3]` 同样计算，三步为 `[1,3,-2] → [1,3,0] → [1,3]`。

函数 `build_fixed_ffn()` 使用 `nn.Sequential` 按顺序调用三层；第一层的权重形状为 `[3,2]`，第二层为 `[2,3]`，偏置都手动置零。PyTorch `Linear` 实际按 `input @ weight.T + bias` 计算，因此每个权重行定义一个输出特征。

`with torch.no_grad()` 中的 `weight.copy_(...)` 将已知数字写入现有参数；末尾下划线表示原地操作。这里是在初始化教学权重，不通过这些赋值构建求导图。不要在正常训练的前向过程中随意重写权重。

已有 [model.py](../示例工程/app/model.py) 的 FFN 使用 **GELU**，本课 ReLU 是便于手算的独立示例，未替换模型。GELU 可以理解为用一个平滑门控制输入：`GELU(x)=x*Φ(x)`，其中 Φ 是标准正态分布累计到 x 的概率。它不是随机抽样，也不会把所有负数都严格置零。例如 `GELU(-1)` 约为 -0.1587，`GELU(1)` 约为 0.8413。先理解它引入非线性，概率公式可稍后复习。

### 为什么需要中间的非线性

若两层之间只有线性计算，把两次乘矩阵和偏置合并，仍可表示成一次仿射变换。ReLU／GELU 根据输入值改变变换方式，增加可表达的函数种类。中间维度 `F` 决定这里的特征容量与计算量；本工程不是要求所有模型固定 `F=4D`，也没有在本课实现门控 FFN。

`nn.Linear` 保持前面的 `B,T` 轴，只变换最后一轴。不同 token 使用同一组参数，但不互相读取对方输入。后面的迁移练习会实际检查这一点。

## 4. 残差：把更新加回输入

可以先把子层看成“产生一次特征更新”，原输入保留在另一条路径：`output = input + update`。对上面的 `[2,-1]` 和 FFN 输出 `[5,-3]`，残差结果为 `[7,-4]`。

这不是列表拼接，也不是把向量平均；两个对应位置直接相加。本课 `add_residual()` 要求形状完全相同，避免 PyTorch 自动广播把错误形状扩展成貌似能运行的结果。例如 `[1,2,2]` 与 `[2]` 在 PyTorch 中能相加，但它不是我们当前期望的两个同形子层张量。

从梯度看，标量小例子 `y=x+3x` 的导数是 `1+3=4`，其中 1 来自原输入这条直接路径。向量版本可写为单位映射加上子层的导数矩阵。这解释了直接梯度路径的来源，但不保证任意深度、初始化和学习率下都没有梯度消失或爆炸。

创建 `lesson_norm.py`，导入 `torch` 与 `normalize_features`，对 `torch.tensor([ [ [7.0, 7.0] ] ])` 运行函数。先写下均值、方差和预期输出。

### 独立：检查 FFN 与残差

输入改为 `[ [-2, 1] ]`，手算三层输出及残差，再新建 `lesson_ffn.py` 验证。提示：第一层是 `[-2,1,-3]`。完成标准：结果正确，并能解释为什么第二层输出无需全部为正。

> [!example]- 完整答案与解析

> import torch
>

> 
> values = torch.tensor([[-2.0, 1.0]])
> network = build_fixed_ffn()
> with torch.no_grad():
>     updates = network(values)
>     print(updates.tolist())

> 输出为 `[ [0.0, 1.0] ]` 和 `[ [-2.0, 2.0] ]`（空格格式可能略不同）。ReLU 后是 `[0,1,0]`，第二层不改变这两个结果；残差再加回 `[-2,1]`。

### 迁移：改变别的位置会不会影响当前输出

对两个 token `[[[2,-1],[1,3]]]` 运行 FFN，再只把第二个 token 改成 `[99,7]`。第一位置输出应怎样？对 LayerNorm 同样做一次检查。提示：用 `.clone()` 创建另一份张量，避免把基准输入一起改掉。

> [!example]- 完整答案与解析
> ```python
> import torch
> 
> from block_parts_demo import build_fixed_ffn, normalize_features
> 
> original = torch.tensor([[[2.0, -1.0], [1.0, 3.0]]])
> changed = original.clone()
> changed[:, 1] = torch.tensor([99.0, 7.0])
> network = build_fixed_ffn()
> with torch.no_grad():
>     print(torch.allclose(network(original)[:, 0], network(changed)[:, 0]))
>     first_norm = normalize_features(original)[:, 0]
>     changed_norm = normalize_features(changed)[:, 0]
>     print(torch.allclose(first_norm, changed_norm))
> ```
> 保存为 `lesson_position.py` 并运行，两行均为 True。`[:,0]` 选所有 batch 的第一个 token，`[:,1]` 选第二个。两次 FFN 使用同一个 network，排除了不同随机参数这个干扰。结论只覆盖逐位置 FFN 和当前逐特征 LayerNorm，不扩展到会读其他位置的注意力。

## 7. 接回 Pre-Norm 与 Post-Norm

回到 [TransformerBlock.forward](../示例工程/app/model.py)，先只看注意力这一半。Pre-Norm 是 `x + attention(norm(x))`；Post-Norm 是 `norm(x + attention(x))`。FFN 这一半使用相同顺序原则，只是子层换成 FFN。

一个辨认顺序的实验：把注意力与 FFN 的参数全部设为零，保留 LayerNorm 默认参数、Dropout=0。于是两种子层的输出都为零：

- Pre-Norm 的每次残差仍是 `x + 0`，整个 Block 输出等于输入。
- Post-Norm 仍在每次加法后归一化，输出为两次 LayerNorm 后的值，通常不等于输入。

这不是训练建议；零参数只是让两种计算图的差异暴露出来。在同一目录新建 `lesson_norm_order.py`：

```python
import torch

from app.model import TransformerBlock

values = torch.tensor([[[1.0, 3.0], [10.0, 14.0]]])
for norm_first in (True, False):
    block = TransformerBlock(2, 1, 3, dropout=0.0, norm_first=norm_first)
    with torch.no_grad():
        for parameter in block.attention.parameters():
            parameter.zero_()
        for parameter in block.feed_forward.parameters():
            parameter.zero_()
    block.eval()
    with torch.no_grad():
        result = block(values)
    print(norm_first, torch.allclose(result, values))
```

运行后两行是 `True True` 和 `False False`。三个位置参数依次是隐藏维度 2、头数 1、FFN 中间维度 3；`norm_first` 选择归一化顺序。只清零子层参数，**不要把 LayerNorm 的 γ 也清零**，否则你改变了另一个条件。

完成后回到第 4 讲画图：圈出归一化位于哪条支路，说明一次前向调用的顺序。不要从这个零权重实验推出哪种模型训练效果一定更好。

## 常见错误与完成判断

| 现象 | 检查与修复 |
|---|---|
| 均值形状不是 `[B,T,1]` | 检查 dim 是否为 -1、是否保留维度 |
| 手算与库结果差一点 | 核对 eps、是否除以 D、γ／β 和浮点容差 |
| Linear 提示矩阵维度不能相乘 | 最后特征维应等于 in_features，本课输入为 2 |
| Linear 提示 Float／Double 类型不一致 | 固定 FFN 默认参数是 float32，输入也使用 float32；手算 LayerNorm 支持 float64 不代表另一网络会自动转换参数 |
| 残差输出意外重复 | 检查是否发生广播；本课显式要求同形 |
| FFN 结果每次不同 | 是否忘记使用固定权重函数，或两次重新创建了随机网络 |
| GPU 张量和 CPU 参数相加报错 | 本课统一 CPU；后续迁移设备时输入与模型一起移动 |

你应能独立手算一次归一化、一条 FFN、一条残差；说明张量轴与参数形状；再解释 Pre/Post-Norm 的零子层实验。作者测试通过不能代替这些操作。

# 第 6 讲：完成知识库验收与引用对照

## 验收不是“模型回答听起来像真的”

知识库验收要回答四个问题：来源和定位能否追溯？不同 chunk 策略是否在相同查询集上比较？新版本与删除是否让所有索引保持一致？回答引用是否确实来自允许访问的原文？

本示例只运行资料解析、切块、SQLite 持久化、词面检索和引用输出。它没有语言模型生成回答。为了避免伪造证据，检索结果只回传真实存储的原文和定位；没有命中时应返回“当前资料未找到依据”，而不是编造一个来源。

## 操作流程

在 VS Code 的示例工程目录运行：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py
..\..\..\.venv\Scripts\python.exe -m pytest -q tests
..\..\..\.venv\Scripts\python.exe -m ruff check .
```

demo 的策略对照使用三条固定 query 和对应 gold 段落/CSV 行定位计算 Recall@3 命中题数；随后展示 chunk 数、原文定位、行级权限过滤、重复导入和删除。这个小探针只有三题且用词面检索，仅示范测量流程。要给策略下结论，需准备代表真实用户问题的固定 query 集、标注每题相关段落、保持检索后端等其他条件一致，并报告 Recall@K/MRR 和失败样例。模块 14 会进一步讲系统检索评估。

## K/C 映射与当前边界

- K13-01：可运行解析 Markdown、HTML 和 CSV；PDF 数字文本/OCR 边界有官方依据说明，但当前环境缺 `pypdf`，没有执行 PDF 抽取。
- K13-02：实现固定字符窗口和按解析结构切块；语义切块的工作原理有说明，当前无真实语义边界模型。
- K13-03：SQLite 保存 source/version/locator/permission/content hash；测试重复导入、版本替换、权限过滤和级联删除。
- K13-04：讲解 Embedding 维度/任务/设备及向量库；没有安装模型/库，不宣称真实向量检索已验证。
- C13-01：示例 SQLite schema 与返回结果含来源、段落定位、版本、权限。
- C13-02：demo 对固定窗口和结构切块做三条教学 query 的段落级 Recall@3 探针；学习者仍需用更有代表性的标注集补充效果对比。
- C13-03：自动测试验证重复导入、版本变化、删除后查询不再命中。真实多服务索引对账尚未实现。
- C13-04：系统只展示数据库中的原文片段和定位，不接生成式模型；“无命中时拒绝编造”是后续答案层必须实现并测试的规则。

## 综合练习

**跟做：** 删除 `compute` 来源，重新搜索“GPU 显存训练”，确认检索为空；再重建后确认引用有 source/version/locator。

**独立：** 增加 5 个 query 和标注相关资料段落，比较 fixed 与 structure 的 Recall@1、Recall@3，并手工抽查引用完整性。每个 query 至少标出 1 条 gold 段落。

**迁移：** 为 FAQ 知识库写出接入真实 Embedding/向量数据库前的检查单，覆盖隐私授权、ACL 过滤、模型版本、增量、删除、备份、引用和空检索行为。完成标准：另一位学习者能重跑数据集、理解指标分母，并能从每个结果回到原资料。

> [!example]- 参考答案与解析
> 一个 query 的 Recall@K = 前 K 个结果中命中的相关 gold 数 / 该 query 的 gold 相关项总数；再对 query 求宏平均。不要用“来源 ID 命中”掩盖 chunk 错误：严格评估应标注相关 chunk/段落。若生成答案包含找不到的引用 ID，应拒绝展示并记录验证失败；可回答“没有足够的检索证据”，但不能把模型常识当知识库证据。

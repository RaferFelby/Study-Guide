# 第 1 讲：清洗 PDF 网页与表格文本

> [!nav] 页面导航
> [[01_学习指南/12_RAG数据工程/00 RAG 数据工程学习地图#学习顺序|单元 12：RAG 数据工程]] · [[01_学习指南/12_RAG数据工程/逐讲学习/02 保留来源页码版本与权限|下一讲]]

## 这一讲要解决什么

RAG（检索增强生成）要先从资料中找出相关内容，再把内容交给语言模型。若输入知识库的资料缺页、乱码、把表格列拼错，之后的检索和回答也会跟着错。数据工程的第一步不是“把文件塞进向量库”，而是把内容整理成可检查、可追溯的文字段落。

本讲先学文件格式和清洗，再区别 PDF 里的真实文字与扫描图片。需要会读 Python 函数、路径和列表；陌生部分可回看 [[01_学习指南/01_Python工程化/逐讲学习/01 运行Python并统计工单|单元 01 第 1 讲]]。

## 先用最小示例看结果

在 VS Code 打开本单元的 `示例工程` 文件夹。PowerShell 当前目录应是这个文件夹。运行：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py
```

工程读取 `fixtures` 中的 Markdown、HTML 和 CSV。网页解析会忽略导航、页脚和脚本；表格会变成“列名：单元格值”的行文本。打开源码导航中的 [ingestion.py](../示例工程/ingestion.py)，先看 `parse_source`，再看 `clean_text`。

`Path` 表示文件路径；`suffix` 是扩展名；`read_text(encoding="utf-8")` 明确按 UTF-8 读文字。Python [HTMLParser 官方文档](https://docs.python.org/3/library/html.parser.html)说明它会在遇到开始标签、文字和结束标签时调用处理函数，因此代码可以只收集正文文字。它是简单解析器，不是浏览器，也不负责执行网页 JavaScript。

`csv.DictReader` 把表头映射到每行字典，例如 `{"topic": "公开培训"}`。拼接行时保留列名，可以避免丢失“这段文字属于哪一列”的关系。夹具里的 `permission` 列会作为每一行的权限元数据保存，不会混进正文。对表格中的合并单元格、多层表头、公式和单位还要制定额外规则；本例 CSV 只有平面表头。

## PDF 为什么不能当作普通文本

PDF 的目标是让页面显示或打印正确，不保证文件内部有“标题、段落、表格”这些语义标签。提取程序可能拿到字符，但阅读顺序、双栏顺序、页眉页脚、表格列和公式仍可能错。官方 [pypdf 文本提取说明](https://pypdf.readthedocs.io/en/stable/user/extract-text.html)也把表格和阅读顺序列为需要判断的难点。

PDF 分成三种常见情况：数字生成的 PDF 通常带有文本；扫描 PDF 主要是页面图片，需要 OCR（光学字符识别，即从图片识别文字）；OCR PDF 同时含扫描图和后台识别出的文字，仍可能有识别错误。pypdf 可以提取文本层，但它本身不是 OCR 工具。抽取后应抽查页码、段落顺序、表格行列和关键数字。

本机共享 `.venv` 没有 `pypdf`，所以我们不安装新包，也不声称已经跑过 PDF 抽取。未来接入时可在独立 `PdfParser` 适配器中逐页读取，输出 `{text, page_number}`，再复用后面讲的清洗和切块流程；pypdf 示例及版本接口以其当前官方文档为准。图片 PDF 则须另选 OCR 工具，并单独核对识别质量。

## 动手检查与预期结果

1. 打开 `fixtures/webpage.html`，数一下导航、正文、脚本、页脚各有几段。
2. 运行 demo；输出的引用定位与后几讲有关，先观察所有解析来源都变成了文本块。
3. 用 VS Code 打开 `ingestion.py`。找到 `handle_starttag`，确认 `nav/footer/script/style` 进入忽略状态；找到 CSV 部分，确认首行是表头，数据行编号从 2 开始。
4. 执行 `..\..\..\.venv\Scripts\python.exe -m pytest -q tests`。正常结果是测试全部通过。

若中文乱码，检查文件编码并保持为 UTF-8；若 HTML 脚本被收进内容，检查忽略标签处理；若 CSV 行字段错位，检查分隔符、表头及引号，不要直接删除异常行来掩盖问题。

## 练习

**跟做：** 修改网页夹具，在正文增加一个 `<p>`，运行 `parse_source` 测试后确认正文出现、页脚没有出现。

**独立：** 新建 `fixtures/notes.txt`，包含两个由空行分隔的段落，确认输出定位从“段落 1”递增。

**迁移：** 选择一份自己有权处理的 PDF，先判断能否复制文字、是否是扫描件，再记录页码、双栏、表格和数字抽查计划。本讲示例不执行 PDF 解析；不要将隐私资料上传到第三方 OCR 服务。

完成标准：能说出“解析、清洗、OCR”的差别；能运行本例并指出 CSV 的列名、HTML 的过滤规则和 PDF 的限制。

> [!example]- 参考答案与解析
> TXT 读取后按空行切分，所以输入两段应得到两个带序号的段落；如果把两段之间改成单个换行，当前最小解析器会视为同一段。真实数据可能换行风格不同，进入切块前应检查而不是假设段落标记一致。

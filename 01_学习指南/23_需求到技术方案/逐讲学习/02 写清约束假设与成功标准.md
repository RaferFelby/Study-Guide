## 本讲任务与前置

把愿望拆成约束、假设和验收。先完成上一讲的场景；需要会读 JSON 字典，不要求会设计企业流程。约束是当前不能越过的边界，假设是暂时用来规划但需要验证的说法，验收是判定产物是否满足约定的方法。

“预算100单位”是边界，“每月1000次查询”是待证估计，“50条任务至少45条事实正确”是一个候选验收。它们不能互相代替。预算数字也可能来自假设，但一旦作为本轮上限，就应在评审中明确是谁给定、适用到何时。

## 把约束写成可检查的句子

本例给定30人时、每天最多4小时、月运行成本上限100个虚构单位、估算运行成本20单位、假定内存8GB、GPU数量0。人时是一个人投入一小时的工作量；两人各一小时是两人时，不代表日历上必然能同时完成。

“GPU数量0”是这个原型场景的资源条件，不表示课程以后不能学习GPU。这里选择关键词与模板来验证需求，不训练模型。未来换神经检索或生成模型时，需要重新评估硬件、质量、成本和依赖。

数据约束比文件格式更早：本例使用合成资料或经授权的脱敏资料，禁止真实账户和秘密。延迟约束要写测量环境、任务分布、是否含检索/网络、分位数；“P95≤1000ms”是待测目标，不能抄前面模拟时钟的数据来证明。

安全约束：只读、权限过滤、来源引用、缺证据拒答。人员约束：谁维护政策、谁判断冲突、谁处理失败。把“安全”和“有负责人”写成词语还不够，必须给出可执行的检查或处理动作。

## 假设清单怎样使用

A01估计每月1000次查询；A02估计人工90秒、辅助后含复核45秒；A03估计70%任务在范围内、成功率90%。这些数字用于演算，不是观测。逐项写验证方式：抽样日志核对任务量，同任务对照计时，审核多样任务判断范围和质量。

先验证最可能改变决策的假设。如果真实问题几乎都不在政策范围，优化检索速度意义有限。如果人工复核很费时，模型输出快也可能没有业务收益。可以先用纸面流程或少量人工检索验证需求，不必先建完整服务。

## 最小示例：检查数字是否相互一致

在示例工程新建 `lesson_constraints.py`：

```python
import json
from pathlib import Path
from planning import validate_plan

plan = json.loads(
    (Path(__file__).parent / "fixtures" / "plan.json").read_text(encoding="utf-8")
)
result = validate_plan(plan)
print(result["planned_hours"])
print(result["estimated_units"] <= result["budget_units"])
print(result["evidence_status"])
```

`from planning import validate_plan` 从同目录源码导入函数，导入时不会运行演示。函数读取方案，检查选项、预算、依赖和验收字段；有矛盾时抛出 `ValueError`，正常时返回汇总字典。`<=` 比较是否不超过上限，返回布尔值。

用共享解释器运行 `lesson_constraints.py`。预期输出 `30`、`True`、`structural_check_only_not_business_validation`。最后一行明确：这里只做结构一致性检查，不验证人工时间、费用估算、真实硬件性能或政策授权。

## 动手：做一次可解释的失败检查

不要修改原始 `fixtures/plan.json`。另建脚本，先读取它，再在内存中把 `plan["constraints"]["estimated_monthly_cost_units"]` 改成 `101`，随后调用 `validate_plan(plan)`。预期出现“估算费用超过给定预算”的 `ValueError`。

可运行的完整失败练习如下，保存为 `lesson_over_budget.py`：

```python
import json
from pathlib import Path
from planning import validate_plan

plan = json.loads(
    (Path(__file__).parent / "fixtures" / "plan.json").read_text(encoding="utf-8")
)
plan["constraints"]["estimated_monthly_cost_units"] = 101
try:
    validate_plan(plan)
except ValueError as error:
    print("预期失败：", error)
else:
    raise AssertionError("超预算方案意外通过，需要检查规则")
```

这段只修改内存里的字典，原JSON文件不变。`try`尝试检查，`except ValueError`只捕获本练习预期的校验失败并打印原因；没有宽泛吞掉未知错误。`else`在没有异常时运行，主动报告“意外通过”，避免让错误结果看起来正常。运行后应打印“预期失败：估算费用超过给定预算”。

这次故意失败让你确认规则生效。修复方法有三种方向：核实估计是否算错、缩减真实消耗、由有权的人重新批准预算。练习中不要只把预算改大来让结果变绿，先解释为什么改变。

## 常见错误

把目标写成结果：在条目后加“目标，未执行”，并记录计划测法。把成本范围漏掉：本例20是运行成本假设，维护时间另算；真实项目需说明开发、评估、存储、服务、监控是否纳入。把30人时写成“两周保证完成”：补依赖、未知事项和停止条件，留有重新评估机会。

## 练习与完成判断

跟做：列出三条数字约束及单位。独立：把“回答很快”改为包含环境、样本、分母和阈值的验收。迁移：场景需要读取不同部门文档时，增加一条权限约束和对应失败用例。

完成判断：每条约束可以检查；每条假设有状态和验证方法；每条目标不会被误读成既成事实。

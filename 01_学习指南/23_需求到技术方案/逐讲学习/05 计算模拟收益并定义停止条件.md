## 本讲任务与前置

用模拟数字算收益，并检查改变假设后结论是否反转。ROI是投入回报比，本例定义为“净收益÷成本”。这里使用虚构价值单位，不是货币报价、实际商业收益或投资建议。你需要理解乘除、百分比；`Decimal` 是十进制数类型，用于减少二进制小数表示造成的意外尾数，不能提高输入假设的真实性。

## 从任务量逐项推导

每月1000次任务，其中70%属于MVP，范围内90%成功，每次节省90−45=45秒。预计节省小时：1000×0.7×0.9×45÷3600=7.875。3600是一小时的秒数；每项相乘表示逐层缩小可受益任务，再换算时间。

每小时按10虚构单位估值，收益是78.750单位。每月维护3小时，维护成本30单位，加运行20单位，总成本50单位。净收益78.750−50=28.750；ROI=28.750÷50=0.575，即57.5%。

这种简化只计算当前列出的持续成本，未纳入初始开发、机会成本、误答损失、失败任务额外耗时或现金回收。因此不能直接据此决定真实预算。节省员工时间也不等于企业立即节省同等现金；时间是否能转为有效产出还需要证据。

## 最小可运行示例

在示例工程创建 `lesson_value.py`：

```python
from planning import projected_value

result = projected_value(
    monthly_tasks=1000,
    eligible_fraction=0.7,
    success_fraction=0.9,
    before_seconds=90,
    after_seconds=45,
    value_units_per_hour=10,
    maintenance_hours=3,
    running_units=20,
)
print(result["saved_hours_projected"])
print(result["net_units"])
print(result["roi_ratio"])
```

这里按参数名传值，避免把八个数字的位置混淆。`fraction` 是0到1之间的比例；`before_seconds` 和 `after_seconds` 必须是完整人工任务时间。函数先拒绝负数、非有限数和非法比例，再转为十进制数计算。返回字符串保留展示精度。

用共享解释器运行，预期 `7.875`、`28.750`、`0.575`。若改成功比例为 `0.5`，预计节省4.375小时，净收益−6.250，ROI−0.125。同一套系统仅改变成功假设，就可能由正变负。

## 动手：敏感性和停止条件

敏感性分析就是改变一个输入，观察结果如何变化；不能同时变四项后猜是哪项造成反转。复制脚本分别将成功比例设0.9、0.7、0.5，保留其他参数，记录结果。再单独将维护时间提高到6小时，说明新的负担来自哪里。

为了保证每次只改变成功比例，另建 `lesson_sensitivity.py`：

```python
from planning import projected_value

for success_fraction in [0.9, 0.7, 0.5]:
    result = projected_value(
        monthly_tasks=1000,
        eligible_fraction=0.7,
        success_fraction=success_fraction,
        before_seconds=90,
        after_seconds=45,
        value_units_per_hour=10,
        maintenance_hours=3,
        running_units=20,
    )
    print(success_fraction, result["net_units"], result["roi_ratio"])
```

每次循环将一个比例交给同名参数，其他值固定。预期三行分别为 `0.9 28.750 0.575`、`0.7 11.250 0.225`、`0.5 -6.250 -0.125`。即使三次都顺利计算，也只是三种假设；没有新增任何实测证据。

停止条件不是“困难就不做”，而是事先约定何时停止扩大试验、恢复人工流程、重做需求或重新评审。本例：资料未获授权则停止导入；政策来源冲突则停止自动给事实；出现任意未授权读取/写入则停止试用并调查；预算或人时超范围则缩减范围或请负责人重新评审。

停止扩大试验不等于删除证据。保留不含秘密的日志、失败任务ID和版本，按单元22的方法确认根因，再决定是否继续。不要为了“满足ROI”删掉失败样本。

## 预期与常见问题

成本为0时ROI返回 `None`，因为不能除以0；仍可看净收益，不要把它显示成无限商业收益。`after_seconds` 大于 `before_seconds` 会报错：本函数限定演算节省时间，若系统导致任务更慢，应在真实报告记录额外时间并调整模型，不能输入负时间逃过检查。

结果小数位不同：`Decimal`输出可能带尾零，数值含义相同。精确算出0.575不意味着预测精确；假设误差通常远大于表示误差。

## 三类练习

跟做：解释成本50如何得到。独立：按成功率0.7手算净收益再运行核对。迁移：场景中每个失败任务额外耗时20秒，说明原公式漏了哪项。

> [!example]- 参考答案与推导
> 维护3×10=30，加运行20得50。成功率0.7时节省1000×0.7×0.7×45/3600=6.125小时，收益61.250，净11.250，ROI0.225。失败额外耗时应按失败数量×20秒另计成本，并明确“失败”的范围和原来人工时间是否已经计入；不能把正常未纳入范围的任务都算成系统失败。

完成判断：能从任务量推到净收益，能解释数字来自假设，能用至少一次反转说明为什么要先验证关键输入。

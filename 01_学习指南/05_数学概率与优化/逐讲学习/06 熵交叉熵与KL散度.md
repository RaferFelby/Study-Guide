## 熵：不确定性的平均信息量

一个事件概率越低，发生时带来的惊讶程度越高。本工程统一用以 2 为底的对数，因此信息量用 bit（比特）计；例如概率为 1/2 的事件含有 1 bit 信息。分布的熵是所有事件信息量的概率加权平均：

~~~text
H(P) = -Σ p(x) log₂ p(x)
~~~

这里 `P` 表示整个概率分布，`x` 是某一种可能结果，`p(x)` 是它的概率，`Σ` 表示把所有结果对应的项相加。`log₂(1/2)=-1`，因为 `2` 的 `-1` 次方是 `1/2`。因此事件信息量 `-log₂(1/2)=1`。

例如公平硬币 `P=[0.5,0.5]`：

```text
H(P) = -0.5 × log₂(0.5) - 0.5 × log₂(0.5)
     = 0.5 + 0.5
     = 1 bit
```

在**相同有限结果集合**上，均匀分布的熵最大；两种结果最多 1 bit，四种结果最多 2 bit，不能忽略结果数直接比较。如果分布确定地只会发生一个结果，例如 `[1,0]`，熵为 0。熵不是“正确率”，一个很自信但答错的模型也可能输出低熵分布。

“惊讶”帮助理解罕见事件的代价，实际计算仅由概率决定，不测量人的情绪。bit 也不是说每次事件都一定能用恰好这么多个整数二进制位编码；这里先把它当作信息量单位。

## 交叉熵：用 Q 描述来自 P 的数据

交叉熵定义为：

~~~text
H(P, Q) = -Σ p(x) log₂ q(x)
~~~

分类任务中，目标标签通常是 one-hot 分布。正确类别的 p 为 1，其他类别为 0，于是交叉熵简化为正确类别预测概率的负对数。正确概率越接近 1，损失越小；如果模型给正确类别极小概率，损失会很大。

one-hot（独热）表示只把正确类别的位置写成 1，其余写成 0。先约定列表顺序为 `[猫, 狗]`：真实类别是猫，目标 `P=[1,0]`；模型给 `Q=[0.9,0.1]`，只有第一项参与加权，损失是 `-log₂(0.9)≈0.152003` bit。如果预测变为 `[0.6,0.4]`，仍然把猫排第一，但损失变为约 `0.736966` bit。目标和预测的类别顺序必须相同。

目标也可以是软分布，即多个类别都分到概率，例如 `P=[0.75,0.25]`。这时两项都要计算，不能只取概率最大的目标类别。交叉熵中用 **P 作权重、取 Q 的对数**；这正是它与只使用一个分布的熵的区别。

这也解释了为什么只看准确率不够：把正确类别从 0.51 提高到 0.99，准确率可能不变，但交叉熵能反映置信度改善。

## KL 散度：从交叉熵拆出来

~~~text
KL(P || Q) = Σ p(x) log₂(p(x) / q(x))
          = H(P, Q) - H(P)
~~~

若使用自然对数 `ln`，数值单位会变成 nat；两种定义只差一个固定换算因子。本工程和本讲练习使用 bit，与源码中的 `math.log2` 保持一致。某些机器学习框架的交叉熵默认使用自然对数，比较数值时要先确认对数底数。

当目标分布 P 固定时，H(P) 是常数，因此最小化交叉熵等价于最小化 KL(P||Q)。但 KL 不对称：KL(P||Q) 和 KL(Q||P) 通常不同；它也不是真正意义上的距离，因为不满足对称性和三角不等式。

用 `P=[0.75,0.25]`、`Q=[0.5,0.5]` 手算一遍：

| 项目 | 计算 | 结果（bit） |
| --- | --- | --- |
| H(P) | `-0.75×log₂(0.75)-0.25×log₂(0.25)` | 0.811278 |
| H(P,Q) | `-0.75×log₂(0.5)-0.25×log₂(0.5)` | 1.000000 |
| KL(P∥Q) | `1-H(P)` | 0.188722 |
| KL(Q∥P) | `0.5×log₂(0.5/0.75)+0.5×log₂(0.5/0.25)` | 0.207519 |

数学上 KL 非负，P 与 Q 相同时为 0；单个求和项可以为负，不能逐项截成非负数。有限精度计算时，接近 0 的结果可能有很小舍入差异，应用容差核对。这里使用两个分布的有限交叉熵；遇到无穷大时不能随意做无穷大减无穷大的运算。

## 从最大似然看交叉熵

假设每个样本标签来自模型给出的概率 Q，并假设给定输入与模型参数后，各样本标签条件独立。整个数据集的条件似然才可写成所有正确标签概率的乘积。最大化似然等价于最大化对数似然，也等价于最小化负对数似然；对 one-hot 分类标签，逐样本负对数似然正是交叉熵。语言模型序列内部则按条件概率链式分解，不能直接把各token视为互相独立。

因此交叉熵不是随意选择的惩罚函数，它来自一个概率模型：希望模型为真实观测分配更高概率。实际工程中仍要检查标签是否正确、类别是否平衡以及概率是否经过正确归一化。

例如两个已观测正确标签的预测概率分别为 0.8、0.5，在上述条件独立假设下，似然为 `0.8×0.5=0.4`。负对数似然为 `-log₂(0.4)≈1.321928` bit，也等于 `-log₂(0.8)-log₂(0.5)`；平均到两个样本为约 `0.660964` bit。取对数把乘积变成求和，再取负号把“越大越好”变成“越小越好”。求和与平均的最优点在样本数固定时相同，但数值尺度不同。

## 数值稳定性

当`p(x)=0`时，该项按约定贡献0，应直接跳过，不去计算`log(0)`；例如P=Q=[1,0]的交叉熵是0。当`p(x)>0`而`q(x)=0`时，数学交叉熵为正无穷，本教学函数选择抛出明确错误，不把它伪装成有限损失。KL采用相同支持集检查；不是“预测概率中任何0都非法”。

直接计算 softmax 再取 log 可能因为指数溢出或下溢产生 inf/nan。工程实现通常使用 log-sum-exp 技巧或框架提供的 logits 版本交叉熵。学习阶段先理解概率公式，写代码时优先使用经过验证的稳定实现。

`inf` 表示无穷大，`nan` 表示不是有效数值。另一个陷阱是先计算 `t/p`：当 p 极小但仍大于零，比值可能溢出。配套 `kl_divergence` 使用 `log₂(t)-log₂(p)`，避免这个中间比值；这不会把 p=0 变成合法输入，也无法恢复已经因上游下溢变成 0 的概率。

本课接收归一化后的概率列表。后续 PyTorch 的 `CrossEntropyLoss` 接收未归一化分数 logits，并按其接口计算损失，不要把本课函数的输入约定直接搬过去；官方说明见 [CrossEntropyLoss 输入与忽略标签](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)。框架训练放在单元 06／08，此处不需要运行 PyTorch。

1. 在 VS Code 打开 `01_学习指南/05_数学概率与优化/示例工程` 文件夹。
2. 在这个文件夹中新建 `lesson_03_information.py`，与 `app` 文件夹平级，不要放进 `app` 内。

```python
import math

from app.math_basics import cross_entropy, entropy, kl_divergence


def main():
    target = [0.75, 0.25]
    predicted = [0.5, 0.5]
    target_entropy = entropy(target)
    prediction_loss = cross_entropy(target, predicted)
    divergence = kl_divergence(target, predicted)
    print(f"公平硬币熵={entropy([0.5, 0.5]):.6f} bit")
    print(f"目标熵={target_entropy:.6f} bit")
    print(f"交叉熵={prediction_loss:.6f} bit")
    print(f"KL(P||Q)={divergence:.6f} bit")
    print(f"KL(Q||P)={kl_divergence(predicted, target):.6f} bit")
    print("恒等式成立=", math.isclose(prediction_loss - target_entropy, divergence, abs_tol=1e-12))
    for correct_probability in [0.9, 0.6]:
        loss = cross_entropy([1.0, 0.0], [correct_probability, 1.0 - correct_probability])
        print(f"正确类概率={correct_probability:.1f}，损失={loss:.6f} bit")


if __name__ == "__main__":
    main()
```

### 从公式找到源码执行顺序

打开 [math_basics.py](../示例工程/app/math_basics.py)，按 `entropy` → `cross_entropy` → `kl_divergence` 阅读：

- `_validated_distribution` 先转成列表，拒绝空列表、负数与非有限值，再用容差检查总和。它不会偷偷替你归一化。
- `entropy` 从 `total=0.0` 开始，遍历每个正概率，加上该事件的信息量贡献。
- 交叉熵与 KL 先检查两个列表长度相同。`zip` 将同一类别的目标与预测配对，例如依次得到 `(0.75,0.5)`、`(0.25,0.5)`；因此必须先检查长度，不能让配对遗漏多出来的类别。
- 目标概率为零的项跳过。目标为正时预测也必须为正，然后逐项累加。
- KL 中 `log_ratio` 是对数之差，对应数学上的概率比的对数；返回值都是单个浮点数，单位 bit。

### 运行成功边界与失败边界

同一目录新建 `lesson_03_boundaries.py`：

```python
from app.math_basics import cross_entropy, kl_divergence


def main():
    print("目标为零的项允许预测为零：", cross_entropy([1.0, 0.0], [1.0, 0.0]))
    cases = [
        ("总和错误", [1.0, 0.0], [0.2, 0.2]),
        ("目标类别被预测为零", [1.0, 0.0], [0.0, 1.0]),
        ("类别数错误", [1.0], [0.5, 0.5]),
    ]
    for name, target, predicted in cases:
        try:
            print(name, cross_entropy(target, predicted))
        except ValueError as error:
            print(name, "预期拒绝：", error)
    tiny_prediction = [1e-320, 1.0]
    print(f"极小正概率 KL={kl_divergence([1.0, 0.0], tiny_prediction):.3f} bit")


if __name__ == "__main__":
    main()
```

运行 `..\..\..\.venv\Scripts\python.exe lesson_03_boundaries.py`。依次应得到零损失、三个预期拒绝，最后得到有限值约 `1063.017 bit`。极小量加到 1 上会在浮点表示中舍入为 1，此处通过总和容差检查；不是允许任意未归一化的输入。

三条报错分别包含 `sum to one`、`must be positive`、`same length`。第二条英文提示较简短，具体条件是目标正概率所在类别的预测必须为正，并非所有类别都禁止零。`try/except ValueError` 只处理此处故意输入导致的预期错误，其他程序错误仍应暴露。

## 常见错误

- 把熵、交叉熵和 KL 都叫“误差”而不说明输入分布。
- 忘记概率必须非负并且和为 1。
- 把 KL(P||Q) 当成 KL(Q||P)；方向代表不同的惩罚行为。
- 用普通指数计算大 logits，导致数值溢出。

遇到 `No module named app`，检查脚本是否与 `app` 平级以及终端目录；不要混用其他单元的同名 `app`。数值相差约 1.4427 倍时检查 bit／nat：`bit数 = nat数 / ln(2)`，反向则乘 `ln(2)`。遇到无穷或报错，先检查零概率和对齐关系，不先随意加小常数改变目标。

### 独立练习

在同一目录创建 `lesson_03_binary.py`，实现 `binary_log_loss(label, positive_probability)`。`label` 是 Python 整数 0 或 1；`positive_probability` 是模型给**类别 1**的概率，不一定是正确类别的概率。返回单样本损失，单位 bit。

本练习明确选择严格接口：概率必须是有限 Python int／float 且 `0<q<1`，不接受布尔值，不裁剪。边界拒绝是一项教学接口选择；例如标签 1、q=1 的数学损失本来是 0，不能因接口拒绝就称它数学错误。

提示：标签 1 用 `-log₂(q)`；标签 0 用 `-ln(1-q)/ln(2)`。可用 `math.log1p(-q)` 计算后者的对数，在 q 接近 0 时避免先算 `1-q` 丢掉细小差异。机制依据见 [Python 3.13 math.log1p](https://docs.python.org/3.13/library/math.html#math.log1p)。先写函数，再预测 `(1,0.8)` 与 `(0,0.8)` 谁的损失大。

> [!example]- 完整参考答案与解析
> ```python
> import math
>
>
> def binary_log_loss(label: int, positive_probability: float) -> float:
>     if type(label) is not int or label not in (0, 1):
>         raise ValueError("label must be integer 0 or 1")
>     if type(positive_probability) not in (int, float):
>         raise ValueError("probability must be a Python number")
>     if not math.isfinite(positive_probability) or not 0 < positive_probability < 1:
>         raise ValueError("probability must be finite and strictly between 0 and 1")
>     if label == 1:
>         return -math.log2(positive_probability)
>     return -math.log1p(-positive_probability) / math.log(2.0)
>
>
> def main():
>     for label, probability in [(1, 0.8), (0, 0.8), (1, 1e-12), (1, 1 - 1e-12)]:
>         print(label, probability, f"{binary_log_loss(label, probability):.6f} bit")
>     print("微小但非零：", binary_log_loss(0, 1e-20) > 0)
>     for probability in [0.0, 1.0, -0.1, float("nan")]:
>         try:
>             binary_log_loss(1, probability)
>         except ValueError as error:
>             print("预期拒绝：", error)
>
>
> if __name__ == "__main__":
>     main()
> ```
> 运行 `..\..\..\.venv\Scripts\python.exe lesson_03_binary.py`。四项损失约为 `0.321928`、`2.321928`、`39.863137`、`0.000000` bit；最后一项只是显示舍入为零，真实值约 `1.44e-12`，并未严格等于零。下一行是 `微小但非零： True`，最后四行均为预期拒绝。
>
> 当真实类别为 0 而 q=0.8 时，正确类别概率只有 0.2，所以损失更大。`type(...)` 限定这里的教学输入，防止把 Python 中也能当数字使用的布尔值误作概率；这不是所有数值库的通用接口标准。完成标准：能解释两个分支、单位换算、拒绝边界及舍入显示，并独立加入一个非法标签案例。

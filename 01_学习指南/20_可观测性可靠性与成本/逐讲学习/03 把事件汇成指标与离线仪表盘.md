# 第 3 讲：把事件汇成指标与离线仪表盘

## 要解决的问题与前置

一条trace能说明某次故障，不能告诉我们总体是否变差。本讲把24份任务汇总为可用性、契约质量、P95、token与错误，并生成一份离线HTML表。前置是比例、排序、单元19适用分母；没有安装在线监控平台。

## 两种成功，先说明含义

availability是本工程“结果不是failed”的占比。查询回答、缺证据拒答、冲突待核实都代表服务处理完，算可用；4份模拟上游超时为failed，20/24≈0.8333。

quality是与gold的状态/天数字段契约一致率。超时任务gold本就要求明确failed，而非编造答案，所以正确报告超时也可quality通过。baseline质量24/24但可用20/24，并不矛盾。这是有限夹具的契约质量，不是用户全部拿到答案，也不是现实LLM通用质量。

界面上若只写“成功率100%”会误导，需要指标全名和分母。真实业务可另定义“用户目标完成率”，不必照搬本例availability公式。

## 最小示例：P95并不是平均

新建`lesson_percentile.py`：

```python
from reporting import percentile_nearest_rank

latencies = [10, 10, 10, 100]
average = sum(latencies) / len(latencies)
p95 = percentile_nearest_rank(latencies, 0.95)
print("平均", average)
print("P95", p95)
```

预期平均32.5、P95 100。本工程采用nearest-rank：排序后取ceil(n×0.95)位置，数学位置从1开始，Python索引减1。4×0.95=3.8向上取4，所以取最慢值；不同统计库可能插值，比较报告要注明方法。

P95的直觉是约95%观测不慢于此值，不是“95%的请求耗时相等”。只有4条时它很粗糙，不能夸大精度；样本数量和窗口同样重要。

## 动手：生成并读仪表盘

在示例工程终端运行`demo.py --output-dir report-01`，若目录已有换report-02。用VS Code打开dashboard.html看文件，或在文件管理器双击一次用浏览器查看离线结果；这个HTML不启动服务、不向外发送数据。

列顺序为版本、n、availability、quality、p95_ms、模拟输入/输出token、虚构cost_units、cache_hits、errors。baseline n24、可用20/24、质量1、P95 305ms、token1024/708、成本2.680、命中0、超时4。

cached命中10，token512/354，但P95仍305ms；大量任务变快不代表最慢尾部已改善。bad_crop质量16/24≈0.6667，不能因为成本2.480低于2.680就称整体更好。

## 逐步读reporting.py

summarize先拒绝空集，取任务rows而不是span事件；Counter按error_code计failed；成功数除n；对duration_ms排序算P95；累计每任务usage与Decimal成本；记录cache_hit数量。

write_dashboard按固定列显示，每个单元格用html.escape，防任务字符串被当HTML标签执行。即使离线报告也不能把不可信文本直接插入页面。当前表全是合成指标，不提供交互筛选、自动刷新或在线告警。

为了练“从总数回到个案”，在report.json中找到baseline.rows的failed项，复制其trace_id，到baseline-trace.jsonl筛同ID，应该有tool TimeoutError、无model。这样完成指标→任务→阶段的排查链。

## 指标标签和采样

指标按variant、模型、工具、错误类别等少量固定标签聚合。每个request_id/用户邮箱做一个标签会产生大量不同序列，称高基数，增加存储和查询成本。个案ID应放trace/log，而非无界指标标签。

真实trace可能采样，只保存部分；指标分母仍应来自全体计数或说明采样范围。不能拿10%采样日志行数直接当全部流量，失败采样比例不同还会偏置成功率。当前工程完整记录全部24×5版本，无采样。

## 常见错误

- span行数当任务数：按根或rows计，一次任务多调用。
- 平均好就说长尾好：另看P95/超时与场景分布。
- 两报告P95方法不同却直接比：固定nearest-rank或明确转换。
- 把模拟token当实际供应商usage：列名simulated，费用/设备结论另测。
- 仪表盘显示100%就上线：看权限、安全、真实数据和SLO，本报告是合成机制。

## 练习与答案

跟做：抄baseline的n/可用性/质量/P95/超时数，并各写一句含义。完成判断：能解释质量1为何仍有4个错误。

独立：20条耗时都10ms，1条1000ms，本方法P95是多少？提示：ceil(21×0.95)=20。

迁移：为真实服务设计6个必要指标，写单位、窗口、分母、标签和从指标到trace的方法。

> [!example]- 参考答案与解析
> 第20个仍10ms，所以P95=10；极慢项需同时看最大/超时/P99，不能仅靠P95就完全观察所有异常。
>
> 可选任务业务完成率、技术可用率、P95墙上耗时、上游超时率、调用重试数、每成功任务成本；ID放trace，少量组件/版本标签放metrics。每项明确定义，避免一个“成功”覆盖多个目标。

## 本讲任务与前置

JD是Job Description，岗位说明，通常写职责、资格、技能、地点与申请方式。先用五条官方页面练拆解，不按标题猜工作，也不自动认定你满足资格。前置是本单元地图和Python字典/列表；不需要已经求职或提交简历。

本例五条在2026-10-11访问时有岗位正文与申请入口，见 [[01_学习指南/25_岗位分析项目表达与投递复盘/官方岗位快照与复核方法|来源页]]。它们来自两家公司、多为资深岗位，是分析材料，不是针对你的投递推荐、当地初级市场样本或未来仍开放的保证。你的地点、资格与真实经验未评估；实际申请前需自己按最新页面复核。

## 四类信息不能混成技能清单

资格条件可能包括经验、教育或履职条件；日常任务告诉你每天解决什么问题；技术要求支持任务；加分项可能提高匹配但不一定必要。地点/办公/出差影响可行性，也要单列。页面写“适合你的情况”不总是法律或招聘系统的绝对硬性门槛，需要保留原语气，不能自己把所有条目都改为必须。

例如FDE页面列端到端需求/设计/交付与客户协作，也列经验和当地出差安排；推理工程更关注性能瓶颈、GPU/分布式；观测工程关注日志/指标/轨迹与生产系统；部署产品关注全栈/接入；后训练评估关注测量可靠性和回归。相同Python关键词并不代表岗位可互换。

## 逐步阅读一条岗位

先核对公司官方入口和具体岗位链接，记录标题、地点、检查日和是否看到申请入口。再用不同标记划出职责、资格、加分、办公条件。每个技术词旁边写它支持哪项任务，例如GPU优化支持低延迟推理，不能只抄名词。

最后写“已知、未定、需要证据”。官方页没写的年限不要自己补；个人条件不明就标未评估；行业含义不懂先查术语/对应课程。不要因为资深页面要求多就把自己所有课程顺序打乱，先找与你实际阶段接近的正式岗位做下一轮样本。

## 最小示例：读取五条快照

VS Code打开本单元示例工程，创建 `lesson_jobs.py`：

```python
import json
from pathlib import Path
from career import validate_jobs

jobs = validate_jobs(json.loads(
    (Path(__file__).parent / "fixtures" / "jobs.json").read_text(encoding="utf-8")
))
print("条数：", len(jobs))
for job in jobs:
    print(job["id"], job["checked"], job["learner_fit"])
```

共享环境命令：

```powershell
& ..\..\..\.venv\Scripts\python.exe lesson_jobs.py
```

三个`..`回工作区根，运行共享解释器，不新建单元环境。预期条数5，J01～05检查日2026-10-11、learner_fit都not_assessed。validate_jobs检查条数、来源格式、日期和基本字段，不重新访问网络，也不验证今天职位是否仍开放。

## 动手与排错

在Obsidian学习记录挑一个官方链接，亲自打开后记录你看到的检查日、正文和申请入口；若失效标失效并换另一官方岗位，保留旧检查记录。不要为了达到5条复制同职位多个地区当五种独立能力需求。

未知专业词：回学习目录对应单元，不假装熟悉。链接失效：从公司官网招聘入口重新搜索并记录结果，不用旧搜索摘要断言开放。代码日期报错：用YYYY-MM-DD；字段丢失：对照夹具恢复，程序只是结构检查。

## 练习与完成判断

跟做：一条JD按四类信息分栏。独立：解释“写了Python”为什么不能证明你适合该岗位。迁移：自己收集5～10条与你地点/资历/兴趣接近的当前正式页面，保留来源与日期。

> [!example]- 参考答案与解析
> Python只说明一部分实现工具，岗位还可能要求生产系统、实验设计、客户沟通或履职条件。分析要从任务找能力再找证据。未写年限时记录未说明；别把作者资深样本强行当初级硬标准。收集完成标准是链接可核对、条目不重复、任务与资格分开、个人缺口状态明确。

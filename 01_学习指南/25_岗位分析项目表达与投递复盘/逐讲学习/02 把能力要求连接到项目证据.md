## 要解决的问题

“学过RAG”很难证明“可以设计并评估检索”。证据台账将能力要求连接到你亲自完成的任务、代码、配置、数据、结果和限制。前置是 [[01_学习指南/22_Case分析与系统联调/00 Case分析与系统联调学习地图|可复现Case]] 与 [[01_学习指南/19_Agent评估体系/00 Agent 评估体系学习地图|指标分母]]；不默认作者工程就是你的经历。

## 证据的三层强度

读过解释表示接触概念；跟做并能解释输入/输出表示练习；独立改造、复查错误与他人复现能提供更强的实践证据。它们不是统一招聘评分，也不能互相冒充。作者替你写好的源码可以学习，只有你实际完成并能说明的部分才能作为自己的贡献。

一条证据含：能力、问题、个人负责部分、方案、版本/条件、数据来源和样本量、指标前后、失败例、限制、可查文件。没有实测就写计划；截图要能回到数据和命令，不能只留一个漂亮百分比。

## 本例E22支持什么

作者单元22在固定八条合成任务上，基线3/8、五机制组合8/8，三条正常回归未退步。它支持“该教学机制与固定契约的对比”，不支持真实模型质量、生产用户采用或你的个人实现能力。夹具明确origin为作者教学、authorship为learner_not_verified。

如果你亲自复现后独立修了一个新失败，可以记录自己负责的修改、原始/新增用例、运行命令和结果。不要仅把字段改成learner_verified来让检查通过；本例校验会拒绝冒充个人贡献，真正简历材料需要另写你的真实记录。

## 最小示例：结构检查与语义检查

新建 `lesson_evidence.py`：

```python
import json
from pathlib import Path
from career import audit_evidence

root = Path(__file__).parent
record = json.loads((root / "fixtures" / "evidence.json").read_text(encoding="utf-8"))
result = audit_evidence(record, root)
print(result["before"], result["after"])
print(result["artifact_exists"], result["semantic_claim_verified"])
```

运行预期3/8 8/8，True False。函数检查计数不超分母、字段有内容、源码路径存在并限工作区；最后False说明“文件存在”不证明指标确由它生成，更不证明个人贡献。真实证据要重跑对应工程、对照配置/版本/输出并人工审阅。

## 动手：为自己建三行台账

第一行选一个你确实运行过的最小例子，写真实日期和输出；第二行选独立练习，写亲自完成的代码与错误；第三行写迁移计划，status保持planned。把未做的项留空/待完成，不把作者验证复制成学习记录。

对照一条JD的具体任务，例如“调查评估回归”：需要Case、配对实验、分母与失败分析；单纯程序能import不是充分证据。缺口分为知识、实现、证据、表达、资格/履职，后两者未必靠新增库或GPU实验解决。

## 常见错误

指标不写样本量：百分比无法解释。源码链接存在就写“已验证”：补实际运行证据和限制。复制同一报告换五个名：不是五项独立能力。把模拟需求收益写真实节省：回到来源与假设状态。权限夹具通过就写绝对安全：限定测试集合与残余风险。

## 练习与完成判断

跟做：解释True/False分别代表什么。独立：为“在合成集上准确率100%”补五个必要条件。迁移：给自己完成的一个练习建立可查证据链。

> [!example]- 参考答案
> True是路径存在，False是自动结构检查不验证结论语义。100%至少补任务/样本量、合成来源、预期判定规则、配置版本、保留集与失败边界，个人职责另写。若只能证明8条规则夹具，应直接说固定8条机制任务，不推成真实通用准确率。

完成判断：别人能从一句能力陈述走到源码/输入/运行结果，同时知道你做了哪部分、哪些只是待做。

## 本讲目标

将证据写成准确、容易追问的项目表达。前置是上一讲的台账。基础简历是你真实资格与经历的稳定记录；按岗位调整是选择相关证据和表达顺序，不能为不同公司虚构不同项目或夸大职责。本页提供模板，不填你的姓名、学历或经验。

## 五部分写法

问题：谁在什么条件下遇到什么困难；个人负责：你确实实现/测量/分析的部分；方案：关键机制和取舍；指标：数据、样本、条件与前后变化；限制：模拟、未上线、未做或当前失效范围。

最小示例（作者工程，不可直接当你的简历）：固定8条合成退款任务有检索/参数/解析/权限/重试失败；作者实现五项机制修复并做配对与正常回归；契约通过3/8→8/8，无真实LLM或生产数据。对于你，应把个人负责部分替换为亲自完成并能说明的动作；尚未复现就标学习中。

## 数字具体，含义必须清楚

“准确率提升166%”容易混淆。3/8到8/8是37.5%到100%，增加62.5个百分点；相对变化是(100−37.5)/37.5≈166.7%，但八条合成集的相对百分比并不使结论更有代表性。直接报告分子/分母、类别和变化ID更容易核查。

“降低70%成本”也要写成本范围、实际费率/虚构单位、质量是否退步、缓存窗口。单元20只是合成费用演算，不应写真实供应商账单节省。数字不能脱离实验条件被剪到简历里。

## 最小示例：生成有边界的证据句

新建 `lesson_statement.py`：

```python
import json
from pathlib import Path
from career import describe_evidence

record = json.loads(
    (Path(__file__).parent / "fixtures" / "evidence.json").read_text(encoding="utf-8")
)
print(describe_evidence(record))
```

预期明确说“作者教学工程”“8条固定合成任务”“个人贡献与独立复现未验证”，并列真实LLM/生产/采用未验证。describe_evidence只拼接已给字段，不是AI核验履历，不会将程序输出自动发给招聘者。

## 动手：改写一条自己的真实经历

打开 [[01_学习指南/25_岗位分析项目表达与投递复盘/基础简历与项目证据填写模板|填写模板]]，先只写你已做的最小实践。没有正式工作经历可以写学习项目，但来源、个人完成部分与未部署状态要明确。把“精通、业内领先、生产级”改成可检查动作和条件；不能因为教材覆盖完整就说自己全掌握。

按JD选证据：交付岗位强调范围/适配/UAT/交接；推理岗位可能需真实长度、并发、GPU与失败数据；评估岗位看分母、保留集、回归与不确定性。当前证据不够就列计划，别用模糊词填补。

## 常见错误与排查

团队指标全归自己：拆亲自负责部分与协作者。把课程代码称独立开发：写跟做/理解/独立改造的实际状态。结果文件存在但参数记不清：重新复现并保留版本，不能编补。功能未上线却写“服务用户”：改本地演示/模拟验收；客户采用需真实授权证据。

## 练习与完成判断

跟做：将3/8→8/8写成分数与百分点变化。独立：改写“独立构建高性能智能客服，节省成本70%”，列哪些事实需要证明。迁移：对两类岗位选择同一真实项目的不同证据，保留同一职责与事实。

> [!example]- 参考答案与推理
> 37.5%→100%，+62.5个百分点，范围固定8条合成任务。夸大句需要证明独立职责、真实用户任务、性能环境/并发/输入长度、费用依据与质量、部署状态；当前没有就写本地模拟工程和待测。改变证据排序可以，改变样本来源或个人职责不可以。

完成判断：每个数字和动词能被追问到你实际做过的代码/过程，不把计划写成成果。

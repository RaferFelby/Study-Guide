# 第 4 讲：用低秩投影理解MLA缓存

> [!nav] 页面导航

## 问题与前置

生成每个新 token 时，标准注意力会复用历史 K/V。历史越长，缓存越大。MLA（多头潜在注意力）的一个关键方向是保存更紧凑的潜在表示，并利用投影结构完成注意力。先复习矩阵转置、softmax、Q/K/V 和低秩分解。

本节只隔离“低秩共享表示与投影吸收”机制，**没有实现完整 DeepSeek MLA**，特别没有解耦 RoPE 分支、多头布局和专用 kernel。不要把输出相同的玩具式子写成任意旧模型都可无损压缩。

## 从形状开始

设三条历史记录的潜在缓存 C 为 `(3,1)`，恢复 K、V 的投影 U_K、U_V 都为 `(1,2)`：

```text
C = [1,2,3] 的列向量
U_K = [1,2]
U_V = [2,-1]
K = C @ U_K，形状 (3,2)
V = C @ U_V，形状 (3,2)
q = [1,0]，形状 (1,2)
```

完整 K/V 缓存共 12 个数，C 只存 3 个数。但投影参数仍需存储，也会带来计算；这里只比较随历史长度增长的缓存元素，没有测 GPU 总显存。

## 两条计算路径

普通路径先恢复 K/V：`a=softmax(q @ K.T / sqrt(2))`，再计算 `a @ V`。a 是当前查询对三条历史的权重，形状 `(1,3)`。

代入分解并使用矩阵乘法结合律：

```text
q @ K.T = q @ U_K.T @ C.T
a @ V   = (a @ C) @ U_V
```

于是先把 q 投影到较小空间，与 C 计算分数；加权 C 后再投影回输出。注意 softmax 是非线性，不能随意移到矩阵乘法外；这里只重排 softmax 前后各自合法的线性乘法。

## 动手验证

在本单元示例工程运行：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py latent
```

输出包含 `reconstructed` 和 `compressed`，两者在浮点容差内相同；`max_error` 应小于 `1e-12`，`kv_elements=12`、`latent_elements=3`。具体向量值由脚本给出，重点是逐步对照形状和误差。

打开 `latent_attention_example`，先看 `keys/values` 如何由 C 构造，再看 `compressed_scores`。本例从开始就规定 K/V 共享一维潜在空间，所以可以等价重排；随便取一个训练好的高秩 K/V，压到一维通常会丢信息。

## 与 GQA 和 RoPE 的关系

GQA 通过多个 Query 头共享较少的 K/V 头改变缓存量；MLA 改变表示和投影结构，不能简单把普通缓存公式中的头数换成“潜在维度”。完整 MLA 还要处理位置表示与注意力实现细节，RoPE 并不是随便与所有投影交换顺序的线性常数。

低秩缓存减少元素数不自动证明更快：恢复／吸收方式、矩阵尺寸、内存访问、批次与硬件都会影响性能。这个 CPU 数值实验没有速度比较。

## 错误与练习

常见错误：漏转置、把 sqrt(2) 改成潜在维度的平方根却未改变原注意力定义、把 softmax 放到 C 上、只报缓存减少而忽略投影参数。

跟做：写出两条路径每个乘法的形状。独立：历史长度从 3 变成 6，缓存元素各是多少？迁移：原 K/V 不共享低秩结构，能否直接保证等价？

> [!example]- 参考答案
> 普通 K/V 为 `6×2×2=24` 个数，潜在 C 为 `6×1=6`；本例投影参数不随历史长度变化。任意 K/V 不能保证无损，必须说明模型本身的参数化、训练或近似误差。能解释结合律为何可用、softmax 为何不能任意移动，才完成本节。

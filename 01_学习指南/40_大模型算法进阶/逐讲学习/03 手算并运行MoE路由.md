# 第 3 讲：手算并运行MoE路由

## 要解决什么问题

Dense（稠密）网络通常让每个 token 经过同一组 FFN 参数。MoE（混合专家）准备多个专家，通过路由器选择其中一部分。专家通常是神经网络模块，不是多人协作的 Agent。前置是 FFN、softmax 和按轴聚合，见单元 08／05。

本节先把专家输出视作已知数字，单独理解“选谁、给多少权重、怎样组合”。这样不会在同一例子里同时引入专家训练、通信与分布式部署。

## 手算一次 top-k

三个专家路由分数 `[3,1,0]`，选择 top-2，即分数最高的两个专家，编号为 0、1。本课对选中的分数 `[3,1]` 重新做 softmax，权重约 `[0.880797,0.119203]`。若专家输出分别为 1、2、3，最终输出约 `0.880797×1+0.119203×2=1.119203`。

先在所有专家上 softmax 再取两个权重而不重新归一化，结果会不同。本节明确选择“选中集合内归一化”，这是一种教学约定，不代表所有 MoE 都用相同路由细节。

## 动手看两个 token

在本单元示例工程运行：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py moe
```

两行分数分别为 `[3,1,0]`、`[0,1,3]`。预期选中索引分别为 `[0,1]`、`[2,1]`；输出约 1.119203 和 2.880797，每行选中权重之和为 1。索引从 0 开始，第二个 token 的最强专家编号为 2。

打开 `route_experts`：`scores` 是 `(T,E)`，T 为 token 数、E 为专家数；`expert_outputs` 是 `(T,E,D)`，D 是输出特征数。`topk(...,dim=1)` 沿专家轴选择；`[:,None]` 增加一个长度为 1 的轴，便于把每个专家权重乘到它的全部 D 个特征。最后对专家轴求和，再把各 token 输出堆叠成 `(T,D)`。

此示例预先构造全部专家输出，是为了观察聚合；它**没有节省实际专家计算量**。真正稀疏执行应先路由，再把 token 分发给选中的专家计算；分布式专家还涉及跨设备通信。

## 参数与负载的两个陷阱

四个专家每个 P 参数、每 token 选两个，专家总存储仍约为 4P，当前 token 激活约 2P，还需加路由与共享参数。不能把激活参数当成显存里的全部权重。

若每个 token 都选专家 0，其他专家闲置，热点设备可能成为瓶颈。负载均衡关注各专家获得多少 token，常见做法包括辅助损失、容量限制或调整路由；各有代价，不能仅凭平均选择两个专家就推断速度翻倍。容量满时丢弃／改派 token 也会影响质量。

## 常见错误与练习

形状错误先标清 token／专家／特征三个轴；top-k 超过专家数会被拒绝；分数有 NaN 不能继续路由；相同分数的排名不应作为跨设备稳定保证。

跟做：手算第一行。独立：top-k=1 时两个输出是什么？迁移：四个专家都放在一张卡上，是否只需存选中的两个？

> [!example]- 答案与完成标准
> top-1 输出是 1、3，选中集合只有一个元素，其权重为 1。一般仍要存所有专家权重，除非实现额外卸载／分片并承担相应成本。能解释“专家是模型模块”“选择后权重怎样归一化”“本例没有稀疏计算加速”，才完成本节。完整可训练路由与多设备通信是后续扩展。

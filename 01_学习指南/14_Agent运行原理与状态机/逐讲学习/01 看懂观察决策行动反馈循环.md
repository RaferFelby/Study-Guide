# 第 1 讲：看懂观察决策行动反馈循环

## 要解决什么问题

用户问存储保留多久，一次语言模型回答可能没查资料。如果把本地查询工具交给一个任务循环，程序可以先提出查询动作，拿到实际结果，再决定回答或继续查。这类系统常叫 **Agent（智能体）**：在任务和环境反馈下选择并执行动作的系统。

“有Agent”不等于“能无限自主完成任何任务”。关键是循环中谁决策、谁执行、谁记录、谁限制权限和终止。当前示例用规则替代模型做决策，让这些责任可见。

前置只需函数、参数、返回值和判断。**工具**在这里是一个带明确输入输出的可调用函数；**观察**是工具返回的外部信息；**动作**是决策器提出的下一步请求。

## 从直接函数开始

在示例工程新建 `inspect_tool.py`，写完整脚本：

```python
from tools import lookup_policy

result = lookup_policy({"service": "storage"})
if result.ok:
    print(result.data["retention"])
else:
    print("查询失败：", result.error_code)
```

运行共享解释器，预期 `30 days`。字典给工具 `service` 参数；`ToolResult` 有ok、data和error_code；成功才读取retention，失败不能假定data里有答案。

把storage改unknown，预期not_found。这说明调用完成不一定有可用结果。一个工具错误也可以成为观察，让系统明确告知资料缺失；不必每个错误都让进程崩溃。

## 四个词的执行顺序

1. **观察**：初始是用户任务；之后加入工具结果。
2. **决策**：读取当前可见信息，选择调用哪个工具、什么参数，或输出最终答案。
3. **行动**：控制器核验后执行工具。决策器提出动作不等于已经执行。
4. **反馈**：记录实际结果，更新可见信息，回到下一次决策。

可以类比查快递：先知道订单号，决定查物流，读取物流状态，再决定回答。但实际机制是函数调用和状态更新；程序不会拥有人的真实意图或常识，未编码的约束仍可能漏掉。

本单元默认两次决策：第一次没有tool_records，`policy_lookup`提出lookup_policy；控制器执行后记录30 days；第二次决策看到结果，返回final动作。这里“两步”指两次决策，工具执行不是另算第三步。

## 决策器与控制器分别做什么

打开 `policy.py` 的 `policy_lookup`：

```python
if not state.tool_records:
    return Action("tool", "lookup_policy", {"service": "storage"})
```

`not`对空列表为真，表示尚未查过工具。`Action`只是一份请求数据：kind是tool、名称lookup_policy、参数字典。return离开决策函数，并没有在这里调用工具。

下一分支读最后一条记录：`[-1]`表示列表末尾。如果ok为False返回无法回答；成功则把真实retention和citation组成final。这种策略把服务写死为storage，**没有解析用户任意任务**。改变task字符串不会自动查询compute，这是教学简化，应在报告中明确。

控制器 `run_agent` 负责：步数限制、取消、校验动作、查注册工具、检查重复、要求确认、执行并记录结果、转入终态。真实模型也只能提出动作，控制器仍应掌握这些约束。

## 动手跑完整循环

在示例工程终端运行：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py
```

预期状态completed、步数2、内存工单0；最终答案包含30 days。打开 `results/trace.json`，暂时只找event中的decision_started、tool_started、tool_observation、final_answer。

`completed`表示控制器接受了一个非空final并结束，不是“答案一定真实完整”。真实LLM可能在有证据时仍答错，所以仍需要上一单元的正确性/引用评估。Agent控制流与答案质量是两个层面。

## 常见错误

直接把Action打印当结果：你看到的是请求，真正工具还没执行。反复只把用户问题传给决策器：如果不给新观察，它无法利用工具反馈。每轮都清空tool_records：会让规则反复查询，被循环检测终止。

工具结果里有“请忽略规则”：它是资料内容，不是可信指令。当前例子无恶意文本，但真实资料可能包含提示注入，应保留指令与数据边界，后续安全单元继续处理。

## 练习与参考答案

**跟做：** 手画默认两步调用链，并标出每次return返回的是Action还是ToolResult。完成标准：箭头能对应trace。

**独立：** 修改个人副本的策略先查compute，再依据返回回答14 days。提示：只改第一步service，不把最终答案写死。完成标准：答案由工具结果产生。

**迁移：** 设计“先查政策，再查订单”的三步循环，写每步输入/输出、何时可以结束、第二个工具失败时怎样说明。先画图，暂时不引入框架。

> 第一次decide返回tool Action；execute返回ToolResult；第二次decide返回final Action。compute策略仍读取result.data，不应硬编码14 days。三步任务通常要保存两个观察，最终回答指出哪个字段已查到、哪个未查到；不能把工具未返回的订单状态编出来。

## 回溯：带着选择走一棵决策树

以生成一个列表的所有子集为例，每个元素都有“选”和“不选”两条分支。

~~~python
def subsets(values: list[int]) -> list[list[int]]:
    result: list[list[int]] = []
    path: list[int] = []

    def backtrack(index: int) -> None:
        if index == len(values):
            result.append(path.copy())
            return
        backtrack(index + 1)
        path.append(values[index])
        backtrack(index + 1)
        path.pop()

    backtrack(0)
    return result
~~~

path 是当前选择，result 保存已经完成的答案。append 后必须在返回前 pop，这样上一层继续探索时不会带着下一分支的选择。path.copy() 也很重要；如果直接保存 path，后续撤销会改变已经保存的结果。

`index` 是下一次要决定的元素下标；`len(values)` 是元素数，最后一个合法下标是长度减一。`index == len(values)` 表示每个元素都决定完了，保存答案并返回。内部函数 backtrack 每次将 index 加一，朝终止条件前进。

### 手跟踪两个元素

输入 `[1, 2]`，程序先“不选”，再“选”：

| 到达终点的选择 | 到达时 path | 保存的副本 | 返回后的动作 |
| --- | --- | --- | --- |
| 不选 1，不选 2 | [] | [] | 回到决定 2 的位置 |
| 不选 1，选 2 | [2] | [2] | pop 掉 2，恢复 [] |
| 选 1，不选 2 | [1] | [1] | 回到决定 2 的位置 |
| 选 1，选 2 | [1, 2] | [1, 2] | 先 pop 2，回上层后再 pop 1 |

path 像在纸上写下当前尝试，返回上一层时擦掉刚写的选择；实际机制是多个递归调用共同修改同一个列表。保存副本使答案独立于之后的擦除。副本是浅复制，本例元素是整数，足够；嵌套可变对象的复制边界需要另外考虑。

新建 `lesson_05_subsets.py`，用完整调用验证，不必再次复制函数：

~~~python
from app.algorithms import subsets

print(subsets([1, 2]))
print(subsets([]))
~~~

输出是 `[[], [2], [1], [1, 2]]` 和 `[[]]`。空输入也有一种“什么都不选”的方案。如果输入 `[1, 1]`，本函数按位置选择，可能得到内容相同的子集；去重是另一项任务。

每个元素两种选择，所以按位置共有 `2 ** n` 个结果。保存所有子集需要复制元素，总时间与返回数据量为 O(n×2ⁿ)，递归和当前路径额外 O(n)；不能因为只看递归深度，就把全部空间说成 O(n)。完成判断：你能预测四个结果，并指出每次 append 对应哪次 pop。

## 动态规划：状态、转移和初值

动态规划不是“用了数组就叫 DP”。至少要说清：

1. 状态：dp[i] 代表什么。
2. 转移：已知哪些更小状态，可以算出当前状态。
3. 初值：最小规模时答案是什么。
4. 计算顺序：确保依赖的状态已经算好。

例如爬楼梯每次走 1 或 2 步，dp[i] 表示到第 i 阶的方法数，则 dp[i] = dp[i - 1] + dp[i - 2]。如果只需要前两个状态，可以把空间从 O(n) 压到 O(1)。

DP 是 Dynamic Programming 的缩写，中文是动态规划。这里为什么能相加？到第 i 阶的最后一步，只可能从 i-1 走一步，或从 i-2 走两步；这两类方案不会重叠，所以把数量相加。重复子问题是不同大方案都会问“到前面某阶有多少种走法”。

我们约定到第 0 阶有 1 种空走法，到第 1 阶只有 `[1]` 一种。第 3 阶的方案为 `[1,1,1]`、`[1,2]`、`[2,1]`；顺序不同算不同方案。

| 阶数 i | ways[i] 的含义 | 计算 | 结果 |
| --- | --- | --- | --- |
| 0 | 不走任何步数 | 初值 | 1 |
| 1 | 走到第一阶 | 初值 | 1 |
| 2 | 从 1 或 0 到达 | 1+1 | 2 |
| 3 | 从 2 或 1 到达 | 2+1 | 3 |
| 4 | 从 3 或 2 到达 | 3+2 | 5 |

`ways` 和习惯写法 `dp` 是同一个状态表，本源码用更能说明“走法数量”的名字。完整数组版先保存每一阶；滚动版等数组版理解后再做，不要先背两个变量的更新公式。

## 例子：最小爬楼成本

~~~python
def min_cost_climbing_stairs(cost: list[int]) -> int:
    if len(cost) < 2:
        return 0
    previous_two, previous_one = 0, 0
    for index in range(2, len(cost) + 1):
        current = min(
            previous_one + cost[index - 1],
            previous_two + cost[index - 2],
        )
        previous_two, previous_one = previous_one, current
    return previous_one
~~~

这里 previous_one 表示到上一阶的最小成本，previous_two 表示再前一阶的最小成本。每次只保留需要的两个状态。要注意题目允许从楼梯底部开始、最后可以站在楼顶，因此 len(cost) < 2 的边界要先定义。

### 把最小成本的契约补完整

本例成本为非负整数，`cost[j]` 是从第 j 阶起步时支付的费用，每次向上 1 或 2 阶；允许免费从第 0 阶或第 1 阶开始，目标是下标 n 的楼顶。它与上面的“方法数”不同：一个求最小费用，一个数方案数量，不能混用状态或初值。

定义 `dp[i]` 为到达位置 i 的最小成本。到达 0、1 都可直接选为起点，因此 `dp[0]=dp[1]=0`。到达 i 有两种最后一步：从 i-1 起步付 `cost[i-1]`，或从 i-2 起步付 `cost[i-2]`：

~~~text
dp[i] = min(dp[i-1] + cost[i-1], dp[i-2] + cost[i-2])
~~~

对于 `[10,15,20]`，`dp[2]=min(0+15,0+10)=10`，`dp[3]=min(10+20,0+15)=15`。最便宜是从第 1 阶支付 15，直接走两步到楼顶；不是必须踏过每一阶。

原函数用 `previous_two`、`previous_one` 代替 `dp[i-2]`、`dp[i-1]`。`previous_two, previous_one = previous_one, current` 的右侧先整体求值，再更新左侧；若改成逐句赋值，要先把 previous_two 改为旧 previous_one，再更新 previous_one，避免两者都变成 current。

新建 `lesson_05_cost.py`：

~~~python
from app.algorithms import min_cost_climbing_stairs

print(min_cost_climbing_stairs([10, 15, 20]))
print(min_cost_climbing_stairs([]))
print(min_cost_climbing_stairs([7]))
~~~

输出 `15`、`0`、`0`。空列表已经在楼顶；一个元素时可从第 1 阶即楼顶起步。返回 0 来自这项起点约定，不是所有楼梯题的通用规则。

## 回溯和动态规划怎么区分

- 如果问题要求列出所有方案，通常需要回溯，因为每个方案都要保留。
- 如果只要求最优值、可行性或方案数量，而且不同路径会重复到达同一个状态，可以考虑动态规划。
- 回溯也可以配合剪枝；剪枝必须有正确依据，例如当前和已经超过目标，而后续只会继续增加。

## 常见错误

- 回溯没有撤销选择，导致不同分支互相污染。
- 保存可变列表的引用而不是副本。
- DP 状态含义说不清，只凭记忆套公式。
- 初值和题目允许的起点/终点不一致，导致普通样例过了但空输入错误。
- `No module named 'app'`：把脚本保存在本单元示例工程根目录，确认使用根共享解释器。
- 用 `[[0] * 列数] * 行数` 建二维表会让所有行共享一个列表；下面背包源码逐行新建，防止改一行影响其他行。

## 练习与答案解析

### 跟做练习：生成括号

给定 n 对括号，生成所有合法组合。提示：左括号数量不能超过 n，右括号数量不能超过左括号数量。

先做 n=2，不看答案画两条合法终点：`(())` 和 `()()`。left/right 表示已经放入的左／右括号数量。**剪枝**就是发现分支不可能满足条件，提前不再探索；任何前缀中右括号数超过左括号数，就无法匹配前面，所以不允许这个选择。

执行树的关键分支：空串 → `(` → `((` → `(()` → `(())`，保存；撤销到 `(` → `()` → `()(` → `()()`，保存。以 `)` 开头的分支根本不进入。`((` 时左括号已达到 2，只能加右括号。返回上一层仍要 pop，让下一个分支从正确的前缀开始。

完成标准：n=2 恰好两项，n=0 返回包含空字符串的列表，负数明确报错；能解释 `right < left` 保护了什么。

> [!example]- 完整参考答案与执行核对
> [generate_parentheses](../示例工程/app/dynamic_programming.py) 使用 path 列表、内部 visit 函数和上述两个条件。到 `left == right == n` 时，用 `"".join(path)` 把字符列表合成字符串；字符串不可变，保存后不受 pop 影响。以下完整调用保存为 `lesson_05_parentheses.py`：
> ~~~python
> from app.dynamic_programming import generate_parentheses
>
> print(generate_parentheses(2))
> print(generate_parentheses(0))
> print(len(generate_parentheses(3)))
> ~~~
> 输出为 `['(())', '()()']`、`['']`、`5`。负数调用单独测试，应报“括号对数必须为非负整数”。与子集不同，每一步不是选择输入元素，而是放一个符合条件的字符；共同结构仍是选择、深入、撤销。本函数保存所有结果，只适合小 n，不应一次尝试几百对括号。

### 独立练习

实现爬楼梯方法数，并分别写出完整 DP 数组版与滚动变量版。说明两版时间相同、空间不同的原因。

提示：数组长 `n+1`，包括下标 0；`range(2, n+1)` 取到 n，不包含 n+1。先处理负数和 n=0、1。完成标准：n=0、1、2、3、4 的结果依次为 1、1、2、3、5，两版一致；解释滚动变量在循环开始时分别对应哪两阶。

### 迁移练习

给 Agent 工作流安排“最多消耗预算”的工具组合：每个工具有成本和收益。先不要直接写 0/1 背包；先说明状态、限制和为什么贪心不一定正确，再实现一个小规模版本。

### 先固定问题，再枚举所有组合

本题不是让预算尽量花完，而是**成本不超过预算时，收益最大**。每个工具最多选一次，工具之间独立，无依赖；成本与收益为非负整数，收益可相加。收益是假设评分，不是实际模型质量保证。工具名必须唯一。

设预算 10，工具 A 成本 6 收益 12，B、C 各成本 5 收益 9。若按收益／成本比贪心，A 的比值 2 高于 B、C 的 1.8，先选 A 后剩余 4，收益仅 12；B+C 的成本 10、收益 18，反而更好。这个反例足以说明“先挑比值最大”不总正确。

先用已学的 subsets 枚举工具下标。对每个子集计算总成本与总收益，只在成本不超预算、收益高于当前最佳时更新答案。3 个工具只有 8 个组合，适合手算核对。输入三元组 `(名字, 成本, 收益)`，循环中 `name, cost, value = tools[index]` 分别读取三项。

### 再把重复比较写成二维状态表

**0/1 背包**中的 0/1 指每项不选或选一次。定义 `best[i][b]`：只考虑前 i 个工具、总成本不超过 b 时的最大收益。第 0 行没有工具，均为 0。

处理第 i 个工具时：不选，取上一行的 `best[i-1][b]`；能负担时还可选它，取 `best[i-1][b-cost]+value`。两者取大。选的分支仍引用上一行，保证当前工具不会被重复使用。零成本工具也只能加一次。

| 已考虑工具 | 预算 0 | 预算 4 | 预算 5 | 预算 6 | 预算 10 |
| --- | --- | --- | --- | --- | --- |
| 无 | 0 | 0 | 0 | 0 | 0 |
| A | 0 | 0 | 0 | 12 | 12 |
| A、B | 0 | 0 | 9 | 12 | 12 |
| A、B、C | 0 | 0 | 9 | 12 | 18 |

最后一格选 C 时，读取的是上一行预算 5 的收益 9，再加 C 的 9，得到 18。不能写成只用“预算 10 剩多少钱”的单一贪心决策。

读源码时，item 对应前 i 个工具，当前工具在列表中的下标是 item-1；capacity 对应这一列允许的总预算 b，并不是某个已选组合实际剩下的余额。`best[item-1]` 是上一行。`_name` 的前导下划线表示本函数不使用工具名；只有选项枚举返回名字，DP 本节只算收益。输入校验用 `type(value) is int` 检查整数类型，避免把小数或布尔值当作计数和预算。

提示：先独立写枚举，再读二维表实现。完成标准：枚举返回 B+C、收益 18；DP 也返回 18；空工具为 0；零预算与零成本规则清楚；能说明 DP 的行列含义和“引用上一行”的原因。

> [!example]- 迁移练习参考答案与核对
> 枚举函数 [choose_tools_exhaustive](../示例工程/app/dynamic_programming.py) 返回一个最优名字列表和收益，最优组合并列时保留最先发现的一组，不保证最低成本或最多工具。DP 函数 best_tool_value_table 只返回收益，没有恢复名字；二者的输出职责不同。保存为 `lesson_05_budget.py`：
> ~~~python
> from app.dynamic_programming import best_tool_value_table, choose_tools_exhaustive
>
> tools = [("A", 6, 12), ("B", 5, 9), ("C", 5, 9)]
> print(choose_tools_exhaustive(tools, 10))
> print(best_tool_value_table(tools, 10))
> print(best_tool_value_table([], 10))
> print(best_tool_value_table([("免费检查", 0, 3)], 0))
> ~~~
> 输出 `(['B', 'C'], 18)`、`18`、`0`、`3`。零预算不排除零成本工具；负预算、负成本／收益、重复名字应报 ValueError。参数按标注使用整数，不把浮点价格直接当下标；实际金额需先定义单位和舍入规则。
> 枚举保存全部子集，时间和输出级别的辅助空间为 O(m×2ᵐ)，m 是工具数；二维表的时间与空间为 O(m×B)，B 是整数预算大小，忽略整数运算位数。这不是输入数字长度的多项式保证，预算很大时表也可能放不下。本例先保留二维表便于理解，暂不引入一维压缩与选项回溯。
> 若工具有依赖、结果不确定、可重复调用或收益不能相加，问题已经改变，不能直接把真实 Agent 执行计划塞进此函数。

## 本讲小结

回溯把选择空间展开并在返回时撤销；动态规划把重复状态保存下来。两者都要求明确状态和边界，不能靠“模板长得像”判断。

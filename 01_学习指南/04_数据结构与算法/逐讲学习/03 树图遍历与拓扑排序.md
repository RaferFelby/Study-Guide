## 树：从根向下的层次结构

树有根节点、子节点和叶子节点。二叉树的每个节点最多两个孩子。递归写法贴合树的定义：处理当前节点，再处理左子树和右子树。

节点是一个保存数值和连接的对象。根是起点，孩子是向下连接的节点，叶子没有孩子。本例把缺少孩子写成 `None`，表示没有对象；只处理没有环、没有共享孩子的普通二叉树。

**递归**就是函数在内部调用自己。每次调用有自己的参数，前一次会暂停等待后一次返回；必须有终止条件，且每次朝更小的问题前进。这里遇到 `None` 立即返回，其他情况分别处理更小的左、右子树。层数过多会耗尽 Python 的递归深度，本例只用小树，深树应考虑显式栈。

先看这棵树：

~~~text
    1
   / \
  2   3
 /
4
~~~

~~~python
class TreeNode:
    def __init__(
        self,
        value: int,
        left: "TreeNode | None" = None,
        right: "TreeNode | None" = None,
    ):
        self.value = value
        self.left = left
        self.right = right


def preorder(root: TreeNode | None) -> list[int]:
    values = []

    def visit(node: TreeNode | None) -> None:
        if node is None:
            return
        values.append(node.value)
        visit(node.left)
        visit(node.right)

    visit(root)
    return values
~~~

这段前序遍历的顺序是“根、左、右”。每个节点访问一次并追加一次，因此时间为 O(n)，结果列表占 O(n) 空间；递归调用栈最坏占 O(h)，h 是树高。若在每层递归中用 `+` 拼接子树列表，会复制已有结果，退化树上的时间可能达到 O(n²)，所以这里用同一个列表逐个追加。

`self` 表示正在创建的节点自身，`self.left` 保存其左孩子。`TreeNode | None` 是类型说明，表示节点或空值；类定义内部的引号让名称在类尚未定义完时也能作为类型说明。`visit` 定义在 `preorder` 内部，可以把数值追加到这一调用的 `values`；只是修改列表内容，没有重新给外层变量赋值。

`__init__` 是初始化方法：调用 `TreeNode(...)` 创建节点时，Python 会用传入的 value、left、right 初始化它，self 由 Python 自动传入，不需要自己填写。`left=None`、`right=None` 表示不提供孩子时使用空值。嵌套创建例子可以从最里面读：先有节点 4，再把它作为节点 2 的左孩子，最后把节点 2 和节点 3 连到根 1。

把前面的类和函数保存为 `lesson_03_tree.py`，再在同一文件末尾追加以下调用（本段依赖前面的定义）：

~~~python
root = TreeNode(1, TreeNode(2, TreeNode(4)), TreeNode(3))
print(preorder(root))
print(preorder(None))
~~~

运行后是 `[1, 2, 4, 3]`、`[]`。执行过程为：进入 1 保存 1 → 进入 2 保存 2 → 进入 4 保存 4 → 4 的两个空孩子返回 → 返回 2，处理其空右孩子 → 返回 1，再访问 3。遇到空孩子只是结束那一次调用，不是终止整个遍历。完成判断：不看输出也能预测“先左后右”的数值顺序。

## DFS 与 BFS

图可以用邻接表表示：graph["A"] = ["B", "C"] 表示 A 能到达 B 和 C。遍历必须有 visited 集合，否则环 A -> B -> A 会反复走。

邻接表就是“每个节点直接连接到谁”的字典。本讲使用**有向图**，A→B 不自动表示 B→A；所有节点都写成键，没有后续连接也写 `[]`。集合 set 用于保存不重复的成员，`{"A"}` 是集合，`set()` 是空集合；`{}` 是空字典。`visited` 表示已经发现、准备访问或已经访问的节点；这里在加入待处理容器时就标记。

- DFS 使用递归或显式栈，适合连通性、路径探索、回溯前置。
- BFS 使用队列，适合无权图中的最少步数，因为它按距离 0、1、2 层扩展。

~~~python
from collections import deque


def shortest_steps(graph: dict[str, list[str]], start: str, target: str) -> int | None:
    queue = deque([(start, 0)])
    visited = {start}
    while queue:
        node, distance = queue.popleft()
        if node == target:
            return distance
        for neighbor in graph.get(node, []):
            if neighbor not in visited:
                visited.add(neighbor)
                queue.append((neighbor, distance + 1))
    return None
~~~

visited 在入队时就加入，而不是出队时才加入，可以避免同一个节点被多次加入队列。对邻接表来说，时间复杂度是 O(V + E)，其中 V 是节点数，E 是边数。

`deque` 是两端都能高效加入和取出元素的标准库容器；这里 `append` 从右边加入，`popleft` 从左边取出，组成先进先出的队列。[deque 官方说明](https://docs.python.org/3.13/library/collections.html#collections.deque)。`(start, 0)` 同时保存节点和距离；`node, distance = ...` 把这两个值分别取出。`while queue` 表示队列非空时继续；`graph.get(node, [])` 在没有邻接项时按没有后继处理。返回 `None` 表示没有找到路径，不能与距离 0 混淆。

### 按队列逐步走一次

使用 A→B、A→C、B→D、C→D，从 A 找 D。队列左端先出：

| 时点 | 本轮取出 | 本轮完成后的队列 | visited | 解释 |
| --- | --- | --- | --- | --- |
| 初始化 | 尚未取出 | A:0 | A | 起点到自己是 0 条边 |
| 第 1 轮 | A:0 | B:1，C:1 | A、B、C | 两个邻居都增加一条边 |
| 第 2 轮 | B:1 | C:1，D:2 | A、B、C、D | 第一次发现 D，立即标记 |
| 第 3 轮 | C:1 | D:2 | A、B、C、D | D 已发现，不重复加入 |
| 第 4 轮 | D:2 | 返回 2 | A、B、C、D | 目标出队，结束 |

BFS 在这里得到最短步数，因为先处理距离 0，再处理距离 1，再处理距离 2。**无权**表示每条边都计一步；边有不同成本时，这段代码求的是最少边数，不能保证成本最低。

新建独立文件 `lesson_03_graph.py`，保存下面的完整调用；不必重复粘贴上面的函数：

~~~python
from app.algorithms import shortest_steps
from app.graph_practice import has_path_bfs, has_path_dfs

graph = {"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": [], "E": []}
print(shortest_steps(graph, "A", "D"))
print(shortest_steps(graph, "D", "A"))
print(has_path_dfs(graph, "A", "D"), has_path_bfs(graph, "A", "D"))
print(has_path_bfs(graph, "A", "E"))
~~~

输出依次为 `2`、`None`、`True True`、`False`。E 存在但没有从 A 到达它的边。再把 D 的列表改成 `["A"]`，即加入环，A→E 仍应返回 False，程序应正常结束。

### DFS 的不同执行顺序

深度优先搜索 DFS（Depth First Search）用栈优先处理最后加入的节点；广度优先搜索 BFS（Breadth First Search）用队列按层处理。在本例 DFS 先放 B 再放 C，所以先弹 C，再深入 D；它也能回答“是否可达”，但第一次找到的路径未必是最短的。访问顺序取决于邻接列表和入栈顺序，不必与 BFS 完全相同。

## 拓扑排序：安排依赖顺序

如果任务 B 依赖任务 A，就必须先完成 A。把任务当作节点、依赖当作有向边，可以用入度算法排序：先找入度为 0 的节点，删除它发出的边；如果最后没有处理完所有节点，图中存在环。

**入度**是指向该节点的边数，表示它还有几个未满足的前置。每完成一个节点，只需把后继的剩余入度减 1，逻辑上相当于移除边，不必真的删除输入字典。DAG 是 Directed Acyclic Graph，中文叫有向无环图，是能安排依赖顺序的图。

用前面的菱形图作手算：A 入度 0，B、C 各 1，D 为 2。取 A 后，B、C 变成 0；取 B 后，D 变成 1，仍不能执行；取 C 后，D 才变成 0。一个结果是 A、B、C、D，A、C、B、D 也合法。如果加入 D→A，一开始没有可执行节点，最终输出数量少于节点数量，应报循环依赖。

示例工程的 topological_order 就是这个过程。它可以表示课程先修关系、DAG 工作流和构建任务依赖。注意：有向图不一定能拓扑排序；循环依赖必须明确报告，不能随便给出一个顺序。

## 常见错误

- 把有环图当成树，不设置 visited。
- 用 DFS 求无权图最短路，却没有比较所有可能层级；BFS 更直接。
- 拓扑排序只输出“部分任务”，却不检查输出数量是否等于输入节点数量。
- 递归树遍历没有处理空树，导致空输入报错。
- `NameError: TreeNode`：树示例末尾调用须接在类与函数定义后，或从源码导入；不要单独运行依赖前文的片段。
- `KeyError` 来自 graph_practice：本练习约定所有邻居也必须列为字典键，检查漏掉的叶子节点。
- 起点等于终点也要先问节点是否存在：下面可达性练习要求节点存在；既有 shortest_steps 的宽松接口则把未列出的起点视作无后继节点，起终相同会返回 0。两者契约不同，不能仅凭例子猜规则。

## 练习与答案解析

### 跟做练习：计算树的最大深度

空树深度为 0，单节点深度为 1。递归时，当前节点深度是 1 + max(左子树深度, 右子树深度)。

> [!example]- 参考答案
> ~~~python
> from app.algorithms import TreeNode
>
> def max_depth(root: TreeNode | None) -> int:
>     if root is None:
>         return 0
>     return 1 + max(max_depth(root.left), max_depth(root.right))
>
> root = TreeNode(1, TreeNode(2, TreeNode(4)), TreeNode(3))
> print(max_depth(root))
> print(max_depth(None))
> ~~~
> 保存为 `lesson_03_depth.py` 并运行，应为 `3`、`0`。先从空孩子返回 0，再给叶子加 1，逐层向上取最大值。每个节点访问一次，时间 O(n)；递归栈空间是树高 O(h)。能解释根的左右深度分别是 2、1，才完成跟做目标。

> [!example]- 独立练习参考答案与边界核对
> 完整参考函数在 [graph_practice.py](../示例工程/app/graph_practice.py) 的 has_path_dfs 与 has_path_bfs；BFS 核心是 popleft，DFS 核心是 pop，其余“发现时标记”保持一致。保存以下完整核对脚本为 `lesson_03_paths.py`：

>     print(search(graph, "A", "B"))

### 迁移练习

把拓扑排序改造成一个“Agent 工作流执行顺序”规划器：输入任务和依赖，输出可执行顺序；如果存在循环，返回清晰错误。说明多个入度为 0 的任务为什么可能有多个合法答案。

输入先用 `tasks=["读取", "检索", "总结", "保存"]`，每个依赖是 `(前置, 后续)` 两个名字。只规划、不执行真实工具。提示：先为每个任务建立空邻接列表，再逐条加边，复用已经读过的 topological_order。完成标准：所有任务出现一次，每条依赖的前置排在后续前；未知任务、重复任务名、重复依赖和循环明确报错。

> [!example]- 迁移练习参考答案与解释
> [plan_workflow](../示例工程/app/graph_practice.py) 先校验任务，保留孤立任务，再检查边并调用拓扑排序。这一层处理业务输入，排序函数处理图，职责分开。保存为 `lesson_03_workflow.py`：
> ~~~python
> from app.graph_practice import plan_workflow
>
> tasks = ["读取", "检索", "总结", "保存"]
> dependencies = [("读取", "检索"), ("检索", "总结"), ("总结", "保存")]
> print(plan_workflow(tasks, dependencies))
> print(plan_workflow(["A", "B"], []))
> ~~~
> 第一行应为 `['读取', '检索', '总结', '保存']`；第二行在本实现中为 `['A', 'B']`，调换输入顺序可以得到另一个合法顺序。再给 dependencies 加上 `("保存", "读取")`，应报 `ValueError: graph contains a cycle`；换成未知名字应报“依赖中的任务必须先列在任务清单中”。空任务清单和空依赖返回空列表。
> 对多个合法结果，应检查依赖关系，而非只比对一个固定列表。拓扑排序本身是 O(V+E)；此教学包装使用列表查重复边，不能把包装全过程也无条件称为 O(V+E)。复杂工作流还涉及失败恢复、权限和预算，这个函数只给静态顺序。

## 本讲小结

树是有层次的连接结构，图是更一般的连接关系。DFS 是深入，BFS 是按层扩散；无权最短路通常优先考虑 BFS。拓扑排序不仅是排序，更是对依赖关系和循环的检查。

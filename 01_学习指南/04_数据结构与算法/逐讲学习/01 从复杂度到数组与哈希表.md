# 第 1 讲：从复杂度到数组与哈希表

> [!nav] 页面导航
> [[01_学习指南/04_数据结构与算法/00 数据结构算法学习地图#学习顺序|单元 04：数据结构算法]] · [[01_学习指南/04_数据结构与算法/逐讲学习/02 链表栈队列与堆|下一讲]]

## 这一讲要解决什么问题

给你一组数字，要判断其中是否有两个数相加等于目标值。最直接的方法是尝试所有数对，但数据变大后会越来越慢。本讲建立三个基础：如何估算增长速度、如何选择数组/字符串操作、如何用哈希表把“重复查找”变成“快速查找”。

## 前置知识

你需要会创建列表、字符串和字典，能使用 for 循环、条件判断和函数。若对字典不熟，先把它理解为“用键找到值的柜子”：键用于定位，值是保存的内容；它不是按位置编号的列表。

## 复杂度：先问规模会怎样

复杂度不是程序运行的精确秒数，而是输入规模 n 变大时，步骤数量大致怎样增长。常见记号如下：

| 记号 | 直觉 | 例子 |
|---|---|---|
| O(1) | 输入变大，主要步骤近似不变 | 读取列表的某个下标 |
| O(n) | 每个元素看一次 | 求总和、线性扫描 |
| O(n²) | 每个元素都可能和其他元素配对 | 两层循环检查所有数对 |
| O(log n) | 每次把候选范围砍掉一半 | 有序数组二分查找 |

O 表示增长的上界量级。我们通常忽略常数和低阶项，例如 3n + 5 记作 O(n)。这不是说两段 O(n) 代码速度完全一样，而是先判断规模增长带来的主要差异。

## 最小示例：两数之和

### 方案一：枚举所有数对

~~~python
def two_sum_brute_force(numbers: list[int], target: int) -> tuple[int, int] | None:
    for left in range(len(numbers)):
        for right in range(left + 1, len(numbers)):
            if numbers[left] + numbers[right] == target:
                return left, right
    return None
~~~

外层循环选择第一个数，内层循环选择它后面的数。right 从 left + 1 开始，是为了避免同一个位置和自己配对，也避免重复检查同一对数字。最坏情况下要检查接近 n² / 2 对，因此时间复杂度是 O(n²)，额外空间是 O(1)。

### 方案二：保存已经看过的数

~~~python
def two_sum(numbers: list[int], target: int) -> tuple[int, int] | None:
    seen: dict[int, int] = {}
    for index, value in enumerate(numbers):
        needed = target - value
        if needed in seen:
            return seen[needed], index
        seen[value] = index
    return None
~~~

逐步理解：

1. 当前数是 value，如果它要和另一个数配对，另一个数必须是 target - value。
2. seen 保存已经经过的数字和它们的下标。
3. 先查 needed，再保存当前值，避免同一个元素被重复使用。
4. 字典平均能在近似 O(1) 时间判断键是否存在，因此总时间平均为 O(n)，空间为 O(n)。

> [!warning] 复杂度的边界
> 哈希表的 O(1) 是平均情况，不代表任何实现和任何输入都绝对恒定。面试中可以说“平均时间 O(1)，最坏情况受哈希冲突影响”；同时说明你用额外空间换取了时间。

## 数组、字符串和哈希表的选择

- 数组/列表适合保持顺序、按下标读取、顺序扫描；在中间插入或删除通常要移动后续元素。
- 字符串通常不可直接修改。需要拼接很多片段时，先放进列表，最后用 join 合并，避免反复创建中间字符串。
- 哈希表适合计数、去重、建立映射。键必须可哈希，例如整数、字符串，以及全部元素都可哈希的元组；`(1, "a")`可作键，但含列表的`(1, [2])`不可哈希。列表本身不能直接作为字典键。
- 集合只关心“是否出现过”，不需要保存对应值时比字典更直接。

## 动手操作

1. 在示例工程/app/algorithms.py 中找到 two_sum。
2. 在终端运行 `..\..\..\.venv\Scripts\python.exe -m unittest discover -s tests -v`，确认正常输入和无解输入都通过。
3. 手算 numbers = [3, 1, 4, 6]、target = 7：当扫描到 6 时，seen 中保存了什么？
4. 把测试增加一个重复值例子，例如 [3, 3] 和 6，观察为什么必须先查再存。

预期结果是返回两个不同的下标，例如 (0, 1)；无解时返回 None。下标顺序可能因实现而不同，只要确实指向两个数且和为目标即可。

## 常见错误

- 把 needed 保存成值却返回值，题目要求下标时会答错；先确认输出契约。
- 先把当前值放进 seen，再查 needed，可能在目标为两倍当前值时错误地使用同一个位置。
- 看到哈希表就写 O(1)，却没有说明总循环仍要执行 n 次。
- 忽略空列表、只有一个元素、重复值、负数和目标不存在的情况。

## 练习与答案解析

### 跟做练习：统计第一个重复字符

输入字符串，返回第一个第二次出现的字符；没有重复时返回 None。提示：只需要记录已经出现过的字符。

> [!example]- 参考答案
> ~~~python
> def first_duplicate(text: str) -> str | None:
>     seen: set[str] = set()
>     for char in text:
>         if char in seen:
>             return char
>         seen.add(char)
>     return None
> ~~~
> 每个字符最多加入和查找一次，平均时间 O(n)，额外空间 O(k)，其中 k 是不同字符数量。

### 独立练习

写 count_words(words)，返回每个单词出现次数。完成标准：空列表返回空字典；重复单词计数正确；能说出时间复杂度和空间复杂度。

### 迁移练习

把 two_sum 改成返回所有不重复的数值组合，而不是第一组下标。先说明“重复组合”的定义，再设计测试；不要直接复制网上的双指针模板。

## 本讲小结

先写清输入和输出，再比较最直接方案的复杂度。数组保留顺序，哈希表加快按键查找，集合用于去重。优化并不只是“更快”，而是明确用多少额外内存换取什么时间收益。

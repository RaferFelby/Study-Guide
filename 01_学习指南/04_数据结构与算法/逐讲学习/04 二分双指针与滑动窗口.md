## 这一讲要解决什么问题

很多低效解法的问题不是代码写错，而是重复检查了同一批候选。二分利用有序性砍掉一半范围；双指针让两个位置协同移动；滑动窗口维护一个连续区间，避免每次重新计算整个区间。

本讲前置是列表、索引、循环与字典。索引从 0 开始；`numbers[start:stop]` 取 start 到 stop 前一项，长度为 stop-start。先完成手算，再在本单元 `示例工程` 中创建下方完整脚本；源码从 [[01_学习指南/04_数据结构与算法/示例工程/README|代码导航]]进入。阅读顺序：二分 → 两个位置的职责 → 最短正整数窗口 → 日志时间边界 → 操作与练习。

## 二分查找：先写清不变量

二分只能在候选范围具有单调性时使用。最经典的条件是数组已经升序排列。下面使用左闭右闭区间 [left, right]：

~~~python
def binary_search(numbers: list[int], target: int) -> int:
    left, right = 0, len(numbers) - 1
    while left <= right:
        middle = left + (right - left) // 2
        if numbers[middle] == target:
            return middle
        if numbers[middle] < target:
            left = middle + 1
        else:
            right = middle - 1
    return -1
~~~

循环不变量是：如果目标存在，它仍在 [left, right] 内。等于目标时返回；中间值小于目标时，左半部分不可能包含目标；大于目标时，右半部分不可能包含目标。每轮排除约一半元素，时间 O(log n)，空间 O(1)。

例如 `[1,3,5,7,9]` 找 7：先检查索引 2 的 5，目标更大，于是 left 变成 3；再检查索引 3 的 7，返回 **索引 3**，不是返回数值 7。空列表初始 right=-1，循环不会进入，返回 -1。存在重复目标时，本函数返回其中一个匹配位置，不承诺第一个位置。

输入已排序是调用者保证的前置。本实现没有先排序，也没有用 O(n) 扫描验证有序性，所以不能把总复杂度写成“包含排序仍然 O(log n)”。无序输入可能偶然命中，但不再保证正确。

## 双指针：让两个位置配合

对已排序数组找两数之和时，一个指针在左端、一个指针在右端：总和太小就增加左指针，总和太大就减少右指针。这个移动规则依赖排序；未排序数组不能直接套用。

双指针也常用于反转数组、合并有序数组、判断回文和移除重复元素。写代码前说明每个指针代表什么，以及为什么移动后不会错过答案。

跟做题的“原地去重”使用另一种职责：fast 逐个读取，slow 指向下一个写入位置。空列表返回 0；非空时第一个值先保留，所以 slow=1。新值不同于 `numbers[slow-1]` 才写入，然后 slow 前进。结束时只承诺前 slow 项有效，原列表长度不变，后面的旧内容不能当作结果。完整参考实现见 [window_practice.py](../示例工程/app/window_practice.py) 的 `deduplicate_sorted()`。

## 滑动窗口：维护连续区间

例如求“没有重复字符的最长子串”：右指针不断加入字符；当窗口出现重复时，左指针向右移动，直到窗口重新满足条件。

~~~python
def longest_unique_substring(text: str) -> int:
    left = 0
    last_seen: dict[str, int] = {}
    best = 0
    for right, char in enumerate(text):
        if char in last_seen and last_seen[char] >= left:
            left = last_seen[char] + 1
        last_seen[char] = right
        best = max(best, right - left + 1)
    return best
~~~

关键是 last_seen[char] >= left。字符可能曾经出现在窗口外；如果它的旧位置小于 left，不能把左边界向后移动。每个字符位置最多使指针前进一次，时间 O(n)。

用 `abba` 检查这一条件：读到第二个 b，left 从 0 跳到 2；最后的 a 上次在索引 0，已不在当前窗口，所以 left 仍为 2。答案是 2，而不是把 left 退回 1 后错误地得到 3。字典的额外空间与出现过的不同字符数有关，不能说它总是 O(1)。

## 正整数最短窗口：为什么满足条件后反复收缩

题目要求连续子数组的**元素和**至少为 target，并让长度最短。本课只接受正整数元素和正整数 target；空数组或无解返回 0。

`left/right` 是当前窗口两端，`window_sum` 保存其中元素和，`best` 保存见过的最短有效长度。右端加入一个正整数只会增加和；移除左端正整数只会减少和。这种单调变化允许我们在达到目标后不断缩小左端，直到刚好不满足。

参考实现的核心顺序如下，完整输入校验在源码中：

```python
for right, value in enumerate(numbers):
    window_sum += value
    while window_sum >= target:
        best = min(best, right - left + 1)
        window_sum -= numbers[left]
        left += 1
```

这是函数内部片段，不能单独作为脚本运行；下面提供完整调用。`enumerate` 同时给出索引和值；先记录当前有效窗口，再删左端，因为删完后可能已经不达标。用 while 而不是 if，是为了同一次右端扩张后尝试多次缩短。

手算 `[2,3,1,2,4,3]`、target=7：

| right 与新值 | 加入后的和 | 本轮记录的有效长度 | 收缩后 left／和 | 当前最短 |
| --- | --- | --- | --- | --- |
| 0，2 | 2 | 无 | 0／2 | 尚无 |
| 1，3 | 5 | 无 | 0／5 | 尚无 |
| 2，1 | 6 | 无 | 0／6 | 尚无 |
| 3，2 | 8 | 4 | 1／6 | 4 |
| 4，4 | 10 | 4、3 | 3／6 | 3 |
| 5，3 | 9 | 3、2 | 5／3 | 2 |

两个指针在整个过程中各自最多向右走 n 次，因此循环合计 O(n)，不是看到嵌套 while 就断言 O(n²)。输入校验也是 O(n)，没有改变总的数量级；除输入外只保存几个数，额外空间 O(1)。

若允许负数，移除左端可能让和变大，不能沿用这个证明。例如 `[1,-1,5]`、target=5 的真正最短长度为 1；直接套上述规则可能在移除 1 后得到和 4 就停止，漏掉后面的 `[5]`。本函数拒绝负数，含负数问题需要另一种方法，不能仅删除校验就认为已支持。

## 日志窗口：先约定时间边界再写代码

给定按时间非降序排列的事件秒数，找事件最多的一个 60 秒窗口。本课把时间窗口明确规定为 **`(end-60, end]`**：右端包含，左端不包含。差值刚好 60 秒的两个事件不在这个窗口里。

时间戳使用同一时间基准下的非负整数秒。相同时间戳表示多条独立事件，各计一次；跨天仍使用连续增加的秒数，不把午夜后重置为 0。本课处理离线已排序日志，未实现乱序网络事件、水位线或去重。

源码 `busiest_window()` 每加入一个右端事件，就把与当前结束时刻差值 **大于或等于 60** 的左端事件移出去。记录窗口事件数；只有严格大于历史最好值才更新，所以并列时保留先遇到的最优窗口。

为什么只尝试以事件时间为右端的窗口？若一个窗口右端落在两条日志之间，把右端向左移动到窗口内最后一条事件，仍包含原先的全部事件，左边还可能多纳入更早事件。因此一定存在一个最大计数窗口，其右端恰好是某条事件的时间；不必逐秒枚举没有事件的时刻。

例如 `[0,59,60,60,119]`：以 60 为结束时刻时，0 被移走，59 和两条 60 留下，共三条；以 119 结束时，59 恰好相差 60，被移走，两条 60 与 119 也是三条。并列保留前一个结果。

函数返回事件列表中的 **`[start,stop)` 索引**，用于 Python 切片；这与上面的时间区间端点不是同一件事。本例返回 `(1,4)`，`timestamps[1:4]` 为 `[59,60,60]`，长度是 `4-1=3`。空日志返回 None，避免编造不存在的时间段。两个指针合计 O(n)，额外空间 O(1)。

## 操作与预期结果

在 VS Code 打开本单元 `示例工程`，新建 `lesson_04.py`。它与 app 目录平级；不要放进另一个单元的同名 app 中。

```python
from app.algorithms import binary_search, longest_unique_substring
from app.window_practice import (
    busiest_window,
    deduplicate_sorted,
    min_positive_subarray_length,
)


def main():
    print("二分索引", binary_search([1, 3, 5, 7, 9], 7))
    print("最长无重复", longest_unique_substring("abba"))
    numbers = [1, 1, 2, 2, 3]
    valid_length = deduplicate_sorted(numbers)
    print("去重前缀", numbers[:valid_length])
    print("最短长度", min_positive_subarray_length([2, 3, 1, 2, 4, 3], 7))
    timestamps = [0, 59, 60, 60, 119]
    interval = busiest_window(timestamps)
    if interval is not None:
        start, stop = interval
        print("日志窗口", interval, timestamps[start:stop], "数量", stop - start)


if __name__ == "__main__":
    main()
```

## 常见错误

- 二分区间一会儿用 [left, right]，一会儿用 [left, right)，导致漏查或死循环。
- 计算 middle 后没有排除 middle，范围不变，循环无法结束。
- 滑动窗口遇到重复字符时直接 left += 1，没有跳到重复字符之后，效率和正确性都可能受影响。
- 只凭“看起来像”就用双指针，忽略题目是否提供排序或单调性。

## 练习与答案解析

### 跟做练习：移除有序数组重复值

用 slow 表示下一个应该写入的位置，用 fast 扫描数组。完成后返回有效长度。原地修改时要在题目允许的范围内写。

> [!example]- 参考思路
> 运行上面的完整脚本，再将 numbers 改为 `[2,2,2]` 和 `[]`，有效长度分别为 1 和 0，对应前缀 `[2]` 与 `[]`。每次遇到新值才写入 slow，并推进 slow；源码先校验有序和整数，再开始写入，避免发现非法输入时已经改了一半。算法不缩短原列表，后缀内容未作承诺。能解释 slow 是“下一个写入位置”并只使用有效前缀，才算完成。

### 独立练习

实现“元素和至少为 target 的连续子数组的最小长度”。本练习令数组元素与 target 都为正整数，无解或空数组返回 0。例如 `[2,3,1,2,4,3]`、target=7 的答案为 2，对应 `[4,3]`。如果允许负数，普通滑动窗口规则不再直接成立。

先合上源码，在 `lesson_min_window.py` 写自己的函数与 main 调用；用上方共享解释器命令改成这个文件名运行。提示：best 初始设为 n+1，表示还没有答案；结束时将这个占位值转换为 0。至少自己运行 `[]`、`[1,2]`、`[9]`，target 都为 7。

> [!example]- 参考答案与完成标准
> 完整参考函数为 [min_positive_subarray_length](../示例工程/app/window_practice.py)。空输入结果 0；[1,2] 总和不到 7，结果 0；[9] 单项已经达标，结果 1。每轮先扩张右端，达到目标后先记录长度，再反复收缩左端。对标准示例手算最后一轮先检查长度 3，再检查长度 2；写成 if 只收缩一次就可能漏掉最短答案。源码测试还用小规模穷举逐个子数组核对，不把几个成功例子当成完整证明。

### 迁移练习

把滑动窗口用于 Agent 日志：给定按时间排序的事件，找出 60 秒内事件数量最多的时间段。说明时间戳相等、空日志和跨天数据的处理规则。

将完整脚本中的 timestamps 分别改成 `[0,60]`、`[]`、`[86390,86410,86420]`。空输入分支可增加 `else: print("空日志")`。最后尝试乱序 `[10,5]`，预测报错而不是静默排序。

> [!example]- 参考答案与完成标准
> [0,60] 最多 1 条，并列返回第一条的索引区间 (0,1)；空输入返回 None，应打印空日志，不解包；跨天例子跨度 30 秒，返回 (0,3)，共 3 条。相同时间戳不合并，乱序输入抛出 ValueError。完整实现见 busiest_window。若业务定义为闭区间 [end-60,end]，恰好 60 秒的边界会不同，必须连比较条件、预期输出和测试一起调整，不能只改文档中的名字。

## 本讲小结

二分需要有序或单调性，双指针需要能证明指针移动不会漏掉答案，滑动窗口需要一个随着边界移动仍可维护的条件。模板只是外形，真正要解释的是区间定义和移动理由。

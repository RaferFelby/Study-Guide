## 先把一轮损失算对

### 为什么不能直接平均两个批次

假设三个样本的损失分别为 `1、3、9`。批次大小为 2 时，第一个批次平均损失是 `(1 + 3) / 2 = 2`，末批只有一个样本，平均损失是 `9`。

- 直接平均批次：`(2 + 9) / 2 = 5.5`。末批的一个样本占了总权重的一半。
- 按样本数汇总：`(2 × 2 + 9 × 1) / (2 + 1) = 13 / 3 ≈ 4.333333`，与逐样本平均相同。

关键是先恢复每批的损失总和，再除以总计数。在 VS Code 新建 `lesson_04_average.py`，保存完整代码：

~~~python
from app.diagnostics import weighted_mean_loss


def main():
    batch_records = [(2.0, 2), (9.0, 1)]
    batch_average = (2.0 + 9.0) / 2
    observation_average = weighted_mean_loss(batch_records)
    print(f"直接平均批次：{batch_average:.6f}")
    print(f"按实际计数：{observation_average:.6f}")


if __name__ == "__main__":
    main()
~~~

..\..\..\.venv\Scripts\python.exe lesson_04_average.py
~~~

共享解释器前面的三个 `..` 从示例工程逐层返回工作区根目录。输出应为 `5.500000` 和 `4.333333`。`batch_records` 的每个二元组是“这一批的平均损失、这个平均实际除过的计数”。`:.6f` 表示以六位小数显示。

打开 [diagnostics.py](../示例工程/app/diagnostics.py) 中的 `weighted_mean_loss`：循环中 `mean_loss * count` 恢复总和，`total_count` 累加计数，循环结束才相除。空记录或非正整数计数会抛出 `ValueError`，因为没有可定义的总体平均值；不能把“没有数据”报告成损失 0。

### 分母不总是样本数

本工程使用 MSE（均方误差）：每个预测值减去对应目标值，再平方并平均。`nn.MSELoss()` 默认对**所有输出元素**平均。对于 `[B, 1]`，计数是 `B`；对于 `[B, 2]`，计数是 `2B`。例如预测值为 `[1, 2]`、目标为 `[0, 0]`，MSE 是 `(1 + 4) / 2 = 2.5`，不是 5。

因此工程训练端用 `loss × targets.numel()` 恢复每批平方误差和；验证端用 `reduction="sum"` 直接得到该和，最后都除以目标元素总数。`numel()` 返回张量中元素的数量。每个样本输出数量固定且一致时，按样本数加权批次均值也等价，但不能把验证端的平方误差总和仅除以样本数，混成另一种指标。

进阶时再考虑变长文本：若每批损失是“有效 token 的平均”，计数必须是实际参与损失的 token 数，不能把补齐位置算进去。如果先对每个序列取平均、再平均序列，得到的是另一种定义。使用类别权重或忽略标签时，还要依据该损失函数的实际分母，不能机械套 `batch_size`。

## 跑完一轮并重新测量

### 最小例子：只有一个需要学习的权重

本次模型为 `预测 = 输入 × 权重`，没有偏置。三个训练输入都是 1，目标依次为 2、2、4。这样可以手算参数变化。先不加入裁剪、调度器或混合精度，避免同时追踪多个状态。

在同一目录创建 `lesson_04_loop.py`：

~~~python
import torch
from torch import nn
from torch.utils.data import DataLoader, TensorDataset

from app.diagnostics import weighted_mean_loss
from app.training import evaluate


def main():
    features = torch.ones(3, 1)
    targets = torch.tensor([[2.0], [2.0], [4.0]])
    loader = DataLoader(TensorDataset(features, targets), batch_size=2, shuffle=False)
    model = nn.Linear(1, 1, bias=False)
    with torch.no_grad():
        model.weight.fill_(0.0)
    optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
    loss_function = nn.MSELoss()
    batch_records = []

    model.train()
    for batch_index, (batch_features, batch_targets) in enumerate(loader):
        optimizer.zero_grad(set_to_none=True)
        predictions = model(batch_features)
        loss = loss_function(predictions, batch_targets)
        batch_records.append((loss.item(), batch_targets.numel()))
        loss.backward()
        optimizer.step()
        print(f"批次 {batch_index}：更新前损失 {loss.item():.4f}，更新后权重 {model.weight.item():.4f}")

    print(f"一轮内记录的训练损失：{weighted_mean_loss(batch_records):.6f}")
    train_at_end = evaluate(model, loader, torch.device("cpu"))
    print(f"轮末重新测量训练集：{train_at_end['loss']:.6f}")
    valid_loader = DataLoader(
        TensorDataset(torch.ones(2, 1), torch.tensor([[3.0], [3.0]])), batch_size=2
    )
    valid_at_end = evaluate(model, valid_loader, torch.device("cpu"))
    print(f"轮末测量验证集：{valid_at_end['loss']:.6f}")


if __name__ == "__main__":
    main()
~~~

轮末重新测量训练集：3.281067
轮末测量验证集：3.534400
~~~

### 顺着执行顺序理解

1. `TensorDataset` 把输入和目标配对；`shuffle=False` 保持手算顺序，批次大小分别是 2 和 1。这是课堂选择，不是要求所有训练都不打乱。
2. `Linear(1, 1, bias=False)` 只有一个权重。初始化时用 `no_grad()`，因为把初值设为 0 不需要形成求导过程。
3. `zero_grad(set_to_none=True)` 清除上一次梯度，让本次反向传播从干净状态开始。这里每个批次更新一次；有意跨批累积梯度属于后续进阶内容。
4. `model(batch_features)` 做前向计算；`loss_function` 比较预测与目标。`loss.item()` 提取一个 Python 数，供记录使用；反向传播仍调用原来的张量 `loss.backward()`。
5. `backward()` 计算梯度，`optimizer.step()` 才使用梯度修改参数。第一批梯度为 `2 × (0 - 2) = -4`，所以权重变成 `0 - 0.1 × (-4) = 0.4`。
6. 第二批目标是 4，损失为 `(0.4 - 4)² = 12.96`，梯度为 `-7.2`，权重变成 `1.12`。之前算出的 `loss` 仍记录更新前结果，不会因参数更新自动重算。
7. `evaluate` 在轮末固定参数、切换验证模式并关闭梯度记录。它返回字典，`['loss']` 取出损失值。可以在 [training.py](../示例工程/app/training.py) 查看实现；`@torch.no_grad()` 表示函数执行期间不记录梯度。

### 为什么两次训练集损失不相等

一轮内汇总的是两个时刻的测量：第一批使用权重 0，第二批使用权重 0.4。因此为 `(4 × 2 + 12.96 × 1) / 3 ≈ 6.986667`。

轮末重测使用同一个权重 1.12：前两个样本平方误差都是 `0.88²`，最后一个为 `2.88²`，平均约为 `3.281067`。数据相同，测量时的参数不同，结果仍会不同。

完整工程日志中的 `train_loss` 是前一种边训练边测量的汇总，`valid_loss` 是轮末固定模型的测量；两条曲线还涉及数据不同、Dropout 等模式不同。不能仅凭某一轮 `valid_loss < train_loss` 判断代码错误。本例两个验证目标只是帮助计算，不足以证明模型能泛化到真实任务。

## 训练和验证各自改变什么

| 操作 | 做什么 | 不会自动做什么 |
|---|---|---|
| `model.train()` | 设置训练模式，影响 Dropout、BatchNorm 等模块 | 不会自动反向传播或更新参数 |
| `model.eval()` | 设置评估模式，例如关闭 Dropout 的随机丢弃 | 不会关闭梯度记录 |
| `torch.no_grad()` | 关闭作用范围内的梯度记录，减少不必要开销 | 不会设置模型为评估模式 |
| `optimizer.step()` | 根据梯度和优化器状态更新参数 | 不会替你计算或清空梯度 |

Dropout 在训练时随机屏蔽部分激活，评估时停用该随机操作。BatchNorm 涉及批次统计量和运行统计量，默认配置下两种模式的使用方式不同；具体机制可稍后学习。这里先掌握：验证同时需要 `eval()` 和关闭梯度记录。

`no_grad()` 也不会删除已经存在的 `.grad`。验证不新增梯度，不意味着训练留下的梯度张量必定消失。下一轮必须再次调用 `model.train()`；工程的 `train_one_epoch` 已负责这一步。

## 梯度裁剪到底限制什么

梯度范数可以理解为把所有参数梯度排成一个长向量后计算的长度。梯度为 `[3, 4]` 时，二范数是 `sqrt(3² + 4²) = 5`。`clip_grad_norm_` 按总范数缩放梯度，上限设为 1 时，得到约 `[0.6, 0.8]`；末位会受实现中防止除零的小量影响。

**裁剪直接约束梯度范数，不能一般性地保证参数更新量不超过某个值。** 对不带动量和权重衰减的普通 SGD，更新为 `-学习率 × 梯度`，所以更新范数受学习率与裁剪上限的乘积约束。AdamW 还涉及历史状态、自适应缩放和独立权重衰减，不能直接套这个结论。

工程在反向传播后、更新前计算裁剪前范数，再裁剪。启用梯度缩放时先还原梯度尺度再检查和裁剪。必须先确保梯度有限；裁剪不是修复 NaN 的办法。裁剪阈值越小也不保证效果越好。

## 读完整工程的日志

### 运行并找到输出

在示例工程目录终端运行。选用自己尚未使用的输出目录，避免覆盖之前的实验：

~~~powershell
..\..\..\.venv\Scripts\python.exe train.py --epochs 30 --output-dir results/lesson04-baseline
~~~

`--epochs 30` 表示最多 30 轮，`--output-dir` 指定相对当前目录的保存位置。程序自动选择可用 CUDA，否则使用 CPU。程序可能没有逐轮进度输出，结束后在 VS Code 展开输出目录，打开 `history.json`。正常会有 `history.json`、`best.pt`、`last.pt`；触发早停时可能少于 30 轮。

### 每个字段的定义

JSON 文件是一个数组，每个元素是一轮的记录。

| 字段 | 本工程的含义 |
|---|---|
| `epoch` | 从 0 开始计数，0 表示第一轮 |
| `train_loss` | 这一轮各批次更新前 MSE，按输出元素数汇总 |
| `valid_loss` | 轮末固定模型在验证集的 MSE |
| `learning_rate` | 本轮训练实际使用的学习率，在轮末调度器更新前记录 |
| `gradient_norm` | 每个批次裁剪前总梯度范数的算术平均，不是最大值 |
| `samples_per_second` | 训练循环内样本数除以耗时，含数据读取和检查，不含轮末验证和保存 |
| `device` | `cpu` 或 `cuda` |
| `cuda_memory_peak_bytes` | 本轮 CUDA 已分配显存峰值，单位为字节；CPU 为 `null` |

吞吐量只是本工程的粗略观测；不能当成经过严格预热、同步与重复测量的 GPU 算子基准。显存字段也不是整个系统或显卡的全部占用。CPU 的 `null` 表示“不适用”，不能改成 0 来暗示测得零占用。

`last.pt` 保存最近完成一轮后的训练状态；`best.pt` 按本工程早停器的显著改善规则更新：验证损失必须严格小于此前接受的最好值减去 `min_delta=1e-5`。微小下降不一定刷新文件，因此它不保证对应日志中数值最低的那一轮。下一讲会拆开解释保存、恢复与早停。

### 做一个有对照的改动

保持其余参数不变，缩小裁剪上限：

~~~powershell
..\..\..\.venv\Scripts\python.exe train.py --epochs 30 --clip-norm 0.1 --output-dir results/lesson04-small-clip
~~~

先核对设备、种子和数据划分一致，再比较两份日志的趋势。裁剪后梯度受上限约束，但日志记的是**裁剪前**范数，出现大于 0.1 的值正常。按轮平均的范数无法告诉你每个批次是否都触发了裁剪；若需要裁剪频率，应逐批记录或统计触发次数。

## 常见错误与排查

| 现象 | 先检查 | 处理 |
|---|---|---|
| 找不到共享解释器或 `torch` | 当前目录与 VS Code 解释器选择 | 返回根 README 环境说明，不另建本单元环境 |
| 末批较小时 epoch loss 对不上 | 是否直接平均批次均值 | 恢复每批总和，再除以对应计数总和 |
| 多输出的验证损失成倍变大 | 训练、验证是否使用同一个分母 | 对齐每元素 MSE 定义，核对预测和标签形状 |
| 验证仍有随机丢弃或记录梯度 | `eval()`、`no_grad()` 是否都使用 | 两者职责分开检查 |
| 裁剪上限 0.1，日志却大于 0.1 | 记录在裁剪前还是之后 | 本工程记录裁剪前，不要为了数字好看改日志含义 |

## 练习与答案解析

### 跟做练习：解释曲线与测量时机

任务一：用纸笔复算最小实验中的 `6.986667` 和 `3.281067`。任务二：某实验训练损失从 1.0 降到 0.05，验证损失从 1.1 先降到 0.4 再升到 0.9，你能确认什么，还要检查什么？

提示：先区分“在同一参数状态测量”与“训练过程中累积”，再判断跨轮趋势。完成标准：说明两次训练集测量的参数状态不同；不把单次曲线当成唯一诊断证据。

> [!example]- 参考答案
> 两个数的计算已在最小实验中逐步展开。验证先降后升、训练继续下降是过拟合迹象，但还要核对划分、指标定义、模式切换、验证规模与波动。可以保留验证表现较好时的状态，再通过固定划分的对照实验检查；不能只依据最后一个训练 loss 宣称模型更好，也不能依据这个验证集反复调参后当作独立测试成绩。

### 独立练习：写出自己的加权汇总

不调用现成函数，自己实现 `weighted_mean_loss(batch_records)`。输入 `[(2.0, 2), (9.0, 1)]` 应得 `13/3`；合并为 `[(13/3, 3)]` 应得到相同结果。空记录、计数 0、非有限损失应明确报错。

提示：准备总和与总计数两个变量，循环后只做一次除法。完成标准：两个有效输入一致，三个错误输入都被拒绝，能解释计数代表什么。

> [!example]- 参考答案与源码阅读顺序
> 完整实现见 [diagnostics.py](../示例工程/app/diagnostics.py) 的 `weighted_mean_loss`，行为例子见 [test_metrics.py](../示例工程/tests/test_metrics.py)。先检查每个 `mean_loss` 是否有限，再检查 `count` 为正整数，累加乘积与计数；最后拒绝空记录和溢出的总和。若去掉计数加权，例子得到 5.5，暴露末批权重错误。该辅助函数服务本课明确分母的均值，不自动推断任意损失函数的语义。

### 迁移练习：类别不均衡时查看召回率

真实标签为 `[0, 0, 0, 0, 1]`，模型全预测为 0。计算准确率，以及每个类别的召回率（该类实际样本中被正确识别的比例）。如果某类没有真实样本，应该如何报告？

提示：每一类都单独计数。完成标准：得到准确率 0.8、类别 0 召回率 1、类别 1 召回率 0；说明分母为 0 时不能凭空填 1。

> [!example]- 可运行答案
> 在示例工程创建 `lesson_04_recall.py`，保存下列代码，使用共享解释器运行。这里的类别编号来自已知任务定义。
>
> ~~~python
> def main():
>     actual_labels = [0, 0, 0, 0, 1]
>     predicted_labels = [0, 0, 0, 0, 0]
>     correct_count = 0
>     for actual, predicted in zip(actual_labels, predicted_labels):
>         if actual == predicted:
>             correct_count += 1
>     print("准确率：", correct_count / len(actual_labels))
>     for label in [0, 1, 2]:
>         actual_count = 0
>         correct_for_label = 0
>         for actual, predicted in zip(actual_labels, predicted_labels):
>             if actual == label:
>                 actual_count += 1
>                 if predicted == label:
>                     correct_for_label += 1
>         recall = None
>         if actual_count > 0:
>             recall = correct_for_label / actual_count
>         print(label, "召回率：", recall, "实际数量：", actual_count)
>
>
> if __name__ == "__main__":
>     main()
> ~~~
>
> `zip` 把位置对应的真实与预测标签配对。本例长度已知相同，真实工程还需检查长度，避免 `zip` 截断较长一侧。输出类别 2 的召回率为 `None`、数量为 0，表示本次样本无法估计该类召回率。0.8 的准确率掩盖了类别 1 全部漏检；要同时看类别数量与逐类表现。

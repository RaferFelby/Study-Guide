## 先观察数据而不修改数据

### 三类数字与空张量

**NaN** 是“不是一个数”的标记，常见于无定义的数值运算；**Inf** 是正或负无穷，可能来自除零或溢出。**有限数**指既不是 NaN、也不是正负无穷的数。`torch.isfinite` 为每个位置返回布尔判断。

观察器应报告异常，不能悄悄删除坏样本后继续训练。空张量没有最小值或最大值；全是非有限数时也没有有限极值，此时用 `None` 表示“没有可报告的值”，不填 0。

在示例工程目录创建 `lesson_06_inspect.py`：

~~~python
import torch

from app.diagnostics import describe_tensor


def main():
    batches = {
        "正常": torch.tensor([[1.0, -2.0], [0.0, 3.0]]),
        "异常": torch.tensor([[float("nan"), float("inf"), -1.0]]),
        "空": torch.empty(0, 2),
        "全异常": torch.tensor([float("nan"), float("-inf")]),
    }
    for name, values in batches.items():
        print(name, describe_tensor(values))


if __name__ == "__main__":
    main()
~~~

~~~powershell
..\..\..\.venv\Scripts\python.exe lesson_06_inspect.py
~~~

命令使用根目录共享环境；脚本不启动训练，也不写结果。各字段应符合下表：

| 名称 | shape | dtype | NaN 数量 | Inf 数量 | 有限最小值 | 有限最大值 |
|---|---|---|---|---|---|---|
| 正常 | `[2, 2]` | `torch.float32` | 0 | 0 | -2.0 | 3.0 |
| 异常 | `[1, 3]` | `torch.float32` | 1 | 1 | -1.0 | -1.0 |
| 空 | `[0, 2]` | `torch.float32` | 0 | 0 | `None` | `None` |
| 全异常 | `[2]` | `torch.float32` | 1 | 1 | `None` | `None` |

### 顺着实现读一遍

打开 [diagnostics.py](../示例工程/app/diagnostics.py) 的 `describe_tensor`：

1. 本例只面向稠密实数张量，复数会明确拒绝；不把它当作所有张量布局的通用检查器。
2. `detach()` 得到不参与梯度记录的观察视图；它并不意味着复制了独立数据。因此后面只读，不做原地修改。
3. `observed[torch.isfinite(observed)]` 选出有限元素，只用于计算报告中的极值。原始训练张量不变，也不会把这些筛选值送回模型。
4. `numel() > 0` 才求最小、最大值，避免对空集合做无定义操作；`.item()` 将单个张量数值取成 Python 数。
5. `torch.isnan` 和 `torch.isinf` 产生真假标记，求和就是对应计数；后者同时统计正负无穷。`shape` 和 `dtype` 帮助检查维度与数值类型。

返回字典用于观察，不保证张量满足训练契约。例如分类标签常需整数类型，而本工程是浮点回归；输入形状也要与模型相符。本工程的 [training.py](../示例工程/app/training.py) 另用 `check_batch` 拒绝空数据、形状错误与非有限输入，前向后还检查预测与目标形状相同，防止广播悄悄改变损失含义。

## 从第一个异常位置向前追

NaN 是结果，不能仅凭它断定学习率太大。先找哪一步从正常变成异常：

| 检查位置 | 要回答的问题 | 发现问题后先做什么 |
|---|---|---|
| 输入与标签 | 是否非空、有限，形状与类型是否符合任务 | 检查数据读取、缺失值处理、归一化的分母 |
| 前向输出 | 输入正常时，哪一层开始输出非有限数 | 用同一批数据缩小到最小运算，检查数值范围 |
| 损失 | 预测、标签是否匹配，运算定义域是否满足 | 检查除零、对数输入、错误广播、损失接口 |
| 反向梯度 | 损失有限，但求导是否产生非有限数 | 检查求导路径、损失尺度、溢出及梯度缩放 |
| 参数更新 | 梯度正常时，更新量是否异常 | 核对学习率、优化器状态与参数尺度 |

“定义域”就是一个运算允许的输入范围。以实数对数为例，要得到有限的 `log(p)`，输入 `p` 必须严格大于 0。概率还应不超过 1，所以概率的对数通常小于或等于 0；**不能要求对数概率大于 0**。`log(0)` 会得到负无穷，对负数取实数对数会得到 NaN。分类任务优先使用适合任务的稳定损失接口，不应为绕过报错随意把概率加一个常数。

记录应包含轮次、批次编号、形状、数据处理步骤和配置。注意训练中的 `batch 0` 是当前加载器的第一个批次，打乱后不等于原始数据的第 0 行；若需追溯具体样本，数据集应额外保留样本标识。本工程当前只报告训练批次编号，未实现通用逐层自动定位。

## 动手制造并修复一次已知故障

### 第一步：建立正常对照

在示例工程终端运行。每次选一个尚未使用的结果目录，避免旧文件混入证据：

~~~powershell
..\..\..\.venv\Scripts\python.exe train.py --epochs 3 --output-dir results/lesson06-baseline
~~~

`--epochs 3` 将最大训练轮数设为 3；`--output-dir` 是相对当前目录的保存位置。正常结束后打开 `history.json`，确认损失为有限数且存在 `best.pt`、`last.pt`。程序自动选择可用 CUDA，否则使用 CPU；本命令没有开启 AMP（自动混合精度）。

### 第二步：只加入一个已知故障

~~~powershell
..\..\..\.venv\Scripts\python.exe train.py --epochs 3 --inject-nan --output-dir results/lesson06-nan
~~~

`--inject-nan` 在训练时复制首批输入，再把其中一个值改为 NaN；不会改写原始数据文件。预期程序以非零退出码停止，错误末尾包含：

~~~text
ValueError: invalid training batch 0: batch contains NaN or infinite values
~~~

这里在第一批前向和参数更新之前拒绝输入。对于新的输出目录，本次运行不应生成训练日志和检查点。若目录里已有旧文件，它们不会自动消失，所以必须使用独立目录，不能以“目录中有文件”认定失败运行保存了成果。PowerShell 中运行命令后可输入 `$LASTEXITCODE` 查看上一条本机程序的退出码，正常通常为 0，预期故障应非 0。

定位顺序：终端最后一行说明批次含非有限数 → 查看 `train_one_epoch` 的注入和 `check_batch` 调用 → 确认检查发生在前向之前。异常向上报告保留调用位置；不是捕获错误后继续使用这个批次。

### 第三步：移除原因并复验

~~~powershell
..\..\..\.venv\Scripts\python.exe train.py --epochs 3 --output-dir results/lesson06-repaired
~~~

本次去掉 `--inject-nan`，其余训练配置与正常对照相同。检查新目录中的三份结果文件和有限损失。对这个人工注入故障，移除注入就是修复；如果真实数据已含 NaN，必须修复数据来源或定义明确的缺失值处理流程，不能照搬“去掉开关”。

预期故障被拦截，只能证明这条检查路径有效；修复后正常完成，才能说明正常路径也可继续。两者都不能证明模型在真实任务上有效。

## 怎样判断过拟合和梯度异常

### 过拟合：先核对测量，再解释曲线

过拟合指模型对训练数据拟合得更好，却不能同样改善未参与参数更新的数据表现。训练损失持续下降、验证损失上升是迹象；还需排除小验证集的波动、分布差异、错误模式和指标定义变化。不要仅凭单个 epoch 下结论。

保持验证集不变，把训练数据缩到 12 条：

~~~powershell
..\..\..\.venv\Scripts\python.exe train.py --epochs 30 --overfit-small --output-dir results/lesson06-small
~~~

与同样最多 30 轮、不带此开关的基线比较。由于训练数据少，每轮的批次数也会改变；这不是只改变数据量、其他优化条件完全等效的实验。该配置提供观察小样本拟合的机会，**不保证一定出现明显过拟合曲线**。若没有出现，就如实记录，不编造预期图形。

可以一次改变一个主要因素，例如模型容量、权重衰减或数据量。早停选择较早状态，不能修复验证集泄漏；最终效果仍需要独立评估。

### 梯度异常：范数大不自动等于错误

梯度爆炸是梯度随计算或训练过程异常放大的现象；一次范数大也可能只是数据或损失尺度不同。先看裁剪前范数，再看损失和参数变化。对一组参数可比较“更新向量长度 ÷ 更新前参数向量长度”；分母为 0 时比例没有定义，应同时报告绝对更新量，不能硬填一个正常比例。

在独立目录试较大学习率：

~~~powershell
..\..\..\.venv\Scripts\python.exe train.py --epochs 5 --learning-rate 2.0 --output-dir results/lesson06-large-lr
~~~

学习率会影响参数更新幅度，但大值不保证触发 NaN，也可能只表现为更大的有限损失。查看实际日志或实际错误，不把“程序运行完”当成优化良好。工程的轮均梯度范数还会掩盖个别批次的峰值，必要时需增加逐批观测。

梯度裁剪直接限制梯度总范数；AdamW 含有历史状态与自适应缩放，不能把裁剪上限当成参数更新量上限，详见 [[01_学习指南/06_PyTorch训练闭环/逐讲学习/05 训练验证与指标记录#梯度裁剪到底限制什么|第 5 讲的边界解释]]。梯度已经 NaN 时，裁剪不能把它变回可靠梯度。

梯度长期很小可能来自饱和激活、深层链式相乘等，也可能是接近某个平稳点。应同时检查参数是否更新、优化器是否包含这些参数、梯度是否为 `None`，不能直接判断“梯度消失”。

## 常见错误与修复顺序

| 错误做法 | 为什么不充分 | 下一步 |
|---|---|---|
| 一看到 NaN 就降低学习率 | 数据可能在进入模型前已坏 | 先运行观察器检查同一批输入和标签 |
| 把 NaN 全换成 0 当作通用修复 | 可能改变标签或数据语义 | 明确缺失值含义，检查上游处理并保留证据 |
| 故障实验复用正常输出目录 | 旧文件会混淆是否保存成功 | 每次使用独立的新目录 |
| 只记录每轮平均范数就断言无峰值 | 平均值可能掩盖单批异常 | 按定位需要增加逐批记录 |
| 以训练集最优评价泛化 | 训练集已参与更新 | 核对独立验证流程和划分方式 |

## 练习与答案解析

### 跟做练习：建立排错表

为“输入含 NaN”“训练下降而验证上升”“梯度突然变大”各写三个检查项，并标注它属于数据、模型、损失或优化层。提示：沿数据流从前向后查。完成标准：至少有一个可实际检查的数值或位置，不只写“调参”。

> [!example]- 参考答案
> 输入 NaN：数据层检查读入值与缺失值；预处理层检查标准化分母是否为 0；损失层检查对数输入和除数是否合法。验证变差：数据层核对划分与泄漏；模型层核对 `eval()`；指标层核对分母、样本数量与多轮趋势。梯度变大：数据层看数值范围；损失层看损失是否从 mean 改成 sum；优化层看学习率、裁剪前逐批范数和参数更新量。定位后每次改变一个主要因素并复验。

### 独立练习：实现自己的观察器

暂时不看实现，写一个函数返回 shape、dtype、NaN 数量、Inf 数量、有限最小值和有限最大值。分别试正常、含 NaN、空张量、全非有限值四种输入。提示：先筛选有限元素，仅在非空时求极值。

完成标准：结果与本讲表格一致；正负无穷都被计数；输入内容不变；无有限元素时返回 `None`；不会把观察后的筛选结果替换原始训练数据。

> [!example]- 参考答案与边界解析
> 对照 [diagnostics.py](../示例工程/app/diagnostics.py) 的 `describe_tensor` 和 [test_metrics.py](../示例工程/tests/test_metrics.py) 的观察器用例。实现先分离梯度记录，然后构造有限值掩码，再分别求计数和极值。NaN 参与普通 min/max 可能传播 NaN，所以字段明确叫 `finite_min`、`finite_max`。它只帮助定位，不自动判定业务合理范围；例如有限但明显错误的年龄或标签，还需要任务规则检查。

### 迁移练习：写一次有证据的故障记录

把本讲 NaN 注入实验写成记录，包含影响、发现时间、运行环境、最小复现、根因、修复、回归结果和剩余限制。提示：复制实际命令与错误，时间填你实际运行的时间。完成标准：其他人能按命令复现，同一原因被修复后有正常对照；不得把下面模板当成自己已执行的证据。

> [!example]- 参考记录结构
> - 发现时间：填写实际时间；环境：填写共享解释器的 Python、PyTorch 版本与日志中的设备。
> - 影响：故障实验在第一批停止，未完成任何 epoch；使用的新目录没有本次检查点。
> - 最小复现：复制 `--epochs 3 --inject-nan` 的实际命令和实际输出目录。
> - 证据：错误包含 `invalid training batch 0`；源代码中复制首批后写入 NaN，随后 `check_batch` 拒绝。
> - 根因：本例的人工注入破坏了输入有限性，不是已经证明学习率过大。
> - 修复：移除注入开关，保持其他训练配置一致，在新的目录重新运行。
> - 回归：记录实际退出码、完成轮数、损失是否有限及三个结果文件是否存在。没有运行的项目写“未执行”。
> - 剩余限制：只检查此合成数据路径；不代表排除了真实数据缺失、所有层内数值问题或跨设备差异。

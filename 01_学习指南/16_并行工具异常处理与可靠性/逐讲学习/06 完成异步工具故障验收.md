## 要解决什么问题

“并行更快”不足以验收：超时会不会无限重试？失败会不会丢成功结果？取消后后台仍执行吗？本讲用可预测的合成故障检验机制，再把错误接到Agent决策。

开始前闭卷说出：并发与速率不同；max_attempts包含首次；写超时可能结果未知；gather不自动提供业务部分成功；长预览不能当JSON完整结果。如果不清楚先返回最小实验。

## 运行检查与读取结果

在示例工程VS Code终端：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py
..\..\..\.venv\Scripts\python.exe -m pytest -q tests
..\..\..\.venv\Scripts\python.exe -m ruff check .
..\..\..\.venv\Scripts\python.exe -m ruff format --check .
```

demo三次只读合成工具，串行/并发相同输入和工具延迟，成功3/3；并发2时通常较快。作者一次约144ms/95ms，仅说明这台机器这轮等待重叠，不是生产吞吐基准。测试用峰值活跃计数验证并发，不用脆弱“必须快2倍”的断言。

冲突示例facts为空、conflicts保留两份retention、failures保留unknown_tool、is_complete=False；长返回预览100字符、原JSON912字符、正文回查900字符。

## 故障矩阵

| 场景 | 应看到什么 | 不该发生什么 |
|---|---|---|
| 读超时 | 限次timeout、清理子协程 | 无限尝试 |
| 非幂等写超时 | outcome_unknown、一次尝试 | 盲目重复写 |
| 限流一次后恢复 | 遵守等待后成功 | 立刻猛发 |
| Retry-After超预算 | 停自动重试 | 提前重试 |
| 相同安全请求 | 同批执行一次、各ID回填 | 错配/数据共享污染 |
| 部分失败 | 成功保留、失败结构化 | 假称全成功 |
| 值冲突 | 保留来源、禁止静默覆盖 | 随便取最后值 |
| 父取消 | 子任务finally、取消再抛 | 自动重试取消 |
| 长输出 | 明确截断与ref | 半JSON当完整结果 |
| 批次超限 | 执行前拒绝 | 无界排队 |

测试使用pytest普通函数内部asyncio.run，不额外依赖pytest-asyncio。熔断冷却用假时钟，长等待用及时取消，不需要真实等10/30秒。

## Agent收到错误怎样重规划

先按错误码分支，不把所有错误叫“未知错误”：

```text
invalid_arguments_or_result → 修参数/输出适配，不原样重试
unknown_tool → 查注册工具或明确当前不能做
rate_limited/circuit_open → 尊重等待/降级，保留已有结果
timeout（安全读）→ 当前控制器已限次，之后另评任务预算
outcome_unknown（写）→ 回查状态或人工核实，不再次写
needs_full_result → 取得有权限的完整结果再判断
```

重规划是根据公开结果选择下一合法动作。`replanning.py`提供这些规则分支，demo打印下一步；它不调用真实LLM、不自动执行新动作。你可以在单元14的policy中接入，执行仍由控制器约束权限/预算。来源冲突还需先核实，不能直接使用冲突字段。

## 报告怎么写

记录Python/平台、工具延迟、并发、速率间隔、批上限、每次超时、尝试数、退避预算、熔断参数和输出预算。性能报告至少多次运行，比较中位数与尾部，并记录成功率；不能拿一轮144/95ms说普遍提高多少。

失败报告每条写call_id、错误码、attempts、已完成的部分、是否可能有副作用、下一动作。没有实现半开探针/全任务时限/外部取消/持久存储，就写未实现；不要把教程概念当工程现成功能。

## 持续项目接入

企业知识与工单助理可把政策检索与工单只读查询放同批；需要订单ID的查询放下一阶段。所有请求仍先通过单元15契约/授权；Scheduler不是代替Schema和权限的执行沙箱。

返回结果保留ID、错误、来源和摘要标志。将它转回role=tool时仍按原call_id关联；实时数据失败时答复要说明缺失，不能让模型拿一般政策补成当前订单事实。

## 练习与解析

**跟做：** 跑demo和测试，从timeout/写未知/取消各挑测试解释输入与断言。

**独立：** 增加一个两次I/O故障后成功的安全读工具，max_attempts分别2/3；记录attempts和结果。完成标准：不会让失败路径消失于打印。

**迁移：** 设计持续项目的两阶段工具批次，加入一次部分失败与冲突，给出用户说明及下一合法动作。完成标准：不绕过权限、不重写未知副作用、失败也保留有用证据。

> [!example]- 参考答案与解析
> max_attempts2不够通过前两次故障，第三次不会执行；设3才成功。要使模拟I/O错误按已知暂时故障处理，可抛OSError，并显式标只读。非幂等写即使配置3仍最多一次。冲突不能自动取较新命名来源，须核实日期/权威/适用范围。

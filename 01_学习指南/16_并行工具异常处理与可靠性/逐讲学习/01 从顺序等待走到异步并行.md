# 第 1 讲：从顺序等待走到异步并行

## 要解决什么问题

查政策和查订单都要等返回，而且互不依赖。顺序等两次会浪费等待时间；并发可以在一个查询等待时推进另一个。asyncio适合I/O等待型任务，不保证CPU计算在多个核心同时加速。

**协程**是可在await处暂停/继续的任务；**事件循环**安排哪个协程现在运行；**Task**把协程提交给循环调度。需要复习时读[[01_学习指南/01_Python工程化/逐讲学习/09 用异步处理多个任务|异步基础]]。

## 先运行一条协程

在示例工程创建 `first_async.py`：

```python
import asyncio

async def read_policy():
    print("开始查询")
    await asyncio.sleep(0.1)
    print("收到结果")
    return "30 days"

async def main():
    answer = await read_policy()
    print(answer)

if __name__ == "__main__":
    asyncio.run(main())
```

运行共享解释器，预期开始查询→收到结果→30 days。async def定义协程函数；调用read_policy()创建协程对象；await等它完成，并在等待时允许循环运行其他任务。sleep模拟等待，不是真实查询。

只调用read_policy()而不await/创建Task，会有“coroutine was never awaited”警告，主体没有自动执行。asyncio.run建立顶层循环并运行main，结束后清理；已有循环的环境不能随意再嵌套run。

## 完整串并行对照

新建 `compare_async.py`：

```python
import asyncio
from time import perf_counter

async def read_value(name):
    await asyncio.sleep(0.1)
    return name

async def main():
    started = perf_counter()
    first = await read_value("policy")
    second = await read_value("order")
    print("串行", first, second, round(perf_counter() - started, 3))

    started = perf_counter()
    first_task = asyncio.create_task(read_value("policy"))
    second_task = asyncio.create_task(read_value("order"))
    first, second = await asyncio.gather(first_task, second_task)
    print("并行", first, second, round(perf_counter() - started, 3))

if __name__ == "__main__":
    asyncio.run(main())
```

预期串行约0.2秒、并行约0.1秒。perf_counter差值是秒；Windows定时和负载会使数值略大，不要求精确倍数。第一段第二项尚未启动；第二段都create_task后才gather，等待重叠。

gather结果顺序对应传入顺序，即使完成顺序不同；仍保留call_id，避免换聚合方法时错配。协程里time.sleep阻塞线程，长CPU循环也不让出；写async不会自动加速它。真实应用使用异步I/O，线程适配也不能保证取消底层工作。

## 再看工程执行

demo三个工具各sleep0.04秒；串行理想等三份，并发上限2则等两轮。Scheduler先创建task，再gather，并保存任务引用。官方机制见[Python协程与任务](https://docs.python.org/3.13/library/asyncio-task.html)。

ToolSpec(read_fact, is_read_only=True)由可信注册声明只读；默认False，避免新工具未判断副作用时自动重试。输入是参数dict，输出是结果dict，协议仍要单独校验。

## 常见错误与环境排查

await在普通def里会语法错误，放到async def。创建Task时没有循环会报no running event loop，先进入asyncio.run。把time.sleep换成asyncio.sleep时必须await，否则没等待。

作者沙箱中本机socketpair创建停滞，导致asyncio.new_event_loop无法完成；沙箱外共享解释器正常。见[[90_参考与维护/单元验证/16 并行工具异常处理与可靠性验证记录|验证记录]]。自己的VS Code先跑最小脚本定位，不要随意改系统Python、关闭安全设置或安装无关依赖。

## 练习与解析

**跟做：** 跑两种模式，画0～0.2秒时间线，标哪个查询在等待。

**独立：** 先await第一Task再创建第二Task，预测是否重叠，再实验。完成标准：看创建位置，不只看await数量。

**迁移：** 找持续项目两个真正无依赖的只读查询，写结果关联。完成标准：不把必须先拿订单ID的工具盲并行。

> [!example]- 参考答案与解析
> 第一Task结束才创建第二，仍是顺序；先创建两Task才能重叠。并发是等待交错，不是CPU多核承诺。真实网络还需超时和授权，当前sleep只合成延迟。

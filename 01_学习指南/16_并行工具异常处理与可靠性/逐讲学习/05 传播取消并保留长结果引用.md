## 要解决什么问题

用户取消父任务，后台工具仍在跑；或者工具返回十万字符，直接塞给模型超上下文。前者需要取消传播和清理，后者需要完整存储、有限摘要及回查引用。

本讲前置async/await、Task和异常finally。**取消传播**让父任务结束请求传到子任务；**finally**在正常返回/异常/取消时做清理。取消不等于撤销已发生的外部写入。

## 一个会清理的取消例子

在示例工程新建 `inspect_cancel.py`：

```python
import asyncio

async def read():
    try:
        print("查询开始")
        await asyncio.sleep(10)
    finally:
        print("查询清理")

async def main():
    task = asyncio.create_task(read())
    await asyncio.sleep(0.01)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("父任务确认取消")

if __name__ == "__main__":
    asyncio.run(main())
```

预期查询开始→查询清理→父任务确认取消，不等10秒。cancel提出请求，协程在下一个合适await点收到CancelledError；await task等待它清理结束。finally适合释放资源，不应再启动未授权写操作。

CancelledError在当前Python继承BaseException，不能随便吞掉。Scheduler捕获后取消所有已创建Task，gather收拢，然后重新raise，把取消继续交给上层。不是包装成ok=False继续重试。

## 取消的现实限制

同步阻塞函数/CPU循环没有让出时，事件循环不能及时处理取消；线程中的库调用也不一定因协程取消而停止。外部请求已提交，取消不能撤销；需结果回查和业务补偿。

测试只验证本地协作式工具进入finally，没有证明现实网络取消/数据库撤销。生产需各接口明确取消支持、写入状态和清理时限。

## 长结果先保存，再给摘要

Scheduler将完整data序列化为JSON文本，若字符数超过max_output_characters：把完整dict保存在full_results，以SHA256得到result_ref；返回is_summary=True、preview、原长度、摘要长度、truncated和ref。

preview是文本预览，可能在JSON中途截断，所以preview_format=text；整个返回外壳仍是合法dict。**不能把preview当完整JSON解析，也不能声称预览是全部资料。** 短结果则is_summary=False并有content。

字符预算是教学单位，不是token预算或内存总量。完整data已在内存生成，截断只减小传给决策器的内容，不防止工具一次生成巨大数据。生产需流式读取、字节上限、持久存储、token预算和权限回查。

## 完整回查实验

创建 `inspect_long_output.py`：

```python
import asyncio
from scheduler import Request, Scheduler, ToolSpec

async def read(arguments):
    return {"text": "中文资料" * 100}

async def main():
    scheduler = Scheduler({"read": ToolSpec(read, is_read_only=True)}, max_output_characters=20)
    result = (await scheduler.run_batch([Request("long-1", "read", {})]))[0]
    summary = result["data"]
    print(summary["is_summary"], summary["truncated"], len(summary["preview"]))
    full = scheduler.read_full_result(summary["result_ref"])
    print(len(full["text"]))

if __name__ == "__main__":
    asyncio.run(main())
```

预期True True 20，然后400。完整对象和摘要长度单位不同：原JSON长度含键和引号，full.text是正文字符数。read_full_result返回副本，调用者改它不会污染原记录。

引用是内容摘要标识，不是权限凭证；知道ref不应自动获得读取权限。当前无真实认证，完整数据仅当前Scheduler内存，进程结束丢失，也没有TTL/容量淘汰，不能当生产存储服务。

## Agent如何使用摘要

先检查ok，再检查is_summary。需要具体字段却只有预览，按ref获取允许的完整结果或进一步分页；不能从半句作结论。无需完整内容的任务可报告概要，但说明截断。

merge_facts遇摘要会返回needs_full_result；策略据此回查，而不是忽略该任务。返回摘要保留错误与来源尤其重要，不能把失败字段截掉导致模型误判成功。

## 常见错误与练习

取消后“Task exception was never retrieved”：没有await收拢任务。取消后自动重试：错误分类吞掉了CancelledError。摘要解析失败：它是文本，不是JSON。回查404/KeyError：检查Scheduler实例/生命周期，内存引用不能跨新进程直接使用。

**跟做：** 跑取消与长结果两个脚本，解释输出顺序/长度。

**独立：** 设计返回短结果与摘要的读取分支，要求都先检查ok。完成标准：不对摘要取content、不对预览json.loads。

**迁移：** 长工单数据设计分页、权限、存储保留期、回查ID和模型摘要。完成标准：摘要不能泄露无权字段，取消不会删除已提交业务记录。

> [!example]- 参考答案与解析
> ok=False先处理error；ok=True且is_summary=False读取content；摘要按ref回查或说明未完整读取。finally清理应释放连接和本地资源，不能自行回滚未获授权的现实资源。生产ref要结合身份和版本校验。

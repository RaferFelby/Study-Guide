## 要解决什么问题

工具卡住不能无限等，限流也不该立刻打更多请求。先判断故障与副作用，再设置每次超时、最多尝试次数、等待预算。**超时**是超过允许等待；**重试**是再次发同一操作；**退避**是重试前等待。

前置是上一讲异步与单元15幂等。安全重试既要错误可能恢复，也要操作可重复；缺一个都不能无条件重试。

## 最小超时实验

在示例工程新建 `inspect_timeout.py`：

```python
import asyncio

async def slow_read():
    await asyncio.sleep(1)
    return "data"

async def main():
    try:
        result = await asyncio.wait_for(slow_read(), timeout=0.05)
        print(result)
    except TimeoutError:
        print("本次读取超时")

if __name__ == "__main__":
    asyncio.run(main())
```

预期超时说明。wait_for请求取消协程，等它清理后抛TimeoutError；不是系统强制结束。协程吞取消或同步阻塞时可能超过0.05秒。官方见[asyncio超时](https://docs.python.org/3.13/library/asyncio-task.html#timeouts)。

工程timeout_seconds只覆盖单次工具执行，不包括排队/速率窗口/退避/全部尝试。总时限需另加外层预算和取消设计，不能称整任务最多0.2秒。

## 哪些错误原样重试有意义

读超时、暂时I/O、限流可能恢复；参数/返回格式错、无权限、工具不存在通常要修参数/重规划/说明限制。非幂等写超时或网络异常可能已经提交，标outcome_unknown，禁止盲重试。

ToolSpec.safe_to_retry由可信is_read_only或is_idempotent推导，默认False。标幂等须真实实现，不是为了绕过限制。max_attempts包含首次：2代表首次加一次重试；不安全写仍只尝试一次。

## 指数退避和上游等待要求

base_delay=0.01时，前几次失败后的等待0.01、0.02、0.04秒。生产可加随机抖动减少同时重试，当前为确定教学未加。

Retry-After是上游要求至少等待多久。工程取它与指数等待的较大值；超过max_delay预算则停止自动重试，返回限流错误，不能把30秒截成0.2秒后提前重试。退避在并发槽外，其他请求可继续。

## 受控限流完整例子

创建 `inspect_retry.py`：

```python
import asyncio
from scheduler import RateLimitedError, Request, Scheduler, ToolSpec

attempts = 0
async def read(arguments):
    global attempts
    attempts += 1
    if attempts == 1:
        raise RateLimitedError(0.01)
    return {"answer": "ready"}

async def main():
    scheduler = Scheduler({"read": ToolSpec(read, is_read_only=True)}, max_attempts=2)
    result = (await scheduler.run_batch([Request("q1", "read", {})]))[0]
    print(result["ok"], result["attempts"])

if __name__ == "__main__":
    asyncio.run(main())
```

预期True 2。global让函数修改脚本外计数，仅用于最小例子；工程测试用闭包隔离各场景。max_attempts=1则失败且次数1；Retry-After=30则因等待预算停止，不真的等30秒。

## 未知结果应先核实

outcome_unknown不能写成“必然失败”。Agent应按外部请求ID/幂等键回查，必要时人工处理；不要再次创建。取消/超时不能证明远端没提交。

本地sleep无真实提交，测试只验证不盲重试。生产须把确认、持久幂等、超时和对账一起设计。未知程序异常仍抛出并收拢任务，不装成普通成功。

## 常见错误与练习

次数多一：核对首次是否计入。所有错误都重试：分开可恢复故障与参数/权限。退避堵住其他任务：检查是否仍占并发槽。重复退款：先处理未知状态。

**跟做：** 对照2次/1次配置，解释attempts。

**独立：** base=0.1、max_attempts=4，列三次等待；Retry-After=2、max_delay=0.5时预测行为。

**迁移：** 为读政策/创建工单写故障重试矩阵。完成标准：次数有限、遵守上游等待、不重复未获授权写。

> [!example]- 参考答案与解析
> 等待0.1/0.2/0.4，总退避0.7秒，另加执行/排队。要求2秒超过0.5预算，停止自动重试，不提前打上游。非幂等工单写超时先查状态；读政策可对暂时故障限次重试。

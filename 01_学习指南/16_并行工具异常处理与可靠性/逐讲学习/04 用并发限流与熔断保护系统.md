## 要解决什么问题

一口气提交一万工具调用，即使每个正确，也可能耗尽连接、内存和上游额度。上游已经连续失败，继续猛发又会扩大故障。需要控制并发、启动速率、接收数量，并在持续故障时暂时停止调用。

**并发上限**控制同时在执行区的数量；**速率限制**控制一段时间开始多少次；**背压**让上游提交速度受下游能力限制；**熔断**在连续失败后暂时不再访问故障工具。它们控制的量不同。

## 先用Semaphore控制两条通道

Semaphore（信号量）像有固定数量的通行证，拿到才能进执行区，离开自动归还。实际机制是异步计数和等待队列，不是新建两个线程。见[Python异步同步原语](https://docs.python.org/3.13/library/asyncio-sync.html#asyncio.Semaphore)。

在示例工程创建 `inspect_semaphore.py`：

```python
import asyncio

async def read(number, semaphore):
    async with semaphore:
        print("进入", number)
        await asyncio.sleep(0.05)
        print("离开", number)

async def main():
    semaphore = asyncio.Semaphore(2)
    tasks = [asyncio.create_task(read(number, semaphore)) for number in range(4)]
    await asyncio.gather(*tasks)

if __name__ == "__main__":
    asyncio.run(main())
```

预期最多两条同时进入，之后才进入剩余两条。`async with`进入时获取槽，异常/取消离开时也释放；`*tasks`把列表展开为gather的多个参数。列表推导式只负责按0～3创建任务，展开成for也可以。

## 并发2不等于每秒2次

若每次0.01秒，并发2可能每秒开始近200次；若每次2秒，并发2吞吐很低。要限制请求频率，需要单独速率窗口。

工程rate_interval_seconds表示相邻执行启动至少间隔多久。rate_lock保护next_start：看当前时间、等剩余间隔、更新下一允许时间。同进程所有工具共享这条启动间隔，是教学简化，不是每用户/每模型配额系统。

速率等待目前发生在Semaphore槽内，简单但会占住执行槽；退避在槽外。更复杂生产调度可用队列/令牌桶协调，但须测公平性与总延迟，不能仅增加一个配置名就声称所有资源都受控。

## 背压先从接收上限开始

Scheduler默认max_calls=20，超过则整批拒绝，未执行任何工具。调用方应拆批或等待，而不是递归无限创建Task。Semaphore限制活跃任务，单独并不限制排队内存；批次上限同时限制当前接收量。

这不是完整流式生产队列。真实服务还要有队列容量、等待超时、每租户公平性和负载拒绝；无限排队只把错误变成更晚的超时。也不能把大批拆为同时发出的无限小批，绕过接收预算。

## 熔断如何开启和冷却

CircuitBreaker按工具记录连续最终故障，达到failure_threshold（默认2）则open_until=当前单调时间+cooldown。期间新请求返回circuit_open，不执行工具。冷却到期清零并重开；成功重置失败计数。

在示例工程创建 `inspect_breaker.py`：

```python
from scheduler import CircuitBreaker

now = [0.0]
breaker = CircuitBreaker(failure_threshold=2, cooldown_seconds=5, clock=lambda: now[0])
breaker.record_failure("read")
breaker.record_failure("read")
print(breaker.allows("read"))
now[0] = 5.0
print(breaker.allows("read"))
```

预期False、True。lambda是一个短匿名函数，返回列表中的当前时间；列表可更新，所以无需真实等5秒即可验证边界。生产默认monotonic计时，系统日历修改不会直接影响冷却。

完整熔断器通常有closed/open/half-open三个状态，half-open允许少数探针确认恢复。当前没有半开探针，冷却后直接重开；这可能瞬时恢复很多请求，报告中必须承认。已有执行任务也不被熔断自动撤销。

## 降级不应制造答案

**降级**是在当前工具不可用时选择较弱但明确的可用路径，例如只返回公开政策、不查实时工单，或者告知暂时不可查询。过期缓存要标时间与适用范围，不能冒充实时状态。

Agent收到circuit_open/rate_limited可选择独立替代工具或说明等待；收到permission_denied不能靠别的接口绕过授权。工程提供结构化错误，后续决策应遵守同样边界。

## 常见错误与练习

峰值并发超过2：是否重试/子任务绕开同Semaphore？同名工具仍调用：检查等待槽后是否重新检查熔断，工程在获取槽后会再验。冷却不断延长：要区分新故障与已拒绝请求，拒绝本身不应当作一次真实执行失败。

**跟做：** 跑Semaphore和假时钟熔断例子，解释每个输出。

**独立：** 并发2、每次0.1秒、启动间隔0.2秒，哪个约束更强？说明为何不能同时当“每秒20次”。

**迁移：** 为模型与数据库分别配置并发、速率、队列、等待时限、熔断和降级。完成标准：单位清楚、故障时不会无界排队或泄露权限数据。

> 启动间隔0.2秒近似最多每秒5次（边界窗口计数需具体定义），比并发容量约每秒20次更强。半开和多租户配额当前未实现；应作为生产扩展，不能填入已验证成果。

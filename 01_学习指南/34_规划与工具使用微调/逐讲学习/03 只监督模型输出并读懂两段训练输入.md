## 本讲任务与前置

查看同一轨迹拆出的两行张量，指出输入哪些位置可见、哪些位置参与损失，然后读一轮更新。需要上一讲的行数、张量形状与 SFT 基础；忘记张量到 [[01_学习指南/06_PyTorch训练闭环/00 PyTorch训练闭环学习地图|PyTorch 基础]]，忘记监督微调到 [[01_学习指南/26_SFT与LoRA全流程/00 SFT与LoRA全流程学习地图|SFT 详细教程]]。本讲重新解释本例的标签与移位。

完成标准：能解释 `(2,15)`、6 和 3，能说明观察应进入输入但不由模型伪造为训练输出，以及为什么生成时看不到未来答案。

## 要解决什么问题

我们要教模型生成调用和答案。如果把环境观察也当成它的输出目标，模型可能学着“演出工具已经返回”的文字，却没有真的执行工具。解决方法是分别给两次模型输出制作训练行：第一次学调用；第二次已经收到真实观察，再学答案。

监督是告诉模型哪些输出应接近正确目标。标签是目标 token 的编号；掩码是标出哪些位置不参与评分。本例用 `-100` 表示忽略位置，`ignore_index=-100` 告诉损失函数不计算这些标签。它不会删除模型可见的上下文，只是不把这些位置当作它必须回答的目标。

## 概念与直觉：两段完整上下文

第一行输入四 token：`query color item-0 case-00`；目标六 token：`plan color call get_color item-0 <eos>`。训练时把输入与目标拼在一起，方便逐位置计算，但目标起点以前的标签全为 -100。

第二行上下文十二 token：四个请求、六个已完成动作、`observation red` 两个环境字段；目标三 token：`final red <eos>`。上下文中的 `<eos>` 是第一轮结束，最终生成函数只在本轮新输出出现 `<eos>` 时停，所以它不会因为输入已有结束标记而立即退出。

像给学生题目和资料，只批改作答部分；实际机制是损失按标签值跳过题目位置，而模型仍用它们计算后续概率。这个类比不意味着模型能理解资料真实性，真实性来自前一讲的重放与后续真实执行。

## 最小示例：查看监督边界

在本单元示例工程新建 `lesson_03.py`，保存并用共享解释器运行。

```python
from data import batch_rows, make_training_rows

rows = make_training_rows()[:2]
inputs, labels = batch_rows(rows)
print(tuple(inputs.shape), tuple(labels.shape))
for index, (prompt, answer) in enumerate(rows):
    print(index, len(prompt), len(answer))
    print(labels[index].tolist())
    print("监督token数", int((labels[index] != -100).sum()))
```

```powershell
..\..\..\.venv\Scripts\python.exe lesson_03.py
```

预期先输出 `(2, 15) (2, 15)`。第 0 行上下文长 4、目标长 6、监督 token 数 6；第 1 行上下文长 12、目标长 3、监督数 3。第一行标签前四个及末尾五个为 -100；第二行前十二个为 -100。中间的正整数是词表编号，直接对照 `data.py` 的 `TOKENS`，不要求背数字。

`[:2]` 取列表前两行；`enumerate` 同时给索引与内容；`shape` 是张量各维大小。2 表示两行，15 是本批最长拼接长度。第一行总长 10，所以补五个 `<pad>`，意为占位填充，标签仍忽略。`labels != -100` 逐位置比较，True 求和得到参与监督的数量。

## 逐步讲解：编号、因果模型与移位

打开 [model.py](../示例工程/model.py) 和 [training.py](../示例工程/training.py)，按以下顺序读，不需要一次理解全部 PyTorch 内部实现。

1. `encode` 把 token 转成固定词表整数。词表 66 项，本例不使用外部 tokenizer；未知文本会报错，不会自动拆字或翻译。
2. `Embedding` 把每个编号变成 32 个数，形成可学习的表示。输入形状是“行数×长度”，表示形状变为“行数×长度×32”。
3. `GRU(32,48)` 是按从左到右读取的循环网络，每一步更新 48 个数的状态。它只看之前的状态和当前位置输入，不能看后面的目标；没有双向层。`Linear(48,66)` 为下一 token 给出 66 个分数，分数称为 logits，不是已经归一化的概率。
4. `model(inputs)[:, :-1]` 去掉最后位置的预测，`labels[:, 1:]` 去掉第一个标签。位置 t 的分数对准位置 t+1 的目标，这叫移位。第一行第 3 个位置已读完四个请求 token，用它预测位置 4 的 `plan`，不能先看到 plan 再预测它自身。
5. `cross_entropy` 在非 -100 的标签上衡量正确 token 的概率是否高。它内部处理 logits 与概率，无需先手动 softmax。第二行观察位置被忽略，但后面的 final 输出仍可借助观察的信息。

训练时给出前面正确目标 token 再预测下一 token，通常称 teacher forcing，即用正确历史辅助学习。推理时没有正确历史可供照抄，只能把模型刚生成的 token 接回输入，再预测下一个，所以损失下降不保证自由生成一定正确。

## 一次更新与推理如何不同

训练每轮先 `model.train()`，再清理梯度、前向、损失、`backward()` 反向计算梯度、裁剪、`optimizer.step()` 更新。清理防止把上一轮梯度意外加上本轮；AdamW 是根据梯度调整权重的优化器。本例每次处理全部行，即全批次更新，200 次更新不代表 200 条轨迹。

这里已有 SFT 基础后加入一个稳定性动作：`clip_grad_norm_(...,1.0)` 把整组梯度的总长度限制在 1 以内，避免大更新。它不会修正错误标签；网络很小，统一使用 FP32，不引入混合精度状态。损失与梯度出现非有限值会明确失败，不继续保存成功结果。

推理函数 `generate` 使用 `model.eval()` 和 `inference_mode()`；后者不记录梯度。它每次选分数最高的 token，称贪心生成，遇本轮 `<eos>` 或生成八 token 后停止。八是本例明确的长度上限，不是所有工具调用都只需八 token。

## 动手操作与常见错误

在运行后手工标出第一行四个忽略位置、六个目标位置、五个填充位置。然后在第二行找到观察位置 10、11（从 0 起算），解释它们为什么为 -100。完成判断：能用自己的话区分“看得到”和“要预测”。

如果模型把 `observation` 当作最终生成的一部分，先检查行拆分是否把观察误放进目标；不要用额外输出删除规则替模型遮掩。若标签和预测位置没有移位，模型可能通过当前输入识别当前标签，不能证明学会预测。若目标缺 `<eos>` 或上下文太长，`batch_rows` 明确报错；恢复正确样本，而不是关闭检查。

## 分级练习与答案解析

### 跟做练习：数标签

第二行删除两个观察 token 后，输入与目标总长度如何变化？这样的修改有什么风险？提示：长度不是唯一目标。

> [!example]- 参考答案
> 长度从 15 变 13，目标仍 3 个。但模型无法读到工具本次返回值，更可能记旧目录。完成标准：指出监督数量没变，信息条件却变了，不能把缩短样本当等价实现。

### 独立练习：第一目标由谁预测

请求长 4，plan 的标签在位置 4。经过移位，哪一位置的 logits 预测它？它见过哪些 token？

> [!example]- 参考答案
> 原 logits 位置 3，对齐原标签位置 4。GRU 此时见过位置 0～3 的请求，没有见到位置 4 的 plan。完成标准：能画出 t→t+1 的对应，不把数组位置与第几项混淆。

### 迁移练习：不监督观察是否保证利用观察

有人说“用了正确掩码，就证明模型依赖观察”。你怎样检查？提示：改变工具返回内容，其余任务保持相同。

> [!example]- 参考答案
> 将目录颜色、大小交换，执行同类任务，检查第二次输入收到新观察，最终答案是否对应新值。正确掩码是设计条件，改变观察后的实测才是该探针的行为证据；仍不能证明所有环境都能泛化。完成标准：分别写出机制证据与行为证据。

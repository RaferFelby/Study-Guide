## 本讲任务与前置

读取旧任务、未训练工具、未见对象探针，把结果写成带范围的采用结论。需要上一讲的共同分母，以及数据切分中“编号不重合但对象重用”的区别。若忘记数据分组，返回本单元第 2 讲；旧能力退化的更多案例见 [[01_学习指南/33_DPO与偏好优化/00 DPO与偏好优化学习地图|偏好优化单元]]。

完成标准：能用自己的报告填写四类任务计数，解释两个分支没有观察到重放收益、未见工具失败，写出下一步验证方案。不能为了得到漂亮结果把失败探针删掉。

## 要解决什么问题：一个满分不是所有任务都满分

正常工具任务 12/12 只说明这批任务通过。微调可能遗忘旧任务，也可能只学到固定工具名和已见对象。若换一个没训练的工具仍报喜，学习结论就超过证据。

泛化指在未训练条件下仍表现正确，必须说清“新”在哪里。新案例编号、新对象、新属性工具、新语言表达是不同条件；本例普通测试只换编号，其他两项另测，真实自然语言表达尚未测试。

## 概念与探针定义

旧任务是两条固定复述：`chat red→red <eos>` 和 `chat blue→blue <eos>`。它们是 Base 曾学的内容，微调后再次运行检查是否遗忘；最多说明这两个样本的保持，不能替代普通对话评测。

未训练工具探针请求 `shape`，对应 `get_shape`，六个已见对象，返回值 round。工具与词表早已存在，但训练轨迹从未使用 shape、get_shape、round；模型推理时也没有收到新的工具说明。它检查“无此训练是否自动学会”这一有限问题，不是提供新工具 schema 后的自然语言零样本泛化。

未见对象探针查 `item-6` 的颜色、大小两项。item-6 在词表和执行目录中存在，却没有出现在训练任务；两个探针都用新的 `case-unseen` 标记。因此失败可能与未训练对象表示、标记或任务分布组合有关，不能仅凭两条结果诊断唯一根因。

探针是一个针对疑问的小测试，像敲某一处看是否牢固；它不是整座房子的质量保证。实际结论必须受样本量与变化范围限制。

## 最小示例：读取三类边界结果

在本单元示例工程新建 `lesson_06.py`，CPU 报告仍使用你第 4 讲创建的目录。

```python
import json
from pathlib import Path

with (Path("report-my-cpu-01") / "report.json").open(encoding="utf-8") as file:
    report = json.load(file)
for name, result in report["evaluations"].items():
    chat = result["old_chat"]
    unseen_tool = result["unseen_tool"]
    unseen_entity = result["unseen_entity"]
    print(name, "旧任务", chat["correct"], chat["n"])
    print("新工具", unseen_tool["end_to_end"], unseen_tool["n"])
    print("新对象", unseen_entity["end_to_end"], unseen_entity["n"])
print(report["source_split"], report["evaluation_protocol"])
```

```powershell
..\..\..\.venv\Scripts\python.exe lesson_06.py
```

作者 CPU 与 CUDA 每个分支都得到旧任务 2/2、新工具 0/6、新对象 0/2。最后显示 `case_ids_disjoint_but_entities_shared`、`fixed_diagnostic_not_blind_benchmark`，分别说明切分范围和评估已被查看。输出数字会受实际训练条件影响；用自己的报告写结论，不把参考数字填进失败运行。

## 逐步读失败：从哪个环节开始

先展开 `unseen_tool→details`，读第一条 action。检查它是否仍选择已训练的 color 或 size、是否生成 get_shape、是否有 `<eos>`，再看三个语义标记。不要在失败后让宿主把 get_color 偷换成 get_shape，然后把完成归功于模型。

再展开 unseen_entity，对照生成对象和请求的 item-6。即使生成的是允许目录里的 item-0，也属于参数错误；语法允许不代表请求正确。宿主拒绝了这种错误，工具没有被调用，必须保留为任务失败。

最后核对 old_chat 的 answer 与 expected。这次 tool_only 和 with_replay 都 2/2，没有观察到旧任务退化，也没有观察到重放分支改善。重放是一个可试的设计，并不是本实验已经证明必要或更好；只有两个简单样本，也无法排除其他旧能力损伤。

## 写采用结论：从证据到行动

本次可以保留为教学演示：模型实际学会在已见对象、两类工具和固定语法下生成调用，读取变化后的当前观察并回答；不可用时拒答，宿主校验先于执行。采用范围限定在此合成只读任务，不将它作为真实开放工具系统的可靠模型。

暂停扩展到新工具的理由是实际 0/6；新对象 0/2 也提醒固定词表中的“存在”不等于训练后会使用。下一步先诊断样本不足和输入条件，再制作带工具说明、不同对象和表达的训练／开发数据；留一个未反复查看的评估集，避免每次失败都按答案调参。

若加入 shape 后再次评估同六条，结果改善只能说它们变成已训练类别上的回归验证，不能仍称未见工具泛化。可以另外保留一个新属性工具，或设计新工具说明与新参数组合，预先规定判断。真实评测还需扩大旧对话样本，而不是拿两条复述替代。

两个训练分支同 200 次更新、行数不同；若要研究重放收益，可增加有挑战的旧任务、多个种子，并设匹配 token 预算的对照。目前没有做这些实验，结论保持有限。

## 动手操作：写自己的复盘

在 Obsidian 的 [[02_学习记录/00 我的学习记录|我的学习记录]] 本单元下，先记录亲自操作，再用六句话复盘：

1. 我运行的设备、版本与报告目录。
2. 正常任务的格式／语义／执行／最终计数与分母。
3. 变化目录与不可用时的结果。
4. 旧任务、未训练工具、未见对象结果。
5. 本次可采用的范围与不能推出的结论。
6. 下一项验证及不改变判定来迎合模型的理由。

建议先写自己的结论，再读 [[90_参考与维护/单元验证/34 规划与工具使用微调验证记录|作者记录]]。学习者勾选只在完成实际操作、独立解释和练习后修改，作者报告不替你完成。

## 常见错误与排查

“词表包含新工具，所以已经学过”：词表只是编号可表示，训练更新才赋予本任务使用能力；查训练行确实没有 shape。若你增加了样本，要同步修改未见标签与记录。

“旧任务 2/2，所以完全没有遗忘”：先写覆盖只有两个固定复述，再提出扩展任务集。若表里丢失某探针，核对 `evaluate_model` 是否仍构造它，不删除低分项。若样本不足想进一步实验，保存新报告并记录配置，保留原失败证据；别覆盖旧目录或修改原作者结果。

## 分级练习与答案解析

### 跟做练习：填写结果与结论

用自己的报告写“是否观察到旧任务退化”“是否观察到重放收益”。提示：比较两个分支在同两条旧任务上的输出。

> [!example]- 参考答案
> 作者结果两个分支均 2/2，故该探针未观察到退化，也没有显示重放收益。不能写所有对话能力不退化，也不能写重放一定无用。完成标准：每句话带任务范围，使用自己的实际计数。

### 独立练习：训练后的新工具

把 shape 样本加入训练，再测同一批 shape 任务通过。还能叫未见工具测试吗？应怎样调整验收？

> [!example]- 参考答案
> 不能，同类别工具已进入训练。这批成为回归或同分布测试；另留未训练工具或预先设计的新工具说明／参数组合，清楚记录变化条件。完成标准：不靠改名称让训练过的内容冒充未见。

### 迁移练习：修订采用声明

把“模型工具能力全面提升且普通对话不退化”改成符合本实验的两句话。提示：写正常集、旧任务规模和失败范围。

> [!example]- 参考答案
> “在固定合成语法、已见对象和两类工具的 12 条诊断任务上，微调分支从 Base 的 0/12 提升到 12/12；变化目录探针也通过。两条旧复述保持 2/2，但未训练工具 0/6、未见对象 0/2，不能据此声称开放工具泛化或广泛对话保持。”完成标准：保留收益与失败的实际证据，不让范围超过测量。

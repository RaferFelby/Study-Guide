## 本讲任务与前置

先运行轨迹过滤，解释四种失败，再看如何构造正确的不可用拒答。需要上一讲的格式与语义区分、字典与列表，以及 `try/except` 异常捕获；后者表示程序在明确错误处记录失败，而不是继续使用错误结果。数据来源与切分更详细的基础见 [[01_学习指南/31_推理与工具数据构造/00 推理与工具数据构造学习地图|数据构造教程]]。

完成标准：能算出 52→48→108→116 各数字的含义，能解释为什么错误调用不能直接当正答案，以及为什么案例编号不重合还不能证明泛化。

## 要解决什么问题

如果示范把颜色请求标成查大小，训练会奖励错误工具。若调用正确但观察被改成旧值，模型可能学到忽略工具返回。因此不能仅检查“文件能读、字段齐全”；还要重放工具、核对结果。

过滤是把不适合作为正示范的数据隔离出来，不是删除失败证据。本工程保留全部原始轨迹及拒绝原因，正确轨迹才进入正常训练。失败还可以转成有明确上下文的正确拒答样本，教模型在工具不可用时说明不能完成。

## 最小示例：检查过滤与行数

在 VS Code 的本单元示例工程新建 `lesson_02.py`，保存下面代码，在同目录的 PowerShell 运行。

```python
from data import make_training_rows, prepare_traces

raw, valid, rejected = prepare_traces()
print(len(raw), len(valid), len(rejected))
for row in rejected:
    print(row["raw_index"], row["reason"])
tool_rows = make_training_rows()
mixed_rows = make_training_rows(include_chat=True)
print(len(tool_rows), len(mixed_rows))
print(tool_rows[96][1])
```

```powershell
..\..\..\.venv\Scripts\python.exe lesson_02.py
```

预期输出：

```text
52 48 4
48 轨迹语义不符
49 轨迹语义不符
50 观察或最终答案不符
51 观察或最终答案不符
108 116
['refuse', 'unavailable', '<eos>']
```

`raw` 是原始列表，`valid` 是通过校验的列表，`rejected` 是拒绝记录。`for row in rejected` 一次读取一项；`raw_index` 是原列表中的位置，便于找到完整反例。单条来源编号 `case-00` 有颜色和大小两项，故不能只靠它唯一标识一条轨迹；本次定位以原始位置为准。

## 概念与机制：三道校验

打开 [data.py](../示例工程/data.py)，按 `prepare_traces→validate_trace→make_training_rows` 阅读。

1. **字段与来源。** 轨迹必须有请求、动作、观察、答案等字段，标记 `synthetic_verified_rule` 和 `local_teaching_only`。它说明本地规则生成、供教学使用。字段声明只是记录，不会自动赋予真实对话的训练权利；本例没有真实用户对话。
2. **调用与任务。** `parse_call` 校验六 token 结构；`semantic_checks` 对照请求，检查计划、工具、对象。原始位置 48 改了工具，49 改了对象，均被拒绝。
3. **重放与结果。** `execute_tool` 在固定目录重新读取，观察必须等于读出的值，最终答案必须为 `final 当前值 <eos>`。位置 50 修改观察，51 修改答案，均被拒绝。校验依赖这个确定的合成环境，不能照搬成任意外部数据验证器。

原始 48 条来自 24 个案例，每个案例两类请求。另复制第一条，分别注入四种错误，原始总数 52；复制错误条与原条同来源是故意用于演示过滤，不把它们混作独立证据。运行第 4 讲后，`raw_traces.jsonl` 逐行保存全部 52 条；JSONL 的意思是一行一个 JSON 对象，方便逐条检查。

## 失败怎样利用：明确正确目标

有两类情况要分开。第一类是错误工具或对象：它们不进入正动作标签，可以作为评估反例，检查宿主是否拦截。第二类是正确调用后的工具不可用：调用本身没有错，此时正确目标应是 `refuse unavailable <eos>`，意思是承认工具不可用并停止，而不是猜一个颜色。

本例从前 12 条正确轨迹另构造上下文：请求 + 正确动作 + `error unavailable`。输出目标为明确拒答。没有把原来四条坏轨迹的错误调用复制成正确动作，也没有训练模型在无观察时编造答案。拒答只覆盖这一种合成故障；未知错误类型尚未测试。

每条正常轨迹拆成两行：第一行请求→动作，第二行请求+动作+观察→最终答案。因此 48×2=96 行；加 12 行拒答得 108 行。每行是一次模型输入和要学习的输出，不等于一次完整任务。

加入旧任务重放时，把 `chat red→red <eos>`、`chat blue→blue <eos>` 两行各重复四次，共加 8 行，得到 116 行。重放指微调时重新练习旧任务，像学习新内容时抽出时间复习；实际是把旧样本重新放入损失计算。重复不是新增八条独立数据，也不保证旧能力一定保持。

## 数据切分：编号与能力新颖性

`case-00`～`case-23` 用于训练，24～29 留作开发，30～35 用于本次固定诊断。开发集已生成，但脚本没有据它选择参数。本次固定 seed 与 200 次更新直接运行；诊断结果作者已经查看，因此不要把它称为最终盲测。

三组编号不重合，但对象都是 `item-0`～`item-5`，查询模板也相同；测试只是在同类结构上换案例编号。编号切分防止原案例直接重用，但不证明物品、新意图、新语言表达的泛化。第 6 讲另外用 `item-6` 和 `shape` 检查未训练的对象与工具，保持失败记录。

## 动手操作与常见错误

跟着输出到 `prepare_traces` 找四个注入分支，把每条原因写回原始位置。再找到 `rows[96]`：索引从 0 开始，所以它是第 97 行，也是第一行故障拒答。完成判断：能指出该行的输入仍含正确调用，但没有正常观察。

若不小心把正目标改为 `final red <eos>`，工具不可用样本会教模型假装完成；恢复正确拒答再运行测试。若 `52 48 4` 不一致，先检查是否修改了数据构造，不要只改预期数字。字段来源校验失败时核对 `origin` 与 `usage_policy`，不能随手伪造来源让未知资料通过。

## 分级练习与答案解析

### 跟做练习：手算训练行

不用代码先算只用 10 条正确轨迹、另加 3 行拒答时有多少训练行。提示：一条轨迹分成两次模型输出。

> [!example]- 参考答案
> 10×2+3=23 行。若再加两条旧任务各重放四次，变为 31 行。完成标准：明确“轨迹条数”和“训练行数”不同，不把拒答错误算成第三次正常输出。

### 独立练习：检验观察

第一条请求 item-0 颜色，动作正确，记录观察 blue、答案也 blue。两个值相互一致，为什么仍应拒绝？提示：答案一致不等于实际读取一致。

> [!example]- 参考答案
> 固定正常目录读取的是 red，重放结果与记录观察不同，所以整个正轨迹应隔离。若目录已经变化，应记录真实环境版本再按对应环境验证，不能混用旧目录和新观察。完成标准：指出需要核对数据环境，而不是仅核对答案与观察相等。

### 迁移练习：写来源边界

你准备换成公司实际对话，能否只改 `origin` 字段就训练？写出在使用前必须确定的两类信息。提示：数据内容与使用权限分别看。

> [!example]- 参考答案
> 要确定数据来源、允许的训练用途及敏感信息处理，也要确定工具记录是否真实、环境版本是否可重放、标签是否正确。字段是声明，不能代替授权或证据。完成标准：说明本单元没有完成这些真实数据条件，保留合成数据即可完成当前课程。

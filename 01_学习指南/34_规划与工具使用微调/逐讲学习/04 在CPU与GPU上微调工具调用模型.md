## 本讲任务与前置

实际运行一次 CPU 实验，阅读生成的权重和报告；设备支持时再运行 CUDA。需要上一讲的训练行、更新与推理，以及 [[01_学习指南/26_SFT与LoRA全流程/00 SFT与LoRA全流程学习地图|模型权重与 SFT]]。本例是全参数监督微调，更新整个小网络；没有 LoRA，也没有 DPO 的偏好损失。

完成标准：自己的新目录中出现三份权重、原始轨迹和报告；能解释两个分支来自相同 Base，能指出权重文件不支持等价续训。不要求你的结果必须与作者逐位一致。

## 要解决什么问题：公平比较从同一基础开始

直接训练随机模型，很难看出新技能是否伤害旧技能。我们先用两条极简单的 `chat` 复述任务训练 Base，再各复制一份：`tool_only` 只学工具和拒答，`with_replay` 加旧任务重放。复述只是输入 red 输出 red、输入 blue 输出 blue，不能称为广泛对话能力。

复制后两个分支彼此独立。若在 tool_only 已更新的模型上继续混合训练，起点就不同了。本工程在 `experiment.py` 用 `copy.deepcopy(base)` 分别复制完整权重，不只是给同一对象换一个变量名。

## 动手操作一：核对目录与共享环境

VS Code 打开 `D:\AI-Agent算法学习`，选择解释器 `D:\AI-Agent算法学习\.venv\Scripts\python.exe`。在本单元示例工程打开 PowerShell 终端，先执行：

```powershell
Get-Location
..\..\..\.venv\Scripts\python.exe -c "import torch; print(torch.__version__); print(torch.cuda.is_available())"
```

`-c` 表示执行后面的短 Python 语句；只读取已有环境信息。本机作者结果为 `2.14.0+cu130`、`True`。CPU 版或无 CUDA 的机器可能是 False，这不妨碍 CPU 路径。需要新安装时先依工作区约定说明方案并取得同意，不为本单元另建环境或升级现有包。

## 动手操作二：完整 CPU 实验

```powershell
..\..\..\.venv\Scripts\python.exe experiment.py --device cpu --output-dir report-my-cpu-01
```

`experiment.py` 是脚本入口；`--device cpu` 选择 CPU 计算；`--output-dir` 指定当前工程下的新结果目录。必须用未存在的名称，脚本不会覆盖旧实验。再次运行可换 `report-my-cpu-02`，不要为重跑删除已有报告。

顺序是：校验设备→创建新目录→设随机种子→训练旧复述 Base 100 次→评估 Base→独立训练两个工具分支各 200 次→分别评估→保存报告。种子是随机过程的起点，有助对比，但跨设备数值不保证完全相同。

预期终端打印 JSON 摘要，包含设备、17154 参数、原始 52 条／有效 48 条、各分支指标。作者 CPU 两个工具分支正常任务和变化目录均 12/12，旧复述均 2/2，未训练工具和对象均 0。Base 正常工具任务 0/12；这些是作者本次结果，你要记录自己的实际计数。

结果目录应有：

| 文件 | 用途 |
| --- | --- |
| `base.pt` | 旧复述任务训练后的权重 |
| `tool_only.pt` | 仅工具分支推理权重 |
| `with_replay.pt` | 工具加旧任务分支推理权重 |
| `raw_traces.jsonl` | 含四条错误的原始轨迹 |
| `report.json` | 环境、损失、逐案例输出和分层计数 |

`.pt` 是 PyTorch 保存文件的常见后缀；本工程还保存词表，防止编号含义丢失。生成物路径不纳入源码提交；自己创建的学习脚本仍可保留在工程中。

## 最小示例：读取自己的报告

CPU 命令完成后，在该工程新建 `lesson_04.py`：

```python
import json
from pathlib import Path

path = Path("report-my-cpu-01") / "report.json"
with path.open(encoding="utf-8") as file:
    report = json.load(file)
print(report["device"], report["parameters"])
for name, record in report["training"].items():
    history = record["history"]
    print(name, record["rows"], record["updates"])
    print(round(history[0]["loss_before_update"], 4),
          round(history[-1]["loss_before_update"], 4))
```

```powershell
..\..\..\.venv\Scripts\python.exe lesson_04.py
```

预期 `cpu 17154`；分支行数分别 108、116，更新次数都 200。作者 CPU 损失打印约 `8.2497 0.0031` 与 `7.977 0.0031`。`Path` 拼接路径，`with` 在读取后关闭文件，`json.load` 还原字典；`items()` 同时取名字和记录；`round` 仅让显示易读，不改变训练。历史值是在相应次更新前计算的损失，最后记录不是额外更新后的重新评估。

## GPU 路径与限制

CUDA 是让 PyTorch 使用兼容 NVIDIA GPU 的计算后端。确认上一条探测为 True 后运行：

```powershell
..\..\..\.venv\Scripts\python.exe experiment.py --device cuda --output-dir report-my-cuda-01
```

PyTorch 模型与训练张量都移到同一设备，执行同样的前向、反向与生成。作者在 RTX 5070 Laptop GPU、CUDA runtime 13.0 上实际训练；两分支训练计时约 1.29、1.18 秒，CPU 约 2.98、3.07 秒。计时只含各分支训练并在 CUDA 结束同步，不包含导入、Base、评估和保存；小模型测速不能推出大模型加速倍数。峰值已分配显存约 82.72 MiB，不是设备总占用或真实 LLM 所需显存。

FP32 指 32 位浮点数；本例模型很小，CPU 与 GPU 都使用它，不启用自动混合精度。学习 CPU 路径可以掌握流程，GPU 路径用于理解设备、显存和同步。多卡训练、真实大模型显存策略后续再学。

## 权重、更新预算与常见错误

两个分支更新次数相同，但重放分支多了 8 行，也多了目标 token，不能说计算预算完全相同。当前比较回答“这个简单重放方案的结果如何”，不足以证明重放本身有因果收益；第 6 讲还要看旧任务是否真的改善。

权重只含词表和模型状态，不含优化器、训练进度及随机状态。它适合加载做推理，不是完整训练检查点；不能从它等价恢复第 201 次更新。

报 `FileExistsError`：换新的结果目录名。报需要可用 CUDA：用探测命令确认，先用 CPU 完成，不安装驱动碰运气。报缺 PyTorch：核对共享解释器是否选错，确实缺包按安装审批规则处理。读报告报 `FileNotFoundError`：检查训练是否成功退出、目录名是否一致；如果失败只创建了目录，要查看最早错误，不能把有目录当实验成功。损失下降但任务失败应保存逐案例结果，第 5 讲找具体环节。

## 分级练习与答案解析

### 跟做练习：核对产物

找到三份权重与报告，在自己的记录写设备、参数、两分支行数。提示：以自己的 report.json 为准。

> [!example]- 参考答案
> 本工程参数 17154；训练行 108／116，均 200 次更新。完成标准：文件真实存在，能找到报告字段；作者成功不代替自己运行。

### 独立练习：继续训练的条件

只保存 `with_replay.pt`，能否声称精确续训？写出至少三类缺少的状态。

> [!example]- 参考答案
> 不能。缺优化器状态、已完成更新位置、随机与数据顺序等必要状态；本次模型很小、没有调度器，也不能因此把权重称为完整检查点。完成标准：区分可加载推理与等价续训。

### 迁移练习：比较 CPU/GPU

你 GPU 计数一致但损失最后小数不同，是否失败？提示：比较任务行为和数值一致是两件事。

> [!example]- 参考答案
> 小幅浮点差异可以正常；仍要分别检查损失有限、任务计数和错误路径。行为明显不同则保存两个报告，核对版本、seed、配置，不能直接抹掉差异。完成标准：记录差异，不把本次计数一致推广为所有硬件完全等价。

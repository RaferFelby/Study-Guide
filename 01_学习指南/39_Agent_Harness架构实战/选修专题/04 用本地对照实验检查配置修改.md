## 今天先做什么

先在纸上算出 `1200 元 + 80000 分 + 300 元`，再预测：只处理前两项会怎样？把“分”误当成“元”会怎样？带着这两个预测运行本节程序，最后交出一份四配置对照报告和一条有适用条件的经验。

## 一、为什么需要实际轨迹

上一讲可以在纸面上说“补齐资料”和“统一单位”，但两个修正影响的是不同问题。只看最后一个总额，可能不知道漏了哪一项；只看处理数量，又可能漏掉单位错误。

这里把任务缩小为三个虚构费用条目。与前面的三文件情景不同，本程序接收内存中的完整列表，并故意只处理其中一部分；“处理范围”不等于实际打开了多少文件。

| 编号 item_id | 数值 amount | 单位 unit | 正确的整数分 |
| --- | --- | --- | --- |
| venue，场地 | 1200 | yuan，元 | 120000 |
| food，餐饮 | 80000 | fen，分 | 80000 |
| travel，交通 | 300 | yuan，元 | 30000 |

合计 `120000 + 80000 + 30000 = 230000 分`，也就是 2300 元。用整数分保存金额，能在本例中避免小数表示误差；这不是完整财务系统，不处理汇率、税率、负数退款或小于一分的数值。

## 二、只改变两个明确的配置项

configuration（配置）是执行前给程序的行为设置。本节有两项：

- `max_items`：最多处理多少项；正整数表示限额，`None` 表示不设这个条目数上限。`None` 是 Python 的“没有具体值”，不是 0。
- `normalize_units`：是否按来源单位转换到整数分。`True` 表示执行单位归一化，`False` 表示故意把所有数值当作元。这是受控错误开关，不是应当保留在真实业务中的正常选项。

| 配置名 | max_items | normalize_units | 相对参考配置改变什么 |
| --- | --- | --- | --- |
| reference，参考 | 2 | False | 两个问题都保留 |
| process，处理范围候选 | None | False | 只补齐条目处理 |
| domain，单位候选 | 2 | True | 只修正单位规则 |
| composed，手工组合 | None | True | 同时采用两个修改 |

保持任务、顺序、程序与数据一致，每次执行重新建立总额和轨迹。这里枚举了两个开关的四种组合，便于区分影响。它没有文件或进程沙箱；内存结果互不共用，不代表能安全运行任意候选代码。

这个练习借用了论文“提出候选、比较执行、组合后再执行”的问题意识。论文的候选来自编辑器，不能把本节硬编码的四套配置称为论文算法实现。[方法来源：Harness² v1 §2.2](https://arxiv.org/html/2610.14224v1#S2.SS2)

## 三、在 VS Code 运行四配置对照

1. VS Code 打开本工作区，找到 `01_学习指南/39_Agent_Harness架构实战/示例工程`。
2. 从 [[01_学习指南/39_Agent_Harness架构实战/示例工程/README|代码导航]]打开 [contrast_lab.py](../示例工程/contrast_lab.py)。文件已经提供，不需要把整段源码复制到笔记。
3. 打开 PowerShell 终端，切换到这个示例工程目录。可以在 VS Code 资源管理器中右键该目录，选择在集成终端中打开，再用 `Get-Location` 确认路径。
4. 先只显示输出，不保存文件：

```powershell
..\..\..\.venv\Scripts\python.exe contrast_lab.py
```

三个 `..` 回到工作区根目录，随后使用共享 `.venv` 的 Python。程序只用标准库，不需要 GPU、额外安装或服务密钥。

预期输出：

```text
reference: items=2 total_fen=8120000 coverage=False total=False accepted=False
process: items=3 total_fen=8150000 coverage=True total=False accepted=False
domain: items=2 total_fen=200000 coverage=False total=False accepted=False
composed: items=3 total_fen=230000 coverage=True total=True accepted=True
```

其中 `items` 是实际参与累计的条目数；`total_fen` 是程序声称的整数分总额；`coverage` 检查是否处理了全部要求的编号，`total` 检查是否符合本例手算答案；`accepted` 要求两项都通过。

前两行的金额很大，是故意把 80000 分当成 80000 元造成的。参考行计算 `(1200 + 80000) × 100`；处理范围候选多加了交通，却没有修正单位，所以金额误差反而更大。**覆盖改善不等于整体结果改善。** 单位候选得到 2000 元，但漏了 300 元交通；组合后才符合当前任务。

再保存一份报告：

```powershell
..\..\..\.venv\Scripts\python.exe contrast_lab.py --output results/contrast-first.json
```

`--output` 指定保存路径；相对路径以终端当前目录为准。程序建立缺少的父目录，并用独占创建模式保存，已有同名文件会报 `FileExistsError`，不会覆盖。再次操作可改名为 `contrast-second.json`，保留前一次证据。

在 VS Code 打开新生成的 JSON：先找 `input_snapshot` 核对输入，再看 `runs` 下四套配置。JSON 是用于保存列表、字典、字符串和数值的文本格式；其中 `null/true/false` 对应 Python 的 `None/True/False`。

完成判断：能从 `domain → execution → trace` 中找到 food 的来源数值 80000、来源单位 fen、计入总额的 80000 分，并指出 travel 没有出现在该轨迹中。

## 四、沿源码读懂它为什么产生这些结果

### 先看数据对象，再看执行函数

`Expense` 是一条费用记录，包含编号、数值和单位；`BudgetConfig` 保存两个设置。`@dataclass` 让 Python 按声明的字段生成初始化等常用方法，省去重复赋值；例如 `Expense("food", 80000, "fen")` 的三个参数按字段顺序进入对象。`frozen=True` 禁止普通属性重新赋值，帮助避免无意修改；它不提供身份认证或恶意代码隔离。

类型标注 `int | None` 表示整数或无值。类型标注不会主动验证参数，所以 `execute_budget()` 开头仍检查：限额是正整数或 None、开关是布尔值、输入非空、编号不重复、数值是非负整数、单位受支持。布尔值不能冒充金额 1。所有输入先做格式检查，实际参与累计的条目才写入轨迹；不要把“校验过格式”误写成“已参与计算”。

函数随后把 `total_fen` 设为 0，把 `trace` 设为空列表。循环每次先判断是否达到上限，达到就 `break` 结束处理；否则按单位计算 `contribution_fen`，更新总额并追加一步轨迹。

`contribution_fen` 是本条对总额的贡献，不是当前累计值。保留来源数值、来源单位和转换后数值，才方便发现“读对了原值，但转换错了”的情况。函数返回新字典，不修改传入费用列表，也不调用 SQLite 或模型。

### 评价与执行分开

`evaluate_budget()` 接收运行结果和本例预先手算的要求。它提取轨迹编号，排序后比较完整列表，所以既能发现漏项，也不会用集合去重掩盖重复处理。总额另行比较，最后用 `and` 要求两项同时成立。

这里的检查器只接受本程序产生的结构，未实现任意不可信报告的结构验证，也没有检查所有语义或中间计算。通过两项检查只意味着“本例这两项要求通过”，不能叫通用正确性证明。

`run_comparison()` 依次运行四套手工配置，然后才分别调用检查器。程序没有根据评分自动选配置。`asdict()` 把数据类转成字典，便于把配置与输入保存进 JSON。保存入口与执行函数分离，因此导入模块不会自动创建报告。

### 组合以后再运行有什么价值

即使两个修改单独看都有理由，也要检查合起来的行为。本例开关相互配合后成功，是当前确定性算术下的结果。在模型系统中，提示之间可能冲突，随机性也可能影响输出；不能从本例推导“把好修改合并一定更好”。

下一次修改若把组合配置的上限改成 1，会再次漏项。应保留之前的配置和报告，撤回不符合要求的新设置，再重新运行旧配置确认。本程序不自动回滚；这个决定由学习者根据证据完成。

## 五、构造总额正确却漏项的反例

把交通费用改成 0 元。只处理前两项时，总额刚好仍是 2000 元，但任务要求列出的交通条目没有被处理。这样的反例能说明只测最终数字为什么不够。

在示例工程中新建 `lesson_contrast_zero.py`：

```python
from contrast_lab import BudgetConfig, Expense, evaluate_budget, execute_budget


def main():
    expenses = [
        Expense("venue", 1200, "yuan"),
        Expense("food", 80000, "fen"),
        Expense("travel", 0, "yuan"),
    ]
    result = execute_budget(expenses, BudgetConfig(2, True))
    report = evaluate_budget(result, ["venue", "food", "travel"], 200000)
    print(result["total_fen"])
    print(report)


if __name__ == "__main__":
    main()
```

运行：

```powershell
..\..\..\.venv\Scripts\python.exe lesson_contrast_zero.py
```

预期结果：

```text
200000
{'coverage_ok': False, 'total_ok': True, 'accepted': False}
```

代码先导入已经解释的四个对象，再创建新的费用列表；`BudgetConfig(2, True)` 表示最多处理两项并按单位换算。检查器收到的要求仍包含三个编号。这里的 `200000` 是此变体重新手算的结果，不能不加区分地沿用原任务 230000。

## 六、写有范围的经验，不记住旧答案

在 [[02_学习记录/00 我的学习记录|个人学习记录]] 的实际记录区按下面六行填写。先自己写，再对照示例；不需要改论文原始模板或新增正式教材文件。

```text
适用条件：存在不同金额单位，任务要求覆盖全部费用条目。
候选改动：取消本例的两项处理限制，按来源单位归一化。
行为证据：process 多处理 travel；domain 将 food 计为 80000 分。
组合结果：当前三条输入得到 230000 分，两项检查通过。
未解决的问题：只有确定性合成数据，未测模型、汇率或真实账单。
复用前要查：新任务的单位、完整条目清单、处理预算与期望结果。
```

其中“取消限制”只对当前小任务成立，不能迁移成“所有 Agent 都取消预算”。遇到大量输入，应设计分批处理与完整性检查，而不是无限运行。可以复用“核对单位和覆盖”的方法，不应复用旧任务的 230000 分作为新任务答案。

论文会根据改进记录提取有条件的经验；本节由学习者手工记录，不会自动写入或检索经验库。证据不足时记录“尚不能归因”，比强行给每次修改标注成功更准确。

## 七、分层练习与答案

### 跟做：说明一个改善和一个未解决问题

保存四配置报告，解释为什么 process 的 coverage 为 True，但 accepted 为 False。提示：对照 food 在两个轨迹中的贡献。

> [!example]- 参考答案与完成标准
> process 补上 travel，所以覆盖通过；food 仍被计成 8000000 分，单位错误没有修复。能指出具体轨迹字段并手算出 8150000 分才算完成，不能只说“模型不够好”，因为本程序没有模型。

### 独立：制造退步并恢复

在 `lesson_contrast_zero.py` 中先把上限改成 `None`，预测并运行；再改为 1，预测并运行。保留两次结果，决定恢复哪套配置。不要修改检查器来迁就失败输出。

> [!example]- 参考答案与完成标准
> None 时三项都处理，总额 200000，三项检查均为 True。上限 1 时只有 venue，总额 120000，覆盖、总额和接受均为 False。恢复 None 并再跑一次确认。这里的“退步”相对于同一个零交通任务，不能把不同输入的结果直接横向比较。能解释恢复依据并重现三个阶段才算独立完成。

### 迁移：未知单位不能沿用旧经验

将一条记录的单位换成 dollar。应该套用乘 100 的规则、静默当元，还是停止并明确缺少什么？下面的最小程序可保存在同目录 `lesson_contrast_unit.py` 验证拒绝路径。

```python
from contrast_lab import BudgetConfig, Expense, execute_budget


def main():
    expenses = [Expense("new_item", 10, "dollar")]
    try:
        execute_budget(expenses, BudgetConfig(None, True))
    except ValueError as error:
        print(error)


if __name__ == "__main__":
    main()
```

用共享解释器运行 `lesson_contrast_unit.py`，预期为 `不支持的单位：dollar`。`try/except` 只处理本节预期的输入错误，保留并显示具体原因；没有把失败包装成成功。

> [!example]- 参考答案与完成标准
> 当前程序只定义了同一货币的元／分换算，dollar 涉及另一种货币。需明确币种、目标币种、汇率来源与时间、舍入要求，才能另行设计规则。本练习只要求拒绝并说明缺失条件，不要求下载汇率或新增库。完成标准是保留错误信息，并写出为何旧经验不适用。

## 常见问题与本节完成判断

| 现象 | 先查什么 | 处理方式 |
| --- | --- | --- |
| 找不到 contrast_lab | 是否在本单元示例工程，文件名是否正确 | 从 README 打开源码，在该目录运行 |
| 报告已存在 | 是否重复使用 --output 路径 | 换一个明确的新文件名，保留旧记录 |
| True 被当作金额拒绝 | 布尔值与数值是否混用 | 使用明确的非负整数金额 |
| 输入为空、编号重复 | 是否误删费用或复制了同一编号 | 修正输入再执行，不删校验 |
| 运行后没有报告 | 是否只运行了不带 --output 的命令 | 此命令只打印；需要保存时加参数 |

能预测四配置结果、定位单位错误、解释零费用漏项、恢复退步配置，并写出经验适用条件后，再勾选本节。当前完成物是本地对照报告与个人经验记录；自动学习、真实模型效果及生产权限隔离尚不在本节范围内。

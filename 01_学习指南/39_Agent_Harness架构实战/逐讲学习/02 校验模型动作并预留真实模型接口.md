## 问题与前置

模型可能输出未知工具、缺参数或多余字段。即使输出是合法 JSON，也不代表动作合法。前置是 Python 字典、异常和单元 15 的工具契约。本节先用坏输入亲自观察拒绝，再看真实后端如何接入。

本工程只接受两种动作：`kind=tool` 带 `name/arguments`；`kind=final` 带 `text`。`kind` 是动作类别，不是执行权限。额外的 `approved=true` 也会被拒绝，模型不能在自己的输出中批准自己。

动作结构检查之后还要检查任务质量。当前退款任务要求笔记与回答的 `text` 使用 `30 天内申请退款 [policy-v1]` 这一固定句式，并核对数字、来源与实际笔记。JSON 合法的自由改写不一定通过最终验收，详见 [[01_学习指南/39_Agent_Harness架构实战/逐讲学习/07 分开检查执行完成与答案正确|结果核验详细课]]；真实模型选做路径同样使用这项约定。

## 最小校验实验

在本工程新建 `lesson_contract.py`，保存后运行 `..\..\..\.venv\Scripts\python.exe lesson_contract.py`。

```python
from contracts import validate_action


def main():
    good = {"kind": "tool", "name": "lookup_policy", "arguments": {"topic": "refund"}}
    print(validate_action(good)["name"])
    bad = {"kind": "tool", "name": "shell", "arguments": {"command": "anything"}}
    try:
        validate_action(bad)
    except ValueError as error:
        print("预期拒绝：", error)


if __name__ == "__main__":
    main()
```

预期先显示 `lookup_policy`，再显示 `预期拒绝： unknown tool`。第一步只验证，没有运行工具；第二步没有创建任何进程。`try` 中是可能失败的调用，`except ValueError` 处理已知契约错误，其他程序错误不应被隐藏。

## 真实后端怎样复用同一条链

`OllamaBackend.__call__` 是一个可调用对象：保存模型名后，像函数一样接收状态和消息，返回动作字典。它用标准库发送本机 HTTP 请求：消息 → `/api/chat` → JSON 响应 → 解析 `message.content` → 交给同一个校验器。这里采用**本课 JSON 动作协议**，没有声称实现所有供应商原生 tool-call 消息格式。

`stream=False` 要求完整响应；`format=json` 约束 JSON 形式，仍需程序检查字段；`num_predict=128` 限制生成长度，长度截断被当作失败；`num_ctx=2048` 是本课小上下文设置。`temperature=0` 减少采样随机性，不保证跨机器逐字一致。`keep_alive=1m` 短时复用已加载模型；读取超时 120 秒不是全任务硬时限，也不会强制取消服务器已经开始的生成。

## 选做：已有本地模型时的操作教程

按本轮学习安排，这部分保留操作教程，不要求安装、下载或运行真实模型。先用 `ollama list` 查看已有模型；没有模型时，先说明安装／下载范围并确认，不直接执行拉取命令。

若已有本机记录中的模型，可在新数据库上运行：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py start --db results/local-model-01.db --model qwen2.5-coder:7b-instruct-q4_K_M
..\..\..\.venv\Scripts\python.exe demo.py step --db results/local-model-01.db
..\..\..\.venv\Scripts\python.exe demo.py show --db results/local-model-01.db
```

模型名必须以自己的现有列表为准。后续步骤与规则后端相同，但模型可能提议非法动作或提前完成；失败应保留，不能改成规则回答后仍称模型成功。当前接口固定 `127.0.0.1`、禁用环境代理，不读取密钥；云端适配需要另行设计认证、费用预算和数据边界。

## 排错与练习

连接拒绝先检查本地服务；超时先区分模型冷加载和生成耗时；字段错误看 `events` 中 `failed.details.reason`；`done_reason=length` 表示输出未完整，不能猜补 JSON。响应体超过 64 KiB 会被拒绝。

跟做：把工具名改为不存在的名字。独立：给合法动作加 `approved=True`，预测是否通过。迁移：模型一次返回两个工具调用，本接口应怎样处理？

> [!example]- 答案与判断标准
> 未知工具被拒绝；多出的 `approved` 字段也被拒绝。本课每轮只允许一个动作，列表会触发类型错误；若支持多个动作，必须设计依赖、逐项授权、结果关联与部分失败，不能简单循环执行。能说清“JSON 可解析、字段合法、有权执行、任务有效”是不同检查，才完成本节。

接口依据：[Ollama Chat API](https://docs.ollama.com/api/chat)。接口与模型能力会变化，教程使用明确的本地协议和边界。

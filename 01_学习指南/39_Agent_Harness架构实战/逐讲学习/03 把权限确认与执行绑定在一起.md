## 为什么不能只保存一个 approved

如果用户批准保存内容 A，模型随后换成内容 B，一个全局 `approved=True` 可能错误放行 B。应批准**具体动作及其参数**。本节使用 SHA256：将排序后的 JSON 编码成字节，再计算固定长度摘要。相同动作得到相同摘要，内容改变通常会得到不同摘要。

摘要不是密码、签名或用户身份凭证。任何能访问数据库的人都可以计算它。本课展示的是防止操作内容错配；生产系统还需认证、会话／用户／资源绑定、授权有效期和可信审计。前置见单元 15 的确认与单元 21 的执行边界。

## 动手：先停在门前

沿用第 1 讲 `results/first.db`，它已经完成一次查询。在同一目录执行：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py step --db results/first.db
..\..\..\.venv\Scripts\python.exe demo.py show --db results/first.db
```

预期 `status=waiting_approval`、`calls=2`、`notes=[]`。检查 `state.pending`：工具是 `save_note`，文字是本地学习笔记；`approval_key` 是摘要。这里先把待确认动作存盘，因此关闭终端再打开不会要求模型重新猜一个动作。

先用错误摘要验证没有写入：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py step --db results/first.db --approve wrong-key
```

仍为等待，笔记数仍为 0，`calls` 仍为 2。等待时没有再次问模型，也不会因为多运行一次就绕过确认。

## 确认后再执行

看清笔记内容并决定允许保存后，在 PowerShell 运行以下三行。第一行把 `show` 的 JSON 转成 PowerShell 对象；第二行读取刚显示的摘要；第三行提交该动作的摘要。不要把这段放进无条件自动批准所有任务的循环。

```powershell
$preview = ..\..\..\.venv\Scripts\python.exe demo.py show --db results/first.db | ConvertFrom-Json
$noteApprovalKey = $preview.approval_key
..\..\..\.venv\Scripts\python.exe demo.py step --db results/first.db --approve $noteApprovalKey
..\..\..\.venv\Scripts\python.exe demo.py step --db results/first.db
```

保存后 `notes` 有一项、`status=ready`，决策数仍为 2；最后一步才生成最终回答，`calls=3`、`status=completed`。工具执行和模型决策是不同动作，批准旧动作无需再次调用模型。

## 程序强制了哪些边界

`validate_action` 只允许两个已注册工具；`lookup_policy` 只读固定 topic；`save_note` 只收最多 500 字符的文本，没有路径、Shell 或网络参数。保存前还检查已有政策观察。模型即使要求访问别的文件，程序也没有相应执行分支。

当前没有“用户 A 和用户 B”的隔离系统；它是一个本机学习者管理一个可信数据库。文件权限、数据库篡改、凭证隔离与沙箱是另外的机制，不应因为一个确认摘要就宣称安全系统完整。

## 常见错误与练习

摘要不匹配时先检查是不是换了数据库或修改过动作；不要关闭校验。若不想保存，执行 `demo.py cancel --db results/first.db`，状态进入 `cancelled`，后续 `step` 不再执行。

跟做：错误摘要后核对笔记数。独立：把笔记文字改一个字，原摘要应继续有效吗？迁移：将保存工具替换为支付，除摘要外还需要哪些字段和外部保证？

> [!example]- 答案与完成标准
> 错误摘要后笔记数为 0；内容改变后必须重新确认。支付至少要把主体、收款方、金额、币种、动作 ID 和有效期绑定授权，还需支付服务端幂等键与查询结果，不能靠本地摘要防止重复扣款。本课没有实现支付。能分别指出输入校验、执行许可、身份认证与业务幂等的职责，才完成本节。

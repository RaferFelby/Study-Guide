## 要判断的不是一个成功字符串

`completed` 是程序按当前检查规则接受结果。它不能证明任意自然语言答案正确，也不能证明系统适合生产。前置是本单元全部控制流程和单元 19 的评估分母。

早期版本只检查答案含 30 与来源标记，会误收“300 天”和否定回答。当前 `evaluate_final` 拆出天数与来源，并核对真实数据库笔记、查询观察与批准动作摘要；分别报告执行完成、答案正确和笔记正确。

本任务笔记与回答采用固定句式 `30 天内申请退款 [policy-v1]`。格式外的正确同义表达也可能被拒绝，因此不能把本检查器当作通用语义评测。完成本讲后进入 [[01_学习指南/39_Agent_Harness架构实战/逐讲学习/07 分开检查执行完成与答案正确|结果核验详细课]]，亲自构造七个反例并复核数据库。保存前仍需检查内容；最终质量失败不会撤销已经提交的笔记。

## 用同一任务检查四类结果

| 维度 | 该看什么 | 本例可复核证据 |
|---|---|---|
| 控制正确 | 非法工具是否执行、等待时是否写入 | failed / approval_required 与笔记数 |
| 恢复正确 | 是否丢预算、重复保存 | calls、pending、事务提交、唯一笔记 |
| 任务质量 | 期限与来源、实际笔记是否符合政策 | evaluation 分项报告；格式外文本人工核对 |
| 资源成本 | 模型尝试几次、外部调用多少 | calls；本地规则不折算成真实 token 费用 |

一次失败可能属于多个维度。超时是调用未正常完成，不等于模型推理错误；参数错是契约拒绝，不等于工具内部故障。

## 动手运行回归

在 VS Code 示例工程终端运行：

```powershell
..\..\..\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`-m unittest` 使用标准库测试框架；`discover` 查找测试；`-s tests` 指定本单元目录；`-v` 显示每项名称。测试使用 `results/test-随机标识` 中的新数据库，保留用于排错，不碰自己的会话。预期全部通过，当前具体数量看作者验证记录。

再创建 `--max-calls 1` 的新会话，连续运行两次 step：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py start --db results/budget-01.db --max-calls 1
..\..\..\.venv\Scripts\python.exe demo.py step --db results/budget-01.db
..\..\..\.venv\Scripts\python.exe demo.py step --db results/budget-01.db
```

第一次查到政策，第二次 `budget_exhausted`，没有笔记。取消实验可沿用第 4 讲正等待确认的 `crash-01.db`：

```powershell
..\..\..\.venv\Scripts\python.exe demo.py cancel --db results/crash-01.db
..\..\..\.venv\Scripts\python.exe demo.py step --db results/crash-01.db
```

两次都应显示 `cancelled`，不会保存笔记；之后提交旧摘要也不应恢复执行。

## 一份可复核的报告

不要只写“跑通”。至少记录：后端类型、代码日期、会话文件、初始目标、事件顺序、模型调用数、批准动作、笔记数、最终结果、人工核对与未测范围。默认完整链应为：创建→查询→等待确认→保存→最终检查，决策数 3，笔记数 1。

对比规则与真实模型时，保持任务、工具、确认策略和评分一致。规则确定性验证控制边界；真实模型验证输出协议与决策行为；两类结果分别报告。本轮按学习者选择，以规则与本地故障实验验收，真实后端是选做入口。

## 练习

跟做：保存一条正常轨迹与一条预算失败轨迹，逐事件解释。独立：模型声称“保存成功”，但 notes 为空，应把问题记在哪一层？迁移：怎样验证两个模型使用同一 harness 时谁更合适？

> [!example]- 参考答案
> 先查动作是否真的被提议、批准、执行并提交；模型文字不是副作用证据。模型比较要有固定但未用于反复调提示的独立题集、相同工具／预算、逐题成功规则、失败类型与调用成本，还应多次运行观察波动。不能凭本课一个退款题的成功选出“最强模型”。

> [!example]- 综合完成标准
> 不看答案画出组件图；使用新数据库完成一次 3 决策、1 笔记的链路；错误摘要不写入；提交后崩溃不重做已提交工具；预算跨命令保留；能解释上下文与事件日志、角色交接与执行权限的区别。以上都亲自完成后才记录个人进度。

## 这一讲要解决什么问题

树模型能表达“如果某特征超过某值就走左边”的规则；随机森林组合许多不同的树；梯度提升逐步训练树来修正之前的误差。它们可能刻画非线性关系，但复杂度也会带来过拟合。怎样在有限数据上公平比较？

## 从决策树到集成模型

- **决策树**递归选择特征和切分点，把数据分成更相似的小组。树太深时会记住训练样本，所以常用 `max_depth`、`min_samples_leaf` 限制复杂度。
- **随机森林**训练许多带随机性的树，再合并其预测，通常比单棵树稳定。更多树会增加训练与推理开销；`min_samples_leaf` 可避免叶子只记一两个样本。
- **梯度提升树**一轮一轮添加小树，关注当前误差。树的数量、每棵树的复杂度和学习率共同影响结果。本工程用 scikit-learn 的 `HistGradientBoostingClassifier`，它使用直方图方法提高大数据效率；不同实现的参数并不完全相同。

它们与线性模型的偏好不同：逻辑回归形式简单且需要数值缩放；树模型能自然处理非线性与特征交互，但不因此自动避免泄漏、偏差或错误切分。

## 交叉验证的直觉

交叉验证（cross-validation，CV）把训练集分成多个折（fold）：轮流用一部分作临时验证，其余作拟合，再汇总分数。它能减少一次随机切分带来的偶然性，但不会创造新数据，也不能替代最终独立测试集。类别任务常用分层折，时间数据则不能随意打乱。

每一折都必须单独拟合预处理。把完整 Pipeline 传给 `cross_validate` 或 `GridSearchCV`，scikit-learn 会在每一折的训练子集上 `fit`；若先用全部训练集算好填补均值再交叉验证，仍会泄漏到折内验证数据。

## 正则化与参数搜索

**正则化**通过限制模型复杂度，降低模型记住噪声的倾向。逻辑回归的 `C` 越小，约束通常越强；树的深度越小，规则通常越简单；随机森林的叶子样本数越大，小分支越难出现。参数搜索只在训练集内部的交叉验证完成，不看外层 dev/test。

下面是一个可选的逻辑回归搜索示意，放在模型比较之后再尝试：

```python
from sklearn.model_selection import GridSearchCV, StratifiedKFold

from app.data import make_customer_dataset
from app.modeling import make_candidate_models, split_data

splits = split_data(make_customer_dataset())
pipeline = make_candidate_models()["logistic_regression"]

search = GridSearchCV(
    estimator=pipeline,
    param_grid={"model__C": [0.1, 1.0, 10.0]},
    scoring="average_precision",
    cv=StratifiedKFold(n_splits=5, shuffle=True, random_state=34),
)
search.fit(splits.x_train, splits.y_train)
print(search.best_params_)
print(search.best_score_)
```

`model__C` 中双下划线表示 Pipeline 里名为 `model` 的步骤参数；`scoring="average_precision"` 指搜索以平均精确率选择参数。训练集样本不多时五折的每份训练更小；数据很多时也可以根据任务选择更少折。搜索结束后仍只能在 dev 选择最终模型，test 保持封存。

## 动手操作与阅读比较结果

示例工程的 `make_candidate_models` 用同一个预处理 Pipeline 比较多数类基线、逻辑回归、受限决策树、随机森林和直方图梯度提升。先运行 `train.py`，记下每个模型 dev AP 与 ROC-AUC。

然后对你最关心的两个模型，在 `x_train/y_train` 上做五折 `cross_validate`。把 `scoring="average_precision"` 的每折得分和平均值写下来；改随机种子再运行一次，观察分数是否明显波动。报告中保留配置和折数，不能只摘最好的一折。

## 常见错误

- **把测试集拿去搜参数。** 搜索尝试次数越多，越容易过拟合到测试分数；CV 在训练集内部进行，dev 选择，test 最终评估。
- **给每个算法用不同的测试样本。** 比较应使用相同划分，否则差异可能来自样本难度。
- **只报告最好的一折。** 这会夸大偶然高分；报告平均值、波动，并保留每折结果。
- **认为树模型无需 Pipeline。** 填补缺失、类别编码与数据切分仍需正确处理，预处理仍应按训练折拟合。
- **把 XGBoost 当成必需项。** 它是可选的提升树实现，可能增加依赖与参数复杂度；先把 scikit-learn 的模型比较做好。

## 练习与答案解析

### 跟做练习

把决策树 `max_depth` 从 4 改成 20，比较训练分数与 dev 分数。你预计哪种情况暗示过拟合？

> [!example]- 参考答案
> 若训练分数继续升高而 dev 分数下降或波动变大，说明更深的树可能记住训练细节，泛化变差。单次结果不足以定论，最好结合 CV 和不同划分稳定性。

### 独立练习

给逻辑回归搜索 `C` 的三个值，并记录每折平均 AP。完成标准：搜索仅用 `x_train/y_train`， Pipeline 包含预处理，最终测试集没有参与选择。

### 迁移练习

若业务数据按客户分组，讨论普通 `StratifiedKFold` 为什么会把同一客户的记录分到训练折与验证折。选一个 group-aware CV 策略并说明它如何避免此问题。

> [!example]- 参考思路
> 同一客户的相近记录可能高度相似，折间共享客户会让验证过于容易。`StratifiedGroupKFold` 在分组不重叠的约束下尽量保持类别比例；若是预测未来，还要考虑按时间验证。

## 本讲小结

树与线性模型有不同表达能力，公平比较要求同一数据划分、同一预处理边界与清楚的复杂度设置。交叉验证只在训练数据内部帮助估计稳定性和选择参数，不能取代最终测试集。

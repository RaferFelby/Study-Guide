## 这一讲要解决什么问题

整体分数会掩盖局部失败：模型可能对 basic 套餐做得很好，对 premium 套餐却经常误报。分类器输出的概率还要通过阈值变成动作。阈值下降通常找回更多正例，也会增加被错误标记的负例。

## 误差切片是什么

**误差切片**是把数据按一个有意义的条件分组，分别统计模型错误与指标。例如按 `plan_type`、使用量高低、地区、时间段或用户类型切片。先提出可能有意义的分组，再检查数量和指标；不要在测试集上不断尝试切片、看到不喜欢的结论后换分法。

下面的片段演示在固定测试结果上按套餐查看混淆情况。它用于一次描述性检查；正式实验应事先定义关心的切片，并同时报告每组样本数：

```python
test_rows = splits.x_test.copy()
test_rows["actual"] = splits.y_test.to_numpy()
test_rows["probability"] = test_probabilities
test_rows["predicted"] = test_rows["probability"] >= threshold

for plan_name, plan_rows in test_rows.groupby("plan_type", dropna=False):
    error_rate = (plan_rows["predicted"] != plan_rows["actual"]).mean()
    print(plan_name, len(plan_rows), round(error_rate, 3))
```

样本太少的切片会有很大随机波动，不能把小组的 100% 错误率当作确定规律；同时检查覆盖人数、误差类型和不确定性。

## 阈值与业务代价

分类器通常先输出概率 `p`。阈值 `t` 把概率转换为动作：`p >= t` 判为正类。本例正类1是续费，负类0是未续费。在同一组固定分数和标签上降低阈值，正类预测数不会减少；有真实正类时，Recall不会下降，但可能保持不变。Precision可能下降、上升或不变，不是数学上必然下降。

例如标签[1,0,1]、分数[0.9,0.7,0.4]：阈值0.5时TP=1、FP=1、FN=1，Precision=0.5、Recall=0.5；阈值0.3时TP=2、FP=1、FN=0，Precision=2/3、Recall=1，两者都上升。下降还是上升取决于新纳入样本的类别；在示例工程的`test_metrics.py`可运行此反例。

若错误代价可估计，可对阈值 `t` 计算总成本：

`成本(t) = 假正例数(t) × 单个假正例代价 + 假负例数(t) × 单个假负例代价`

假设业务对“预测不续费”的客户做挽留：把本会续费的客户错判为不续费（FN），可能浪费挽留资源；把不会续费的客户错判为续费（FP），才可能漏掉挽留机会。这里正类仍是续费；若改成流失为正类，FP/FN名称也要随标签定义改变。最佳阈值由业务动作、资源容量、成本和风险决定；F1最大值只是某一种折中，不是普遍业务最优。

工程的 `choose_f1_threshold` 只在 dev 标签和 dev 概率上选阈值。随后在测试集上评估一次。它让你看到阈值从 0.5 改变后的影响，但报告必须注明阈值按开发集 F1 选择，且未根据真实业务成本优化。

## 概率校准是什么

概率**校准**关注“报 0.8 的样本中，约 80% 是否真的为正类”。它和排序能力不同：模型可以 AP 很高，却把概率普遍报得太高。可用可靠性图检查，并结合 Brier 等概率评分；Brier 还反映区分能力等因素，不能仅凭其下降证明校准改善。拟合校准器需要独立于基础模型拟合的数据，或适当的折外预测，不能拟合最终测试标签。

先知道概率并非天然可信，再完成 [[01_学习指南/07_传统机器学习与数据分析/逐讲学习/09 手算概率误差与可靠性表|可靠性表、Brier 与 ECE 手算]]和 [[01_学习指南/07_传统机器学习与数据分析/逐讲学习/10 隔离校准数据并检查校准是否改善|独立校准实操]]。不要因为函数名叫 `predict_proba` 就声称概率已校准；也不要在很小的测试集上过度解读可靠性图。

## 动手操作

1. 运行 `train.py`，记下开发集所选模型、阈值、测试混淆矩阵。
2. 在 `train.py` 输出报告中加入一个预先选定的业务切片：按套餐统计数量与错误率。确认每组样本量，缺失套餐单独列出。
3. 在开发集分别用 0.3、0.5、0.7 计算 Precision、Recall、F1，观察阈值变化；不要用测试标签选出“最漂亮”的阈值。
4. 写下对业务可解释的单个 FP 和 FN 成本，说明这些数值来自真实数据、领域假设还是纯教学假设。
5. 对照结果报告中 `threshold_selected_on_dev` 与 `test_metrics`。阈值在 test 之前已确定，不能看到 test 后再改它。

## 常见错误

- **把 F1 最优阈值当成业务最优。** 如果 FP/FN 代价不同，应直接比较业务成本或受约束的召回/精确率。
- **在测试集选阈值。** 这样测试集就参与了模型选择，最终分数偏乐观；阈值在 dev 上选好，再锁定用于 test。
- **只报告一个小切片的百分比。** 小样本组指标不稳定；必须报告组样本量、正例数和错误数量。
- **把高 AP 解释为概率校准。** 排序和概率数值的可信程度是不同问题。
- **忽视部署限制。** 即使低阈值提高召回，人工审核量也可能超出团队处理能力；阈值要结合容量约束。

## 练习与答案解析

### 跟做练习

把阈值从 0.5 降到 0.3，预期正类预测数怎样变化？通常哪个指标会增加、哪个可能下降？

> [!example]- 参考答案
> 更多样本满足 `p >= threshold`，所以正类预测数不会减少。Recall 通常会上升，Precision 可能下降；具体幅度要通过固定数据集计算，不能只凭方向猜数值。

### 独立练习

假设 FP 成本为 2，FN 成本为 10。按 0.1 步长在开发集选择总错误成本最低的阈值。完成标准：阈值只基于开发标签选择，并记录每个阈值的 FP/FN 数。

### 迁移练习

模型服务对象包括不同使用频率的客户。选择一个切片方法，写出切片数量、正例数量、Recall 和阈值，并讨论小组样本少时怎样向决策者表达不确定性。

> [!example]- 参考思路
> 可按使用频率预先定义“低/中/高”组，报告每组总体数和正例数，再报告 Recall。小组样本少时明确结果不稳定，避免用单一百分比作部署决策；必要时收集更多数据或合并有业务意义的组。

## 本讲小结

错误切片回答“在哪些样本上出错”；阈值把概率变成有成本的动作；校准回答概率数值是否可信。先定分析问题和数据边界，再读结果，避免事后挑分组或测试阈值。

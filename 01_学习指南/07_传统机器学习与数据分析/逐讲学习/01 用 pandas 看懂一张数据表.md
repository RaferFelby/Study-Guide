# 第 1 讲：用 pandas 看懂一张数据表

## 这一讲要解决什么问题

建模前，我们要先知道数据长什么样。列可能代表数字、类别或目标；数据可能缺失；类别比例也可能不均衡。如果不先检查，程序虽能运行，模型却可能学到错误的东西。

## 开始前需要什么

会运行 Python 文件、调用函数和读取终端输出即可。若还不熟悉导入模块与运行脚本，先看 [[01_学习指南/01_Python工程化/逐讲学习/01 运行Python并统计工单|运行 Python 脚本]]。本讲使用 pandas 表格和 NumPy 随机数；安装依赖的规则见 [[01_学习指南/07_传统机器学习与数据分析/00 传统机器学习与数据分析学习地图#前置与完成标准|单元环境说明]]。

## 表格、行、列与目标

pandas 的 `DataFrame` 是带列名的表格：每一行通常代表一个样本，每一列记录样本的属性。比如一行是一位客户，`age` 是年龄，`plan_type` 是套餐类别，`renewed` 是我们要预测的结果。

我们把输入属性叫**特征**（feature），把要预测的列叫**目标**（target）。这个例子的目标是 `renewed`：1 表示续费，0 表示没有续费。特征必须是在预测发生时实际可获得的信息；事后才出现的列不能拿来预测过去。

## 最小示例：查看数据概况

在示例工程目录打开 VS Code 终端，执行：

```powershell
..\..\..\.venv\Scripts\python.exe -c "from app.data import make_customer_dataset; data = make_customer_dataset(); print(data.head()); print(data.shape)"
```

`-c` 表示让 Python 直接执行引号中的一小段代码；`head()` 看前五行，`shape` 返回“行数、列数”。应看到 1200 行、6 列。随机种子固定，所以本机重复运行会产生相同数据。

## 逐步检查

本讲对应代码在 [app/data.py](../示例工程/app/data.py)，数据生成函数叫 `make_customer_dataset`。为了看到常用检查，可以在终端继续执行：

```powershell
..\..\..\.venv\Scripts\python.exe -c "from app.data import make_customer_dataset; data = make_customer_dataset(); print(data.dtypes); print(data.isna().sum()); print(data['renewed'].value_counts(normalize=True).round(3)); print(data.describe())"
```

- `dtypes` 显示每列的数据类型。数值列可以计算均值；类别列保存文字，不应直接假装成连续数值。
- `isna()` 对每个单元格判断是否缺失，`sum()` 逐列统计缺失数量。
- `value_counts(normalize=True)` 显示类别比例。若目标中 0 占 90%，只预测 0 也能得到 90% accuracy；所以准确率并不总能代表模型有用。
- `describe()` 汇总数值列的计数、均值、标准差和分位数。分位数告诉我们数据分布的位置，不能单独证明因果关系。

示例生成的 `age`、`monthly_usage`、`late_payments` 是数值特征；`plan_type` 和 `region` 是类别特征；`renewed` 是目标。部分输入特征带有缺失值，后面会学习怎样只从训练数据估算填补值。

## 动手操作

1. 打开 `示例工程/app/data.py`，找到返回 `DataFrame` 的字典，确认哪一列是目标。
2. 运行上面的检查命令，抄下行数、列数、每列类型、缺失数量和目标比例。
3. 把 `make_customer_dataset()` 改为 `make_customer_dataset(sample_count=200)`，再查看 `shape`。传入 50 时应该收到清晰的 `ValueError`；原因是代码要求至少 100 行，避免后续划分过小。
4. 解释类别列为何不是“有缺失时就填 0”：`plan_type` 的 0 可能被理解为真实数值，而非一个套餐名称。

## 常见错误

- **把目标列也放进输入特征。** 模型会直接读到答案，形成数据泄漏；创建模型前要把目标与特征分开。
- **只看前几行。** `head()` 只能帮助快速浏览，不代表整张表没有坏数据。还要看类型、缺失和类别比例。
- **把缺失值等同于 0。** 0 可能有实际意义，应先理解字段定义，再选择填补方式或明确标记缺失。
- **把类别数字当作大小。** 若把套餐映射成 basic=0、plus=1、premium=2，模型可能误以为 premium 与 plus 的距离等于 plus 与 basic；类别编码的选择需要表达正确语义。
- **把合成数据当作业务证据。** 本数据由已知公式生成，只适合练流程；不能据此断言真实客户续费规律。

## 练习与答案解析

### 跟做练习：读懂比例

运行 `value_counts(normalize=True)`。如果续费比例约为 0.4，未续费比例约为 0.6，只预测“未续费”的 accuracy 大约是多少？这能说明模型有用吗？

> [!example]- 参考答案
> 只预测占多数的“未续费”，accuracy 约为 0.6。它只是一个很简单的基线，不能说明模型已学到有用关系；还需要与基线比较 Precision、Recall、AP 等指标，并考虑错误代价。

### 独立练习

写一段检查代码，打印各类别列的不同取值数。完成标准：能发现拼写差异（例如 `north` 与 `North`）会被当成两个类别。

### 迁移练习

假设表中新增 `account_closed_date`（销户日期），任务是在每月 1 日预测客户下月是否续费。解释为什么不能直接把这个字段用于预测，并举一个真正可在预测时获得的替代特征。

> [!example]- 参考思路
> 月初预测时，下月销户日期尚未发生，字段包含了未来信息，会让离线结果虚高。可使用月初之前累计的逾期次数、近 30 天使用量等特征，但仍需确认这些数据在预测时间点可获得。

## 本讲小结

先确认行、列、类型、目标、缺失和类别比例，再决定怎样切分和建模。探索分析是发现数据问题的过程，不是通过观察测试集反复修改模型的借口。

## 这一讲要解决什么问题

一个可复核的实验不只是“某模型得分很高”。读者需要知道预测什么、数据如何生成、怎样切分、比较了什么、怎样选阈值、模型在哪里失败，以及结论不能推广到什么地方。本讲把前五讲串成一份一页报告。

## 一页报告的结构

复制以下模板到示例工程 `results/experiment_report.md`，用实际运行结果填写。运行结果暂时不可用时，把未知信息标成“待运行”，不要编数字。

```markdown
# 实验报告：合成客户续费分类

## 问题与目标
- 预测时点、正类定义、可能的业务动作：

## 数据与切分
- 数据来源、行数、特征、目标、缺失与类别比例：
- 切分方法及理由（train/dev/test）：
- 随机种子和任何时间/分组约束：

## 方法与对照
- 基线、线性模型、树模型及关键参数：
- 预处理 Pipeline 与拟合边界：
- 开发集模型选择指标、阈值选择规则：

## 结果
- 每个候选模型的开发集 AP / ROC-AUC：
- 选中模型、阈值、最终测试集 Precision / Recall / F1 / AP：
- 测试混淆矩阵与预先定义的误差切片：

## 没有改善的方案
- 哪些模型/设置没有超过基线，证据是什么：

## 限制与适用范围
- 数据、切分、样本量、标签、校准和业务成本的限制：
- 这些结果可以支持什么决策，不能支持什么决策：
```

## 如何保证结论可信

1. **先写任务定义。** 正类、预测时点、实际动作若不明确，指标没有统一解释。
2. **说明数据来自哪里。** 本工程由固定公式合成；它只能练习工作流，不代表客户真实规律或业务效果。
3. **把选择与最终评估分开。** 模型、参数和阈值在训练/CV/dev 决定；test 只评估最终方案一次。
4. **报告未改善方案。** 基线或树模型未超过逻辑回归也是有效结果。不要删掉不利实验，也不要只挑最高指标。
5. **把指标连到动作。** 解释一个 FP 和 FN 分别意味着什么、阈值如何影响工作量；成本假设要标明来源。
6. **讲明适用边界。** 样本量、合成数据、时间变化、分组泄漏、类别不平衡、未校准概率等，都可能改变结论。

工程运行后生成的 `results/report.json` 保存机器可读结果；人工报告补充问题定义、指标解释、未改善方案和适用范围。运行命令及文件位置见 [示例工程 README](../示例工程/README.md)。

## 动手操作

1. 在示例工程目录运行 `..\..\..\.venv\Scripts\python.exe train.py`，确认 `results/report.json` 存在。
2. 逐字段核对报告：数据种子、开发集排序、阈值、测试指标和限制是否与程序输出一致。
3. 按模板新建 `results/experiment_report.md`。如模型没有超过基线，就把它写在“没有改善的方案”里。
4. 交给另一位读者，只看报告回答：模型预测什么？测试集是否参与选阈值？一个假负例会造成什么？数据是否代表真实客户？若对方无法回答，补充上下文。
5. 写清楚“合成数据实验不能支持真实营销部署”这一边界；不得把模拟收益写成业务成果。

## 常见错误

- **只放最高分。** 没有基线和未改善方案，读者无法判断复杂模型是否值得。
- **把 dev 结果称作测试结果。** 表头标出 split 名称，别把调参分数写成最终泛化成绩。
- **没有预测时点。** 可能用了未来信息；报告应说明每列在预测当时是否可见。
- **省略数据限制。** 合成数据、少数类样本少或时间不稳定都会限制外推。
- **把相关性写成因果。** 模型发现的关系不等于改变某特征就能改变续费结果。

## 练习与答案解析

### 跟做练习

填写模板的“数据与切分”和“没有改善的方案”。用两三句解释为什么 test 不应在调参时重复查看。

> [!example]- 参考答案
> 报告需写出固定随机种子的合成数据、特征和三份切分；未改善方案需列模型与开发集分数。若反复根据 test 调模型，test 就参与了选择，最终分数会偏向这组测试样本，不能再作为未见数据的公正估计。

### 独立练习

用报告解释一个混淆矩阵中的 FP 和 FN，并写出业务代价假设来自哪里。完成标准：能分别解释两个错误，不把成本假设伪装成实测事实。

### 迁移练习

把任务换成“预测设备未来 7 天是否故障”。重写预测时点、切分策略、正类、主要错误代价和一个时间相关误差切片。

> [!example]- 参考思路
> 预测时点为每个设备的每日截点，正类为之后 7 天内故障。按时间向前验证，并按设备分组避免相邻窗口跨集合。FN 可能导致停机，FP 可能带来不必要检修；应按设备型号或月份切片，并注明类别比例和样本量。

## 单元结业检查

- [ ] 我能从表格中分清特征与目标，并检查缺失值和类别比例。
- [ ] 我能解释为什么预处理要放在 Pipeline 中、并只在训练折拟合。
- [ ] 我能按数据生成方式选择随机、分组或时间切分，并保留最终测试集。
- [ ] 我比较过多数类基线、线性模型和树模型，并解释至少两个分类指标。
- [ ] 我能读混淆矩阵，说明阈值和 FP/FN 代价。
- [ ] 我完成一页报告，保留未改善方案和适用范围。

勾选前请确认有自己运行的输出和报告；作者示例或参考验证记录不能代替学习者证据。

## 本讲小结

好的实验报告让别人能复核设置和限制，而非只记住一个分数。写清数据、切分、对照、选择、错误、失败方案和适用范围，传统机器学习闭环才算完整。

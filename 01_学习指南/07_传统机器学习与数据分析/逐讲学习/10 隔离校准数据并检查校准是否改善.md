## 1. 校准器究竟学什么

基础模型把客户的年龄、使用量等特征变成一个分数。校准器再学习“这样的分数应对应多大的正类概率”。它需要带标签的数据；调用一个名叫“校准”的函数并不意味着结果一定可靠。

本课使用 sigmoid 映射：

`校准概率 = 1 / (1 + exp(A × f + B))`

`f` 是基础分类器的分数，`exp` 是指数函数；`A` 控制映射变化方向与幅度，`B` 调整位置。A、B 都是利用校准集标签拟合的参数，不是你根据测试效果手填的常量。符号正负属于公式约定，不应把它机械地对应为逻辑回归源码中的权重名称。

本例的基础模型是逻辑回归 Pipeline，它提供 `decision_function` 原始分数。scikit-learn 校准器优先用这个接口；不存在时才用 `predict_proba`。所以这里不是把已输出的概率直接当作公式中的 f。库负责参数估计和数值细节，教学公式只解释映射机制。[接口依据：CalibratedClassifierCV](https://scikit-learn.org/stable/modules/generated/sklearn.calibration.CalibratedClassifierCV.html)。

还会遇到 **isotonic（保序）校准**：学习一个随分数非递减的映射，可形成平台并让多个分数得到相同概率。它比两参数 sigmoid 更灵活，也更容易在小数据上过拟合；不是“方法更复杂就一定更准”。本课默认只拟合预先确定的 sigmoid；选法需要另留开发数据，不能看到 test 后再选。

## 2. 为什么要隔离三份数据

| 数据 | 数量 | 本课允许做什么 | 不能顺手做什么 |
|---|---:|---|---|
| train | 720 | 拟合缺失值填补、标准化、类别编码与逻辑回归 | 用它的拟合内预测冒充独立校准样本 |
| calibration | 240 | 让已冻结基础模型给分，再拟合 sigmoid | 同时不断选模型、调参数，再声称没有选择偏差 |
| test | 240 | 固定方案后对原模型与校准后模型作一次描述性比较 | 反复换校准法、阈值或箱数，挑最高分后当最终成绩 |

原 `split_data` 返回的中间划分字段叫 `x_dev/y_dev`。本独立实验把这份划分**专门用于 calibration**，没有运行 `train.py` 的开发集选模型流程。字段名没改，职责在这次实验中明确改变；不要把两份实验的选优过程混在一起。

`FrozenEstimator` 包住已经训练好的整个 Pipeline，使校准时对基础模型的拟合成为空操作。这样填补器、标准化器、编码器和分类器都保持原拟合状态。**冻结不检查数据重叠**；仍须自己保证训练和校准样本分离。本课 `require_disjoint_rows` 检查三组保留的唯一行索引，但无法识别不同记录是否属于同一用户，也无法替代时间切分。

冻结包装也不是不可变备份。不要在校准后直接对原 `base_model` 再调用 `fit` 或改写其参数；这可能改变校准器所依赖的基础模型。重新训练基础模型后，应重新准备与之匹配的校准过程。

若真实数据有重复用户、时间顺序或分布变化，应先按实体或时间重新划分。独立行索引只能证明“没有复用同一行编号”，不能证明业务上没有泄漏。

## 3. 先运行完整演示

在 VS Code 打开 `01_学习指南/07_传统机器学习与数据分析/示例工程`，从 [README 代码导航](../示例工程/README.md)打开 [calibration_demo.py](../示例工程/calibration_demo.py)。PowerShell 也位于该工程目录，运行：

```powershell
..\..\..\.venv\Scripts\python.exe calibration_demo.py
```

三个 `..` 回到仓库根，共享解释器执行指定脚本。命令不传参数，数据量、模型、方法与 5 箱约定均在源码中预先固定。不要为使输出好看而遍历随机种子。

在本次核对的 Python 3.13.12、NumPy 2.5.3、scikit-learn 1.9.1 下，主要输出为：

```text
train=720, calibration=240, test=240
固定方案：逻辑回归 + sigmoid；未根据 test 选模型或校准法
原模型: Brier=0.181333, ECE(5)=0.035047, LogLoss=0.544993, AP=0.528163
校准后: Brier=0.186542, ECE(5)=0.053182, LogLoss=0.556782, AP=0.528163
```

两行指标中间还有可靠性表，不必把完整输出逐字抄到教材。版本变化可能带来浮点或算法实现差异；记录实际版本与输出，不用修改程序去“凑”上述数值。

这里 **Brier、ECE 和 LogLoss 都变大了**。LogLoss 是二分类对数损失，也叫交叉熵损失：实际标签为 1 时看 `-ln(p)`，为 0 时看 `-ln(1-p)`，再对样本平均；对数底数为 e，越小越好。概率极端却预测错时惩罚大。更详细的对数与损失解释见 [[01_学习指南/05_数学概率与优化/逐讲学习/06 熵交叉熵与KL散度|交叉熵]]；库对 0/1 概率采取数值保护，不应据此说这些极端预测风险很小。

该结果只能支持：“在这次固定合成数据及划分上，这个校准方案没有改善所列概率指标。”它既不证明校准总无用，也不意味着代码出错。基础模型可能已经较合适，校准集只有 240 条，额外拟合也有样本波动。

AP 相同表明本次排序保持不变，而概率数值变了。严格递增的映射会保持排序；但不要把这个结论推广到所有校准方案。保序映射会产生并列，多个模型的概率平均也可能改变排序。即使排序不变，固定 0.5 阈值下的类别预测也可能变。[方法背景：scikit-learn 校准指南](https://scikit-learn.org/stable/modules/calibration.html)。

### 看一箱，而不是只看一个总分

原模型的 `(0.6,0.8]` 箱只有 5 条，平均概率约 0.6607、实际正例比例 0.8。0.8 在这里仅是 4/5；少一条正例就会变为 3/5=0.6。不能把这个小箱的偏差解释成稳定规律。

校准后 `(0.6,0.8]` 和 `(0.8,1]` 都没有样本。不是高概率事件都预测对了，而是预测不再落入这些区间。比较两个可靠性表时，同一箱的成员会改变；不能把两个箱当作固定客户的前后配对实验。

## 4. 自己组装一次调用

新建 `lesson_calibration.py`，复制下面完整小例子。这里将中间划分显式命名为 calibration，便于读清用途：

```python
from app.data import make_customer_dataset
from app.modeling import split_data
from calibration_demo import (
    fit_base_model,
    fit_calibrator,
    probability_metrics,
    require_disjoint_rows,
)

splits = split_data(make_customer_dataset())
x_calibration = splits.x_dev
y_calibration = splits.y_dev
require_disjoint_rows(splits.x_train, x_calibration, splits.x_test)

base_model = fit_base_model(splits.x_train, splits.y_train)
calibrated_model = fit_calibrator(base_model, x_calibration, y_calibration)
for name, model in [("原模型", base_model), ("校准后", calibrated_model)]:
    probabilities = model.predict_proba(splits.x_test)[:, 1]
    metrics = probability_metrics(splits.y_test, probabilities, n_bins=5)
    print(name, f"Brier={metrics['brier']:.6f}", f"ECE={metrics['ece']:.6f}")
```

在相同工程目录运行：

```powershell
..\..\..\.venv\Scripts\python.exe lesson_calibration.py
```

预期两行 Brier、ECE 与完整演示一致。逐步看源码时注意：

1. `fit_base_model` 先检查训练标签同时包含 0、1，然后组装既有预处理器与逻辑回归，调用 `fit`。本课固定 C=1.0；C 是正则化强度的倒数，不是校准强度。
2. `fit_calibrator` 先确认基础模型已经拟合、类别为 `[0,1]`、校准标签含两类，再构造 `CalibratedClassifierCV(FrozenEstimator(fitted_model), method="sigmoid", ensemble=False)`，最后只传校准数据给 `fit`。
3. `ensemble=False` 明确只保留一个基础模型／校准器组合；因为使用已拟合的冻结模型，这里不会再做五折基础模型训练。类名有 CV 不表示每一种用法都实际交叉验证。
4. `predict_proba` 返回形状为 `[样本数,2]` 的数组。`[:,1]` 选择所有行的第二列。它代表正类 1 是因为本课检查了 `classes_=[0,1]`，不能对任意标签模型机械假定第二列的业务含义。
5. 只有最后评估函数接收测试标签。测试特征用于预测，测试标签没有进入两个拟合函数。所有输出只打印，不写文件。

循环中的 `name, model` 把每一对“显示名称、模型对象”拆开，方便对两套预测使用相同评分函数。源码 `require_disjoint_rows(*feature_groups)` 的星号表示可接收多组表格：三份或后面练习的四份都可以逐一检查。`set` 保存已经出现的行索引，`intersection` 找出重复索引；这项检查依赖保留原始索引，不能靠重编号来消除真实重叠。

## 5. 校准、阈值与方法选择要分开

校准修改概率映射；阈值选择根据概率与业务成本决定动作。即使校准更好，也不能自动证明 F1、成本或某个固定阈值下的准确率更好。

本课没有选阈值，也没有在 sigmoid 与 isotonic 之间选优。如果需要选校准法、是否保留校准，或重新选业务阈值，增加独立开发集，或设计正确的交叉验证流程。完成选择后再对保留的最终测试集评价。已经看过的测试集可以继续用于探索，但必须标记为探索数据；不能把探索过程清零后重新称作未见测试集。

在已有生产模型上追加校准时，要一起保存基础模型、预处理、类别顺序和校准器的版本。基础模型变了，旧分数与标签的关系可能改变，旧校准器不应直接视作仍然有效。本课没有实现模型持久化、线上漂移检测或多分类校准。

## 6. 练习与答案解析

### 跟做：写一段不夸大效果的结论

用四句写清数据、方法、观察、限制。完成标准：包含三份样本量，明确三项概率指标变差与 AP 未变，不把合成结果外推到真实客户。

> [!example]- 参考答案
> 使用 1200 条合成续费记录，按 720/240/240 分成训练、校准和测试。预先固定逻辑回归及 sigmoid，用独立校准数据学习映射。此次测试上 Brier 从 0.181333 增至 0.186542，ECE 和 LogLoss 也增大，AP 为 0.528163 未变。该方案在这次划分上未改善概率指标；小样本与合成机制限制了结论，不能据此保证真实场景效果，也没有据此继续在 test 上选方法。

### 独立：证明校准没有重新训练基础模型

校准前复制基础模型的 `coef_`（权重）与测试概率，校准后比较它们；再翻转测试标签，检查评分改变而预测不变。提示：`np.array_equal` 逐元素比较，`.copy()` 保存一份独立数组。完成标准：说明冻结检查与“没有泄漏”检查为什么是两件事。

> [!example]- 参考答案
> 保存为 `lesson_frozen_calibration.py` 并用共享解释器运行：
> ```python
> import numpy as np
> 
> from app.data import make_customer_dataset
> from app.modeling import split_data
> from calibration_demo import fit_base_model, fit_calibrator, probability_metrics
> 
> splits = split_data(make_customer_dataset())
> base_model = fit_base_model(splits.x_train, splits.y_train)
> weights_before = base_model.named_steps["classifier"].coef_.copy()
> base_before = base_model.predict_proba(splits.x_test).copy()
> calibrated = fit_calibrator(base_model, splits.x_dev, splits.y_dev)
> print(np.array_equal(weights_before, base_model.named_steps["classifier"].coef_))
> print(np.array_equal(base_before, base_model.predict_proba(splits.x_test)))
> 
> probabilities = calibrated.predict_proba(splits.x_test)[:, 1]
> score = probability_metrics(splits.y_test, probabilities)["brier"]
> changed_score = probability_metrics(1 - splits.y_test, probabilities)["brier"]
> print(np.array_equal(probabilities, calibrated.predict_proba(splits.x_test)[:, 1]))
> print(score != changed_score)
> ```
> 四行应为 True。`named_steps` 按名字取 Pipeline 中的步骤；`coef_` 是拟合后的权重数组。翻转标签仅用于这个隔离性实验，不能改真实标签来提高分数。冻结只保证原模型没重新拟合；若错误地把 test 标签传给校准器，基础模型仍可能完全不变，所以还必须检查数据流。

### 迁移：还要选择业务阈值时，怎样留数据

在原先 240 条中间划分中再分出 120 条校准、120 条开发数据，保持原 720 条训练与 240 条 test。只演示划分，暂不拟合或读取最终测试成绩。完成标准：四组索引无交集，并准确说出每组用途；不能声称 120 条一定够用。

> [!example]- 参考答案
> 保存为 `lesson_four_splits.py`：
> ```python
> from sklearn.model_selection import train_test_split
> 
> from app.data import make_customer_dataset
> from app.modeling import split_data
> from calibration_demo import require_disjoint_rows
> 
> splits = split_data(make_customer_dataset())
> x_calibration, x_selection, y_calibration, y_selection = train_test_split(
>     splits.x_dev,
>     splits.y_dev,
>     test_size=0.5,
>     random_state=34,
>     stratify=splits.y_dev,
> )
> require_disjoint_rows(splits.x_train, x_calibration, x_selection, splits.x_test)
> print(len(splits.y_train), len(y_calibration), len(y_selection), len(splits.y_test))
> ```
> 输出 `720 120 120 240`。`test_size=0.5` 只表示把这里传入的中间数据分出一半，不表示整体最终 test；返回变量 `x_selection/y_selection` 是用于选方法或阈值的开发集。`stratify` 尽量维持两类比例。train 拟合基础模型，calibration 拟合映射，selection 选方法／阈值，test 最后评价。校准和开发集变小会增加不确定性，真实方案需要样本量评估或交叉验证，不能只照抄比例。

## 7. 错误排查与后续

| 现象 | 先检查什么 |
|---|---|
| 找不到 sklearn.frozen | 核对当前解释器和 sklearn 版本；本课已在共享 1.9.1 验证。不要自行升级，按根 AGENTS 安装审批流程处理 |
| NotFittedError | 是否先调用 `fit_base_model`，再冻结并校准 |
| 提示拟合数据需要两类 | 检查划分后的标签数量，不能补造标签；增加数据或重新设计划分 |
| 提示重复行索引 | 不要重置索引来绕过检查；先查是否复用了样本，再检查业务实体是否也重叠 |
| 校准后分数更差 | 可以是正常实验结果；保留输出、核对数据边界和版本，不保证校准必胜 |
| 所有分数变成 0/1 | 检查是否误传分类标签、使用了过拟合映射，或错误抽取概率列 |

可在本工程运行 `..\..\..\.venv\Scripts\python.exe -m pytest test_calibration.py -q` 查看边界检查；测试通过只说明已覆盖行为符合预期。完整实测与限制见 [[90_参考与维护/单元验证/07 传统机器学习与数据分析验证记录|作者验证记录]]。回到第 11 讲，将数据用途和未改善的方案也写进报告。

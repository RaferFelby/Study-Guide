## 这一讲要解决什么问题

模型要在未来的新样本上工作。若训练过程中提前看到了最终测试数据的答案或统计特征，我们得到的分数就不再是公平的“未来表现”估计。这种偷看称为**数据泄漏**（data leakage）。

## 前置知识：拟合与预测

模型的 `fit` 是从示例中学习参数；`predict` 是把学到的规则用于新输入。训练集用于 `fit`，开发集（dev/validation）用于比较模型、调设置和选择阈值，测试集只在方案确定后做一次最终评估。测试集不能反复参与选择，否则它也变成开发集了。

## 随机分层切分的示例

工程中的 `split_data` 使用 `train_test_split`。它先留出 40%，再把这部分平分为 dev 和 test，于是最终约为 train/dev/test = 60%/20%/20%。`stratify=labels` 尽量让三份数据中的 0/1 比例相似；`random_state` 固定切分，便于复现。

```python
features = frame.drop(columns="renewed")
labels = frame["renewed"].astype("int64")

x_train, x_remaining, y_train, y_remaining = train_test_split(
    features, labels, test_size=0.4, random_state=34, stratify=labels
)
x_dev, x_test, y_dev, y_test = train_test_split(
    x_remaining, y_remaining, test_size=0.5, random_state=34,
    stratify=y_remaining
)
```

`x` 是模型输入，`y` 是正确答案；`remaining` 是第一次切分后暂存的 40%。两次切分都分别处理输入和标签，因此样本与答案的行顺序保持对应。

随机分层适合“每一行可近似独立抽取”的教学数据。它不适用于所有现实任务：同一用户有多行时，应按用户分组切分，避免用户同时出现在训练和测试；预测未来时应按时间先后切分，不能让较晚记录去预测较早记录。切分方法要服从数据如何产生、模型在何时使用。

## 为什么预处理也必须在 Pipeline 中

填补缺失和标准化也会从数据计算信息。比如均值填补要先计算均值；如果先对全表计算，dev/test 的分布就被传回了训练过程。`Pipeline` 把处理步骤和模型连在一起：调用 `fit(x_train, y_train)` 时，填补器和标准化器只从训练输入学习；调用 `predict` 时，使用已保存的训练统计量转换新数据。

本工程的处理分两条路径：

- 数值列：用训练集中的中位数填补，再标准化。标准化把数值按训练集均值和标准差缩放，便于逻辑回归比较不同单位的特征。
- 类别列：用训练集中最常见类别填补，再做独热编码。独热编码把 `basic`、`plus` 等类别转换成 0/1 列；`handle_unknown="ignore"` 让新类别不会让预测直接报错。

这些组件都由 `ColumnTransformer` 与 `Pipeline` 组合，见 [app/modeling.py](../示例工程/app/modeling.py) 的 `make_preprocessor` 和 `make_candidate_models`。


三份大小应为 720、240、240；标签比例接近但不必完全相等。接着运行 `train.py`。预处理器不会在数据切分之前拟合；每个模型的 pipeline 在训练集上调用 `fit`。

试着在 `split_data` 前把 `frame["age"].fillna(frame["age"].median())` 加到整张表，再说明为什么这是泄漏风险。修复方式是将填补放在 `SimpleImputer` 中，让 pipeline 在 `x_train` 上 `fit`。

## 常见错误

- **先对完整数据做标准化/填补/特征选择，再切分。** 拟合这些变换时已经用到了留出数据；把转换器放进 pipeline，并把 pipeline 交给交叉验证。
- **切分后忘了对齐标签。** 输入与答案必须来自同一批行；优先使用同一次切分函数返回的 `x_train` 与 `y_train`。
- **对重复用户随机拆行。** 同一个人的历史信息可能泄漏到测试集；使用 group-aware split，并保证组不会跨集合。
- **时间预测仍然随机切分。** 随机切分可能让模型用未来训练、过去测试；按预测时点排序后做时间切分。
- **看过测试分数后多次调参。** 每次依据测试反馈修改方案，都在间接使用测试集；模型选择放 dev/CV，测试结果只在最终方案确定后报告。

阅读 `app/modeling.py`，分别指出哪一步创建训练输入、哪一步创建测试输入、哪一行真正拟合 Pipeline。

> [!example]- 参考答案
> `split_data` 中 `frame.drop(columns=TARGET_COLUMN)` 创建输入；第二次 `train_test_split` 返回 `x_test`；`train.py` 的 `pipeline.fit(splits.x_train, splits.y_train)` 才会拟合填补器、编码器、缩放器与模型。

### 独立练习

想象每位客户各有 12 个月记录。写下一个避免同一客户跨训练/测试集的切分方案，并说明比例为何可能不再精确是 60/20/20。完成标准：同一客户 ID 只出现在一个集合。

### 迁移练习

你的数据是 2024 年 1 月到 2025 年 12 月的按日故障记录，要预测下个月的故障。画出训练、开发、测试的时间顺序，并指出不能随机切分的原因。

> [!example]- 参考思路
> 训练用较早月份，开发用随后月份，测试用最新的完整月份。按预测时间排序，才能模拟真实部署；还要确认特征没有使用预测截止时间之后的信息。

## 本讲小结

切分先于任何会“从数据学习统计量”的预处理。训练集拟合、dev 选择、test 最终评估；分组、时间和分层切分各有适用条件，必须按样本生成与部署方式决定。

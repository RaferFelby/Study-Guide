## 七、推荐执行顺序与里程碑

### 先修关系与首次学习顺序

- 项目主线：2/4 的基础 → 12 → 13/14 的最小实现 → 15/16 → 17、35/36 → 28/29；3、26、30 从第一个可运行版本开始。
- 训练主线：1 的必要数学 → 5 → 7/9 → 8/10 → 11/21～25；不把完整手写 Transformer 作为开始 RAG 的前提。
- 面试基础：33 从第一周持续练习；35 随数据库工具学习；34 在算法分支中提前。
- FDE 主线：31 的需求拆解 → 35/36 → 37 → 38；沟通、演示和交接与开发同步。

### 八周起步计划（每天 2 小时，约 112 小时）

这是岗位未定时的默认探索路线，不代表八周掌握全部 38 项。下表每周 14 小时已包含学习、排错、算法/SQL 和求职工作；超过两小时的额外时间优先用于修复和复习。若已明确选择传统算法、LLM 训练或推理系统，可从第二周按下方替换表切换，不必先做六周 Agent 项目。

| 周次 | 本周范围与模块 | 核心交付 | 14 小时分配 |
|---|---|---|---|
| 第 1 周 | 2/3/4/12 基础、33；先整理 3 条岗位描述 | 可运行的调用/模拟适配器、配置、测试、README、简历初稿 | 项目 7h，基础 4h，练习 2h，岗位整理 1h |
| 第 2 周 | 13/14/16 最小实现、26 起步；岗位样本扩到约 5 条 | 文本检索、引用、一个只读工具、20 条开发样例、短演示 | 项目 8h，原理 2h，练习 2h，投递准备 2h |
| 第 3 周 | 3/15/17/35 | 只读 SQL/统计工具、参数校验、超时、错误测试；记录 5 条失败 Case | 项目 8h，基础 2h，练习 2h，投递复盘 2h |
| 第 4 周 | 4/28/36 基础 | API、流式或普通响应、请求 ID、简单界面、Docker 启动说明 | 项目 8h，基础 2h，练习 2h，投递复盘 2h |
| 第 5 周 | 14/26/30 | 评估集扩到约 50 条，比较一个检索改进，报告成功数/总数与失败分类 | 项目 7h，原理 3h，练习 2h，投递复盘 2h |
| 第 6 周 | 29、31、基础补课 | 权限/注入/异常测试、需求与架构说明、前五周缺口修复 | 项目 6h，补课 4h，练习 2h，投递复盘 2h |
| 第 7 周 | 只选一个岗位分支 | Agent：工作流对照；LLM：训练小实验；FDE：系统适配；泛算法：传统 ML 基线 | 分支实验 8h，原理 2h，练习 2h，投递复盘 2h |
| 第 8 周 | 30/38、岗位面试 | 发布可复现版本、项目报告、模拟面试、修订简历 | 修复与文档 6h，模拟面试 4h，练习 2h，投递复盘 2h |

第 1 周即可筛选职位并投递符合自身条件的机会；第 2 周计划达到“携带 MVP 投递”的门槛，不承诺届时具备所有岗位竞争力。若代码基础或环境配置超出预算，将同一周的范围拆成两周，按实际产出更新简历。

训练分支只有在模块 5/7/9 已完成必要先修时才进行 LoRA；否则第 7 周完成 PyTorch 小模型与标签构造实验，把 LoRA 延后。首八周只做一个检索改进和一个岗位分支，DPO、多机训练、复杂 OCR、多 Agent、任意代码执行均可后置。

### 前两周每日任务（默认探索路线）

每天合计 120 分钟；“项目”包含测试、调试与文档，“基础/原理”使用第十三节对应入口。下表细分上述两周预算，不增加额外学习时间。题目练习可用于重做和复习，不要求每天做新题。

| 日次 | 当天范围与交付 | 分钟分配 | 当天自测或通过条件 |
|---|---|---|---|
| D1 | 创建虚拟环境和项目入口；实现读取 UTF-8 文本的函数 | 项目 50、基础 40、练习 20、岗位整理 10 | 能重新打开终端运行；文件不存在时给出清楚错误 |
| D2 | 把配置、数据读取、主程序拆成三个模块；加入日志 | 项目 60、基础 40、练习 20 | 能解释导入关系，配置缺失时不会悄悄使用错误值 |
| D3 | 定义模型调用接口，接一个已有可用模型后端；mock 单独标记 | 项目 70、基础 30、练习 20 | 输入、输出、模型/模式、耗时均可记录；未接真实模型时标为工程样例 |
| D4 | 定义结构化响应；检查必填字段、字段类型和解析错误 | 项目 70、基础 30、练习 20 | 合法、缺字段、类型错三组输入有不同且可解释的结果 |
| D5 | 为正常、错误、超时添加测试；固定随机/外部依赖 | 项目 70、基础 30、练习 20 | 测试能独立运行，不依赖真实网络；能解释 mock 不代表效果合格 |
| D6 | 整理 README 与本地 Git 提交；写一页简历草稿 | 项目 60、基础 30、练习 20、岗位整理 10 | 从另一空目录按 README 重建环境并运行；未实现内容标注清楚 |
| D7 | 复现与周测；记录三个 JD 的共性和个人缺口 | 项目 40、基础 40、岗位整理 40 | 完成下方 G0/G1；决定保留探索路线还是切换岗位分支 |
| D8 | 收集/编写 3～5 篇短文档，按段落切分，保存稳定来源 ID | 项目 80、原理 20、练习 20 | chunk 可定位原文；空文档、重复导入有预期结果 |
| D9 | 用固定规则或稀疏检索实现 Top-K，列出命中文段 | 项目 80、原理 20、练习 20 | 对五个已知问题人工检查证据；语义检索作为后续对照 |
| D10 | 把检索结果加入模型输入，返回回答和引用 ID | 项目 80、原理 20、练习 20 | 能区分未检索到和检索后答错；真实生成未接通则保留检索 Demo 标签 |
| D11 | 实现一个只读工单查询工具及参数校验、模拟超时 | 项目 80、原理 20、练习 20 | 正确 ID、不存在 ID、非法参数、超时均有测试 |
| D12 | 按第十四节补齐 20 条开发样例，先评 10 条 | 项目 60、原理 20、练习 20、投递准备 20 | 每条有预期行为、证据或检查方法；开始前固定评分规则 |
| D13 | 评完全部样例，统计失败并写短报告；录制演示 | 项目 60、原理 20、练习 20、投递准备 20 | 报告成功数/总数、超时数、案例 ID；演示正常与失败路径 |
| D14 | 从干净环境复现，完成 G2；扩充岗位清单并修订简历 | 项目 40、投递准备 80 | 满足第八节所选分支门槛则携作品投递，否则说明实际进展 |

D9 的词项检索可先用简单规则或字符级检索；它是可解释的检索基线，不应被写成已经完成 Embedding/Reranker。D11 如果采用用户指定工具或规则路由，需明确标为工具集成；只有真实模型完成工具选择、参数生成和结果回传，才称为模型工具调用。

### 自测关卡与未通过时的处理

“独立”允许查看官方文档和自己的笔记，不能直接复制完整答案后视为掌握。每道测试保留输入、输出或讲解记录。

| 关卡 | 必须能完成的自测 | 未通过时的处理 |
|---|---|---|
| G0 编程起点，D1～D2 | 独立写函数读取 JSON/文本；用字典统计工单状态；处理缺字段；解释循环复杂度 | 先用 2～4 个学习时段补函数、容器、文件和异常；后续任务顺延 |
| G1 工程闭环，D7 | 从空环境启动；执行三类测试；解释模块导入；手改一个字段并同步修复测试 | 暂缓 RAG/模型扩展，先修复启动和测试；依赖问题可用标准库小例子定位 |
| G2 MVP 证据，D14 | 完整运行 20 条样例；解释一个误答及来源；解释一个超时；独立演示所选分支 | 只保留命令行、短文本和一个工具；真实模型未接通时不宣称端到端 AI 效果 |
| G3 训练先修，LoRA 前 | 写一次 forward/loss/backward/update；打印张量形状；说明 causal mask；正确对齐标签；有效 label 非零；小样本能过拟合 | 哪项失败补哪项：模块 5、7 或 9；暂停 LoRA，不通过增大模型掩盖数据问题 |

G3 是进入训练实验的必要技术检查，不要求先精通模块 7 的全部优化内容。没有触发该阶段时不占用前两周预算。

### 明确方向后的任务替换（相同时间预算）

| 所选方向 | D8～D11 替换内容 | D12～D14 证据 | 第 3～6 周替换重点 |
|---|---|---|---|
| 传统算法 | 清洗一个小数据集、固定切分、训练简单基线与线性/树模型 | 完整保留集指标、误差样例、无泄漏说明；不使用 20 条代替完整测试集 | 特征、交叉验证、错误切片和编程面试；无需 RAG/工具系统 |
| LLM 算法/训练 | 先过 G3；未过先完成 PyTorch 小模型；通过后再处理语言模型样本 | 数据/标签测试、训练曲线、保存/重载；未微调则不写 SFT 成果 | Transformer 必要基础、SFT/LoRA、小规模对照与误差分析 |
| 推理/系统工程 | 跑通一个模型/已有服务，定义输入长度、输出长度、计时和错误记录 | 可重跑的基准、延迟/吞吐/显存可观测项、一次受控配置对比 | prefill/decode、并发、缓存、服务恢复和压测；无需知识库 |
| FDE | 明确一个用户流程，接入一个真实或模拟数据源，做最简输入/输出界面 | 一页需求、正常与失败 UAT、演示与启动说明 | API/SQL 集成、权限、用户反馈、交接；不要求模型训练 |

D1～D7 中的模型调用可在传统算法分支换为统一预测接口，结构化输出与超时测试换为预测返回格式、非法输入和依赖失败测试。G2 的“20 条”仅适用于默认探索路线；其他方向按本表和第八节自测。

### 岗位深化方向（可提前选择）

以下是作品组织建议，具体优先级按目标 JD 调整；岗位名称在不同公司可能指向不同工作。

| 方向 | 优先模块 | 需要展示的证据 | 初期可延后 |
|---|---|---|---|
| Agent / AI 应用工程 | 12～17、26、28～30、35/36 | 可运行应用、RAG/工具评估、异常 trace、部署 | DPO、CUDA、全参训练 |
| LLM 算法/微调 | 1/5、7～10、21/25/26、34 | 数据处理、训练配置、保留集对照、排错分析 | 多工具复杂规划、完整前端 |
| 大模型推理/系统工程 | 4/8/11/27/28/36，按 JD 补 6 | 显存估算、推理压测、优化前后对照 | 偏好训练、长期记忆 |
| FDE（前线部署工程） | 12～17、28/29、31、35～38 | 需求到验收的闭环、系统集成、演示、交接文档 | 深度训练、算子开发 |
| 泛算法工程 | 1/5/33/34 + JD 对应领域 | 无泄漏 ML 基线、特征/误差分析、编程面试能力 | 不相关 Agent 扩展 |

FDE 的客户沟通、数据集成、定制开发和交付重点参考 [Palantir 官方 FDSE 岗位说明](https://jobs.lever.co/palantir/d084b769-6f53-4409-afa8-c183b059b384)；该职位只作为职责样例，不代表所有公司的要求或对个人可投资格的判断。

### 算力与时间安排

- **日常开发**：5070 Laptop 承担编码、测试、数据准备和轻量实验；具体模型能否运行以实测可用显存、驱动和框架支持为准。
- **GPU 实验**：先确认 3090 集群卡数、单机/多机结构、可用时段、磁盘与数据传输方式；先跑单卡小样本，再扩大训练。未实测前不承诺某尺寸模型能训练。
- **多卡理解**：多卡显存不会自动合并成一张大卡。DDP 通常复制模型以提高数据并行吞吐；需要分片时另评估 FSDP/ZeRO 等方案及通信代价，见 [PyTorch DDP 教程](https://docs.pytorch.org/tutorials/beginner/ddp_series_theory)。
- **最小实验流程**：确认 forward/backward → 小样本过拟合检查 → 正式训练 → 固定评估；保存 checkpoint、配置与日志，减少重复占用算力。
- **工具使用**：现有对话助手用于讲解、代码审阅和模拟面试。项目可用模型服务的权限、接口、配额与预算需单独确认；尚未配置时先用 mock 完成工程测试，并标注其不是模型效果评测。
- **时间核算**：训练后台运行时间单独记录；数据清洗、排错、结果检查计入主动学习时间。每周至少安排一次从干净环境启动和独立讲解。

## 八、分岗位求职验收

### 首次投递：最小可展示门槛

本节用于判断何时能带着项目证据投递。执行“通用门槛 + 所选岗位的一行”，不需要完成其他岗位作品；机会筛选和简历准备可以立即开始。

- [ ] 简历包含真实基础、可用时间、项目进展和可访问的作品入口；
- [ ] 一个与所投岗位相关的作品能按 README 启动或重跑实验，有演示或结果报告；
- [ ] 有固定数据/输入、评价规则、实际结果和至少一个失败分析，mock 与真实结果分开；
- [ ] 能独立解释输入到输出的过程、个人实现部分和下一步改进；
- [ ] 已核对 JD 的资格和明确技能要求，缺失技能如实记录，不以本清单代替实际招聘条件。

| 岗位分支 | 首次携作品投递的证据 | 后续增强目标 |
|---|---|---|
| Agent / AI 应用 | 可运行的检索回答或模型工具调用；约 20 条开发样例含正常、无答案、异常；说明引用或工具结果如何校验 | 独立测试集、一个改进对照、工具诊断、API/权限与回归 |
| LLM 算法/微调 | 可复现的相关模型训练实验、标签/数据检查、训练与保留集结果；JD 要求微调经验时补实际 SFT/LoRA | Base/SFT 对照、数据配比或 LoRA 配置实验、退化分析；DPO 按需 |
| 大模型推理/系统 | 可重跑的模型推理或服务基准；输入/输出长度、并发、硬件/后端、质量与失败记录齐全 | 受控优化对照、负载变化、资源瓶颈、重启恢复；无需 RAG 项目 |
| FDE | 一个需求到可运行原型的流程、数据源适配、演示、正常与失败 UAT、安装说明 | 反馈驱动迭代、权限/恢复、配置与运维交接；无需 LoRA |
| 传统算法 | 一个数据清洗到训练/评估的闭环、简单基线对照、合理切分、完整保留集指标与误差样例 | 交叉验证/阈值或特征实验、领域知识、编程面试；无需 Agent |

### 可靠项目阶段：通用增强验收

- [ ] 使用适合所选任务的开发/回归和独立测试数据；Agent 起步可约 50 条，传统 ML 使用完整保留集，推理使用固定负载配置；
- [ ] 至少完成一次可复现对照实验和一份失败分析；
- [ ] 服务型项目有 API、鉴权、日志、超时和部署说明；实验型项目有数据版本、配置、checkpoint 和复现说明；
- [ ] 至少完成一个所选岗位分支的交付物。

### 作品集：按分支选择

以下是长期成果分类，按所选岗位选择，不是全部必做。可放在同一个仓库的不同目录，无需为了仓库数量拆散项目。

- [ ] **模型基础（LLM 分支）**：手写 Transformer + 单元测试 + 形状说明；
- [ ] **微调实验仓库或目录（训练分支）**：Base/SFT（可选 DPO）对照、配置和评估；
- [ ] **Agent 项目（Agent 分支）**：RAG、多工具、状态/规划、异常、安全和 trace；
- [ ] **评估部署（服务/推理分支）**：评估集或基准输入、回归脚本、API、压测和成本；
- [ ] 每个项目都有架构图、快速启动、结果、失败 Case 和限制说明；
- [ ] 不提交密钥、受限数据、大模型权重或无法说明许可的数据。
- [ ] **岗位补充材料**：FDE 的需求/UAT/交接说明，或算法岗的传统 ML 对照报告，按所投方向选择。

### 项目演示：通用要求与岗位场景

- [ ] 通用：能重跑正常路径，展示一个错误案例及定位过程；
- [ ] 通用：展示对照结果与适用条件，未改善时解释原因；
- [ ] 通用：说明实际测得的耗时/资源与限制，无法测量的项目标为未测。

| 方向 | 演示时增加的场景 |
|---|---|
| Agent | 引用或工具轨迹、无答案、工具失败、注入/越权测试 |
| LLM 训练 | 数据/标签抽查、训练与重载、保留集对照、一条退化样例 |
| 推理系统 | 同一负载配置重跑、延迟/吞吐变化、错误与资源瓶颈 |
| FDE | 用户业务流程、数据源失败或权限拒绝、UAT、交接说明 |
| 传统算法 | 数据切分、基线、特征处理、误差切片及泄漏防护 |

### 面试表达题库（按岗位选择）

## 十、范围控制原则

1. 按八周路线交付最小项目，P0 随项目逐步补齐；不以学完所有 P0 作为开始投递的条件；
2. 没有评估集前，不盲目优化 Prompt、模型或工作流；
3. 没有真实需求时，不为使用新框架而增加系统复杂度；
4. 小模型和模拟工具足以验证原理时，不强求昂贵训练；
5. 每增加一个组件，都要说明它改善了什么指标、引入了什么成本；
6. 先做一个能解释、能复现、有评估的主项目，再决定是否增加第二个项目；
7. 优先根据真实 JD 与面试反馈选择一个深化方向，暂缓与当前目标无关的 P2；
8. 遇到超过两次学习时段的阻塞，记录问题并缩小样例或降级范围；环境和算力问题不应长期占据项目时间；
9. 辅助工具生成的代码必须经过阅读、测试和独立讲解，验收关注本人可操作与可解释的能力。

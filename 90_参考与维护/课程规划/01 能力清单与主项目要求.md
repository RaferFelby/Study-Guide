## 一、使用说明

### 1. 优先级

- **P0 核心必修**：主线中持续补齐的能力，不要求全部完成才开始投递；首次投递按第八节的最小门槛执行。
- **P1 进阶强化**：用于提高项目深度和面试竞争力。
- **P2 岗位选修**：根据目标岗位和算力条件选择，不阻塞主线。

模块编号用于查阅，不表示学习顺序。前 32 项保留原编号，新增 33～38 项应按第七节穿插学习。所有优先级均在所选岗位范围内解释：例如传统算法方向不以 RAG 为必修，FDE 方向不以 LoRA 为必修。岗位未定时默认用 Agent/应用工程项目探索；一旦明确方向，可按第七、八节切换任务与验收，不必同时完成全部分支。

本文件是学习方案，不是岗位录用承诺。尚未确认学历/在读状态、毕业时间、实习可用月份、地点与远程偏好；筛选真实职位时先核对这些硬性条件。泛算法岗还可能需要推荐、搜索、CV、预测等具体领域能力，不能仅靠这份 LLM/Agent 路线覆盖。

**阅读顺序**：先看第七节的个人执行路线与前两周任务；第十三节提供学习入口、练习和产物示例，第十四节提供可复制的评估规范；第八节用于判断投递准备程度，第十一节用于每周复盘。新增基础与交付模块 33～38 位于第七节之后。

### 2. 统一完成标准（Definition of Done）

每个模块不能只以“看过、听懂、能解释”为完成标准。实践模块至少保留可运行代码/配置、验证结果、设计与限制说明；理论模块至少保留推导或解释、一个小例子和一次自测。以下证据按模块选择：

1. 可运行代码和固定依赖版本；
2. README：目标、设计、运行方法、结果和限制；
3. 自动化测试或可重复执行的评测脚本；
4. 实验配置、随机种子、数据版本和结果记录；
5. 至少一个基线、一个改进方案和一组对照结果；
6. 失败案例、根因和改进前后对比；
7. 能用 3 分钟讲清原理、取舍和业务价值。

验收中的样本量、时间和练习数量均为起步目标，可根据任务难度调整；它们不代表统计可靠性或录用门槛。对照实验出现“没有改善”也可完成验收，前提是分析原因并据此做出合理决策。开发集用于调参，最终测试集留到方案冻结后评估；反复查看并修改过的样本应视为开发/回归集，不能继续称为未见测试集。

### 3. 贯穿式主项目

岗位未定或选择 Agent/应用工程、FDE 时，可围绕以下项目积累。传统算法方向可将主项目换为工单分类/预测实验；LLM 方向可围绕语言模型训练或推理基准建设。后两种方向按第八节对应分支验收，无需附带完整 Agent 系统。

> 构建一个“企业知识与工单数据助理”：查询公开或合成的产品手册、FAQ、工单表，回答带来源的问题，查询工单统计，生成处理建议；对资料不足、工具失败和越权请求给出明确结果。使用模拟业务时，在 README 中如实标注。

分三次交付，避免一次实现全部功能：

- **MVP**：文本/Markdown 文档检索、带引用回答、一个只读查询工具、命令行或最简页面、20 条评估样例；
- **可靠版本**：混合检索或重排的对照实验、SQL 工具、鉴权、超时、日志、API、Docker、50 条左右评估样例；
- **岗位深化版本**：Agent 分支增加工作流与工具诊断；LLM 分支增加 SFT/LoRA 和推理实验；FDE 分支增加需求澄清、外部系统适配、演示与交接。记忆、复杂规划、MCP 和代码执行器按真实需求选择。

第一版可用模板化 SQL 或固定参数查询，不强制生成任意 SQL；文档先从可直接解析的文本开始，复杂 PDF/OCR 后补。

推荐项目结构：

```text
agent-project/
├─ app/                 # API 与服务入口
├─ agent/               # 状态、规划、工作流
├─ tools/               # 工具定义与适配器
├─ rag/                 # 解析、索引、检索、重排
├─ models/              # 模型与推理适配
├─ training/            # SFT/DPO 数据和训练代码
├─ evaluation/          # 数据集、指标、回归测试
├─ observability/       # 日志、trace、成本统计
├─ tests/               # 单元、集成、端到端测试
├─ configs/             # 可版本化配置
├─ reports/             # 实验和 Case 分析报告
├─ docs/                # 需求、架构、演示与运维说明
├─ integrations/        # 数据库与外部系统适配
├─ scripts/
├─ pyproject.toml
├─ Dockerfile
└─ README.md
```

## 第一阶段：基础能力与可复现工程

### 1. 数学、概率与优化基础（P0）

**学习内容**

- 线性代数：向量、矩阵乘法、秩、特征值、SVD、常用范数；
- 概率统计：条件概率、贝叶斯公式、常见分布、最大似然、置信区间；
- 信息论：熵、交叉熵、KL 散度；
- 微积分与优化：偏导、链式法则、梯度下降、学习率、偏差—方差权衡。

**验收标准**

- [ ] 能从最大似然角度解释交叉熵，并说明它与 KL 散度的关系；
- [ ] 能手算一个小型反向传播例子，并用 PyTorch 自动求导验证；
- [ ] 能用 SVD/低秩近似解释 LoRA 的直觉、收益与局限；
- [ ] 输出一份“训练常用数学公式 + 张量形状”速查笔记。

### 2. Python 工程化（P0）

**学习内容**

- 装饰器、生成器、上下文管理器、异步编程、异常链；
- 类型注解、数据类、协议/抽象接口、模块与包；
- 配置管理、结构化日志、依赖与虚拟环境；
- 性能分析、资源释放、并发安全。

**验收标准**

- [ ] 实现带参数的计时、重试和指数退避装饰器；
- [ ] 用生成器流式处理 10 万条数据，并记录峰值内存；
- [ ] 建立可安装的多模块项目，核心代码通过静态检查；
- [ ] 日志包含时间、级别、请求 ID 和异常堆栈，并支持文件轮转；
- [ ] 不在代码中硬编码密钥，使用环境变量或密钥管理方案。

### 3. 测试、代码质量与实验复现（P0）

**学习内容**

- pytest、fixture、参数化、mock、覆盖率；
- 单元测试、集成测试、端到端测试的边界；
- lint、format、pre-commit、CI；
- 随机种子、数据版本、配置快照、实验追踪。

**验收标准**

- [ ] 为数据处理、工具调用和输出解析编写测试；
- [ ] 模拟超时、限流、非法 JSON 和部分工具失败；
- [ ] 提交后自动运行格式检查、静态检查和测试；
- [ ] 任意实验能由 README 中的一条命令复现主要结果。

### 4. Linux、Git、Docker 与远程开发（P0）

**学习内容**

- Shell、管道、日志检索、进程/磁盘/GPU 监控；
- SSH、rsync、tmux、远程调试；
- Git 分支、冲突、rebase、revert、stash；
- Dockerfile、镜像分层、卷、网络、资源限制。

**验收标准**

- [ ] 能在远程服务器中持久化运行训练任务并恢复现场；
- [ ] 能从日志、GPU 利用率和进程状态定位一次性能问题；
- [ ] 能解释 merge、rebase、reset 和 revert 的适用边界；
- [ ] 项目可通过 Docker 在干净环境启动，且不把密钥打进镜像。

### 5. PyTorch 与训练闭环（P0）

**学习内容**

- Tensor、广播、内存布局、自动求导；
- Dataset、DataLoader、Sampler、collate_fn；
- nn.Module、初始化、优化器、调度器、混合精度；
- 训练/验证、梯度裁剪、Early Stopping、checkpoint、实验追踪。

**验收标准**

- [ ] 从零训练一个两层网络，在固定数据划分下达到预先声明的基线；
- [ ] 包含训练、验证、断点续训、最佳模型保存和 Early Stopping；
- [ ] 记录 loss、任务指标、学习率、梯度范数、吞吐量和显存；
- [ ] 人为制造 NaN、过拟合或梯度爆炸，并提交排查记录；
- [ ] 能解释 AdamW 的解耦权重衰减及其与 Adam + L2 的差别。

### 6. C++、算子与 CUDA（P2）

**学习内容**

- 指针、引用、RAII、模板与 STL；
- Tensor 内存布局和 PyTorch 扩展；
- CUDA Kernel、线程组织、内存访问和基准测试。

**验收标准**

- [ ] 能阅读一个 ATen 或 Triton/PyTorch 算子的核心路径；
- [ ] 实现一个简单自定义算子并校验正确性；
- [ ] 对比自定义实现与原生实现的耗时，解释结果而非只报告数字。

## 第二阶段：Transformer、LLM 与微调

### 7. Transformer 从零实现（P0）

**学习内容**

- Scaled Dot-Product Attention、padding/causal mask；
- Multi-Head Attention、残差、LayerNorm、FFN；
- Pre-Norm/Post-Norm、位置编码与 RoPE；
- Encoder-Decoder 与 Decoder-only；
- 自回归目标：用已有 token 预测下一个 token；teacher forcing、token 级交叉熵与有效监督位置；
- FlashAttention 的分块、在线 softmax 和 IO 优化思想。

**验收标准**

- [ ] 手写 Attention、MHA 和完整 Transformer Block；
- [ ] 对形状、mask、数值稳定性和梯度编写测试；
- [ ] 画出两种 Norm 结构并解释训练稳定性差异；
- [ ] 能从方差角度解释缩放因子；
- [ ] 用长度为 4 的序列画出“输入位置 → 预测目标”对应关系，解释训练可并行计算、生成通常逐 token 进行的原因；
- [ ] 能区分 FlashAttention 的算法收益与具体硬件/版本条件。

### 8. 主流大模型架构与参数估算（P0）

**学习内容**

- RMSNorm、SwiGLU、RoPE、GQA/MQA；
- Sliding Window Attention、MoE、MLA；
- hidden size、FFN size、层数、注意力头与 KV 头；
- 参数量、KV Cache、训练/推理显存估算。
- 推理基础：prefill 处理输入前缀，decode 逐步生成；greedy、temperature、top-k/top-p、EOS 与最大生成长度；
- KV Cache 复用的内容、长度增长与显存代价，以及 TTFT 与逐 token 延迟分别反映的阶段。

**验收标准**

- [ ] 选择明确版本的两种模型，根据 config 估算参数量，误差小于 10%；
- [ ] 估算不同 batch、序列长度和精度下的 KV Cache；
- [ ] 画出模型结构图，标注张量形状和关键差异；
- [ ] 所有架构结论注明具体模型版本，避免把系列名称当成固定配置。
- [ ] 对固定提示对比 greedy 与采样，记录配置和输出；解释温度变化不等于正确率必然提升；
- [ ] 画出 prefill/decode 与缓存增长过程，说明输入长和输出长为何产生不同性能压力。

入门阅读：[文本生成](https://huggingface.co/docs/transformers/llm_tutorial)、[缓存机制](https://huggingface.co/docs/transformers/cache_explanation)和[推理速度与显存](https://huggingface.co/docs/transformers/llm_tutorial_optimization)。具体 API 和计时方式以所用框架版本为准。

### 9. Tokenizer、对话模板与训练样本（P0）

**学习内容**

- BPE、Unigram、SentencePiece 与字节回退；
- BOS/EOS/PAD/UNK、角色和工具调用 token；
- padding、truncation、attention mask、chat template；
- input_ids、attention_mask、labels 与 loss mask。
- causal LM 的标签移位：区分模型内部 shift 和自定义 loss 手动 shift，避免两次移位；padding mask 与监督 mask 作用不同。

**验收标准**

- [ ] 编码单轮、多轮和工具调用对话并逐段解释 token；
- [ ] 正确屏蔽不参与监督的 label；
- [ ] 分别验证训练和批量生成场景中的左右 padding，说明选择依据；
- [ ] 编写测试防止模板升级后出现重复特殊 token 或标签错位。
- [ ] 对 token `[BOS, A, B, EOS]`，解释 logits 的前三个位置分别监督 `A、B、EOS`；自定义 loss 时对齐 `logits[:, :-1]` 与 `labels[:, 1:]`，使用封装模型时先确认它是否内部移位；
- [ ] 检查至少三个样本的有效监督 token 数大于 0，并确认 user/system 的监督屏蔽与 padding 屏蔽符合训练目标。

参照 [Hugging Face 因果语言建模教程](https://huggingface.co/docs/transformers/tasks/language_modeling)，但不能将教程的数据处理配置未经检查直接套用到所有对话模型。

### 10. SFT 与 LoRA 全流程（P0）

**学习内容**

- Alpaca、ShareGPT、OpenAI 等数据格式与清洗；
- packing、数据配比、泄漏检查；
- LoRA 的秩、alpha、dropout、target modules 和合并；
- 梯度累积、检查点、bf16/fp16、warmup、梯度裁剪；
- 全参训练显存构成与训练稳定性。

**验收标准**

- [ ] 对一个小型模型完成可复现的 LoRA 微调；
- [ ] 设置 Base 与 SFT 对照，并使用保留评估集衡量任务指标；
- [ ] 报告 loss、任务质量、显存、耗时和过拟合情况；
- [ ] 对比至少两组 target modules 或秩配置；
- [ ] 用保留集和失败 Case 判断是否改善；若未改善，说明原因与是否保留微调方案。

**岗位选修范围（P2）**：预训练/继续预训练的数据与目标、知识蒸馏的教师/学生及损失、训练吞吐和数据质量权衡。仅当目标 JD 涉及时展开；起步产物是一个小模型对照或方案说明，不要求开展大规模预训练。

### 11. 长上下文、显存与分布式训练（P1/P2）

**学习内容**

- 注意力计算复杂度与激活显存；
- FlashAttention、gradient checkpointing、packing；
- RoPE scaling、YaRN、滑动窗口及外推风险；
- DDP、FSDP、DeepSpeed ZeRO 的适用场景；
- 数据并行、张量并行和分布式 checkpoint。

**验收标准**

- [ ] 实测序列长度变化对显存、吞吐量和耗时的影响；
- [ ] 对比至少两种显存优化方案并记录质量/速度代价；
- [ ] 能根据模型、显卡和目标吞吐量给出单卡/多卡方案；
- [ ] 无多卡条件时完成设计与显存估算，不强制进行昂贵的全参训练。

## 第三阶段：RAG 与 Agent 核心能力

### 12. LLM API、Prompt 与结构化输出（P0）

**学习内容**

- system/user/tool 等消息语义与指令优先级；
- Few-shot、任务分解、上下文组织；
- JSON Schema、受约束输出、解析与修复；
- 超时、限流、重试、幂等性和缓存。

**验收标准**

- [ ] 对同一任务设计三版 Prompt，并以固定评估集比较；
- [ ] 结构化输出同时进行 schema 校验和语义校验；
- [ ] 统计格式成功率、任务成功率、延迟和 token 成本；
- [ ] 对解析失败设置有限重试与可观测的降级路径。

### 13. RAG 数据工程（P0）

**学习内容**

- PDF、网页、表格等文档解析与清洗；
- 固定长度、语义和结构化 chunk；
- 元数据、权限、版本、去重和增量索引；
- Embedding 模型选择与向量数据库基础。

**验收标准**

- [ ] 建立含来源、页码/段落、版本和权限字段的知识库；
- [ ] 对比至少两种 chunk 策略的召回效果；
- [ ] 支持增量更新和删除后的索引一致性；
- [ ] 回答能够返回可验证引用，不凭模型记忆伪造来源。

### 14. RAG 检索、重排与评估（P0）

**学习内容**

- 稠密检索、BM25、混合检索；
- Query Rewrite、多查询、过滤、Reranker；
- Recall@K、MRR、nDCG、答案正确性、忠实度和引用准确率；
- 无答案检测和检索失败诊断。

**验收标准**

- [ ] 构建至少 50 条含答案和证据位置的评估集；
- [ ] 对比纯向量、混合检索和重排方案；
- [ ] 分离测量“没召回”和“召回后答错”；
- [ ] 对无答案问题拒绝编造，并报告覆盖率与误拒率。

### 15. Agent 运行原理与状态机（P0）

**学习内容**

- 观察—决策—行动—反馈循环；
- 状态、消息、工具记录和中间结果；
- ReAct、工作流/状态机与终止条件；
- 最大步数、循环检测、人工确认点。

**验收标准**

- [ ] 画出完整调用链和状态转移图；
- [ ] 实现一个最小 Agent 循环，不把框架调用当作黑盒；
- [ ] 支持最大步数、重复动作检测、取消和最终状态；
- [ ] 通过 trace 定位每一步的状态、工具参数、结果和耗时；重放使用录制结果或 mock，避免重复执行有副作用的操作。日志无需依赖模型未公开的内部推理。

### 16. 工具调用协议与工具设计（P0）

**学习内容**

- 工具 schema、参数描述、返回协议；
- 模型 tool calls、执行、role=tool 回传；
- 输入校验、权限、幂等性和副作用分级；
- 工具粒度、可发现性和返回摘要。

**验收标准**

- [ ] MVP 完成一个工具；深化时按任务需要扩展，并覆盖不同参数或失败情形，不为凑工具数量增加无用功能；
- [ ] 参数、执行前提、错误码和返回结构有明确契约；
- [ ] 有副作用的操作支持确认、幂等键或可恢复机制；
- [ ] 评测工具选择、参数正确性和最终任务完成率。

### 17. 并行工具、异常处理与可靠性（P0）

**学习内容**

- asyncio 并行、依赖关系和结果聚合；
- 超时、重试、指数退避、熔断与降级；
- 部分成功、冲突结果、返回截断；
- 限流、背压与取消传播。

**验收标准**

- [ ] 对无依赖工具并行执行，并与串行延迟对比；
- [ ] 测试超时、限流、重复请求、部分失败和超长返回；
- [ ] 重试只作用于可安全重试的操作，并设置次数上限；
- [ ] Agent 能利用结构化错误重规划或明确告知用户。

### 18. 记忆与上下文管理（P1）

**学习内容**

- 工作记忆、对话摘要、长期记忆；
- 写入、检索、更新、去重、遗忘与隐私；
- token 预算与上下文压缩；
- 记忆、RAG 与业务数据的边界。

**验收标准**

- [ ] 在超过上下文窗口前按 token 预算压缩历史；
- [ ] 记忆条目带来源、时间、用户范围和置信度；
- [ ] 测试记忆命中、错误记忆和用户删除请求；
- [ ] 能说明“用户经历记忆”和“外部知识检索”的不同治理方式。

### 19. 规划、工作流与重新规划（P1）

**学习内容**

- ReAct、Plan-and-Execute、DAG 工作流；
- 子任务依赖、并行调度、检查点；
- 执行反馈、计划修复和人机协作；
- 确定性流程与自主 Agent 的选择边界。

**验收标准**

- [ ] 完成一个包含依赖和并行节点的任务；
- [ ] 子任务失败时能有限次数重新规划；
- [ ] 对比固定工作流、ReAct 和先规划后执行的成功率/成本；
- [ ] 对高风险步骤设置人工确认，不盲目追求全自主。

### 20. MCP 与工具生态（P1）

**学习内容**

- MCP 的客户端、服务端、工具、资源和提示；
- MCP 与直接 Function Calling 的分工；
- 能力发现、权限边界、连接生命周期和错误处理。

**验收标准**

- [ ] 实现或接入一个最小 MCP 服务；
- [ ] 完成能力发现、调用、异常和权限拒绝测试；
- [ ] 能说明何时适合 MCP、何时直接封装函数更简单。

## 第四阶段：数据构造、推理增强与偏好优化

### 21. 推理与工具数据构造（P1）

**学习内容**

- 问题、推理/计划、工具轨迹、最终答案的数据结构；
- 模型生成、人工修订、规则校验和数据去重；
- 答案正确性、轨迹有效性和数据污染；
- 对话模板对齐与 train/dev/test 切分。

**验收标准**

- [ ] 构造一批经过自动校验和人工抽检的数据；
- [ ] 记录数据来源、许可、生成模型和清洗规则；
- [ ] 检查训练集与评估集泄漏；
- [ ] 数据数量由学习曲线决定，不把“500 条”当作通用充分条件。

### 22. 推理时策略（P1）

**学习内容**

- Self-Consistency、Best-of-N、Verifier/PRM；
- 温度、采样次数、推理预算与成本；
- 循环、超长推理和停止条件。

**验收标准**

- [ ] 在固定评估集比较单次采样与多次采样；
- [ ] 同时报告质量提升、延迟和 token 成本；
- [ ] 设置步骤、时间和预算上限；
- [ ] 用对照结果判断是否值得增加采样；无改善时记录结论并停用该策略，也可完成验收。

### 23. DPO 与偏好优化（P1）

**学习内容**

- chosen/rejected 数据、DPO 目标、reference 模型和 beta；
- SFT、DPO、PPO 的目标与工程差异；
- 偏好数据偏差、长度偏好和过优化。

**验收标准**

- [ ] 从 SFT checkpoint 跑通一次 DPO；
- [ ] 比较 Base、SFT、DPO 的盲测或固定评估结果；
- [ ] 分析至少一种偏好偏差或能力退化；
- [ ] 无合适数据/算力时允许做小模型实验，不为“跑通流程”浪费资源。

### 24. 规划与工具使用微调（P1）

**学习内容**

- 计划、ReAct、工具选择和参数生成数据；
- 无效轨迹过滤与失败轨迹利用；
- 训练后格式、工具和端到端能力评测。

**验收标准**

- [ ] 建立格式正确、语义正确、执行成功的分层指标；
- [ ] 对比微调前后工具选择、参数和任务成功率；
- [ ] 验证是否损害普通对话或未见工具上的泛化能力。

## 第五阶段：评估、部署、可观测性与安全

### 25. 模型公开基准评测（P1）

**学习内容**

- C-Eval、MMLU、GSM8K、HumanEval 等任务边界；
- 0-shot/few-shot、生成参数、答案抽取；
- 版本、Prompt、量化和随机性对结果的影响。

**验收标准**

- [ ] 使用固定版本和配置评测微调前后模型；
- [ ] 报告置信区间或多次运行波动；
- [ ] 与公开结果比较时列出配置差异，不机械要求固定偏差；
- [ ] 公开基准只作为能力切片，不替代业务评估。

### 26. Agent 评估体系（P0）

**学习内容**

- 场景覆盖、难度分层、黄金答案和轨迹标注；
- 任务完成率、工具选择、参数准确率、证据忠实度；
- LLM-as-Judge、人工盲测、位置偏差与自我偏好；
- 回归集、对抗集和线上指标。

**验收标准**

- [ ] 构建 50～100 条高质量评估集，并保留难例；
- [ ] 将检索、规划、工具、回答等环节分开打分；
- [ ] Judge 与人工标注做一致性检查并抽查争议样本；
- [ ] 每次关键修改自动输出回归报告和成本变化。

样本字段、超时计分、成功判定、人工/Judge 一致性与报告格式统一按第十四节执行；第一轮允许人工评分，不以接入 Judge 作为开始评估的前提。

### 27. 推理服务与性能工程（P0）

首次交付以一个可调用服务及基础性能记录为准；量化、完整并发压测和自托管推理优化属于后续深化。

**学习内容**

- vLLM/PagedAttention、Continuous Batching；
- FastAPI、SSE、请求模型、并发和取消；
- TTFT、TPOT、吞吐量、P50/P95 延迟；
- AWQ/GPTQ 等量化方案及质量代价。

**验收标准**

- [ ] 部署一个可流式返回的模型或兼容服务；
- [ ] 在明确硬件、并发、长度下进行压测；
- [ ] 报告 TTFT、吞吐量、P50/P95、显存和失败率；
- [ ] 若实施量化，前后使用任务指标比较，不能只看 perplexity；未实施时记录其为后续选修。

### 28. 可观测性、可靠性与成本（P0）

**学习内容**

- 结构化日志、trace、metrics 和请求关联；
- token、模型、工具、缓存和基础设施成本；
- 缓存、Prompt 压缩、上下文裁剪、模型路由；
- SLO、告警、灰度、回滚与降级。

**验收标准**

- [ ] 从单次任务追踪到每次模型和工具调用；
- [ ] 仪表盘展示成功率、P95 延迟、token、成本和主要错误；
- [ ] 提出至少两种成本优化并验证质量影响；
- [ ] 定义基础 SLO 和降级策略。

### 29. Code 执行器、沙箱与 Agent 安全（P0）

权限与输入信任边界是核心；任意代码执行器只在项目确有需要时实现，属于 P1 扩展。没有执行器时，将对应验收记为“不适用”，先验证数据库和业务工具的访问边界。

**学习内容**

- 代码执行器、进程/容器隔离、超时与资源限制；
- 文件、网络、凭证和工具最小权限；
- Prompt 注入、间接注入、数据外泄和越权调用；
- 内容安全、审计和红队测试。

**验收标准**

- [ ] 若集成执行器，限制时间、内存、文件路径和网络能力，并测试超限终止；
- [ ] 针对已定义的注入测试集验证工具授权和数据访问边界，记录绕过与残余风险；权限校验在模型外执行，不能只依赖提示词；
- [ ] 构造至少三类注入和越权用例，并记录防护结果；
- [ ] 高风险动作默认拒绝或请求明确确认，并保留审计记录。

### 30. Case 分析与系统联调（P0）

**学习内容**

- 根因分类：检索、规划、工具、模型、上下文、解析、权限和基础设施；
- 错误传播与瓶颈定位；
- 单变量实验和端到端验证；
- 模型、工具、框架三层协同。

**验收标准**

- [ ] 起步记录约 5 条失败 Case，后续持续积累真实或压力测试样例，优先覆盖主要根因；50 条可作为深化目标，不作为首次投递门槛；
- [ ] 标记根因、严重度、可复现步骤和责任组件；
- [ ] 针对 Top 根因做单变量实验并报告改进；
- [ ] 输出一份含数据、结论、限制和后续行动的联调报告。

## 第六阶段：业务分析与前沿判断

### 31. 需求到技术方案（P0）

**学习内容**

- 用户、场景、约束、风险和成功标准；
- 技术子问题拆解与方案矩阵；
- 技术指标到业务指标的映射；
- ROI、优先级、里程碑和停止条件。

**验收标准**

- [ ] 对一个真实或明确标注为模拟的场景拆解不少于五个技术子问题；
- [ ] 每个关键问题比较至少两个方案；
- [ ] 给出数据、算力、延迟、成本、安全和人力约束；
- [ ] 写出 MVP 范围、验收指标、风险和两周迭代计划。

### 32. 论文精读与技术趋势判断（P1）

**学习内容**

- Transformer、LoRA、CoT、ReAct、DPO 与 Agent 综述；
- 论文问题、方法、实验、局限和复现条件；
- 技术成熟度、引入成本、预期收益和退出成本。

**验收标准**

- [ ] 每篇笔记回答：解决什么、为何有效、证据是什么、局限是什么；
- [ ] 至少复现或验证其中一个关键结论；
- [ ] 针对一项新技术写选型建议，明确“采用/试点/观望/不采用”；
- [ ] 区分论文效果、工程可用性和当前业务适配性。

## 补充能力模块：基础与岗位交付（33～38）

### 33. 数据结构、算法与编程面试（P0）

**学习内容**

- 数组、字符串、哈希表、链表、栈/队列、堆、树、图；
- 二分、双指针、滑动窗口、DFS/BFS、回溯、基础动态规划；
- 时间/空间复杂度、边界条件、可读代码与口头解释。

**验收标准**

- [ ] 每周完成 3～5 道代表性题目，保留思路、复杂度、测试与错因；数量只是节奏，不以刷题数代替理解；
- [ ] 对做过的典型题，隔周不看答案独立重写，并覆盖空输入、重复值与极端规模；
- [ ] 完成一次 40 分钟模拟：澄清题意、给出方案、编码、测试和复杂度解释；
- [ ] 在项目中实现或解释一个实际应用，如 Top-K、LRU、DAG 拓扑调度。

### 34. 传统机器学习与数据分析（算法岗 P0，其余 P1）

**学习内容**

- NumPy/pandas、探索分析、缺失值、类别编码和特征处理；
- 线性/逻辑回归、决策树、随机森林、GBDT，XGBoost 按需；
- train/dev/test、交叉验证、时间/分组切分、正则化和超参数搜索；
- Precision/Recall/F1、PR-AUC/ROC-AUC、MAE/RMSE、阈值与类别不平衡；
- 数据泄漏、基线、校准、误差切片与业务指标。

**验收标准**

- [ ] 在一个分类或回归数据集上对比简单基线、线性模型和树模型；
- [ ] 将预处理放入训练 Pipeline，标准化/填补/特征选择只在训练数据上拟合；
- [ ] 按数据生成过程解释切分选择，保留独立测试集；
- [ ] 用混淆矩阵或误差切片解释表现，说明阈值选择的业务代价；
- [ ] 提交一页实验报告，包含未改善方案和适用范围。

预处理与数据泄漏的实践依据见 [scikit-learn 官方常见陷阱指南](https://scikit-learn.org/stable/common_pitfalls.html)。

### 35. SQL、数据库与数据集成（P0）

**学习内容**

- SELECT、JOIN、GROUP BY、子查询、CTE、窗口函数和 NULL；
- 主外键、唯一约束、索引、事务、分页与连接池；
- 参数化查询、只读角色、查询限时/限行、迁移与备份；
- 从文档/API/业务表到统一 schema，增量同步、幂等导入和来源追踪。

**验收标准**

- [ ] 建立产品、工单、用户等小型关系表，用 SQL 回答至少 10 个业务问题；
- [ ] 能解释一次 JOIN 重复计数问题，并测试 NULL 和无匹配数据；
- [ ] 用 EXPLAIN 检查一个慢查询，解释索引选择；
- [ ] Agent 使用受限只读账户、参数化查询和行数/耗时上限；若支持生成 SQL，再加入语句限制和隔离测试；
- [ ] 完成一次重复导入不产生重复数据的验证，以及备份恢复演练。

可从 SQLite 做原型，再按部署需要使用 PostgreSQL；参考 [PostgreSQL 官方教程](https://www.postgresql.org/docs/current/tutorial.html)。

### 36. 后端、网络与系统设计（P0；进阶扩展 P1）

**学习内容**

- HTTP/JSON、REST、状态码、SSE 与 WebSocket 适用范围；
- API 验证、认证/授权、会话、分页、错误响应和请求 ID；
- 进程/线程/协程、阻塞 IO、超时和取消；
- 数据持久化、Redis 缓存的键与失效、任务队列与去重；
- 单体服务到分层设计，容量估算、故障恢复、配置与依赖管理。

**验收标准**

- [ ] 用 FastAPI 等框架提供查询、任务状态和健康检查接口；
- [ ] 验证非法参数、无权限、上游超时、客户端断开和服务重启行为；
- [ ] 画出客户端 → API → 模型/检索/工具 → 数据库的数据流，注明同步/异步边界；
- [ ] 测试用户间的数据与缓存隔离；
- [ ] 只在有重复请求或长任务需求时引入缓存/队列，并说明一致性或重复执行的处理方法。

入门范围可参照 [FastAPI 官方教程](https://fastapi.tiangolo.com/tutorial/)。Redis、队列和微服务不作为 MVP 的强制依赖。

### 37. FDE 需求协作、演示与交付（FDE 岗 P0，其余 P1）

**学习内容**

- 用户访谈：现有流程、使用者、痛点、数据、权限和验收负责人；
- 将开放问题转化为范围、成功指标、依赖、排除项和风险；
- 外部 API/数据库适配、开发与测试环境配置；
- 最简页面：输入、流式/普通输出、引用、工具状态、错误提示；
- 用户验收测试（UAT）、需求变更、发布/回滚、运维交接与故障复盘。

**验收标准**

- [ ] 完成一次真实或模拟需求访谈，记录未确定的问题与假设；
- [ ] 提交一页需求说明和架构方案，明确 MVP 与验收范围；
- [ ] 演示一个端到端业务任务，展示正常、资料不足、权限拒绝或服务故障；
- [ ] 对接一个外部数据源；使用 mock 时清楚标注，接口契约与测试可查看；
- [ ] 交付安装/配置、数据导入、备份、回滚、常见错误处理说明；
- [ ] 做一次 5 分钟业务演示和 10 分钟技术讲解，并记录反馈后的修改。

没有真实客户时使用公开或合成场景演练，不将模拟上线、模拟收益写成真实业务经历。线上云部署是可选验证；先完成本地/自有服务器可复现部署，再根据预算与岗位需求补网络入口等配置。

### 38. 岗位分析、项目表达与投递复盘（P0）

**学习内容**

- 从 JD 提取硬性资格、日常任务、技术要求与加分项；
- 将项目经历写成“问题—个人负责部分—方案—指标—限制”；
- 技术面试、项目追问、现场编码和非技术沟通；
- 投递记录、阶段转化、反馈分类和学习优先级调整。

**验收标准**

- [ ] 收集 5～10 条仍有效的 JD，记录链接、日期、资格条件和当前缺口；
- [ ] 准备一份基础简历，再按目标岗位选择证据，不虚构不同项目；
- [ ] 每个简历指标可追溯到配置、评估集、日志或报告，注明样本量与测试条件；
- [ ] 独立讲解项目中的一个关键函数、一条失败链路和一次设计取舍；
- [ ] 每周复盘投递与面试反馈，只挑一到两个反复出现的缺口补齐；
- [ ] 未完成实验和未上线功能标记为进行中，不写成已有成果。
